# Одновременная демонстрация нескольких экранов

**С 0.61.0: до пяти показов одновременно, предел соблюдает сервер.** В браузере и в клиенте Windows показывать может каждый участник; приложение для Android (0.1.6) показы смотрит (крупно выбранный, остальные в ленте), показывать экран с телефона нельзя (не реализовано).

## Как устроено
- **Предел** — `MAX_SCREEN_SHARES = 5` (`backend/app/services/meetings.py`); при настройке «Только один показывающий одновременно» (`screen.one_sharer_at_a_time`, по умолчанию выключена) — 1. Значение уходит странице в `client.max_sharers`.
- **Страница** перед окном выбора экрана считает занятые места (каждый показывающий, кроме этой вкладки; свои другие устройства — тоже место) и при нехватке сразу пишет «Сейчас экран показывают 5 участников — это предел. Место освободится, как только кто-то завершит показ».
- **Сервер** соблюдает предел и при одновременных нажатиях, и для изменённых или старых клиентов: на каждый webhook `track_published` с источником SCREEN_SHARE участник встаёт в очередь (`shares:<встреча>`, Redis, порядок — время первой публикации), очередь сверяется с живыми показами LiveKit (`screen_sharers`); кто не поместился, у того дорожка выключается на сервере (`mute_published_track`), а страница получает `share_stopped` с `reason: "limit"`, прекращает захват и показывает то же сообщение. Завершённый показ из очереди уходит при следующей сверке — место доступно сразу. LiveKit не ответил — показ не останавливается вслепую. Нужен webhook LiveKit (штатная установка его настраивает).
- **Раскладка** (`frontend/src/stage/stageModel.ts`, `chooseMain`): без закреплений и общей сцены все чужие показы — крупно, сеткой, в порядке начала показа (новый встаёт последним, прежние не прыгают); свой показ крупно не ставится, если в комнате есть кто-то ещё. На телефоне крупно самый свежий, остальные — в ленте. Закрепления зрителя и «Показать всем» ведущего главнее.
- **Проверено:** живой сценарий `tests/live/scenario_multi_screen.py` (шесть браузеров: пять показов, шестой — отказ сервера при одновременном нажатии, кадры всех пяти у зрителя, место освобождается сразу, завершение каждого по одному), `tests/live/desktop_multi_screen.py` (клиент на Electron под Linux с окном выбора экрана + два браузера), `LongCallTest.twoScreenShares_bothArrive` (Android, две демонстрации, эмуляторы в CI), `backend/tests/test_screen_limit.py`.

## Нагрузка
- Исходящий поток каждого показа ≈ 1–3 Мбит/с (профили «чётко/баланс/движение»: 1080p при 15 к/с и слой 720p при 5 к/с) и процессор компьютера показывающего.
- Сервер звонков передаёт каждому зрителю один слой каждого показа, на который он подписан; зрители, у которых окно мало (телефон), получают нижний слой (адаптивный поток), поэтому N показов увеличивают нагрузку на сервер примерно в N раз только для тех, кто их действительно открыл крупно.
- Телефон декодирует видео каждого видимого экрана: в ленте показы маленькие (низкий слой), крупно — один. Пять показов у зрителя на компьютере — пять входящих потоков (адаптивный поток выбирает слой по размеру ячейки); на телефоне крупно один. Рекомендация: в больших комнатах держать 2–3 показа одновременно; для больших трансляций — режим презентации (показ ведут руководители и выступающие).
