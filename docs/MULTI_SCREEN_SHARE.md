# Одновременная демонстрация нескольких экранов — оценка

**Вывод: это настройка, а не ограничение архитектуры; в браузере и в клиенте Windows несколько показов уже работают, в приложении для Android (0.1.3) их можно смотреть, показывать экран с телефона нельзя (не реализовано).**

## Что есть сейчас
- Пока включена настройка «Только один показывающий одновременно» (Администрирование → Показ экрана → «Поведение», `screen.one_sharer_at_a_time`; по умолчанию **выключена**), страница комнаты отвечает второму участнику «Сейчас экран уже показывает другой участник» (`RoomPage.tsx`). Если настройка выключена, ограничения нет: каждый участник публикует свою дорожку `screen_share`, LiveKit пересылает их независимо.
- Какой показ смотреть крупно, выбирает сам зритель (закрепление «у себя» в сцене), а ведущий может вывести нужный всем («Показать всем»); остальные видны компактно. В записи видео крупно идёт показ по общей сцене (см. `docs/VIDEO_RECORDING.md`).
- Приложение для Android (0.1.3): основной показ + лента с остальными экранами («… · экран»), выбор нажатием; у каждого показа свой масштаб.

## Нагрузка
- Исходящий поток каждого показа ≈ 1–3 Мбит/с (профили «чётко/баланс/движение»: 1080p при 15 к/с и слой 720p при 5 к/с) и процессор компьютера показывающего.
- Сервер звонков передаёт каждому зрителю один слой каждого показа, на который он подписан; зрители, у которых окно мало (телефон), получают нижний слой (адаптивный поток), поэтому N показов увеличивают нагрузку на сервер примерно в N раз только для тех, кто их действительно открыл крупно.
- Телефон декодирует видео каждого видимого экрана: в ленте показы маленькие (низкий слой), крупно — один. Рекомендация: не более 2–3 одновременных показов в комнате; для больших трансляций — режим презентации (показ ведут руководители и выступающие).

## Что можно сделать дальше (не входит в 0.53/0.1.3)
1. Подсказка в интерфейсе, почему показ недоступен («включена настройка комнаты»), и кто сейчас показывает.
2. Показ экрана из приложения для Android (MediaProjection + служба переднего плана типа mediaProjection) — отдельная задача: разрешения, уведомление и защита содержимого.
3. Ограничение числа одновременных показов числом, а не флагом (например, не более двух).
