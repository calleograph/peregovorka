# SIP-телефония

Телефонный абонент может позвонить в комнату, а руководитель — позвонить абоненту из комнаты. Абонент отображается среди участников как «Телефон: +7000…», его речь попадает в стенограмму и запись так же, как речь остальных.

Телефония **необязательна и по умолчанию выключена**: служба не запущена, порты не открыты, проверки показывают «пропущено».

## Как это устроено

```
АТС (Asterisk/PJSIP или другая)  ⇄  SIP-транк  ⇄  LiveKit SIP Service  ⇄  LiveKit  ⇄  комната Peregovorka
        SIP signalling + RTP                      (контейнер livekit-sip)             (участник «Телефон: …»)
```

* Используется **собственный** LiveKit SIP Service (контейнер `livekit-sip` рядом с LiveKit). Внешних облачных сервисов нет.
* Asterisk — первый вариант, на который ориентирована документация. Модель данных и интерфейс от АТС не зависят: «SIP-профиль» — это обычный SIP-транк (адрес, порт, транспорт, логин, пароль, номер, разрешённые адреса).
* Профиль при сохранении синхронизируется с LiveKit как исходящий и/или входящий транк. Для комнаты с входящими звонками на время идущей встречи создаётся правило направления (dispatch rule) «внутренний номер → комната»; после встречи оно удаляется.
* Исходящий звонок («Позвонить» в комнате) создаёт SIP-участника в идущей встрече. Звонок ждёт ответа абонента и показывает понятную причину отказа (занято, нет ответа, запрещено, нет маршрута).

## Какие порты нужны

| Назначение | Порты | Кому нужны |
|---|---|---|
| Браузерные участники | 443 (HTTPS) и порты LiveKit RTC (`LIVEKIT_TCP_PORT`, `LIVEKIT_UDP_PORT`) | пользователям |
| SIP signalling | `SIP_SIGNALING_PORT` (по умолчанию 5060), UDP и TCP | только АТС / SIP-провайдеру |
| RTP (голос) | `SIP_RTP_START`–`SIP_RTP_END` (по умолчанию 20000–20100), UDP | только АТС / SIP-провайдеру |

Порты телефонии **никак не связаны** с 443 и RTC-портами браузеров. Одному звонку нужна пара портов RTP; диапазон ограничен намеренно — для большего числа одновременных звонков расширьте `SIP_RTP_END`.

Что показывает администратору «Администрирование → SIP-телефония»: включена ли телефония, работает ли служба, связь SIP → LiveKit, Redis, число и состояние транков, последняя проверка, порт signalling и диапазон RTP.

## Включение

```bash
sudo scripts/sip.sh enable          # LiveKit подключается к Redis, запускается livekit-sip, публикуются порты SIP/RTP
scripts/sip.sh status               # включена ли, какие порты нужны
sudo scripts/sip.sh disable         # контейнер и порты убираются, профили в базе сохраняются
```

То же делает кнопка «Включить телефонию на сервере» в админке (через помощник обновлений). **Перезапуск LiveKit прерывает идущие встречи** — включайте вне рабочих часов.

Параметры в `.env`:

| Переменная | Назначение |
|---|---|
| `SIP_ENABLED` | `yes` / `no` (по умолчанию `no`) |
| `SIP_SIGNALING_PORT` | порт signalling (5060) |
| `SIP_RTP_START`, `SIP_RTP_END` | диапазон RTP |
| `SIP_BIND_ADDR` | адрес привязки портов; для внутренней АТС укажите внутренний адрес сервера |
| `SIP_MEDIA_IP` | адрес, объявляемый в SDP, если сервер за NAT |
| `SIP_ALLOWED_CIDRS` | адреса/подсети АТС для правил файрвола |
| `SIP_IMAGE` | образ LiveKit SIP |

## Безопасность

* **Файрвол не меняется автоматически.** `sudo scripts/sip.sh firewall` показывает правила ufw только для адресов из `SIP_ALLOWED_CIDRS`, `--apply` создаёт их. Без `SIP_ALLOWED_CIDRS` скрипт откажется — открывать SIP всем подряд он не предлагает.
* Внутреннюю АТС **не публикуйте в Интернет**: достаточно разрешить порты с адресов АТС.
* Для входящих задайте «Разрешённые адреса АТС» в профиле — звонки принимаются только с них.
* «Допустимые номера назначения» защищают от случайных и платных звонков: комната не наберёт номер вне списка префиксов.
* Пароль транка хранится зашифрованным (`APP_MASTER_KEY`), нигде не показывается и не попадает в журналы, проверки и тестовые вызовы. Номера в журнале маскируются.
* Создание, изменение и удаление профилей, проверки и тестовые вызовы попадают в журнал аудита без паролей.
* Звонить из комнаты и менять телефонию комнаты могут только руководители; профили и сервер телефонии настраивает администратор.

## Настройка Asterisk (PJSIP)

В PJSIP транк состоит не из одной пары «логин+пароль»:

| В Asterisk | В Peregovorka |
|---|---|
| `endpoint` — параметры вызова, кодеки (`allow=`), caller ID | кодеки, «Caller ID / номер», «Допустимые номера» |
| `auth` — учётные данные | «Логин» и «Пароль» (можно не заполнять, если АТС принимает по IP) |
| `aor` — куда отправлять (`contact=sip:host:port`) | «Адрес АТС», «Порт», «Транспорт» |
| `identify` — сопоставление входящего по IP | «Разрешённые адреса АТС» |
| `registration` | не используется: LiveKit SIP не регистрируется на АТС как телефон |

Ориентир (адреса условные):

```ini
[peregovorka]            ; endpoint для звонков с/на сервер Peregovorka
type=endpoint
transport=transport-udp
context=from-peregovorka
disallow=all
allow=ulaw,alaw,g722
aors=peregovorka
direct_media=no

[peregovorka]
type=aor
contact=sip:192.0.2.20:5060

[peregovorka]
type=identify
endpoint=peregovorka
match=192.0.2.20
```

Здесь `192.0.2.20` — адрес сервера Peregovorka, видимый из АТС. В `extensions.conf` направьте внутренний номер комнаты на `PJSIP/peregovorka`.

## Проверка и диагностика

* **Проверить настройки** — состояние службы, наличие транков в LiveKit, ответ АТС на SIP OPTIONS (если АТС его допускает), список ошибок по шагам. Звонок не выполняется.
* **Тестовый вызов** — реальный звонок на указанный номер; показывает время и причину отказа.
* Коды ответов АТС: 401/403 — нет прав или неверный логин/пароль; 404 — нет маршрута к номеру; 408 — АТС не ответила; 480 — абонент недоступен; 486/600 — занято; 488 — не совпали кодеки или шифрование; 503 — АТС перегружена.
* `scripts/verify.sh`, `smoke-test.sh`, `diag.sh`: при выключенной телефонии — «пропущено», не ошибка.
* Если голос односторонний или пропадает через несколько секунд — почти всегда закрыт диапазон RTP или в SDP объявлен недостижимый адрес (`SIP_MEDIA_IP`).

## Что не проверено автоматически

Тесты используют имитацию API LiveKit: на реальном сервере с Docker, LiveKit SIP и Asterisk при первом включении стоит проверить вручную — исходящий и входящий звонок, звук в обе стороны, появление фразы абонента в стенограмме, сброс правила после встречи, поведение за NAT.
