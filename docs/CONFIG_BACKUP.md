# Резервная копия конфигурации

«Администрирование → Сервер → Резервная копия конфигурации»: **шифрованный экспорт и импорт** всех настроек системы, чтобы восстановить работающую установку на новом сервере.

## Что входит и что нет

| Входит | Не входит |
| --- | --- |
| настройки из «Администрирования» (все группы: хранилища, языковая модель, обезличивание, протоколы, запись и транскрибация, доступ и группы каталога, почта, публичный API, Bitrix24, оформление сайта, журнал и др.) | данные встреч: записи, стенограммы, протоколы, карты разговора, чат, схемы, история |
| подключения к каталогу (LDAP/AD) с паролем учётной записи | журналы (аудит, события), очереди писем, история доставки |
| сертификаты УЦ (публичные части) | пользователи, сессии и токены, фото профилей, подтверждения документов |
| почта (SMTP) с паролем и шаблоны писем | личные шаблоны протоколов пользователей, временные переговорки |
| файловые хранилища (SMB/папка) с паролями | задания переноса записей, отчёты сверки |
| профили внешних API с секретными заголовками | параметры окружения `.env` (адреса базы/Redis/LiveKit, ключи LiveKit, **ключ шифрования `APP_MASTER_KEY`**) |
| постоянные переговорки: настройки, роли и доступ, запись и транскрибация, инструкции, SIP-привязка, пароль (как хэш) | TLS-сертификат веб-сервера (nginx): он лежит вне приложения |
| интеграции публичного API (права, комнаты, адреса) и ключи (как хэш), получатели событий с секретом подписи | идентификаторы транков LiveKit SIP старого сервера (после импорта SIP нужно синхронизировать) |
| SIP-подключения с паролем | |
| документы организации, их редакции, оформление (логотипы) | |

**Секреты, которые хранятся только как хэш** (пароли переговорок, ключи API): их исходное значение в системе отсутствует. Архив переносит хэш, поэтому пароль и ключ **продолжают работать**, но показать или повторно выдать их нельзя. Список таких данных показывается перед скачиванием и в предпросмотре импорта.

## Как это защищено

* Содержимое шифруется **AES-256-GCM**, ключ выводится из пароля архива через **scrypt** (n=2¹⁵, r=8, p=1, случайная соль). Любое изменение файла или неверный пароль — отказ расшифровки целиком.
* Пароль архива — **20 случайных символов** (алфавит без похожих знаков, ≈116 бит). Генерируется сервером, **показывается один раз** с кнопкой «Копировать» и нигде не хранится. Без него архив не открыть — восстановить нельзя.
* Архив **не сохраняется на диске сервера**: собирается в памяти и сразу отдаётся в ответе; при импорте принимается в теле запроса и обрабатывается в памяти; между «проверить» и «применить» сервер ничего не хранит (архив отправляется повторно). Ответ с архивом — `Cache-Control: no-store`, без буферизации в прокси (`/api/v1/admin/config/` в web-nginx без `proxy_buffering`/`proxy_request_buffering`; внешний nginx хоста может буферизовать **шифртекст** — открытые данные в нём не появляются).
* Пароли передаются **заголовками**, не адресом: `X-Archive-Password`, `X-Admin-Password`. В журналы приложения и nginx они не попадают. В аудит пишется только факт (кто, когда, результат, размер/число объектов) — без содержимого и паролей.
* Выгрузка и применение требуют **повторного ввода пароля администратора** (локальный — по хэшу; доменный — повторной проверкой в каталоге); неудачи считаются как неудачные входы. Ввод пароля архива ограничен (10 неверных попыток за 15 минут на администратора).
* Защита от враждебных архивов: предел размера файла (64 МиБ) и размера после распаковки, предел параметров scrypt в заголовке, проверка структуры (допустимы только известные таблицы, столбцы, группы и файлы оформления; имена файлов не используются как пути), проверка типов и границ настроек.

## Импорт

1. Выберите файл → показывается версия, дата и размер (если архив создан **более новой** версией, сообщение — до ввода пароля).
2. Введите пароль архива → «Проверить архив»: сервер ничего не меняет, а показывает, **что будет восстановлено**, что **заменится** на этом сервере, **конфликты** (занятый адрес переговорки со встречами блокирует импорт), **предупреждения о привязке к старому серверу** (адреса и имена серверов, SMB, пути, порты, сертификаты, объекты LiveKit, внешний адрес установки) и список хэшей.
3. Подтвердите предупреждения, введите пароль администратора → «Применить». Всё применяется **одной транзакцией**: при любой ошибке изменения откатываются, сервер остаётся прежним.
4. Секреты шифруются **ключом нового сервера**; идентификаторы записей сохраняются. Пользователи, локальный администратор и сессии **не затрагиваются** — вход под локальным администратором работает до, во время и после импорта. Существующие записи с тем же уникальным именем заменяются (переговорка — только если у неё нет встреч); остальное на сервере остаётся.
5. После применения выполняются проверки (каталог, почта, хранилища, внешние API; SIP отмечается «нужна синхронизация») и показывается отчёт: **работает / требует внимания / ошибка проверки** с подсказкой, что делать.

## Права переговорных без переноса пользователей

Пользователи не переносятся, и это не мешает правам: доступ к переговорке выдаётся **группам каталога** (по DN), а отдельным людям — по **идентификатору каталога** (`objectGUID`), а не по строке в таблице пользователей. После импорта пользователь, впервые вошедший на новом сервере (при том же каталоге), сразу видит свои переговорки, а руководитель переговорки по своему идентификатору получает её настройки. Если каталог на новом сервере другой, группы и идентификаторы не совпадут — доступ по ним не сработает до исправления (в предпросмотре есть предупреждение о назначениях отдельным людям). Личные шаблоны протоколов, фото и подтверждения документов не переносятся.

## Откат файлов и сертификатов при ошибке

Изображения оформления и собранный набор доверенных сертификатов — файлы, а не строки базы, поэтому порядок такой: файлы **готовятся** рядом с боевыми (до фиксации базы) → **подменяются** с сохранением прежних → **фиксируется база**. Любой сбой (в том числе при фиксации) возвращает прежние файлы и откатывает базу; временные и резервные файлы убираются. Набор сертификатов — производный файл, при запуске приложения он пересобирается из сертификатов базы, поэтому даже авария между подменой и фиксацией не оставляет рассогласования.

## Окружение и постоянные тома

* Параметры `.env` не переносятся, но **сохраняется их снимок** (секреты — только «задан/не задан») и при проверке архива **сравнивается с новым сервером**: отличия важных параметров (группы администраторов и допуска из `.env`, внешний адрес, сроки хранения, доверенные прокси, режим cookie и др.) показываются отдельным блоком — их нужно сверить и при необходимости внести в `.env` вручную.
* Каждый **постоянный том** из compose и каждый ключ `.env.example` описан в реестре (`VOLUMES`, `ENV_FILE_PREFIX`); тест сверяет реестр с `deployment/compose.yml` и `.env.example`, поэтому новый том или ключ без решения «переносится ли» не пройдёт. Переносятся изображения оформления; набор сертификатов пересобирается; данные встреч (записи, вложения чата, фото) и состояние сервера (модели, помощник обновления) не переносятся.

## Для разработчиков: реестр конфигурации

Единственное место, где решается, что и как переносится, — `backend/app/services/config_backup/registry.py`: для каждой таблицы (переносится или нет, почему), каждого столбца (`data` / `secret` / `hash` / `reset` / `user_ref`), каждой группы настроек, файлов оформления и каждого параметра `.env`. Тест `tests/test_config_registry.py` **падает**, если появился параметр без политики: новая таблица, новый столбец, новая группа настроек, новая переменная окружения (в том числе прочитанная кодом напрямую через `os.environ`). Поэтому при добавлении настройки нужно либо ничего не делать (поле существующей группы входит в копию автоматически), либо осознанно описать исключение.

* Старые архивы: `registry.TRANSFORMS` — цепочка преобразований схемы (`SCHEMA_VERSION`); архив новее сервера отклоняется понятным сообщением.
* Контейнер: `container.py`; сбор содержимого: `exporter.py`; проверка, предпросмотр и применение: `importer.py`; проверки после импорта: `checks.py`; API: `api/config_backup.py`.
* Привязка к серверу: поля, помеченные `bound` в реестре, плюс эвристика по значениям (адреса, URL, пути) — предупреждения даже для новых полей.

## Проверено / не проверено

Автотесты (25): права переговорок на новом сервере без пользователей, откат файлов и сертификатов (сбой при подготовке и при фиксации), снимок и сравнение окружения, реестр томов и `.env`, контейнер (круг, неверный пароль, подмена, «бомба» параметров, размеры, слишком новый архив), реестр (полнота и обнаружение нового параметра), сквозной перенос между двумя серверами с разными ключами (секреты всех видов, переговорки с паролем, интеграции с ключом, сертификаты, документы, шаблоны, SIP, оформление; данные встреч не переносятся; локальный администратор цел; откат при сбое; конфликт переговорок; враждебное содержимое). **Не проверено:** перенос между реальными серверами с настоящим AD/SMTP/SMB (проверки после импорта на настоящих подключениях), работа через внешний nginx хоста с большим архивом, браузеры кроме Edge.
