# Приложение Windows: быстрый цикл разработки

Три команды — три режима (из каталога `desktop/`, после `npm ci`):

| Режим | Команда | Что делает | Время |
| --- | --- | --- | --- |
| Разработка | `npm run dev` | Electron из исходников; правка оболочки (`src/shell`, общие токены и значки веб-интерфейса) → сборка и перезагрузка окна, правка главного процесса или preload → перезапуск Electron; журнал запуска — в терминале. `-- --fresh` — пустой профиль (как первый запуск у пользователя) | сборка ≈ 0,2 с, перезапуск ≈ 0,5 с |
| Предварительная проверка | `npm run preview` | собранная программа **без установщика** (`electron-builder --dir`: asar, предохранители, значки — как в выпуске) и проверки на ней с пустым профилем: первый запуск, работа без сервера, снимки и вёрстка. В Windows — `release\win-unpacked\Peregovorka.exe`; в Linux — `release/linux-unpacked`, а `-- --win` ещё собирает `release/Peregovorka-<версия>-win-unpacked.zip` для запуска на компьютере Windows | ≈ 1 мин |
| Выпуск | `npm run release -- X.Y.Z --push` | только с `main` и чистого дерева, при разделе `## X.Y.Z` в `desktop/CHANGELOG.md`: типы, модульные тесты, безопасность исходников, `preview`; затем версия, коммит, тег `desktop-vX.Y.Z` и отправка. EXE/MSI, подпись, испытания установки/обновления/удаления и публикацию делает CI — только после своей предварительной проверки на Windows | локально ≈ 2 мин, CI ≈ 30 мин |

Без `--push` выпуск останавливается перед отправкой тега. Совместимый выпуск сервера — отдельно: `./scripts/release.sh` (полный CI обязателен).

## Проверки (`scripts/check.mjs`)

Запускаются и из исходников (`--app dev`), и на собранной программе (`--app <путь к exe>`), всегда с пустым профилем (`--user-data-dir`):

```bash
npm run check -- firstrun --app dev      # приветствие, не «not found»/пустое окно, шаг сервера и ошибки адреса, все вкладки настроек, тема;
                                         # ни одной ошибки в консоли оболочки и в журнале главного процесса (preload, протокол app://, отрисовка)
npm run check -- offline  --app dev      # две организации без доступного сервера: переключение, «нет связи», настройки, диагностика
npm run check -- shots    --app dev      # снимки локальных экранов в out/check: 1280×800 и 800×520, масштаб 100/150/200 %, светлая и тёмная тема;
                                         # нет горизонтальной прокрутки (в том числе внутри блоков), обрезанного текста, наложений, разных высот кнопок и полей
```

**Визуальный круг:** `npm run dev` в одном окне терминала → правка CSS (окно перезагружается само) → `npm run check -- shots --app dev` во втором →
смотреть `out/check/*.png` и строки `FAIL вёрстка …` → исправить. Проверка ловит грубое; снимки всё равно смотрятся глазами.

## Диагностика запуска

`Peregovorka.exe --debug-log` (или переменная `PEREGOVORKA_DEBUG=1`; в `npm run dev` включено всегда): журнал главного процесса — и в терминал,
пути запуска (`userData`, `app.asar`, наличие файлов оболочки), ошибки preload (`preload.error`), консоль оболочки (`shell.console`), ответы протокола
`app://` (`shell.not_found`), сбои отрисовки и процесса окна, необработанные исключения главного процесса. Без ключа предупреждения и ошибки оболочки
всё равно пишутся в `%APPDATA%\Peregovorka\logs\main.log`. Отчёт без интерфейса: `Peregovorka.exe --diagnostics=<файл.json>` (раздел `shell`: отрисован ли мастер).

## CI

* `desktop.yml`, любой коммит в `desktop/`: модульные тесты и типы (Linux) → **preview** на Windows (`npm run preview`, снимки — артефакт `peregovorka-preview-screens`).
  Установщики не собираются, серверные тесты не запускаются (`ci.yml` пропускает изменения только клиента).
* `main`, теги `desktop-v*`, ручной запуск: после preview — EXE/MSI, подпись, установка/обновление/удаление, обновление из приложения, агент подписи, выпуск.

## Ревизия сборки (2026-10-24)

| Часть | Как сделано | Решение |
| --- | --- | --- |
| Сборка кода | esbuild (`build.mjs`): main, preload, оболочка; значки и токены — из `frontend/` | оставлено: одна сборка за 0,2 с; общий источник с веб-интерфейсом (`tokens.css`, `Icons.tsx`) — без копии |
| Упаковка | electron-builder: asar, предохранители (`electronFuses`), NSIS, подпись `CSC_LINK` | стандартно; добавлены `--dir`-сборки для проверок |
| MSI | WiX 5 из той же распакованной программы (`installer/msi`) | оставлено: цель `msi` electron-builder не даёт свойств MSI для политик с «запоминанием» и записей `Policies\Peregovorka`, нужных для GPO |
| Запуск оболочки | свой протокол `app://shell` + CSP | оставлено (рекомендация Electron вместо `file://`); ошибка 1.0.0 — в адресе файла, исправлена стандартным `pathToFileURL` |
| Обновление | свой модуль ≈ 150 строк: манифест Ed25519 → установщик NSIS `/S --updated --force-run` | оставлено пока: `electron-updater` проверяет только Authenticode издателя и без сертификата УЦ установил бы неподписанное обновление; наш манифест проверяется независимо от подписи кода и работает с корпоративным зеркалом. Пересмотреть, когда появится сертификат УЦ |
| Испытания окна | CDP окна (`scripts/cdp.mjs`) | Playwright `_electron` не подходит: ему нужен `--inspect` главного процесса, а он закрыт предохранителем в собранной программе. Два клиента CDP (`check.mjs` на Node и живой сценарий `tests/live/desktop_*.py` со стендом) — второй нужен для сценариев с сервером и главным процессом |
| Убрано | `scripts/win-e2e.mjs` | заменён `scripts/check.mjs` (общий для разработчика, preview и CI) |

Навыки для агентов (`.claude/skills`): свои — `release`, `desktop-dev`; сторонние — `electron-development`, `playwright-expert`, `debugging-wizard` (источники и лицензии — `.claude/skills/THIRD_PARTY.md`).
