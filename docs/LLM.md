# Языковые модели: подключение по API

Протоколы, краткие резюме и карты разговора формирует **языковая модель, подключённая по API**: облачная (OpenAI, Anthropic), корпоративный шлюз или собственный
сервер модели в сети организации (любой OpenAI-совместимый, например vLLM, Ollama, LM Studio). Цепочка: **GigaAM (распознавание речи, на этом сервере) → стенограмма →
обезличивание (на этом сервере) → языковая модель по API → протокол или резюме.**

> Встроенная локальная модель Qwen3 (контейнер `llm-local`, llama.cpp) **удалена в 0.56.0**.
> Обновление само удаляет её контейнер и файл модели (≈1,3 ГБ); настройки переводятся бережно — см. «Переход с прежних версий» ниже. Распознавание речи (GigaAM) не менялось.

## Подключение

**Администрирование → Языковая модель (LLM):**

| Вкладка | Что там |
| --- | --- |
| **Назначения** | какая модель формирует **протокол**, **резюме** и **карту разговора** по умолчанию; что делать, если выбранная для комнаты модель недоступна |
| **Подключения** | каталог подключений: тип (OpenAI-совместимый, OpenAI, Anthropic, свой), адрес, **имя модели**, ключ (хранится зашифрованно), заголовки, лимиты, «Проверить подключение» |
| **Параметры генерации** | режим протокола (свободный по инструкции или структурный), лимиты ответа, окно контекста |
| **Статистика**, **Диагностика** | время и объём запросов по моделям; проверка доступа к модели |

Одно подключение = адрес + модель + ключ. Подключений может быть несколько (например, облачная модель и внутренний шлюз); комнате и встрече можно назначить своё —
отдельно для протокола и для резюме (цепочка **система → комната → встреча**). Недоступная выбранная модель не ломает комнату: действует правило «Если выбранная модель
недоступна» (системная модель с пометкой либо «модель недоступна»). На чистой установке подключений нет — документы пишут «модель не настроена», пока администратор её не подключит.

## Что уходит в модель

* **Пароли, токены, ключи и строки подключения убираются из текста всегда** — до отправки, для любого вызова модели (протокол, резюме, карта, проверка подключения),
  при любых настройках комнаты. Если проверка не выполнилась, запрос не отправляется («проверка конфиденциальности не выполнена»).
* **Обезличивание** (имена, контакты, адреса, реквизиты, серверы, суммы…) — по правилам раздела «Обезличивание» и настройке переговорки: [ANONYMIZATION.md](ANONYMIZATION.md).
* В модель уходит только текст стенограммы, участники (при обезличивании — обозначения) и инструкция. Аудио и записи не отправляются.

## Переход с прежних версий (миграция 0056)

* «Протокол: локальная Qwen» → **«по API»**, если подключение к модели уже настроено, иначе **«отключено»** (документы честно пишут, что модель не настроена);
* резюме и карта «локальная» → «так же, как протокол»; выбор «локальная» у комнат и встреч → «системная модель»;
* подключения к моделям, инструкции, шаблоны, протоколы, стенограммы и статистика сохраняются; статистика прежней Qwen остаётся в истории.

## Структурный режим протокола

Режим «структурный» («Параметры генерации») даёт одинаковый проверенный документ у любой модели: стенограмма делится на фрагменты, модель по каждому отвечает строго
JSON по схеме (темы, решения и предложения, поручения «ответственный + что + срок», открытые вопросы), а проверку каждого пункта по репликам, слияние, удаление повторов
и оформление с источниками делает код. Свободный режим — по инструкции пользователя (Markdown).

## Время задания, отмена и перезапуск сервера

Время считается на **всё задание**, а не на один запрос. Цель — **5 минут**, жёсткий предел — настройка `protocol.job_limit_s`, 60–7200 с, — с момента, как задание взято в работу (ожидание в очереди — отдельно и ограничено 10 минутами).

- Конвейер подбирает размер ответов под скорость модели, чтобы уложиться в цель; итоговый абзац модель пишет только если до цели осталось не меньше минуты, иначе его собирает код из проверенных пунктов.
- Не хватает времени обработать всю стенограмму: **резюме** выдаётся с явной отметкой «неполное» и долей обработанного (например, «обработано 3 из 8 фрагментов, около 38%»); **протокол** получает статус **«Превышено время выполнения»** и не выдаётся за готовый.
- По истечении предела идущий запрос к модели **отменяется** (соединение с моделью закрывается), новые не отправляются. Статус не остаётся «Создаётся».
- Пользователь может нажать **«Отменить формирование»** (документ получает статус «отменено»). Остановка и отмена доступны администратору, руководителю комнаты и организатору встречи.
- Статусы документа: **в очереди** → **формируется** (с этапом: подготовка материалов, анализ «обработано N из M», подготовка документа; прошедшее время и предел) → **готово / ошибка / превышено время / отменено**.
- После перезапуска сервера документы, которые числились «в очереди» или «формируется», при запуске переводятся в «ошибка: формирование прервано перезапуском сервера» (стенограммы и материалы встречи не затрагиваются); сформировать документ можно заново.

## «Модель вернула пустой ответ» — что это значит (с 0.44.0)

Пустой текст после ответа провайдера (`integrations/llm.py`) разбирается по признакам самого ответа, а не называется одинаково:

| Код | Признак | Что делает сервис | Что делать |
| --- | --- | --- | --- |
| `empty_length` | `finish_reason=length` (`stop_reason=max_tokens`) и текста нет — лимит ответа ушёл на «рассуждения» (`reasoning_content`, блоки `thinking`, незакрытый `<think>`) | один повтор с лимитом вдвое больше (не выше окна контекста модели или 16 000 токенов); не помогло — понятная ошибка | поднять «лимит ответа» в «Языковая модель (LLM)», выключить режим рассуждений у модели или выбрать другую модель |
| `empty_refusal` | поле `refusal` / `stop_reason=refusal` | повторов нет | другая модель |
| `empty_filtered` | `finish_reason=content_filter` и аналоги | повторов нет | другая модель или правка материалов |
| `empty` | остановка штатная, текста нет | повторов нет; в тексте ошибки — отметка, были ли «рассуждения» | проверить провайдера, модель, шлюз |

Сообщение содержит модель, `finish_reason`, число токенов ответа и лимит; в статистику клиента (`stats["empty"]`) попадает запись о каждом пустом ответе. Модели, принимающие только `max_completion_tokens` (HTTP 400 с таким указанием), получают один автоматический повтор с этим параметром. Бесконечных повторов нет: максимум один повтор по лимиту и один — по `temperature`/`max_completion_tokens`.
