# Частная конфигурация и публичный репозиторий

Проект публичный и универсальный: он знает, **как** подключить LLM, LDAP или SMTP, но не знает, **какие именно** использует ваш сервер.

## Что хранится где

| Что | Где живёт | В git |
|---|---|---|
| Внешние API (адреса, модели, ключи, заголовки), назначения моделей, шаблоны писем, тексты cookie | база данных сервера (секреты зашифрованы мастер-ключом) | нет |
| LDAP/AD (адреса, DN, группы), SMTP-профили, хранилища | база данных сервера и `${DATA_ROOT}` | нет |
| Мастер-ключ, пароли, токены | `.env` и каталог данных вне репозитория (`.env` в `.gitignore`) | нет |
| Универсальные примеры и значения по умолчанию | репозиторий: `.env.example`, документация, тесты | да (только `example.com`, `*.test`, `corp.local` и т. п.) |

* **Чистая установка**: внешних API нет; назначения «Протокол / Резюме / Карта разговора» — «не настроено»; встроенная Qwen3 1.7B доступна как поддерживаемая модель, но не включена по умолчанию.
* **Обновление**: настройки, ключи, назначения и статистика сохраняются; обновление не записывает конфигурацию сервера в каталог проекта и не перезаписывает её при `git checkout`.
* **Тестовые данные** (CI/demo) — только вымышленные значения в `tests/`; дамп или конфигурация боевой базы фикстурой не используются.

## Проверка в CI

`python3 scripts/check_private_data.py` (отдельное задание `private-data` в CI) работает **по списку разрешённого** `scripts/private-data.allow`: каждый домен, адрес e-mail и IP в отслеживаемых файлах должен
оканчиваться записью оттуда (универсальные примеры и публичная инфраструктура), иначе проверка падает. Так не нужен список «чужих секретов», который негде хранить.
Свои запрещённые шаблоны (названия организации, внутренние хосты) можно подключить **вне репозитория**: `PRIVATE_DENY_FILE=/путь/deny.txt python3 scripts/check_private_data.py` (по регулярному выражению в строке).
Разовая проверка всей истории git: `python3 scripts/check_private_data.py --history --all`.

## Если нашлось
Заменить значение универсальным (`https://api.example.com/v1`, `example-model`, `DOMAIN\\user`, `<LLM_BASE_URL>`). Если секрет или имя уже попали в **историю** git, одной правкой файла это не исправить: нужна очистка истории
(`git filter-repo`) с принудительной публикацией и перевыпуском тегов — решение владельца репозитория.
