# Журнал событий, API-профили и защита входа

## Журнал событий

**Где:** Администрирование → Журналы → «Журнал событий»; настройки — «Хранение журнала». Журнал аудита (кто что изменил) — отдельный раздел и вручную не удаляется.

**Что записывается** (категории): `auth` — входы, отказы, блокировки, выход; `room` — вход и выход из комнат, отказы во входе; `network` — обрывы, повторные подключения, ICE (`ice_failed`, `ice_slow`), сведения о сети;
`device` — занятый или недоступный микрофон/камера, отказ браузера в разрешениях, список устройств; `client` — показ экрана и прочие события браузера; `llm` — создание протоколов (профили API, было ли обезличивание), проверки API;
`storage` — ошибки выгрузки записей; `admin` — действия администраторов (зеркало журнала аудита); `system` — запуск приложения.
Пароли, ключи, токены и содержимое разговоров в журнал не попадают (маскирование, ограничение размера полей).

**Диагностика клиента.** При входе браузер сообщает сведения для разбора жалоб: тип и задержку сети, число ядер и объём памяти, размер экрана, число и названия микрофонов/камер, состояние разрешений. Если соединение
устанавливается дольше 4 секунд, записывается `ice_slow`; если не установилось — `ice_failed` с тем же набором данных. Тип пути (UDP/TCP, прямой/через ретранслятор) виден в «Диагностике клиентов».

**Просмотр.** Бесконечная лента без страниц. Столбцы: время, уровень, категория, событие, пользователь, комната, IP, браузер и ОС, сообщение (подробности и данные события — по щелчку на строке).
Фильтры: поиск, период, уровень, категория, пользователь, комната, диапазон дат, «быстрые» наборы и произвольные условия (поле + «равно / не равно / содержит / не содержит / начинается с / не ниже» + значение). Щелчок по значению в таблице добавляет условие.

**Удаление.** Флажки у записей (Shift — диапазон), «Удалить выбранные» или «Удалить все по фильтру» (с подтверждением). Каждое удаление записывается в журнал аудита.

**Выгрузка.** «Выгрузить за сутки» и «Полный архив за 30 дней» — ZIP с `journal.csv` (для Excel), `journal.ndjson` и `audit.csv`.

**Срок хранения.** По умолчанию 30 дней; записи старше удаляются автоматически (раз в час) из базы и из внешнего хранилища. Кнопка «Применить срок хранения» делает это сразу.

**Где хранить.** Хранение в базе сервера можно выключить (`keep_local`) и вести журнал только во внешнее хранилище (каталог на отдельном диске, примонтированном в `DATA_ROOT`, или SMB): файлы
`journal/ГГГГ-ММ-ДД/ЧЧММСС-xxxx.ndjson` пишутся пакетами. Если выключены оба варианта, журнал не ведётся. Размер журнала виден на панели «Состояние системы».

## Несколько API и обезличивание

- «Языковая модель» и «Обезличивание»: основной API (общие настройки) + дополнительные профили; один отмечается «по умолчанию для всех», у переговорки можно выбрать свой.
- Обезличивание можно **выключить** — в общих настройках или в конкретной переговорке. Тогда протоколы и резюме создаются как обычно, а текст уходит в модель без обезличивания (окно «Сформировать протокол» об этом предупреждает).
  Если обезличивание включено, действует правило «fail closed»: при сбое сервиса данные наружу не отправляются.

## Защита входа (быстрый аудит)

| Что | Как |
| --- | --- |
| Перебор паролей | после 20 неверных вводов на логин вход блокируется на 5 минут (без обращения к AD); по IP — 60. Параметры: `LOGIN_MAX_FAILURES_PER_USER`, `LOGIN_MAX_FAILURES_PER_IP`, `LOGIN_LOCKOUT_SECONDS`. **В существующем `.env` значения не меняются автоматически.** |
| Блокировка в AD | пока наш лимит не сработал, неверные пароли доходят до AD и считаются его политикой (обычно 5–10 ошибок). Если порог в домене ниже 20, уменьшите `LOGIN_MAX_FAILURES_PER_USER`. |
| Символы в логине | только буквы, цифры, `. _ -`; допустимы формы `логин`, `ДОМЕН\логин`, `логин@домен`; проверка на клиенте и на сервере; в LDAP-фильтры значения экранируются |
| Пароль | по символам не фильтруется: допустим любой набор (звёздочки, слэши, скобки, кавычки, кириллица); пароль передаётся в AD как значение, а не как часть фильтра |
| Журнал | в поле «логин» люди иногда вводят пароль: некорректный логин в журнал не записывается |
| Нагрузка | событий диагностики клиента — не более 240 в минуту на пользователя |
| Выгрузка CSV | ячейки, начинающиеся с `= + - @`, экранируются (защита от формул Excel) |
| Кэширование | ответы API — `Cache-Control: no-store` |
| Небезопасное соединение | работает, если `COOKIE_SECURE=false` (http); для микрофона и экрана браузеру всё равно нужен HTTPS |

Уже было в системе: CSRF-токен и проверка Origin, HttpOnly-cookie сессии, подпись webhook LiveKit, сравнение секретов за постоянное время, заголовки CSP/X-Frame-Options/nosniff на web-контейнере, `/internal` не публикуется.
