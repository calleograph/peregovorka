# Первая настройка в браузере (после установки)

После `sudo ./install.sh` на сервере остаётся только локальный администратор. Всё остальное — подключение к домену, сертификаты, группы администраторов, файловое хранилище и почта —
настраивается в веб-интерфейсе: править `.env` и конфигурационные файлы не нужно. Пароли в интерфейсе **никогда не показываются** (только «пароль задан», «Изменить»); все действия пишутся в журнал аудита.

> В примерах — нейтральные имена (`example.local`, `user1`, `admin`). Подставьте свои.

## Вход и мастер

1. Откройте адрес из блока «ПЕРВИЧНЫЙ ВХОД» (https://… — браузер предупредит о самоподписанном сертификате).
2. Войдите как `admin` с первичным паролем и **замените его на свой** (не короче 12 символов, не менее двух видов символов).
3. Откроется **мастер первоначальной настройки**: LDAP → CA → группы администраторов → хранилище → почта → проверка системы. Каждый шаг можно пропустить; «Закрыть и не показывать снова» отключает мастер. Всё то же доступно в **Администрирование**.

Локальный администратор не зависит от каталога: если домен недоступен или группы настроены неверно, вход остаётся. Забыли пароль — на сервере `sudo /opt/peregovorka/scripts/admin-reset.sh` (новый пароль, запись в аудит, завершение старых сеансов).

## LDAP и доступ

### Сертификаты (CA)
Загрузите корневой (и промежуточные) сертификат удостоверяющего центра, которым подписаны сертификаты ваших контроллеров домена: файл `.pem/.crt/.cer` (PEM или DER) либо вставьте PEM текстом.
Перед сохранением показываются Subject, Issuer, серийный номер, отпечаток SHA-256, срок действия и тип (корневой / промежуточный / сертификат сервера). **Закрытые ключи не принимаются** (файл с ключом отклоняется целиком).
Сертификат сервера (не CA) добавляется только с явным подтверждением. Набор общий: им проверяются LDAPS и (по желанию) SMTP.

### Подключения LDAP
«Добавить подключение»: название, сервер (имя или IP), протокол (LDAPS, порт 636, или LDAP+STARTTLS, порт 389), Base DN, домен NetBIOS и суффикс UPN, таймаут, сервисная учётная запись (только чтение) и её пароль.
Флаги: **вход пользователей** и **вход администраторов**. Подключений может быть несколько (разные домены): они проверяются по порядку, а подсказки `ДОМЕН\логин` и `логин@суффикс` выбирают нужное.
Кнопка **«Проверить»** выполняет реальную проверку по этапам: DNS → TCP → TLS с проверкой цепочки и имени узла по загруженным CA → вход сервисной записи → чтение Base DN; при сбое показывается понятная причина (имя не найдено, нет соединения, цепочка не доверена, имя не совпадает с сертификатом, пароль отклонён…).
Атрибут электронной почты (по умолчанию `mail`) используется для рассылки материалов встреч.
Если до 0.3.0 каталог был задан в `.env`, он продолжает работать как «основное подключение» до тех пор, пока вы не добавите подключение в интерфейсе.

### Доступ к администрированию
Отдельный раздел — **группы AD, члены которых (включая вложенные) получают права администратора**; поиск групп идёт по каталогу, либо введите DN. Дополнительно можно ограничить вход группами допуска. Изменения действуют при следующем входе пользователя.
Здесь же — сведения о локальном администраторе и смена его пароля.

## Хранилища
**Серверы файлов** — SMB или каталог создаются один раз (адрес, учётная запись, пароль), а записи, протоколы, вложения чата и журнал только выбирают их. Подпапки создаются автоматически. Подробности и **сверку хранилищ** — в [STORAGE.md](STORAGE.md).

## Электронная почта
**Исходящая почта (SMTP)** — профиль (сервер, порт, защита None/STARTTLS/SSL-TLS, аутентификация, отправитель, таймаут), «Проверить соединение» (DNS → подключение → сертификат → вход) и «Отправить тестовое письмо» на введённый адрес. **Правила рассылки** и **Журнал отправки** — в [MAIL.md](MAIL.md).

## Проверка
**Состояние системы** показывает PostgreSQL, Redis, LiveKit, ASR и каталог. Пока каталог не подключён, он отображается как «не подключён» без ошибки — вход локальным администратором работает.

## Что где лежит (для администратора сервера)
| Что | Где |
| --- | --- |
| Проект и `.env` | `/opt/peregovorka` (`.env` — права 600; **сохраните его копию**: в нём ключ шифрования `APP_MASTER_KEY`, без которого сохранённые пароли подключений не восстановить) |
| Данные (БД, записи, сертификаты CA, вложения чата) | `/srv/peregovorka-data` |
| Служебные команды | `scripts/status.sh`, `scripts/logs.sh`, `scripts/update.sh`, `scripts/admin-reset.sh` |
