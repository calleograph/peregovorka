# Первая настройка в браузере (после установки)

После `sudo ./install.sh` на сервере остаётся только локальный администратор. Всё остальное — подключение к домену, сертификаты, группы администраторов, файловое хранилище и почта —
настраивается в веб-интерфейсе: править `.env` и конфигурационные файлы не нужно. Пароли в интерфейсе **никогда не показываются** (только «пароль задан», «Изменить»); все действия пишутся в журнал аудита.

> В примерах — нейтральные имена (`example.local`, `user1`, `admin`). Подставьте свои.

## Вход и мастер

1. Откройте адрес из блока «ПЕРВИЧНЫЙ ВХОД» (https://… — браузер предупредит о самоподписанном сертификате).
2. Войдите как `admin` с первичным паролем и **замените его на свой** (не короче 12 символов, не менее двух видов символов).
3. Откроется **мастер первоначальной настройки**: LDAP → CA → группы администраторов → хранилище → почта → проверка системы. Каждый шаг можно пропустить; «Закрыть и не показывать снова» отключает мастер. Всё то же доступно в **Администрирование**.

Локальный администратор не зависит от каталога: если домен недоступен или группы настроены неверно, вход остаётся. Забыли пароль — на сервере `sudo /opt/peregovorka/scripts/admin-reset.sh` (новый пароль, запись в аудит, завершение старых сеансов).

## LDAP и доступ

### Сертификаты (CA)
Загрузите корневой (и промежуточные) сертификат удостоверяющего центра, которым подписаны сертификаты ваших контроллеров домена: файл `.pem/.crt/.cer` (PEM или DER) либо вставьте PEM текстом.
Перед сохранением показываются Subject, Issuer, серийный номер, отпечаток SHA-256, срок действия и тип (корневой / промежуточный / сертификат сервера). **Закрытые ключи не принимаются** (файл с ключом отклоняется целиком).
Сертификат сервера (не CA) добавляется только с явным подтверждением. Набор общий: им проверяются LDAPS и (по желанию) SMTP.

### Подключения LDAP
«Добавить подключение»: название, сервер (имя или IP), протокол (LDAPS, порт 636, или LDAP+STARTTLS, порт 389), Base DN, домен NetBIOS и суффикс UPN, таймаут, сервисная учётная запись (только чтение) и её пароль.
Флаги: **вход пользователей** и **вход администраторов**. Подключений может быть несколько (разные домены): они проверяются по порядку, а подсказки `ДОМЕН\логин` и `логин@суффикс` выбирают нужное.
Кнопка **«Проверить»** выполняет реальную проверку по этапам: DNS → TCP → TLS с проверкой цепочки и имени узла по загруженным CA → вход сервисной записи → чтение Base DN; при сбое показывается понятная причина (имя не найдено, нет соединения, цепочка не доверена, имя не совпадает с сертификатом, пароль отклонён…).
Атрибут электронной почты (по умолчанию `mail`) используется для рассылки материалов встреч.
Если до 0.3.0 каталог был задан в `.env`, он продолжает работать как «основное подключение» до тех пор, пока вы не добавите подключение в интерфейсе.
**Старая конфигурация LDAP.** Если каталог был задан в `.env` (версии до 0.3.0, `LDAP_*`), после обновления вход по домену продолжает работать. Система сама пытается перенести её в управляемые настройки: сертификат CA из `LDAP_CA_FILE`, подключение, пароль сервисной учётной записи (шифруется, в `.env` не меняется) и группы доступа; перенос засчитывается **только после успешной проверки подключения**. Если автоматически не получилось, на этой странице и в «Состоянии системы» появляется «Обнаружена старая конфигурация LDAP» с кнопкой **«Перенести настройки»** (при неудаче ничего не меняется, прежний вход продолжает работать, причина показана по этапам). После переноса строки `LDAP_*` из `.env` можно удалить.

### Доступ к системе (кто может входить)
**Администрирование → LDAP и доступ → Доступ к системе.** Список групп каталога, члены которых вообще могут войти. Порядок входа: пароль в каталоге → проверка допуска → только потом создаётся сеанс; не прошедший проверку не видит ни списка переговорок, ни истории. Достаточно членства в одной из групп (вложенные группы учитываются, группы можно добавлять и убирать по одной). Изменения действуют со следующей попытки входа, перезапуск не нужен.
- **Пока список пуст, входит любой активный пользователь каталога** (так работают установки, обновлённые с прежних версий — никого не блокируем). Страница показывает предупреждение «Ограничение входа не настроено»; после добавления первой группы список становится закрытым. Мастер первоначальной настройки предлагает выбрать группы отдельным шагом.
- Администраторы (члены групп из «Доступа к администрированию»), локальный (аварийный) администратор и гости по гостевой ссылке от этого списка не зависят.
- **«Проверить пользователя»**: введите логин — увидите, найден ли он, пропустят ли его (и по какой группе), получит ли права администратора. Пароль не нужен.
- В журнале: успешный вход (по какой группе допущен), отказ из-за групп (`login_denied_acl`, причина без пароля и данных каталога), изменение списка (кто, какие группы добавлены и убраны) — также в журнале аудита.

### Доступ к администрированию
Отдельный раздел — **группы AD, члены которых (включая вложенные) получают права администратора**; поиск групп идёт по каталогу, либо введите DN. Это отдельный список: он не смешивается с допуском к системе. Изменения действуют при следующем входе пользователя.
Здесь же — сведения о локальном администраторе и смена его пароля.

## Профиль пользователя и карточка участника
Профиль заполняется из Active Directory при каждом входе: читаются **только** атрибуты `title` (должность), `department` (подразделение), `telephoneNumber` (телефон), плюс ФИО и e-mail; фото из каталога не берётся. Пользователь может обновить данные кнопкой «Обновить данные из Active Directory» (используется сервисная учётная запись; ищется та же учётная запись по `objectGUID`). Аватарка загружается самим пользователем и хранится в `DATA_ROOT/avatars`. Что видят другие участники в карточке — «Общие настройки» → «Карточка участника» (e-mail, телефон; ФИО, должность и подразделение показываются всегда). Новый вариант профиля после обновления заполняется при следующем входе пользователя.

## Языковая модель (LLM)
Страница **Администрирование → Языковая модель (LLM)** устроена сверху вниз:
1. **Какая модель будет вызвана** — по строке на задачу (протокол, резюме): модель по умолчанию, локальная она или внешняя (и тип API), предел длины ответа, готова ли, и в скольких переговорках выбрана своя. Порядок выбора при формировании документа: *модель, выбранная в окне «Сформировать» на один раз* → настройка встречи → настройка переговорки → системное значение по умолчанию.
2. **Системные значения по умолчанию** — чем формировать протокол и резюме: «Локальная: Qwen3 1.7B Q4_K_M» (встроенная, данные не покидают сервер), «Внешняя LLM» или «Отключено» (для резюме ещё «Так же, как протокол»).
3. **Встроенная локальная модель** — файл (размер, контрольная сумма), ответ сервера модели, проверка.
4. **Внешний API по умолчанию** и **Внешние API (профили)** — подключения. Одна форма для любого API: *тип* (OpenAI, Anthropic, OpenAI-совместимый, «свой OpenAI-подобный сервис»), адрес, идентификатор модели, ключ, дополнительные заголовки (секретные значения шифруются и в интерфейс не возвращаются), таймаут, **максимальная длина ответа отдельно для резюме (по умолчанию 2 000 токенов) и для протокола (7 000)**, окно контекста (если указано, ответ не превысит доступное), температура (по умолчанию 0) и возможности провайдера: передавать ли temperature, системное сообщение, строгий JSON, потоковый ответ. Подключение — это не назначение: один профиль может обслуживать и протокол, и резюме, а может быть выбран только для одной из задач.
5. **Показатели моделей** — по созданным документам: сколько, ошибок, оборванных ответов, повторов, среднее и медианное время, средние длины входа и выхода, токенов в секунду. Нагрузка процессора и памяти не собирается.

Для переговорки и встречи выбор делается отдельно для протокола и резюме («Настройки комнаты» → «Языковая модель», «Эта встреча»); наследование: система → переговорка → встреча. Что делать, если выбранная модель удалена или отключена, задаёт параметр **«Если выбранная для комнаты модель недоступна»**; разовый выбор в окне «Сформировать» молча другой моделью не заменяется.

**Окно «Сформировать» и история.** Окно показывает модель, ожидаемое время (диапазон, например «примерно 3–7 минут»; без истории по модели — грубая оценка, с историей — по прошлым документам этой модели) и предел длины ответа. Руководители переговорки и администраторы могут выбрать другую модель на один раз (в журнал аудита пишется выбор). У каждого документа в истории видны: модель, локальная/внешняя, времена «нажато — взято в работу — модель начала — готово», ожидание и работа модели, число частей и повторов, причины остановки. Документ, оборванный по лимиту длины, помечен «обрезано» и не выглядит полноценным.

Локальная модель небольшая: протокол собирается кодом из проверенных пунктов с источниками, любой документ нужно проверять. Подробности — [LOCAL_LLM.md](LOCAL_LLM.md).

## SIP-телефония
**Администрирование → Интеграции → SIP-телефония** (необязательно). Сначала включите телефонию на сервере (кнопка в разделе или `sudo scripts/sip.sh enable`), затем добавьте SIP-профиль для вашей АТС, нажмите «Проверить настройки» и «Тестовый вызов». Порты SIP и RTP отделены от 443 и портов браузерных звонков, их открывают только для адресов АТС. Схема, безопасность и настройка Asterisk — в [SIP.md](SIP.md).

## Хранилища
**Серверы файлов** — SMB или каталог создаются один раз (адрес, учётная запись, пароль), а записи, протоколы, вложения чата и журнал только выбирают их. Подпапки создаются автоматически. Подробности и **сверку хранилищ** — в [STORAGE.md](STORAGE.md).

## Электронная почта
**Исходящая почта (SMTP)** — профиль (сервер, порт, защита None/STARTTLS/SSL-TLS, аутентификация, отправитель, таймаут), «Проверить соединение» (DNS → подключение → сертификат → вход) и «Отправить тестовое письмо» на введённый адрес. **Правила рассылки** и **Журнал отправки** — в [MAIL.md](MAIL.md).

## Проверка
**Состояние системы** показывает PostgreSQL, Redis, LiveKit, ASR и каталог. Пока каталог не подключён, он отображается как «не подключён» без ошибки — вход локальным администратором работает.

## Что где лежит (для администратора сервера)

| Проект и `.env` | `/opt/peregovorka` (`.env` — права 600; **сохраните его копию**: в нём ключ шифрования `APP_MASTER_KEY`, без которого сохранённые пароли подключений не восстановить) |
