# Встроенная локальная языковая модель (Qwen3 0.6B)

Peregovorka умеет формировать краткие резюме и протоколы **без внешних сервисов**: встроенной локальной моделью, которая работает на вашем сервере.
Цепочка обработки: **GigaAM (распознавание речи) → стенограмма → локальная Qwen3 → протокол или резюме.** Данные встречи при этом никуда не отправляются.

## Что это

| | |
| --- | --- |
| Модель | Qwen3 0.6B, квантование Q4_K_M, формат GGUF, ~484 МБ |
| Runtime | llama.cpp (`llama-server`), только процессор (CPU) |
| Где работает | отдельный контейнер `llm-local` в сети compose `llm_internal` с флагом `internal: true`: у контейнера **нет выхода в интернет** и нет опубликованных портов; к нему обращается только backend |
| Интерфейс | OpenAI-совместимый API (`/v1/chat/completions`). Остальная система обращается к модели как к обычному OpenAI-совместимому серверу и от runtime не зависит |
| Для чего | простые задачи: краткое резюме, решения, задачи, ответственные, короткий протокол |
| Ограничение | это **облегчённая** модель: на длинных стенограммах качество может быть ниже, чем у более крупных моделей |

## Установка и обновление

Модель загружает установщик так же, как модели распознавания речи:

* `sudo ./install.sh` (этап `models`) — скачивает файл в `DATA_ROOT/models/llm/` и образ runtime (`ghcr.io/ggml-org/llama.cpp:server-b…`), запускает контейнер;
* `./scripts/update.sh` — **существующий валидный файл не скачивается заново** (модель хранится вне образов); повреждённый — скачивается заново;
* `scripts/models.sh --llm-only` — вручную; `--from-dir КАТАЛОГ` — из заранее скачанного каталога (закрытая сеть); `--check` — проверить файл; `--soft` — не падать без интернета.

Перед использованием проверяются **наличие, размер и SHA-256**. Контрольная сумма кэшируется рядом с файлом (по размеру и времени изменения), поэтому повторные проверки быстрые. Несовпадение размера или суммы — файл считается повреждённым и не используется
(скачанный неверный файл сохраняется как `*.failed` для разбора). Для другого файла/зеркала параметры `LLM_MODEL_FILE`, `LLM_MODEL_URL`, `LLM_MODEL_BYTES`, `LLM_MODEL_SHA256` (`skip` — не проверять сумму) задаются в `.env`.

**Источник.** `bartowski/Qwen_Qwen3-0.6B-GGUF` (файл `Qwen_Qwen3-0.6B-Q4_K_M.gguf`, 484 220 320 байт). В репозитории `tensorblock/Qwen_Qwen3-0.6B-GGUF` файла Q4_K_M нет (только Q2_K и Q3_K_M), поэтому использован bartowski; на диске файл называется `Qwen3-0.6B-Q4_K_M.gguf`.

**Без интернета** установка не прерывается. Установщик явно пишет: «ЛОКАЛЬНАЯ LLM НЕ ЗАГРУЖЕНА… остальная Peregovorka устанавливается и работает», а в итоговом блоке показывает «Локальная LLM (Qwen3 0.6B): НЕ ЗАГРУЖЕНА». Загрузить позже можно кнопкой в
**Администрирование → Языковая модель (LLM) → «Скачать модель»** (её выполняет помощник обновлений) или командой `sudo scripts/models.sh --llm-only`, затем обновление/перезапуск поднимет контейнер.
Отключить совсем: `LLM_LOCAL_ENABLED=no` в `.env` (модель не скачивается и не запускается).

## Режимы

**Администрирование → Языковая модель (LLM) → «Режим»:**

* **Локальная: Qwen3 0.6B Q4_K_M** — встроенная модель; ключей и адресов не нужно;
* **Внешняя LLM** — OpenAI, Anthropic или OpenAI-совместимый шлюз (как раньше; для комнат — профили API);
* **Отключено.**

Настройки, сохранённые до этой версии, остаются прежними: включённая внешняя LLM — «Внешняя», выключенная — «Отключено». По умолчанию локальная модель **не выбирается сама**: её включает администратор.

Для локальной модели обезличивание по умолчанию не применяется (данные не покидают сервер); если в настройках переговорки обезличивание включено принудительно, оно выполняется.
Длинные стенограммы разбиваются на фрагменты по возможностям модели (заметки по фрагментам → итоговый документ). Если стенограмма длиннее ~15 000 знаков, перед созданием протокола показывается предупреждение о качестве облегчённой модели; оно же записывается в сведения о протоколе.

## Состояние, проверка, диагностика

* **Администрирование → Языковая модель (LLM)** — карточка «Встроенная локальная модель»: файл (размер, контрольная сумма), сервер модели, режим, кнопки «Проверить модель» (тестовый запрос) и «Скачать модель».
* **Состояние системы** — «Локальная LLM (Qwen3 0.6B)»: «не загружена» — это не ошибка (необязательная возможность); ошибка — только если режим «Локальная» выбран, а модель не готова.
* `scripts/verify.sh`, `scripts/smoke-test.sh` (тестовый запрос), `scripts/diag.sh` (`local-llm.txt`), диагностический отчёт в админке — отдельная строка «локальная LLM». Проблемы показываются предупреждениями и не ломают остальную проверку.
* «Исправить автоматически» предложит загрузить модель, если файл не загружен/повреждён или не запущен контейнер.

## Как добавить более сильную модель (например, Gemma 3 4B)

API, протоколы и интерфейс от конкретной модели не зависят. Нужно: положить `.gguf` в `DATA_ROOT/models/llm/`; задать в `.env` `LLM_MODEL_FILE`, `LLM_MODEL_URL`, `LLM_MODEL_BYTES`, `LLM_MODEL_SHA256`, при необходимости `LLM_MODEL_ALIAS`, `LLM_LOCAL_CTX`, `LLM_LOCAL_MEM`; добавить запись в `LOCAL_MODELS` (`backend/app/services/local_llm.py`: размер контекста, размер фрагмента, порог предупреждения, `light=False`).
Более крупная модель требует больше памяти и процессора — проверьте ресурсы сервера (распознавание речи работает на тех же ядрах).

## Что проверено

Автоматические тесты: состояния файла (нет, неполный, неверный размер, подменённое содержимое, верный), загрузка из каталога и отказ при несовпадении суммы, поведение без интернета, включение профиля compose только при готовой модели и образе, сеть `internal`,
режимы настройки, протокол через локальную модель (данные не уходят во внешнее обезличивание, `<think>` вырезается), предупреждение для длинной стенограммы, повторная загрузка через помощника. **Не проверено** на реальном сервере: запуск образа llama.cpp и реальные ответы Qwen3, скорость на вашем процессоре, качество резюме на реальных встречах.
