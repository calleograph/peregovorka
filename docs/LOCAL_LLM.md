# Встроенная локальная языковая модель (Qwen3 1.7B)

Peregovorka умеет формировать протоколы и краткие резюме **без внешних сервисов**: встроенной локальной моделью, которая работает на вашем сервере.
Цепочка обработки: **GigaAM (распознавание речи) → стенограмма → структурное извлечение небольшой моделью → проверка и сборка кодом → протокол или резюме.** Данные встречи при этом никуда не отправляются.

## Что это

| | |
| --- | --- |
| Модель | Qwen3 1.7B, квантование Q4_K_M, формат GGUF, ~1,28 ГБ |
| Runtime | llama.cpp (`llama-server`), только процессор (CPU) |
| Где работает | отдельный контейнер `llm-local` в сети compose `llm_internal` с флагом `internal: true`: у контейнера **нет выхода в интернет** и нет опубликованных портов; к нему обращается только backend |
| Память и процессор | около 2,5 ГБ памяти (лимит контейнера `LLM_LOCAL_MEM`, по умолчанию 3500m), потоки `LLM_LOCAL_THREADS` (по умолчанию 4; распознавание речи работает на тех же ядрах); кэш промптов отключён (`--cache-ram 0`), иначе память растёт до 4–5 ГБ |
| Интерфейс | OpenAI-совместимый API (`/v1/chat/completions`). Остальная система обращается к модели как к обычному OpenAI-совместимому серверу и от runtime не зависит |
| Ограничение | это **небольшая** модель. Она годится для рабочих протоколов с проверкой человеком, но не для юридически значимых документов без вычитки |

**Прежняя Qwen3 0.6B снята с вооружения:** на протоколах и длинных резюме она оказалась слишком слабой (подробности в HISTORY.md). Она не скачивается, не показывается и не предлагается; сохранённый ранее выбор 0.6B молча заменяется на 1.7B. Если на сервере остался её файл, его можно удалить: `DATA_ROOT/models/llm/Qwen3-0.6B-Q4_K_M.gguf`. Контейнер `llm-local-17b` версии 0.6.0 (необязательный запуск 1.7B) при обновлении убирается.

## Установка и обновление

Модель загружает установщик так же, как модели распознавания речи:

* `sudo ./install.sh` (этап `models`) — скачивает файл в `DATA_ROOT/models/llm/` и образ runtime (`ghcr.io/ggml-org/llama.cpp:server-b…`), запускает контейнер;
* `./scripts/update.sh` — **существующий валидный файл не скачивается заново** (модель хранится вне образов); повреждённый — скачивается заново. **При переходе с версии 0.6.0 и ранее обновление скачает 1.7B (~1,3 ГБ) — нужен интернет;**
* `scripts/models.sh --llm-only` — вручную; `--from-dir КАТАЛОГ` — из заранее скачанного каталога (закрытая сеть); `--check` — проверить файл; `--soft` — не падать без интернета.

Перед использованием проверяются **наличие, размер и SHA-256**. Контрольная сумма кэшируется рядом с файлом (по размеру, времени изменения и inode), поэтому повторные проверки быстрые. Несовпадение размера или суммы — файл не используется и скачивается заново
(скачанный неверный файл сохраняется как `*.failed` для разбора). Параметры `LLM_MODEL_FILE`, `LLM_MODEL_URL`, `LLM_MODEL_BYTES`, `LLM_MODEL_SHA256` (`skip` — не проверять сумму) задаются в `.env`.

**Источник.** `bartowski/Qwen_Qwen3-1.7B-GGUF` (файл `Qwen_Qwen3-1.7B-Q4_K_M.gguf`, 1 282 439 584 байт); на диске файл называется `Qwen3-1.7B-Q4_K_M.gguf`.

**Без интернета** установка не прерывается. Установщик явно пишет: «ЛОКАЛЬНАЯ LLM НЕ ЗАГРУЖЕНА… остальная Peregovorka устанавливается и работает». Загрузить позже:
**Администрирование → Языковая модель (LLM) → «Скачать модель»** (её выполняет помощник обновлений) или `sudo scripts/models.sh --llm-only`, затем обновление/перезапуск поднимет контейнер.
Отключить совсем: `LLM_LOCAL_ENABLED=no` в `.env`.

## Режимы и раздельный выбор модели

**Администрирование → Языковая модель (LLM):**

* **Какая модель формирует протокол** — «Локальная: Qwen3 1.7B Q4_K_M», «Внешняя LLM» или «Отключено»;
* **Какая модель пишет краткое резюме** — «Такая же, как для протокола», «Локальная», «Внешняя LLM» или «Резюме не формировать». Протокол и резюме — разные задачи, поэтому у них **отдельные цепочки наследования: система → комната → встреча**.

В «Настройках комнаты → Языковая модель» и в окне «Эта встреча» два блока: «Модель для протокола» и «Модель для резюме». Если выбранная модель недоступна (профиль удалён, файл не загружен), комната не ломается: действует правило «Если выбранная модель недоступна» (системная модель с пометкой либо «модель недоступна»). Отметка «Внешний API по умолчанию» у профиля работает только когда соответствующий режим — «Внешняя LLM»; локальную модель и «Отключено» она никогда не перебивает.

Для локальной модели обезличивание по умолчанию не применяется (данные не покидают сервер); если в настройках переговорки обезличивание включено принудительно, оно выполняется.

## Как формируется протокол (структурное извлечение)

Небольшая модель плохо «пересказывает итог» по заметкам: она теряет фрагменты, дублирует, склеивает похожих людей, выдаёт открытые вопросы и отклонённые предложения за решения, придумывает сроки. Поэтому ей отдана только простая задача, остальное делает код:

1. Стенограмма делится на **фрагменты около 6 000 знаков**.
2. По **каждому** фрагменту — отдельные узкие проходы с ответом **строго JSON по схеме** (llama.cpp строит грамматику): **темы**; **решения и предложения** (`status`: `decision` — явно договорились, `proposal` — предложение, не принятое); **поручения** — кто, что и срок **одним объектом**; **открытые вопросы**. Все проходы по фрагменту начинаются с одного и того же текста, поэтому llama.cpp переиспользует уже обработанный фрагмент.
3. **Участники передаются с идентификаторами** (`p01 — Иван Петров`, `p02 — Иван Петренко`…) и пометкой «похожие имена — разные люди»; ответственный в схеме — только `id` из списка или `none`.
4. **Код проверяет каждый пункт:** время реплики существует (цитату берёт код по времени и ближайшей по словам реплике, модель её не пишет); ответственный подтверждён репликой (его называют рядом по имени/фамилии — «Мороз» и «Морозов» различаются, «Соколову» без имени двусмысленно — или он сам говорит), иначе ответственный не назначается, а предположение модели помечается; срок — действительно срок (день недели, дата, «завтра», «к следующей встрече»…), а не время суток или период, и его слова есть в ближайших репликах, иначе «не указан»; адреса, версии, большие числа и слова вроде «августа», «до конца недели», которых нет в репликах, убираются; «решение» с признаком отказа или вопроса переводится в «предложение»/«открытый вопрос»; «открытый вопрос» без вопроса в реплике отбрасывается.
5. **Объединение, удаление повторов и сортировка по времени — кодом.** Задачи с разными ответственными не склеиваются никогда; решение, повторяющее задачу, отбрасывается.
6. **Протокол собирается кодом** в Markdown (темы, решения, поручения с ответственным и сроком, предложения, не принятые как решение, открытые вопросы); у каждого пункта — реплика-источник (время, автор, цитата). Срок, который однозначно переводится, показывается и датой («в четверг (2026-10-15)»). Чего нет в репликах — «не указан».
7. **Краткое резюме** пишет модель, но только по уже проверенным пунктам; если она оборвалась или ответила пусто, показывается перечень пунктов.

Если ответ прохода оборван по лимиту длины (`finish_reason=length`) или не разобрался как JSON, **проход повторяется по половинам фрагмента**; обрезанные данные не используются. Число повторов и пропущенные проходы показываются предупреждением рядом с документом. Индивидуальная инструкция к протоколу локальной модели не применяется (шаблон фиксированный; короткие пожелания учитываются в резюме). Для протокола по своему шаблону выберите внешнюю модель.

Если сервер llama.cpp не поддерживает формат или модель не вернула разбираемый JSON ни для одного фрагмента, используется запасной упрощённый текстовый режим с предупреждением.

**Честно о качестве.** На синтетических встречах (HISTORY.md) 1.7B заметно лучше прежних вариантов, но остаётся небольшой моделью: пропускает часть поручений и путает формулировки. Лучше сухой протокол с «не указан», чем придуманный срок или ответственный, — поэтому сомнительное код убирает или помечает. Любой документ нужно проверять.

## Состояние, проверка, диагностика

* **Администрирование → Языковая модель (LLM)** — карточка «Встроенная локальная модель»: файл (размер, контрольная сумма), сервер модели, режим, кнопки «Проверить модель» (тестовый запрос) и «Скачать модель».
* **Состояние системы** — «Локальная LLM (Qwen3 1.7B)»: «не загружена» — не ошибка (необязательная возможность); ошибка — только если режим «Локальная» выбран, а модель не готова.
* `scripts/verify.sh`, `scripts/smoke-test.sh` (тестовый запрос), `scripts/diag.sh` (`local-llm.txt`), диагностический отчёт в админке — отдельная строка «локальная LLM». Проблемы показываются предупреждениями и не ломают остальную систему.
* «Исправить автоматически» предложит загрузить модель, если файл не загружен/повреждён или не запущен контейнер.

## Как добавить более крупную модель

API, протоколы и интерфейс от конкретной модели не зависят. Нужно: положить `.gguf` в `DATA_ROOT/models/llm/`; задать в `.env` `LLM_MODEL_FILE`, `LLM_MODEL_URL`, `LLM_MODEL_BYTES`, `LLM_MODEL_SHA256`, при необходимости `LLM_MODEL_ALIAS`, `LLM_LOCAL_MEM`; добавить запись в `LOCAL_MODELS` (`backend/app/services/local_llm.py`).
Более крупная модель требует больше памяти и процессора — проверьте ресурсы сервера (распознавание речи работает на тех же ядрах).

## Что проверено

Автоматические тесты: состояния файла (нет, неполный, неверный размер, подменённое содержимое, верный), загрузка из каталога и отказ при несовпадении суммы, поведение без интернета, включение профиля compose только при готовой модели и образе, сеть `internal`, `--cache-ram 0`,
режимы и раздельные цепочки протокола и резюме, структурное извлечение (схема с `id` участников, проверка ответственного и срока, различение Мороз/Морозов и Соколов/Соколова, статусы «решение/предложение/вопрос», слияние кодом, повтор по половинам при обрезке, детерминированный Markdown с источниками), предупреждение об обрезанном ответе.
На **настоящей модели** (llama.cpp той же сборки, что в production) прогнаны синтетические встречи на 3, 20 и 60 минут (стенд и результаты — HISTORY.md). **Не проверено** на реальном сервере в Docker и на реальных записях.
