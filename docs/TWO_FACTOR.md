# Двухфакторная аутентификация (TOTP)

Одноразовые коды по RFC 6238 (HMAC-SHA1, 6 цифр, шаг 30 с): работают с Google Authenticator, Microsoft Authenticator, FreeOTP, Aegis и любым другим приложением «по времени».

## Политика

«Администрирование → Безопасность → Вход и сеансы».

| Значение | Что происходит |
| --- | --- |
| Отключена | Функция скрыта, код при входе не спрашивается (даже у тех, кто успел её включить). |
| По желанию | Каждый включает в «Личном кабинете → Двухфакторная аутентификация». |
| Обязательна администраторам / всем / группам каталога (DN по одному в строке или через «;») | При следующем входе (после пароля) пользователь попадает на экран настройки. Пока 2FA не включена, сессия годится только для настройки: остальные ручки отвечают 403 `totp_enrollment_required` (так обойти требование запросами к API нельзя). Отключить обязательную 2FA пользователь не может. |

Действует и на локального (аварийного) администратора. Изменение политики не разлогинивает уже открытые сессии: требование применяется при следующем входе.

## Как это работает

* **Включение:** пароль → сервер выдаёт секрет и QR-код (секрет до подтверждения лежит только в Redis 10 минут) → пользователь вводит код из приложения → сервер сохраняет секрет и выдаёт **10 резервных кодов** (показываются один раз). Ключ для ручного ввода показан под QR-кодом.
* **Вход:** пароль верен → сессия не выдаётся, сервер отдаёт одноразовую заявку (5 минут, 5 попыток) → код из приложения или резервный код → сессия. Заявка без пароля не создаётся.
* **Хранение:** секрет зашифрован AES-256-GCM ключом `APP_MASTER_KEY` (AAD привязан к пользователю); резервные коды — только HMAC-SHA256 с ключом сервера, каждый гасится одним условным UPDATE (два одновременных входа с одним кодом не пройдут оба).
* **Повтор кода:** сохраняется номер последнего принятого шага; тот же или более старый шаг не принимается, параллельные запросы с одним кодом разрешает условный UPDATE.
* **Перебор:** 5 неверных кодов на заявку, общий с паролем счётчик блокировки входа, при самообслуживании — 10 неверных кодов за 10 минут. Часы допускаются с расхождением ±30 с.
* **Аудит:** `auth.totp_enable`, `auth.totp_disable`, `auth.totp_failed`, `auth.backup_code_used`, `auth.totp_backup_regenerate`, `auth.totp_reset`; в `auth.login` указан способ подтверждения.

## Потеряно устройство

* Есть резервный код — войти им, затем создать новые коды.
* Нет кодов: администратор в «Пользователи» нажимает «сбросить» (нужен его пароль). Пользователь настроит 2FA заново.
* Потерян доступ у единственного локального администратора: на сервере `./scripts/admin-reset.sh` — выдаёт новый пароль и сбрасывает 2FA.

## Ограничения

* Секрет шифруется ключом `APP_MASTER_KEY`: при его потере 2FA у всех придётся сбросить.
* WebAuthn / ключи доступа не реализованы.
* Секрет 2FA и резервные коды в резервную копию настроек не входят (личные данные безопасности); после восстановления на новом сервере пользователи настраивают 2FA заново.
