# Проверки в корпоративной инфраструктуре (то, что нельзя проверить без неё)

Автоматические тесты и живые сценарии используют **подставные** каталог (AD), почтовый сервер и Exchange. Ниже — что необходимо проверить на настоящей установке, какие условия нужны и как понять, что всё в порядке. Пока пункт не выполнен, он считается **не проверенным**.

## 1. Active Directory: права руководителя комнаты, поиск и выдача доступа
Условия: рабочий вход через AD; тестовые учётные записи: руководитель комнаты (в «Руководители» комнаты, пользователем и группой), обычный сотрудник без участия во встрече, сотрудник в **отключённой** учётной записи, группа из 5–10 человек, **вложенная** группа (группа в группе), пустая группа, группа > 300 человек.

| Шаг | Ожидаем |
| --- | --- |
| Руководитель открывает встречу своей комнаты, где не участвовал | История и материалы видны; встреча чужой комнаты — «нет доступа» |
| «Управление доступом» → поиск по ФИО, логину, части фамилии, почте | Находит; русский регистр, «ё/е» не важны; результат ≤ 20 |
| Поиск группы по названию | Группа найдена; сам поиск доступа **не выдаёт** |
| Выдача группе | Показано число людей (включая участников вложенной группы — подтвердить, что состав считается по AD так, как ожидает организация); без нажатия «Подтверждаю: выдать доступ N чел.» ничего не выдаётся; число подтверждения должно совпасть с фактическим |
| Группа > 300 человек | Отказ с понятным текстом |
| Выдача отключённой учётной записи / пользователю, удалённому из каталога | Не выдаётся (или выдача без активного входа) — зафиксировать фактическое поведение в отчёте |
| Выданному пользователю: вход → встреча | Видит **только** эту встречу; материалы другой встречи той же комнаты закрыты; «Управление доступом» и журнал недоступны |
| Отзыв доступа | У ранее открытой вкладки следующее обращение (стенограмма, документы, скачивание, запись) — 404/403; прямые ссылки на документы перестают работать |
| Недоступность каталога во время поиска | Сообщение «каталог недоступен», страница не падает |

Отчёт: скриншоты окна управления доступом, запись из журнала комнаты («Доступ выдан/отозван»), версия AD и схема групп.

## 2. Почта (SMTP / Exchange): рассылка материалов
Условия: активный профиль почты («Администрирование → Электронная почта»), разрешённые домены; тестовая встреча, где готовы **протокол, резюме, стенограмма (> 5 реплик) и карта**; получатели: руководитель, 2 участника, 1 «выбранный» сотрудник; у одного из участников в каталоге **нет** адреса.

| Шаг | Ожидаем |
| --- | --- |
| Комната: протокол — «Всем участникам», резюме — «Только руководителю», стенограмма — «Выбранным», карта — «Всем»; завершить встречу | Письма уходят **один раз**: протокол (и карта отдельным HTML) — участникам; резюме — руководителю; стенограмма — выбранному; участникам стенограмма **не** приходит |
| Нет адреса у участника | В списке получателей и в «Отправленные материалы» — пометка «в каталоге нет адреса», остальным письма доходят |
| Остановить SMTP на время отправки / неверный пароль | Состояние «в очереди» → повторные попытки по политике, затем «не доставлено» с причиной; **материал не пропал**; после восстановления «повторить» (администратор) отправляет без дублей |
| Нажать «Сформировать заново» протокол | Автоматически повторно **не** отправляется; «Отправить материалы» вручную — одно письмо |
| Размер вложений близок к лимиту | Вместо вложения — ссылка на страницу встречи (открывается только у имеющих доступ) |
| Exchange с Kerberos/NTLM-прокси, 2+ релея | Письма идут через рабочий релей; смена активного профиля не теряет очередь |

Отчёт: заголовки 2–3 полученных писем, таблица «Отправленные материалы», журнал комнаты (вкладка «История действий») с получателями и результатом.

## 3. Журнал комнаты
Выполнить на тестовой встрече: вход/выход участников, формирование и пересоздание протокола, правка, удаление (администратор), скачивание, ручная отправка, изменение настроек рассылки и значка, выдача и отзыв доступа. В «Истории действий» (по комнате и по встрече) должны быть все события с исполнителем, временем (UTC в данных, местное время в интерфейсе) и встречей; фильтры по периоду, встрече, пользователю и типу работают; пароли, токены и содержимое материалов не показываются.

## 4. Не относящееся к блоку «руководитель комнаты», но обязательное после развёртывания
* PostgreSQL / Redis: `GET /api/v1/health/db`, отсутствие накопления соединений при нагрузке (`docs/DB_AND_SCALING.md`), перезапуск Redis во время встречи.
* EWS с настоящим Exchange (NTLM/Kerberos): «Администрирование → Outlook → Проверки» и сверка календаря (`docs/OUTLOOK_ADDIN.md`).
* Нагрузка и масштабирование (2000 одновременно активных пользователей — **цель остаётся открытой**): повторить `tests/perf/` на целевом железе, несколько экземпляров backend, LiveKit под нагрузкой.
* Smoke-test после обновления (`scripts/smoke-test.sh`) на публичном адресе: ожидается OK для `/rtc/v1`; реальная ошибка маршрутизации или авторизации по-прежнему даёт FAIL (покрыто тестами `tests/scripts/part_fixes.sh`).
