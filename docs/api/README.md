# Публичный API Peregovorka (v1)

API для интеграций: прочитать список комнат и встреч, стенограмму, протоколы и резюме, карту разговора, сообщения чата и сведения об аудиозаписях; завершить встречу. Базовый адрес — `https://<ваш-сервер>/api/public/v1`.

* Машиночитаемое описание (OpenAPI 3.1): `/api/public/v1/openapi.json`
* Справочная страница: `/api/public/v1/docs` (открывается без ключа, без скриптов)
* Интерфейс управления: **Администрирование → Интеграции → Публичный API**

Адреса в примерах условные (`meet.example.com`).

> Возможности: чтение данных встреч; **фоновые задачи** формирования протоколов, резюме и карт (`202 Accepted`); **`Idempotency-Key`** для операций создания; **короткоживущие ссылки** на скачивание записей; **события (webhooks)** с подписью HMAC. Подробно — разделы 10–13.

## 1. Как это устроено

* **Интеграция** (сервисная учётная запись) — то, чем пользуется ваша система: название, набор **прав** (scopes), область **комнат** и, при желании, список **разрешённых адресов**.
* **Ключ** выпускается интеграции. Формат — `pgk_<8 символов>_<43 символа>`. В базе хранится только SHA-256 секрета, **полный ключ показывается один раз** при выпуске.
* API **выключен**, пока администратор не включит его. Включение, лимиты — Администрирование → Публичный API.
* Вход в интерфейс (cookie-сессия) и ключ API — разные вещи: сессия браузера к публичному API не подходит, ключ не даёт доступа к интерфейсу.

## 2. Сквозной пример: от нуля до стенограммы

1. **Включите API.** Администрирование → Интеграции → «Публичный API» → «Публичный API включён» → «Сохранить».
2. **Создайте интеграцию.** «Новая интеграция» → название (например, «CRM»), права `rooms:read`, `meetings:read`, `transcripts:read`, комнаты — нужные (или «Все»), при необходимости — разрешённые адреса. «Сохранить».
3. **Выпустите ключ.** Кнопка «Выпустить ключ» → скопируйте ключ из окна (позже он не показывается).
4. **Проверьте ключ:**

   ```bash
   export PG_URL=https://meet.example.com/api/public/v1
   export PG_KEY=pgk_xxxxxxxx_...            # ваш ключ
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/me"
   ```
   ```json
   {"client": "CRM", "key_id": "a1b2c3d4", "scopes": ["meetings:read", "rooms:read", "transcripts:read"], "rooms": null, "key_expires_at": null}
   ```
5. **Найдите завершённые встречи** (новые первыми, по 50 на страницу):

   ```bash
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/meetings?state=ended&limit=2"
   ```
   ```json
   {"items": [{"id": "mtg_5e0f…", "room": {"id": "rom_9a1c…", "slug": "sales", "name": "Продажи"}, "state": "ended",
               "started_at": "2026-10-08T09:00:00Z", "ended_at": "2026-10-08T09:55:00Z", "duration_s": 3300,
               "participants_count": 4, "transcription_enabled": true, "record_audio": false}],
    "next_cursor": "WyIyMDI2LTEwLTA4VDA5…"}
   ```
   Следующая страница — `?after=<next_cursor>`. Когда `next_cursor` равен `null`, страниц больше нет.
6. **Получите стенограмму** — JSON постранично или готовый текст:

   ```bash
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/meetings/mtg_5e0f…/transcript?limit=100"          # JSON, с курсором
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/meetings/mtg_5e0f…/transcript?format=srt" -o talk.srt   # txt | md | vtt | srt
   ```
7. **Скрипт на Python** — все стенограммы за период:

   ```python
   import os, requests

   BASE, KEY = os.environ["PG_URL"], os.environ["PG_KEY"]
   s = requests.Session(); s.headers["Authorization"] = f"Bearer {KEY}"

   def pages(path, **params):
       cursor = None
       while True:
           r = s.get(f"{BASE}{path}", params={**params, **({"after": cursor} if cursor else {})}, timeout=30)
           if r.status_code == 429:                         # лимит: подождать, сколько просят, и повторить
               import time; time.sleep(int(r.headers.get("Retry-After", "5"))); continue
           r.raise_for_status()
           page = r.json()
           yield from page["items"]
           cursor = page["next_cursor"]
           if not cursor:
               return

   for m in pages("/meetings", state="ended", started_after="2026-10-01T00:00:00Z"):
       text = s.get(f"{BASE}/meetings/{m['id']}/transcript", params={"format": "md"}, timeout=60).text
       print(m["room"]["name"], m["started_at"], len(text), "символов")
   ```
8. **Когда ключ нужно заменить** — «Заменить» в списке ключей: выпускается новый, прежний работает ещё 24 часа (окно перехода), затем перестаёт. **Отозвать** — ключ перестаёт действовать сразу.

Тот же путь автоматически проверяется живым сценарием `tests/live/scenario_public_api.py` (настоящая админка, внешние HTTP-вызовы, отзыв ключа).

## 3. Права (scopes)

| Право | Что разрешает |
|---|---|
| `rooms:read` | список и карточки комнат |
| `meetings:read` | список и карточки встреч, участники (имя, должность, подразделение — без e-mail и телефона) |
| `meetings:end` | завершить идущую встречу для всех (действие пишется в журнал аудита как `api:<название интеграции>`) |
| `transcripts:read` | стенограмма (JSON, txt, md, vtt, srt) и сохранённые стенограммы-документы |
| `protocols:read` | протоколы |
| `summaries:read` | резюме |
| `maps:read` | карта разговора |
| `recordings:read` | сведения об аудиозаписях (без скачивания) |
| `messages:read` | сообщения чата встречи |
| `protocols:generate` | запускать формирование протоколов (нагружает языковую модель) |
| `summaries:generate` | запускать формирование резюме |
| `maps:generate` | запускать формирование карты разговора |
| `jobs:read` | состояние и отмена **своих** фоновых задач |
| `recordings:download` | получать короткоживущие ссылки на скачивание записей |

Выдавайте минимум. Нет нужного права — ответ `403` с `error.code = "insufficient_scope"` и полем `required_scope`.

**Область комнат.** Интеграция может видеть только выбранные комнаты. Чужая комната, встреча в ней и любой вложенный объект отвечают **`404 not_found`** — так же, как несуществующий объект (чтобы по ответу нельзя было узнать, что объект существует).

## 4. Идентификаторы

Типизированные: `rom_…` комната, `mtg_…` встреча, `pro_…` документ, `map_…` карта, `rec_…` запись, `usr_…`/`gst_…` участник, `msg_…` сообщение. Идентификатор другого типа или «голый» UUID не принимается (`404`).

## 5. Ошибки

Всегда одинаковая форма:

```json
{"error": {"code": "insufficient_scope", "message": "Не хватает права «meetings:read».", "request_id": "3f9c…", "required_scope": "meetings:read"}}
```

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `invalid_cursor` | курсор повреждён или от другой выборки — начните сначала |
| 401 | `unauthorized` / `invalid_api_key` | нет ключа / ключ неверен (одинаковый ответ на неверный секрет и несуществующий ключ) |
| 401 | `key_revoked` / `key_expired` | ключ отозван / срок истёк (сообщается только при верном секрете) |
| 403 | `client_disabled`, `ip_not_allowed`, `insufficient_scope` | интеграция отключена / адрес не разрешён / не хватает права |
| 404 | `not_found` | нет такого объекта или он вне области комнат |
| 400 | `invalid_idempotency_key` | `Idempotency-Key`: 1–64 символа `A-Za-z0-9_.:-` |
| 409 | `not_ready` | документ ещё формируется |
| 409 | `meeting_not_ended` / `llm_not_configured` / `anonymizer_not_configured` / `no_materials` | задачу поставить нельзя: встреча идёт / модель не настроена / не настроено обезличивание / в встрече нечего обрабатывать |
| 409 | `idempotency_conflict` / `idempotency_in_progress` | тот же `Idempotency-Key` для другого запроса / первый запрос ещё выполняется (повторите через секунду) |
| 409 | `not_cancellable` | отменить можно только ожидающую задачу |
| 410 | `link_expired` / `file_missing` | срок ссылки на запись истёк / файл записи удалён из хранилища |
| 429 | `too_many_jobs` | у интеграции уже 5 незавершённых задач |
| 413 | `too_large` | стенограмма слишком велика для текстового формата — используйте JSON с курсором |
| 422 | `validation_error` | неверные параметры (`error.fields` — какие именно) |
| 429 | `rate_limited` | превышен лимит; смотрите `Retry-After` |
| 503 | `api_disabled` | API выключен администратором |
| 500 | `internal_error` | сообщите администратору `request_id` |

В каждом ответе есть заголовок `X-Request-ID` — по нему администратор найдёт запрос в журнале.

## 6. Лимиты

Окно — одна минута, отдельно на каждую интеграцию и класс запросов (`read` — чтение, `write` — изменения). Значения задаёт администратор. В каждом ответе: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (секунд до обновления), `X-RateLimit-Class`; при превышении — `429` и `Retry-After`. Лимит одной интеграции не мешает другим. Сбой хранилища счётчиков не отключает API.

## 7. Постраничный вывод

Параметры `limit` (по умолчанию 50, максимум задаёт администратор) и `after` (курсор). Курсор непрозрачен и привязан к позиции в выборке, а не к номеру страницы: новые встречи, появившиеся во время обхода, не приводят к повторам и пропускам.

## 8. Безопасность

* Ключ — как пароль: не храните в репозитории и логах, передавайте только по HTTPS в заголовке `Authorization`. Ключ в адресе запроса не принимается.
* Секрет хранится только как SHA-256; восстановить потерянный ключ нельзя — выпустите новый.
* Список разрешённых адресов (IP/CIDR) ограничивает, откуда ключ работает. За обратным прокси адрес клиента определяется так же, как для входа в интерфейс (доверенные прокси из настроек сервера).
* Журнал обращений хранит метод, **шаблон** пути (без идентификаторов), статус, время, адрес и `request_id`; заголовки и тела запросов не сохраняются. Срок хранения — в настройках.
* Все изменения интеграций и ключей (создание, замена, отзыв, правка прав) пишутся в журнал аудита.
* HTML-вид документа отдаётся с запрещающей политикой содержимого (`sandbox`).

## 9. Что не входит

Подписки на события создаёт **администратор** в интерфейсе (не интеграция через API): так интеграция с правом чтения не может завести себе «копию» потока событий. Изменение и удаление встреч, протоколов и записей через API не предусмотрено.

## 10. Фоновые задачи: протокол, резюме, карта

Долгие операции не держат соединение: запрос ставит **задачу** в очередь и сразу отвечает **`202 Accepted`** с телом задачи и заголовками `Location` (адрес задачи) и `Retry-After` (когда спросить снова).

```bash
curl -s -X POST "$PG_URL/meetings/$MTG/documents" \
  -H "Authorization: Bearer $PG_KEY" -H "Content-Type: application/json" -H "Idempotency-Key: crm-order-42" \
  -d '{"kind": "protocol", "instruction": "Только решения и поручения"}'
```
```json
{"id": "job_5b1e…", "kind": "protocol", "meeting_id": "mtg_5e0f…", "status": "queued", "created_at": "2026-10-08T10:00:00Z", "started_at": null, "finished_at": null, "error": null, "result": null}
```

* `POST /meetings/{id}/documents` (`kind`: `protocol` | `summary`, необязательная `instruction`) — права `protocols:generate` / `summaries:generate`; `POST /meetings/{id}/map` — `maps:generate`.
* Состояния: **`queued` → `processing` → `completed` | `failed`**, а также **`cancelled`**. `GET /jobs/{id}` (право `jobs:read`) — состояние; при `completed` в `result` лежит `document_id` (или `map_id`), содержимое читается обычными методами (`GET …/documents/{id}`, `GET …/map`). При `failed` — `error` с причиной.
* `GET /jobs?status=…&limit=…&after=…` — свои задачи, новые первыми (курсор). Чужие задачи не видны (`404`).
* `POST /jobs/{id}/cancel` — отменить **ожидающую** задачу; выполняющуюся прервать безопасно нельзя (`409 not_cancellable`); повторная отмена безопасна.
* Условия постановки проверяются сразу, чтобы не плодить обречённые задачи: встреча должна быть завершена, модель настроена, должны быть материалы (иначе `409` с кодом из таблицы ошибок).
* Очередь: задачи выполняются по порядку, число одновременных ограничено настройкой (по умолчанию **одна**) — языковая модель не должна мешать звонкам и распознаванию речи. На интеграцию — не более **5** незавершённых задач (`429 too_many_jobs`). Перезапуск сервиса очередь не теряет; задача, прерванная на середине, получает статус `failed` с понятным текстом.

Опрос с паузой (или подписка на событие `job.completed` — раздел 13):

```python
import time, requests
job = s.post(f"{BASE}/meetings/{mtg}/documents", json={"kind": "protocol"}, headers={"Idempotency-Key": f"proto-{mtg}"}).json()
while job["status"] in ("queued", "processing"):
    time.sleep(5)
    job = s.get(f"{BASE}/jobs/{job['id']}").json()
if job["status"] == "completed":
    text = s.get(f"{BASE}/meetings/{mtg}/documents/{job['result']['document_id']}", params={"format": "md"}).text
```

## 11. Идемпотентность (`Idempotency-Key`)

Сеть оборвалась, и клиент не знает, создалась ли задача. Повторите **тот же** запрос с **тем же** заголовком `Idempotency-Key` (1–64 символа `A-Za-z0-9_.:-`, например идентификатор заказа в вашей системе):

| Ситуация | Ответ |
|---|---|
| первый запрос | обычный (`202`) |
| повтор того же запроса | прежний ответ дословно + заголовок `Idempotent-Replay: true`; вторая задача **не создаётся** |
| тот же ключ, другое тело или адрес | `409 idempotency_conflict` |
| оригинал ещё выполняется | `409 idempotency_in_progress` + `Retry-After: 1` |
| оригинал завершился ошибкой | ошибка не запоминается: повтор с тем же ключом допустим |

Ключ действует в пределах интеграции (чужой тот же ключ не пересекается) и хранится 24 часа (настройка). Параллельные запросы с одним ключом создают ровно одну задачу.

## 12. Ссылки на скачивание записей

Скачивание файла отдельно от ключа API: интеграция получает **ссылку** и отдаёт её плееру или стороннему сервису.

```bash
curl -s -X POST -H "Authorization: Bearer $PG_KEY" "$PG_URL/meetings/$MTG/recordings/$REC/download-url"
# {"url": "/api/public/v1/downloads/<токен>", "expires_at": "…", "expires_in_s": 300, "size_bytes": 1234567, "content_type": "audio/wav"}
curl -s -o talk.wav "https://meet.example.com<url из ответа>"      # без Authorization
```

* Право `recordings:download`, класс лимита `download`. Ссылка действует **5 минут** (настройка), подписана и не содержит ключа API; подделать или продлить её нельзя (`404` / `410 link_expired`).
* При **каждом** использовании заново проверяется, что интеграция включена, право и область комнат прежние: отозванные права, отключённая или удалённая интеграция закрывают уже выданные ссылки.
* Выдача ссылки и каждое скачивание записываются в журнал аудита (`api:<интеграция>`); в журнале обращений токен не хранится (только шаблон пути).
* Запись, удалённая из хранилища, отвечает `410 file_missing`.

## 13. События (webhooks)

Администратор создаёт **получателя** (адрес HTTPS, нужные события и комнаты) в **Администрирование → Публичный API → Подписки на события** и получает **секрет подписи** (показывается один раз).

**События**: `meeting.started`, `meeting.ended`, `document.ready`, `document.failed` (протокол, резюме, карта), `job.completed`, `job.failed`; `webhook.test` — проверочное, по кнопке. В событии только идентификаторы — **без персональных данных и текстов**:

```json
{"id": "evt_0f3a9c…", "type": "meeting.ended", "api_version": "1", "created": "2026-10-08T09:55:02Z",
 "data": {"meeting_id": "mtg_5e0f…", "room": {"id": "rom_9a1c…", "slug": "sales", "name": "Продажи"}, "started_at": "2026-10-08T09:00:00Z", "ended_at": "2026-10-08T09:55:00Z", "end_reason": "manual"}}
```

**Заголовки запроса**: `X-Peregovorka-Event`, `X-Peregovorka-Event-Id` (то же, что `id` в теле), `X-Peregovorka-Delivery`, `X-Peregovorka-Timestamp` (секунды Unix), `X-Peregovorka-Signature`, `X-Peregovorka-Attempt`, при ручной повторной отправке — `X-Peregovorka-Retry: manual`.

**Подпись** — HMAC-SHA256 от строки `"<timestamp>.<тело запроса как есть>"` с секретом получателя, в виде `v1=<hex>`. Пока идёт замена секрета, заголовок содержит **две** подписи через запятую (`v1=…,v1=…`) — достаточно совпадения любой.

**Проверка у получателя** (обязательно: подпись **и** свежесть **и** дубль):

```python
import hmac, hashlib, time

def verify(headers, body: bytes, secrets: list[str], seen_ids: set[str]) -> bool:
    ts = int(headers["X-Peregovorka-Timestamp"])
    if abs(time.time() - ts) > 300:                     # защита от повторного предъявления перехваченного запроса
        return False
    given = [p[3:] for p in headers["X-Peregovorka-Signature"].split(",") if p.startswith("v1=")]
    want = [hmac.new(s.encode(), f"{ts}.".encode() + body, hashlib.sha256).hexdigest() for s in secrets]
    if not any(hmac.compare_digest(g, w) for g in given for w in want):
        return False
    event_id = headers["X-Peregovorka-Event-Id"]        # доставка «как минимум один раз»: дубли бывают, обрабатывайте идемпотентно
    if event_id in seen_ids:
        return True                                     # уже обработано — ответить 200, но не выполнять повторно
    seen_ids.add(event_id)
    return True
```

**Ответ получателя.** Любой код `2xx` — принято. Остальное (включая `3xx` — **редиректы не выполняются**, `4xx`, `5xx`, таймаут) — неудача.

**Повторы.** Задержка растёт: ≈ 10 с, 20 с, 40 с … до часа (с разбросом ±20 %), всего до 8 попыток (настройка), затем событие получает статус «не доставлено» и его можно отправить вручную («История» → «Повторить»: тот же `Event-Id`, новая метка времени и подпись).

**Состояние получателя.** После 5 неудачных попыток подряд — **«деградация»** (события ещё отправляются), после 20 — **«отключён»**: события ему не ставятся в очередь, пока администратор не включит его вручную; ответ `410 Gone` отключает сразу. Успешная доставка возвращает «работает». Автоматическое отключение пишется в журнал аудита и журнал событий.

**Замена секрета без простоя.** «Заменить секрет» выдаёт новый и ещё 24 часа подписывает события обоими; затем действует только новый.

**Безопасность адресов (SSRF).** Адрес проверяется при сохранении и **при каждой отправке**: только `https` (http — по разрешению администратора), без логина и пароля, без фрагмента; имя узла разрешается в IP, и **каждый** адрес должен быть допустим; соединение идёт именно на проверенный IP (с прежним именем в `Host` и SNI), системные прокси игнорируются. **По умолчанию запрещены** loopback, частные сети, CGNAT, link-local, multicast и зарезервированные адреса; адреса служебных метаданных облака не разрешаются никогда. Для установки в закрытой сети администратор перечисляет разрешённые внутренние узлы или сети в настройках («Разрешённые внутренние узлы»).

## 14. Сквозной пример: заказ протокола → событие → чтение

1. Администратор: включает API; создаёт интеграцию с правами `meetings:read`, `protocols:generate`, `jobs:read`, `protocols:read`; выпускает ключ; создаёт получателя на `https://crm.example.com/hooks/peregovorka` с событием `job.completed` и сохраняет секрет подписи.
2. После встречи ваша система: `POST /meetings/{id}/documents` с `Idempotency-Key: crm-<номер сделки>` → `202`, `job_…`.
3. Сервер формирует протокол в очереди и отправляет на ваш адрес `job.completed` с `job_id` и `document_id` (подпись проверяется функцией выше).
4. Ваша система: `GET /meetings/{id}/documents/{document_id}?format=md` — получает текст. Если событие не пришло, `GET /jobs/{job_id}` покажет состояние.

Живой сценарий `tests/live/scenario_webhooks.py` проходит этот путь на настоящем стенде: настоящая админка, внешний приёмник с проверкой подписи, завершение встречи, ошибки и ручной повтор.
