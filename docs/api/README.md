# Публичный API Peregovorka (v1)

API для интеграций: прочитать список комнат и встреч, стенограмму, протоколы и резюме, карту разговора, сообщения чата и сведения об аудиозаписях; завершить встречу. Базовый адрес — `https://<ваш-сервер>/api/public/v1`.

* Машиночитаемое описание (OpenAPI 3.1): `/api/public/v1/openapi.json`
* Справочная страница: `/api/public/v1/docs` (открывается без ключа, без скриптов)
* Интерфейс управления: **Администрирование → Интеграции → Публичный API**

Адреса в примерах условные (`meet.example.com`).

> Эта версия API — только чтение, плюс одно действие («завершить встречу»). Запуск генерации протоколов, скачивание записей и подписки на события (webhooks) — следующий этап, права на них пока не выдаются.

## 1. Как это устроено

* **Интеграция** (сервисная учётная запись) — то, чем пользуется ваша система: название, набор **прав** (scopes), область **комнат** и, при желании, список **разрешённых адресов**.
* **Ключ** выпускается интеграции. Формат — `pgk_<8 символов>_<43 символа>`. В базе хранится только SHA-256 секрета, **полный ключ показывается один раз** при выпуске.
* API **выключен**, пока администратор не включит его. Включение, лимиты — Администрирование → Публичный API.
* Вход в интерфейс (cookie-сессия) и ключ API — разные вещи: сессия браузера к публичному API не подходит, ключ не даёт доступа к интерфейсу.

## 2. Сквозной пример: от нуля до стенограммы

1. **Включите API.** Администрирование → Интеграции → «Публичный API» → «Публичный API включён» → «Сохранить».
2. **Создайте интеграцию.** «Новая интеграция» → название (например, «CRM»), права `rooms:read`, `meetings:read`, `transcripts:read`, комнаты — нужные (или «Все»), при необходимости — разрешённые адреса. «Сохранить».
3. **Выпустите ключ.** Кнопка «Выпустить ключ» → скопируйте ключ из окна (позже он не показывается).
4. **Проверьте ключ:**

   ```bash
   export PG_URL=https://meet.example.com/api/public/v1
   export PG_KEY=pgk_xxxxxxxx_...            # ваш ключ
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/me"
   ```
   ```json
   {"client": "CRM", "key_id": "a1b2c3d4", "scopes": ["meetings:read", "rooms:read", "transcripts:read"], "rooms": null, "key_expires_at": null}
   ```
5. **Найдите завершённые встречи** (новые первыми, по 50 на страницу):

   ```bash
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/meetings?state=ended&limit=2"
   ```
   ```json
   {"items": [{"id": "mtg_5e0f…", "room": {"id": "rom_9a1c…", "slug": "sales", "name": "Продажи"}, "state": "ended",
               "started_at": "2026-10-08T09:00:00Z", "ended_at": "2026-10-08T09:55:00Z", "duration_s": 3300,
               "participants_count": 4, "transcription_enabled": true, "record_audio": false}],
    "next_cursor": "WyIyMDI2LTEwLTA4VDA5…"}
   ```
   Следующая страница — `?after=<next_cursor>`. Когда `next_cursor` равен `null`, страниц больше нет.
6. **Получите стенограмму** — JSON постранично или готовый текст:

   ```bash
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/meetings/mtg_5e0f…/transcript?limit=100"          # JSON, с курсором
   curl -s -H "Authorization: Bearer $PG_KEY" "$PG_URL/meetings/mtg_5e0f…/transcript?format=srt" -o talk.srt   # txt | md | vtt | srt
   ```
7. **Скрипт на Python** — все стенограммы за период:

   ```python
   import os, requests

   BASE, KEY = os.environ["PG_URL"], os.environ["PG_KEY"]
   s = requests.Session(); s.headers["Authorization"] = f"Bearer {KEY}"

   def pages(path, **params):
       cursor = None
       while True:
           r = s.get(f"{BASE}{path}", params={**params, **({"after": cursor} if cursor else {})}, timeout=30)
           if r.status_code == 429:                         # лимит: подождать, сколько просят, и повторить
               import time; time.sleep(int(r.headers.get("Retry-After", "5"))); continue
           r.raise_for_status()
           page = r.json()
           yield from page["items"]
           cursor = page["next_cursor"]
           if not cursor:
               return

   for m in pages("/meetings", state="ended", started_after="2026-10-01T00:00:00Z"):
       text = s.get(f"{BASE}/meetings/{m['id']}/transcript", params={"format": "md"}, timeout=60).text
       print(m["room"]["name"], m["started_at"], len(text), "символов")
   ```
8. **Когда ключ нужно заменить** — «Заменить» в списке ключей: выпускается новый, прежний работает ещё 24 часа (окно перехода), затем перестаёт. **Отозвать** — ключ перестаёт действовать сразу.

Тот же путь автоматически проверяется живым сценарием `tests/live/scenario_public_api.py` (настоящая админка, внешние HTTP-вызовы, отзыв ключа).

## 3. Права (scopes)

| Право | Что разрешает |
|---|---|
| `rooms:read` | список и карточки комнат |
| `meetings:read` | список и карточки встреч, участники (имя, должность, подразделение — без e-mail и телефона) |
| `meetings:end` | завершить идущую встречу для всех (действие пишется в журнал аудита как `api:<название интеграции>`) |
| `transcripts:read` | стенограмма (JSON, txt, md, vtt, srt) и сохранённые стенограммы-документы |
| `protocols:read` | протоколы |
| `summaries:read` | резюме |
| `maps:read` | карта разговора |
| `recordings:read` | сведения об аудиозаписях (без скачивания) |
| `messages:read` | сообщения чата встречи |

Выдавайте минимум. Нет нужного права — ответ `403` с `error.code = "insufficient_scope"` и полем `required_scope`.

**Область комнат.** Интеграция может видеть только выбранные комнаты. Чужая комната, встреча в ней и любой вложенный объект отвечают **`404 not_found`** — так же, как несуществующий объект (чтобы по ответу нельзя было узнать, что объект существует).

## 4. Идентификаторы

Типизированные: `rom_…` комната, `mtg_…` встреча, `pro_…` документ, `map_…` карта, `rec_…` запись, `usr_…`/`gst_…` участник, `msg_…` сообщение. Идентификатор другого типа или «голый» UUID не принимается (`404`).

## 5. Ошибки

Всегда одинаковая форма:

```json
{"error": {"code": "insufficient_scope", "message": "Не хватает права «meetings:read».", "request_id": "3f9c…", "required_scope": "meetings:read"}}
```

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `invalid_cursor` | курсор повреждён или от другой выборки — начните сначала |
| 401 | `unauthorized` / `invalid_api_key` | нет ключа / ключ неверен (одинаковый ответ на неверный секрет и несуществующий ключ) |
| 401 | `key_revoked` / `key_expired` | ключ отозван / срок истёк (сообщается только при верном секрете) |
| 403 | `client_disabled`, `ip_not_allowed`, `insufficient_scope` | интеграция отключена / адрес не разрешён / не хватает права |
| 404 | `not_found` | нет такого объекта или он вне области комнат |
| 409 | `not_ready` | документ ещё формируется |
| 413 | `too_large` | стенограмма слишком велика для текстового формата — используйте JSON с курсором |
| 422 | `validation_error` | неверные параметры (`error.fields` — какие именно) |
| 429 | `rate_limited` | превышен лимит; смотрите `Retry-After` |
| 503 | `api_disabled` | API выключен администратором |
| 500 | `internal_error` | сообщите администратору `request_id` |

В каждом ответе есть заголовок `X-Request-ID` — по нему администратор найдёт запрос в журнале.

## 6. Лимиты

Окно — одна минута, отдельно на каждую интеграцию и класс запросов (`read` — чтение, `write` — изменения). Значения задаёт администратор. В каждом ответе: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (секунд до обновления), `X-RateLimit-Class`; при превышении — `429` и `Retry-After`. Лимит одной интеграции не мешает другим. Сбой хранилища счётчиков не отключает API.

## 7. Постраничный вывод

Параметры `limit` (по умолчанию 50, максимум задаёт администратор) и `after` (курсор). Курсор непрозрачен и привязан к позиции в выборке, а не к номеру страницы: новые встречи, появившиеся во время обхода, не приводят к повторам и пропускам.

## 8. Безопасность

* Ключ — как пароль: не храните в репозитории и логах, передавайте только по HTTPS в заголовке `Authorization`. Ключ в адресе запроса не принимается.
* Секрет хранится только как SHA-256; восстановить потерянный ключ нельзя — выпустите новый.
* Список разрешённых адресов (IP/CIDR) ограничивает, откуда ключ работает. За обратным прокси адрес клиента определяется так же, как для входа в интерфейс (доверенные прокси из настроек сервера).
* Журнал обращений хранит метод, **шаблон** пути (без идентификаторов), статус, время, адрес и `request_id`; заголовки и тела запросов не сохраняются. Срок хранения — в настройках.
* Все изменения интеграций и ключей (создание, замена, отзыв, правка прав) пишутся в журнал аудита.
* HTML-вид документа отдаётся с запрещающей политикой содержимого (`sandbox`).
