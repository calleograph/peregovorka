# Эксплуатационный паспорт экземпляра «Переговорки» — ШАБЛОН

> Шаблон хранится в открытом репозитории **пустым**. Заполненный экземпляр содержит адреса, имена серверов, учётные записи и сведения
> об инфраструктуре организации: храните его во внутреннем хранилище документов эксплуатирующей организации с ограниченным доступом,
> **не в репозитории, не в вики и не в обращениях в открытые трекеры** ([PRIVACY_OF_CONFIG.md](PRIVACY_OF_CONFIG.md)).
> Пароли и ключи в паспорт не вписываются: только **где** они хранятся и **кто** имеет доступ.

Как заполнить быстро: большая часть значений берётся с сервера командами из раздела «Откуда взять» (они только читают).
Обновляйте паспорт после каждого обновления версии, смены сертификата, адресов, хранилища или ответственных.

## 3. Сетевая схема

Нарисуйте или вставьте схему: клиенты → межсетевой экран → reverse proxy → сервер; отдельно — путь медиа UDP/TCP к LiveKit.

| Поле | Значение | Откуда взять |
| --- | --- | --- |
| Публичный адрес приложения (`APP_PUBLIC_URL`) | | `.env` |
| Дополнительные разрешённые адреса (`ALLOWED_ORIGINS`) | | `.env` |
| Адрес сигнализации LiveKit (`LIVEKIT_PUBLIC_URL`) | | `.env` |
| Адрес медиа для клиентов (`LIVEKIT_NODE_IP`) | | `.env` |
| Порты медиа (`LIVEKIT_UDP_PORT`/udp, `LIVEKIT_TCP_PORT`/tcp) и где открыты | | `.env`; `scripts/ports.sh` |
| Порт web (`WEB_BIND_ADDR:WEB_PORT`), порт nginx хоста (`NGINX_LISTEN_PORT`) | | `.env` |
| Reverse proxy: продукт, хост, кто администрирует, где конфигурация | | |
| Ограничения доступа (VPN, только внутренняя сеть, доверенные подсети в приложении) | | «Администрирование → Безопасность → Доверенные подсети» |
| DNS: внутренняя и внешняя зоны, split DNS / hairpin NAT | | |
| Прокси для исходящих соединений сервера (сборка, обновление) | | |
