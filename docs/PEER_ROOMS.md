# Временные равноправные комнаты

Комната на одну встречу **без ведущего**: у всех участников равные права на микрофон, камеру, демонстрацию экрана и доску; записью и транскрибацией управляет любой участник. Подходит для быстрых разговоров «давайте созвонимся», когда не нужна ни роль руководителя, ни постоянный адрес.

По умолчанию функция **выключена**: «Администрирование → Общие настройки → Равноправные комнаты».

## Как создаётся

* **Кнопкой:** в списке переговорок «Равноправная комната» → ссылка вида `https://<сервер>/p/<код>`.
* **Первым переходом по ссылке:** любой вошедший сотрудник, открывший новую ссылку `/p/<код>`, создаёт комнату (можно выключить: «Создавать комнату при первом переходе по ссылке»). Так ссылку можно подготовить заранее — в письме, приглашении календаря.
* Код — 20 знаков безопасного алфавита (≈100 бит): угадать чужую ссылку нельзя. Неверный по формату код, чужая закрытая комната и выключенное создание отвечают одинаково — «комната не найдена».

## Кто что может

| | Участник | Владелец (создатель) | Администратор |
| --- | --- | --- | --- |
| Войти по ссылке | да (любой вошедший сотрудник; в режиме «только приглашённые» — приглашённые) | да | да |
| Микрофон, камера, экран, доска | да | да | да |
| Запись, транскрибация | да (ведущего нет) | да | да |
| Ссылка, срок, доступ, приглашённые, закрытие | нет | да — «Управление ссылкой…» в меню комнаты | да, закрыть любую (пресечение злоупотреблений) |

Владелец **не** становится руководителем комнаты: он управляет только ссылкой, сроком и составом приглашённых. В общем списке переговорок комнату видят владелец, администратор и приглашённые; остальные заходят по ссылке.

## Жизненный цикл

Создана → встреча идёт → все вышли (ожидание возврата, как у временных комнат) → закрыта. Комната, в которую никто не вошёл, закрывается через заданное число часов (по умолчанию 24); владелец может продлить срок. Перевыпуск ссылки делает прежнюю мёртвой (создать по ней новую комнату нельзя). Закрытая комната не удаляется: стенограмма, запись, чат, доска и протоколы остаются в «Истории» по политике хранения.

## Защита от злоупотреблений

Только вошедшие пользователи; не более N новых комнат в час и M активных у одного пользователя, общий предел; проверки ссылок ограничены по частоте (30 в минуту); все действия — в журнале аудита (`room.create_peer`, `room.update_peer`, `room.rotate_peer`, `room.close_peer`). Постоянные комнаты и их адреса не затрагиваются.

## Для интеграций

`POST /api/v1/rooms/peer` (создать, ответ с `link`), `POST /api/v1/rooms/peer/open` `{code}`, `GET|PATCH /api/v1/rooms/peer/{id}`, `POST …/rotate`, `POST …/close`, `GET /api/v1/rooms/peer/users/search?q=`. Права — как у обычного пользователя (сессия); отдельного ключа публичного API для создания комнат пока нет.

## Что не сделано

* Создание комнаты ключом публичного API (нужна новая область прав и привязка создателя).
* Гости без учётной записи: в равноправную комнату входят только сотрудники.
