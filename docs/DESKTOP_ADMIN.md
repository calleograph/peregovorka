# Peregovorka для Windows — инструкция администратора

## Пакеты

| Пакет | Для чего | Куда ставится |
| --- | --- | --- |
| `Peregovorka-Setup-X.Y.Z.exe` | Самостоятельная установка сотрудником. По умолчанию — для текущего пользователя без прав администратора; можно выбрать «для всех». Обновляется само (подписанные обновления издателя). | `%LOCALAPPDATA%\Programs\Peregovorka` (или `Program Files`) |
| `Peregovorka-X.Y.Z-x64.msi` | Централизованное развёртывание (GPO, SCCM/Intune и т. п.), для всех пользователей. Обновляет администратор: приложение само не обновляется. | `%ProgramFiles%\Peregovorka` |

Контрольные суммы — `SHA256SUMS.txt` в выпуске. Подпись: `Get-AuthenticodeSignature .\Peregovorka-X.Y.Z-x64.msi` должна быть `Valid` с издателем
организации-разработчика. **Выпуск с пометкой «Тестовая сборка» не подписан сертификатом удостоверяющего центра** — не распространяйте его как доверенный
корпоративный выпуск.

**Свои подписанные установщики** (сертификатом вашей организации или собственным сертификатом, с адресом вашего сервера внутри MSI) — сервер Peregovorka,
«Администрирование → Windows-клиент → Подпись и корпоративные сборки», подробно [DESKTOP_SIGNING.md](DESKTOP_SIGNING.md). EXE не ставится поверх уже
установленного MSI (код выхода 2). План ручной приёмки на ваших компьютерах — [DESKTOP_ACCEPTANCE.md](DESKTOP_ACCEPTANCE.md).

## Тихая установка и удаление

```powershell
# EXE: тихо, для текущего пользователя
Peregovorka-Setup-X.Y.Z.exe /S
# EXE: тихое удаление (данные пользователя сохраняются)
"%LOCALAPPDATA%\Programs\Peregovorka\Uninstall Peregovorka.exe" /S

# MSI: тихо, с журналом и преднастройкой
msiexec /i Peregovorka-X.Y.Z-x64.msi /qn /l*v install.log SERVERS="Головной офис|https://meet.example.org" ALLOWADDSERVERS=0 AUTOSTART=tray
# MSI: обновление — новый пакет поверх (свойства можно не повторять: значения первой установки сохраняются)
msiexec /i Peregovorka-X.Y.Z+1-x64.msi /qn
# MSI: тихое удаление (политики, автозапуск и схема ссылок удаляются вместе с программой)
msiexec /x Peregovorka-X.Y.Z-x64.msi /qn
```

## Свойства MSI

Все необязательны. **Логины и пароли пользователей в MSI, командную строку и реестр не передаются никогда** — сотрудник входит сам (AD, 2FA),
приложение хранит только отзываемый токен устройства.

| Свойство | Значение | Пример |
| --- | --- | --- |
| `SERVERS` | Преднастроенные организации: `Название\|https://адрес` через `;`. Только HTTPS. Пользователь их не удалит. | `Головной офис\|https://meet.example.org;Филиал\|https://branch.example.org` |
| `ALLOWADDSERVERS` | `0` — запретить подключать другие серверы | `0` |
| `ALLOWEDDOMAINS` | Разрешённые домены через `;` (`*.` — только поддомены) | `example.org;*.example.org` |
| `AUTOSTART` | `off` / `tray` / `window`. Для `tray` и `window` MSI прописывает запуск для всех пользователей. | `tray` |
| `CLOSEACTION` | Кнопка «Закрыть»: `tray` / `quit` / `ask` | `tray` |
| `UPDATEMODE` | `auto` / `notify` / `off` (при установке из MSI приложение само не обновляется в любом случае) | `off` |
| `UPDATEURL` | Корпоративное зеркало манифеста обновлений (для EXE-установок) | `https://mirror.example.org/peregovorka/update.json` |
| `NOTIFICATIONS` | `0` — выключить уведомления Windows | `1` |
| `HIDENOTIFICATIONCONTENT` | `1` — в уведомлении только «Новое сообщение» | `1` |
| `PROXYMODE` | `system` / `direct` / `manual` / `pac` | `pac` |
| `PROXYSERVER`, `PROXYBYPASS` | Для `manual` | `proxy.example.org:3128`, `<local>;*.example.org` |
| `PROXYPAC` | Для `pac` | `https://proxy.example.org/proxy.pac` |

Значения записываются в `HKLM\SOFTWARE\Policies\Peregovorka` (и запоминаются в `HKLM\SOFTWARE\Peregovorka\Desktop\Install` для обновлений).
Чтобы снять значение, заданное через MSI, удалите программу и установите заново без свойства либо управляйте значением групповой политикой.

## Групповые политики

Шаблон: `desktop/installer/admx/Peregovorka.admx` и `ru-RU/Peregovorka.adml`, `en-US/Peregovorka.adml` — скопируйте в центральное хранилище
(`\\<домен>\SYSVOL\<домен>\Policies\PolicyDefinitions`). Раздел «Peregovorka» есть в конфигурации компьютера и пользователя; компьютерные значения сильнее.
Те же значения, что у свойств MSI, плюс `AllowDevTools` (инструменты разработчика — только для диагностики).

Приоритет: политика (HKLM) → политика (HKCU) → настройка пользователя. Поле, заданное политикой, пользователь видит недоступным с пометкой «Задано
администратором». Если сузить `AllowedDomains`, подключения к другим доменам скрываются (данные на компьютере остаются до удаления программы).

## Сервер

* Приложению нужен сервер Peregovorka **0.37.0 или новее** (`/api/v1/desktop/info`). Более старый сервер приложение распознаёт и сообщает об этом.
* **Администрирование → Безопасность → Вход и сеансы → «Приложение Windows помнит вход»** — сколько дней от входа паролем приложение открывается без пароля
  (0 — только в пределах обычного сеанса). Отзыв — как у любого сеанса: «Активные устройства», принудительный выход, отключение учётной записи.
  Смена пароля в AD гасит сохранённый вход при следующем запуске приложения.
* Сертификат сервера: приложение доверяет хранилищу сертификатов Windows. Для внутреннего центра сертификации разверните его корневой сертификат
  групповой политикой («Доверенные корневые центры сертификации»). Отключить проверку сертификата в приложении нельзя.
* Прокси: по умолчанию — как в Windows (включая WPAD/PAC). WebSocket и LiveKit (WebRTC) идут через те же правила, что и браузер Chromium.

## Звук и видео, системные настройки Windows

* Раздел «Звук и видео» (1.3.0) работает без прав администратора и ничего не меняет в Windows: он только читает список устройств, проверяет их и запоминает выбор пользователя в `settings.json` (`media`: названия устройств, шумоподавление, эхо, автоусиление; идентификаторов устройств там нет — они у каждого сайта свои).
* Доступ к микрофону и камере в этом разделе имеет **только окно оболочки** приложения (адрес `app://shell`); страницы серверов получают доступ к устройствам только своей организации, как и раньше. Параметры конфиденциальности Windows («Разрешить классическим приложениям доступ к микрофону») действуют: при запрете окно покажет причину и откроет `ms-settings:privacy-microphone`.
* Кнопка «Открыть настройки микрофона Windows» запускает фиксированную команду `rundll32.exe shell32.dll,Control_RunDLL mmsys.cpl,,1` (окно «Звук», вкладка «Запись»), при неудаче — `ms-settings:sound`. Перечень команд закрыт и параметров от страницы не принимает; на других ОС кнопки скрыты. Монопольный режим меняет сам пользователь в этом окне — приложение его не трогает.
* Страница организации получает значения по умолчанию через мост (`peregovorkaDesktop.media.get`, только чтение); `api` моста остаётся `1`, поэтому старые серверы продолжают работать без изменений и просто не используют выбор.
* **Не проверено на настоящем Windows:** запуск `mmsys.cpl,,1` и `ms-settings:` (выполняется только под Windows вручную), поведение настоящих USB-, Bluetooth- и встроенных микрофонов (в автотестах — поддельные устройства Chromium).

## Диагностика без доступа к переписке

* У сотрудника: **Настройки → Диагностика → Сохранить отчёт** (JSON).
* Без интерфейса (например, удалённо в сеансе пользователя): `"%ProgramFiles%\Peregovorka\Peregovorka.exe" --diagnostics=C:\Temp\pg-diag.json` — приложение
  запишет отчёт и завершится (если оно уже запущено, сначала закройте его из трея: работает один экземпляр).
* Журнал: `%APPDATA%\Peregovorka\logs\main.log` (5 файлов по 1 МБ, ротация). В отчёте и журнале нет паролей, токенов, cookie и текста сообщений —
  только версии, состояние подключений и коды ошибок.

## Данные на компьютере

`%APPDATA%\Peregovorka`: `settings.json` (настройки), `orgs.json` (подключения), `window.json` (положение окна), `trust\*.bin` (токены устройства,
DPAPI), `logs\`, `Partitions\org-*` (cookie и кэш каждой организации, cookie зашифрованы DPAPI). Удаление организации в приложении стирает её раздел и токен.
