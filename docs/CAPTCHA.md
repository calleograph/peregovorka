# Локальная CAPTCHA

Защита от перебора паролей и массового создания переговорок **без внешних сервисов**: сервер выдаёт вычислительную задачу (доказательство работы, формат ALTCHA), браузер решает её сам за доли секунды, сервер проверяет решение. Пользователь ничего не вводит и не кликает; бот, перебирающий пароли, платит процессорным временем за каждую попытку.

## Режимы

«Администрирование → Безопасность → CAPTCHA».

| Режим | Когда проверка нужна |
| --- | --- |
| Никогда | Никогда. |
| После серии неудач (по умолчанию) | После **20** (настраивается) неудачных попыток входа или неверных паролей комнаты с одного IP за окно (по умолчанию 60 минут). Успешный вход сбрасывает счётчик. |
| Всегда | Перед каждым входом, входом гостя по ссылке и созданием временной переговорки. |

Проверяются: вход (`POST /auth/login`), вход гостя по ссылке, создание временной переговорки (последнее — только в режиме «Всегда»: у него нет понятия «неудача»). Второй шаг входа с кодом 2FA CAPTCHA не требует: пароль к этому моменту уже проверен.

## Как это устроено

* Задача: `salt` (со сроком `?expires=…`), `challenge = SHA-256(salt + n)` для секретного `n ≤ maxnumber`, подпись `HMAC(ключ, challenge)`. Ключ — производный от `APP_MASTER_KEY` (без него случайный на процесс).
* Клиент (`frontend/src/captcha.ts`, SHA-256 на чистом JS, работает и по обычному http) подбирает `n` и повторяет запрос с заголовком `X-Captcha`. Если сервер ответил `428 captcha_required`, браузер делает это сам и один раз повторяет запрос; запросы к API со стороны (скрипты) получают в ответе готовую задачу в `detail.challenge`.
* **Повтор:** принятое решение запоминается в Redis до конца срока жизни задачи и повторно не принимается. Просроченное, подделанное и неверное решение — отказ, записывается в аудит (`captcha.rejected`, причина в `details.reason`).
* **Ограничение выдачи:** `GET /captcha/challenge` — не более 60 задач в минуту с одного IP.
* **Сложность:** `difficulty` — верхняя граница числа; в среднем перебирается половина. 50 000 — доли секунды на ноутбуке; для слабых телефонов не поднимайте выше 200 000.

## Ограничения

* Это защита от автоматического перебора, а не от человека: оплата вычислением, а не «распознай картинку».
* Режим «после серии неудач» считает по IP: за общим NAT неудачи разных людей складываются, а при неверно настроенных доверенных прокси (`TRUSTED_PROXIES`) все запросы выглядят как один IP — проверьте настройку, иначе проверка включится у всех.
* Счётчики хранятся в Redis: после его очистки обнуляются.
