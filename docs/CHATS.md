# Корпоративные чаты

Личные и групповые переписки сотрудников вне видеовстреч: кнопка **«Чаты»** в верхнем меню (с числом непрочитанных) открывает большое окно поверх текущей
страницы. Раздел, в котором был пользователь, и идущая встреча не теряются: окно — не переход на другую страницу.

## Возможности

| Что | Как устроено |
| --- | --- |
| Панели | Слева — список переписок (поиск, «Новый чат», папки, вкладки «Все», «Непрочитанные», личные папки, «Архив»), справа — выбранная переписка. На экране уже 760 px — одна панель с переходом «список ↔ переписка». Светлая и тёмная темы — общие токены оформления. |
| Новый чат | Поиск сотрудников: внутренний справочник (кто уже входил: ФИО, логин, почта, подразделение) и корпоративный каталог (AD). Отключённые учётные записи (в AD или в Peregovorka) не показываются. Группы каталога раскрываются в участников. Личная переписка с человеком одна: повторное «написать» открывает существующую. Сотрудник из каталога, ещё ни разу не входивший, получает запись по objectGUID; клиент присылает ссылку и логин, сервер заново ищет по логину и сверяет objectGUID. |
| Группы | Название, изображение (256×256, как аватарки), добавление и исключение участников, назначение администраторов (последнего снять нельзя), выход. Служебные строки в ленте: кто создал, добавил, исключил. Предел участников — настройка. |
| Папки и организация | Личные папки («Работа», «Проекты» …), закрепление, архив, отключение уведомлений, очистка истории и удаление из списка — из контекстного меню (правая кнопка) и меню «⋮». Всё это — **личные** настройки (`chat_members`): у собеседников ничего не меняется. Разрушительные действия подтверждаются. Удаление папки переписки не удаляет. |
| Лента | Свои и чужие сообщения различаются, разделители дней, серии одного автора, время, статус «отправляется / не отправлено (Повторить) / доставлено ✓ / прочитано ✓✓». Новые — без перезагрузки; длинная история — страницами по 50 при прокрутке вверх (позиция чтения сохраняется); отметка «Новые сообщения» при открытии. Разметка: ссылки (только http/https), **жирный**, _курсив_, `код`, блок ``` ```; HTML не интерпретируется. |
| Действия с сообщением | Ответить с цитатой, скопировать, переслать (в свою другую переписку; вложения не копируются — у получателей нет доступа к исходной), изменить и удалить **своё** (проверяет сервер), «Доставка и прочтение». |
| Реакции, эмодзи, упоминания | Реакция участника на сообщение — одна (повтор той же снимает, другая заменяет), только из набора сервера (`chat_reactions`, миграция 0040); быстрая панель — шесть частых, «+» — полный набор. Эмодзи в поле ввода — популярные по группам и недавние (в браузере). «@Имя» в группах — подсказка участников, выделение, уведомление упомянутому даже из чата без уведомлений. Черновик — для каждой переписки в этом браузере; ↑ в пустом поле — изменить своё последнее. |
| Окно | Плавающее, как плеер записей: перетаскивание за заголовки, размер — за угол, двойной щелчок — развернуть; положение — в браузере, открытое окно и переписка переживают переходы и обновление страницы (на время вкладки). Окно целиком остаётся в пределах экрана; уже 640 px — одна панель; на телефоне — во весь экран, меню сообщения — нажатием. |
| Поиск | В переписке — слова и «фразы в кавычках», подсветка, «N из M», переход к предыдущему и следующему, переход к сообщению в истории, фильтр по автору и периоду. Слева — по названиям переписок и по содержимому всех своих переписок. |
| Вложения | Кнопка, перетаскивание, вставка скриншота Ctrl+V. Изображения — миниатюры и общий просмотрщик Peregovorka, документы — название, размер, тип. Правила и хранилище — общие с чатом встречи («Хранилище вложений чата»): тип проверяется по содержимому, исполняемые и «активные» типы запрещены. Файл отдаёт только backend и только участнику переписки (`Content-Disposition`, `nosniff`, `sandbox`); публичных ссылок нет. |
| Диктовка | Кнопка микрофона: распознанный текст появляется в поле (у курсора, набранное вручную сохраняется, повтор фрагмента не добавляется). «Стоп», «Отмена», «Остановить и отправить» (отправляет только после окончательного ответа распознавания; обрыв ничего не отправит). Микрофон освобождается при остановке, отмене, закрытии чата и смене устройства. Во время встречи — подсказка, что участники слышат диктовку, если микрофон встречи включён. |
| Уведомления | Счётчик на кнопке «Чаты» (без переписок с отключёнными уведомлениями), счётчик у переписки, всплывающее уведомление, если открыт другой раздел или другая переписка, звук (личная настройка на всех устройствах). |
| Присутствие | «В сети» — только при открытой вкладке и действии пользователя за последние 3 минуты (клиент подтверждает раз в 30 с); действующая, но неактивная сессия статуса не даёт. Каждый может скрыть свой статус; администратор может выключить присутствие целиком. «Сообщить, когда появится в сети» — добровольно и одноразово; у скрывшего статус уведомления нет, и это не раскрывается. История активности не хранится. |

## Устройство

* **Данные** — PostgreSQL (миграция 0039): `chats`, `chat_members` (роль и личные настройки участника: прочитано до, очищено до, скрыт, без уведомлений,
  закреплён, архив, папка), `chat_messages`, `chat_files` (метаданные; файл — в хранилище вложений), `chat_folders`; `users.chat_prefs` — личные настройки чатов.
  Удаление своего сообщения стирает текст и вложения, в ленте остаётся отметка; «очистить историю» и «удалить чат» — только у себя (`cleared_before_id`, `hidden`),
  общие сообщения физически не удаляются.
* **Доставка в реальном времени** — тот же WebSocket `/api/v1/ws`: клиент подписывается на **личный канал** (`subscribe_user`, Redis pub/sub `user:<id>:events`).
  Событие публикуется в каналы всех участников; его получает подписчик на **любом** экземпляре backend — закреплять клиента за экземпляром не нужно
  (проверено двумя экземплярами на общих PostgreSQL и Redis, `tests/live/chats_multi_instance.py`).
* **Без потерь и дублей** — сообщение с клиента несёт `client_id`; повтор после сбоя сети (в том числе одновременно в два экземпляра) возвращает уже записанное
  (уникальный индекс `chat_id, author_id, client_id`). После переподключения клиент догружает пропущенное (`after_id`), повторы отбрасываются по id. История — в базе
  и переживает перезапуск backend.
* **Несколько устройств** — события идут в личный канал, поэтому все вкладки и устройства учётной записи получают сообщения, а прочитанность (`chat_read`)
  синхронизируется.
* **Поиск** — индекс GIN по `to_tsvector('russian', text)` (русская морфология, латиница — английская), поиск по началу слов, фразы дополнительно сверяются
  по тексту; выдача — не больше 200 совпадений за раз, дальше — по `before_id`. Запрос к базе строится только из букв и цифр (синтаксис tsquery не внедрить).
  Замер на одной машине (PostgreSQL 16 во временном контейнере, 200 тысяч сообщений в переписке): поиск 34–97 мс (первый запрос на холодном кэше — 0,8 с),
  последняя страница 39 мс, список переписок 118 мс, число непрочитанных 113 мс. Это замер, а не нагрузочное испытание.
* **Транзакции** — во время ожидания событий, приёма файла и диктовки транзакций базы нет (настройки читаются в начале, соединение возвращается в пул).
* **Ограничения** — сообщений в минуту на сотрудника (настройка), загрузок 20 в минуту, поисков 40 в минуту, длина сообщения, размер и число файлов, участников в группе.
* **Журналы и аудит** — тексты переписки в технические журналы не пишутся. Аудит: создание и переименование группы, добавление и исключение участников,
  роли, выход, удаление сообщения (без текста), скачивание документа, изменение настроек «Чаты» (в том числе срока хранения). Отдельного аудита на каждое сообщение нет —
  он не нагружает базу при большом потоке переписки.
* **Хранение** — «Срок хранения переписки» (дней, 0 — без срока): сообщения и их файлы старше удаляются фоновой очисткой раз в час (пачками по 500).
  Загруженные, но не отправленные вложения удаляются через 2 часа.

## Диктовка и распознавание речи

Диктовка использует **тот же ASR**, что и встречи (GigaAM, модель и настройки распознавания — из раздела «Распознавание речи»), без отдельной интеграции с внешним API
и **без LiveKit**: браузер шлёт PCM 16 кГц в `/api/v1/ws/dictation`, backend кладёт звук в Redis, служба распознавания режет его по паузам тем же VAD и ставит
фрагменты в общую очередь (контракт — [ASR_CONTRACT.md](ASR_CONTRACT.md), «Диктовка»). Встречи важнее: при заполненной наполовину очереди фрагмент диктовки
не ставится, пользователь видит «распознавание занято»; одновременных диктовок — не больше настройки. Звук не сохраняется: потоки Redis удаляются по завершении
(и истекают при сбое), служба распознавания звук диктовки на диск не пишет и текст не логирует. ASR недоступен — кнопка неактивна, а начатая диктовка сообщает причину.

## Настройки

«Администрирование → Хранение и журналы → Корпоративные чаты»: включение, срок хранения, длина сообщения, участники в группе, сообщений в минуту, присутствие,
диктовка (вкл., длительность, одновременных на сервер). Вложения — «Хранилище вложений чата».

## Проверено и не проверено

* **Автотесты:** backend `test_chats.py` (права и подмена идентификаторов, дубли и гонка повторов, правка и удаление, группы и аудит, очистка и удаление у себя, папки,
  поиск, вложения, пересылка, каталог и отключённые, присутствие, события на несколько устройств, срок хранения, ограничение частоты), `test_dictation_ws.py`;
  ASR `test_dictation.py`; frontend `chat/chatModel.test.ts`.
* **Живые сценарии:** `tests/live/scenario_chats.py` (44 проверки; браузер, два пользователя и второе устройство, подставное распознавание стенда), `tests/live/chats_multi_instance.py`
  (два экземпляра backend, настоящие PostgreSQL 16 и Redis 7).
* **Не проверено:** настоящий AD (каталог — подставной), настоящий GigaAM для диктовки (на стенде — подставное распознавание по тому же контракту; конвейер ASR
  проверен тестами с подставной моделью), нагрузка 2000 одновременно активных пользователей, Firefox и Safari (в том числе отсутствие события `contextmenu`
  при долгом нажатии в iOS — действия доступны и через «⋯»).
