# Установка Peregovorka: руководство для первого раза

Руководство для человека, который ставит Peregovorka впервые. Оно ведёт от выбора сервера до первой встречи: сервер, сертификат, порты, настройка в браузере, приложения, проверка. После каждого шага указан ожидаемый результат.

Адреса в примерах условные: `meet.example.org`, `192.0.2.10`. Подставьте свои.

## Что вы получите

- Сервер Peregovorka на вашем оборудовании.
- Вход по адресу `https://meet.example.org`.
- Звонки из нужных вам сетей.
- Подключённые каталог, почта, языковая модель, если они нужны.
- Приложения на устройствах сотрудников.
- Первую резервную копию.

Время: 10–30 минут на установку и примерно час на настройку сертификата, портов и проверку. Интеграции добавляются позже.

## Что подготовить заранее

| Что | Зачем | Кто обычно даёт |
| --- | --- | --- |
| Сервер с Ubuntu или Debian | здесь работают все службы | администратор инфраструктуры |
| Права `sudo` | установка меняет систему | администратор инфраструктуры |
| Имя в DNS, например `meet.example.org` | адрес для людей и для сертификата | сетевой инженер |
| Сертификат HTTPS на это имя, с полной цепочкой | без доверенного сертификата звонки работают только на устройствах, которым вы вручную разрешили самоподписанный | служба ИБ, удостоверяющий центр |
| Право открыть порты | звук и видео идут напрямую на сервер | сетевой инженер |
| Второе устройство | проверить звонок вдвоём | у вас |

Необязательно на первый день: контроллеры домена и служебная запись для Active Directory, сервер SMTP, адрес и ключ языковой модели, сетевая папка.

## Шаг 1. Выберите сервер

**Система.** Установщик принимает Ubuntu 22 и новее, Debian 12 и новее, рекомендуется Ubuntu 24.04. Архитектура x86_64.

**Ресурсы.** Установщик проверяет порог: 4 vCPU, 8 ГБ памяти, 30 ГБ свободного места в каталоге данных. Это нижняя граница для запуска, а не рабочая конфигурация. На ней система целиком не испытывалась, запись и эфир в этот порог не входят.

Подтверждённой вместимости всей системы нет. Для пилота в проекте предварительно указан запас 8 vCPU и 16 ГБ, он тоже не проверялся сквозным испытанием. Начните с небольшой группы и смотрите на реальную нагрузку: **Администрирование → Обзор → Производительность**. Что измерялось: [Ограничения и требования](https://github.com/calleograph/peregovorka/wiki/Архитектура-Ограничения-и-требования).

**Диск.** Записи занимают основное место. Для эфира на локальном диске нужно место под файл самой длинной записи, плюс столько же в томе записей, плюс 1 ГБ запаса. Эфир 1080p в одном двухчасовом замере дал около 2,2 ГБ в час.

**Другие приложения на сервере.** Если они есть, это руководство не подходит: используйте [Установку на общий сервер](https://github.com/calleograph/peregovorka/wiki/Установка-на-общий-сервер).

Проверьте сервер:

```bash
. /etc/os-release; echo "$PRETTY_NAME"; uname -m; nproc
free -g | awk '/Mem:/ {print $2 " ГБ памяти"}'
df -h /srv
```

**Ожидаемый результат:** система из списка, `x86_64`, не меньше 4 ядер и 8 ГБ, в столбце `Avail` не меньше 30 ГБ.

## Шаг 2. Подготовьте систему

Установщик не запускает `apt upgrade` и не перезагружает сервер, поэтому обновите систему сами.

```bash
sudo apt update && sudo apt upgrade -y
timedatectl | grep -E "synchronized|Time zone"
sudo ss -ltnp | grep -E ':443 ' || echo "порт 443 свободен"
```

**Ожидаемый результат:** `System clock synchronized: yes`, порт 443 свободен. Неверное время ломает TLS, вход и коды второго фактора.

Если записей будет много, заранее смонтируйте отдельный локальный диск, например в `/srv`. Каталог данных должен быть локальным путём Linux. Сетевое хранилище подключается позже, в браузере.

## Шаг 3. Проверьте выход в интернет

Установка скачивает программы и модель распознавания.

```bash
for u in https://github.com https://registry-1.docker.io/v2/ https://pypi.org \
         https://registry.npmjs.org https://download.docker.com \
         https://download.pytorch.org https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/; do
  printf '%s ' "$u"; curl -sS -o /dev/null -m 15 -w '%{http_code}\n' "$u" || true
done
```

**Ожидаемый результат:** у каждого адреса трёхзначный код, в том числе `401`, `403` или `404`. Важен сам ответ. Сообщения `curl: (6)`, `curl: (7)`, `curl: (28)` означают, что адрес недоступен: попросите открыть исходящий 443/tcp.

## Шаг 4. Запустите установщик

```bash
wget -O install.sh https://raw.githubusercontent.com/calleograph/peregovorka/main/install.sh
chmod +x install.sh
sudo ./install.sh --host meet.example.org
```

Параметры установщика (`./install.sh --help`):

| Параметр | Значение |
| --- | --- |
| `--host ИМЯ_ИЛИ_IP` | адрес, по которому сервер открывают в браузере; по умолчанию основной IP сервера |
| `--https-port N` | порт HTTPS, по умолчанию 443 |
| `--dir КАТАЛОГ` | куда поставить проект, по умолчанию `/opt/peregovorka` |
| `--data КАТАЛОГ` | каталог данных, по умолчанию `/srv/peregovorka-data` |
| `--ref ВЕРСИЯ` | версия; по умолчанию последний выпуск |
| `--skip-models` | не скачивать модель распознавания сейчас |
| `--yes` | не задавать вопросов |

Установщик один раз спросит «Продолжить?». Дальше он работает сам:

1. Ставит недостающее: git, curl, openssl, Docker Engine, Compose, Buildx, nginx.
2. Скачивает проект в `/opt/peregovorka`.
3. Создаёт `.env` со случайными секретами и правами 600, самоподписанный сертификат, каталоги данных.
4. Применяет параметры ядра для звонков в `/etc/sysctl.d/99-peregovorka.conf`.
5. Подбирает свободные порты и определяет публичный адрес для звонков.
6. Скачивает модель распознавания, до 2 ГБ.
7. Собирает образы, запускает базу, выполняет миграции, запускает службы.
8. Проверяет систему, ставит помощника обновлений, создаёт локального администратора.

Межсетевой экран установщик не меняет.

**Ожидаемый результат:** блоки **УСТАНОВКА ЗАВЕРШЕНА** и **ПЕРВИЧНЫЙ ВХОД** с адресом, логином `admin` и первичным паролем. Пароль показывается один раз и только в терминале. Сохраните его.

Сразу сделайте копию файла `/opt/peregovorka/.env` и уберите её в сейф паролей. В нём лежит `APP_MASTER_KEY`: без него сохранённые пароли подключений не восстановить.

**Если установка прервалась.** Запустите ту же команду ещё раз: готовые этапы пропускаются, данные не удаляются. Сбой печатается строкой вида `FAIL stage=build service=backend subsystem=docker-buildkit`.

| Сообщение | Причина | Что сделать |
| --- | --- | --- |
| `FAIL stage=preflight` | мало места или памяти, занят порт | прочитать строку выше: она называет проблему |
| `FAIL stage=models` | недоступен источник модели | запустить повторно, докачка продолжится |
| `FAIL … subsystem=registry-network` | недоступен Docker Hub или зеркало | повторить, скачанное сохраняется |
| `FAIL … subsystem=docker-buildkit` | сбой сборщика | установщик сам переходит на старый сборщик; если не помогло, см. [Диагностика](https://github.com/calleograph/peregovorka/wiki/Диагностика) |
| Пароль не показан | итоговая проверка нашла ошибку | прочитать ошибку, исправить, запустить снова |

Потеряли пароль: `sudo /opt/peregovorka/scripts/admin-reset.sh`.

## Шаг 5. Войдите и задайте пароль

1. Откройте адрес из блока **ПЕРВИЧНЫЙ ВХОД**, именно с `https://`. Порт 80 установщик не открывает.
2. Браузер предупредит о самоподписанном сертификате. Подтвердите переход. На шаге 7 вы замените сертификат.
3. Войдите как `admin` с первичным паролем.
4. Задайте новый пароль: не короче 12 символов, не менее двух видов символов, без имени пользователя.

**Ожидаемый результат:** открывается окно **Первоначальная настройка**.

## Шаг 6. Пройдите первоначальную настройку

Мастер ведёт по шагам: каталог, сертификаты, группы администраторов, хранилище, почта, проверка системы. Каждый шаг можно пропустить. Если каталога и почты пока нет, закройте окно кнопкой **Закрыть и не показывать снова**: всё то же доступно в разделе **Администрирование**.

Откройте **Администрирование → Обзор**.

**Ожидаемый результат:** PostgreSQL, Redis, LiveKit и ASR зелёные. ASR становится зелёным через 1–2 минуты. Блок **Требует внимания** называет, что ещё настроить.

Проверьте с сервера:

```bash
cd /opt/peregovorka
sudo ./scripts/status.sh
sudo ./scripts/verify.sh
sudo ./scripts/smoke-test.sh
```

| Команда | Успех |
| --- | --- |
| `status.sh` | строка `Все сервисы работают` |
| `verify.sh` | нет `FAIL`, строка `Peregovorka deployment verified` |
| `smoke-test.sh` | строка `Smoke test: PASS` |

Код `smoke-test.sh`: `0` ошибок нет, `3` система работает, но есть проблема окружения (каталог, прокси, сертификат), `1` сбой самой системы. На этом шаге предупреждения про TLS допустимы.

## Шаг 7. Подключите имя и сертификат

Браузер даёт микрофон и экран только по HTTPS. С самоподписанным сертификатом звонки подключаются лишь на устройствах, которые ему доверяют.

1. Создайте запись DNS и проверьте её:

   ```bash
   getent hosts meet.example.org
   ```

   **Ожидаемый результат:** адрес вашего сервера.

2. Положите на сервер сертификат с полной цепочкой и закрытый ключ, например в `/etc/ssl/peregovorka/`. Ключ должен быть доступен только root: `chmod 600`.

3. Укажите их в `/opt/peregovorka/.env`:

   ```bash
   APP_PUBLIC_URL=https://meet.example.org
   LIVEKIT_PUBLIC_URL=wss://meet.example.org/livekit
   NGINX_SERVER_NAME=meet.example.org
   NGINX_TLS_CERT=/etc/ssl/peregovorka/fullchain.pem
   NGINX_TLS_KEY=/etc/ssl/peregovorka/privkey.pem
   ```

4. Примените изменения. Первая команда пересоздаёт контейнеры по новому `.env`, вторая обновляет сайт nginx:

   ```bash
   cd /opt/peregovorka
   sudo scripts/ctl.sh start backend web
   sudo scripts/install.sh --profile standalone --from nginx
   ```

5. Проверьте:

   ```bash
   openssl s_client -connect meet.example.org:443 -servername meet.example.org </dev/null 2>/dev/null \
     | openssl x509 -noout -subject -issuer -enddate
   sudo ./scripts/smoke-test.sh
   ```

   **Ожидаемый результат:** ваше имя, ваш центр сертификации, срок в будущем; строка `TLS (публичный URL)` показывает `OK`.

Встроенного выпуска Let's Encrypt на основном сервере нет. Новый сертификат применяется командой `sudo nginx -t && sudo systemctl reload nginx`. Если TLS завершает ваш внешний прокси: [Как настроить reverse proxy и HTTPS](https://github.com/calleograph/peregovorka/wiki/Как-настроить-reverse-proxy-и-HTTPS).

## Шаг 8. Откройте порты звонков

Страница идёт через 443, а звук и видео идут напрямую на сервер, минуя HTTP-прокси. Закрытые порты — самая частая причина ситуации «страница открылась, а звука нет».

1. Посмотрите свои порты. Обычно это 17881/tcp и 17882/udp, но установщик мог выбрать другие.

   ```bash
   cd /opt/peregovorka
   sudo grep -E '^LIVEKIT_(TCP|UDP)_PORT=|^LIVEKIT_NODE_IP=|^LIVEKIT_PUBLIC_IP=' .env
   ```

2. Откройте их на всех межсетевых экранах по пути к серверу. Для `ufw`:

   ```bash
   sudo ufw allow 443/tcp
   sudo ufw allow 17881/tcp
   sudo ufw allow 17882/udp
   ```

3. Если сервер за NAT, пробросьте те же порты без смены номера и проверьте:

   ```bash
   sudo scripts/medianet.sh check
   ```

   **Ожидаемый результат:** порты слушаются, показан режим и публичный адрес, напечатаны правила проброса. UDP снаружи с самого сервера проверить нельзя: окончательная проверка на шаге 9.

4. Если адрес определён неверно, задайте его. Для работы только внутри сети укажите `off`. Идущие встречи прервутся.

   ```bash
   sudo scripts/medianet.sh apply --public-ip 192.0.2.10
   ```

TURN в поставке нет: если медиапорты закрыты, звонка не будет. При CGNAT у провайдера проброс не поможет. Схемы: [Публикация во внешний контур](https://github.com/calleograph/peregovorka/wiki/Архитектура-Публикация-во-внешний-контур).

## Шаг 9. Проведите пробную встречу

1. Откройте **Администрирование → Комнаты и пользователи → Комнаты и доступ → Создать комнату**. Укажите название и идентификатор: латиница, цифры, `-`, `_`.
2. Откройте настройки комнаты, вкладку **Доступ и гости**, включите гостевой вход.
3. На главной странице у карточки комнаты нажмите **⋯** и выберите **Скопировать гостевую ссылку**.
4. Войдите в комнату как `admin`, разрешите микрофон.
5. Откройте гостевую ссылку на втором устройстве. Лучше из другой сети, например через мобильный интернет.
6. Скажите несколько фраз.

**Ожидаемый результат:** участники слышат и видят друг друга, в панели **Транскрипция** появляются реплики с именами.

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| Нет микрофона | страница открыта не по HTTPS | использовать `https://` |
| Подключение висит на устройстве | устройство не доверяет сертификату | шаг 7 |
| Участники не слышат друг друга | закрыты медиапорты | шаг 8 |
| Работает только внутри сети | нет проброса или неверный публичный адрес | `sudo scripts/medianet.sh check` |
| Реплик нет | ASR не готов | подождать 2 минуты, затем `sudo scripts/models.sh` |
| «Недопустимый Origin» при входе | открыт не адрес из `APP_PUBLIC_URL` | [Диагностика](https://github.com/calleograph/peregovorka/wiki/Диагностика) |

Всё настраивается в браузере. Подключайте только то, чем будете пользоваться. После каждого подключения нажмите кнопку проверки в разделе.

| Что | Где в **Администрирование** | Инструкция |
| --- | --- | --- |
| Вход сотрудников | **Интеграции → Каталог: подключения LDAP/AD**, **Каталог: сертификаты (CA)** | [Как подключить Active Directory](https://github.com/calleograph/peregovorka/wiki/Как-подключить-Active-Directory) |
| Кто может войти и кто администратор | **Комнаты и пользователи → Кто может входить**, **Администраторы сервера** | [Управление пользователями](https://github.com/calleograph/peregovorka/wiki/Управление-пользователями) |
| Почта | **Интеграции → Почта: сервер SMTP** | [Как подключить почту](https://github.com/calleograph/peregovorka/wiki/Как-подключить-почту) |
| Протоколы и резюме | **Интеграции → Языковая модель (LLM)** | [Как настроить языковые модели](https://github.com/calleograph/peregovorka/wiki/Как-настроить-языковые-модели) |
| Что уходит в модель | **Интеграции → Обезличивание** | [Как настроить обезличивание](https://github.com/calleograph/peregovorka/wiki/Как-настроить-обезличивание) |
| Сетевая папка | **Интеграции → Файловые хранилища** | [Подключение внешних хранилищ](https://github.com/calleograph/peregovorka/wiki/Подключение-внешних-хранилищ) |
| Видеозапись и эфиры | **Интеграции → Видеозапись**, **Трансляции**, кнопка **Установить и включить** | [Как настроить видеозапись и трансляции на сервере](https://github.com/calleograph/peregovorka/wiki/Как-настроить-видеозапись-и-трансляции-на-сервере) |
| Телефония | **Интеграции → SIP-телефония** | [Как подключить SIP-телефонию](https://github.com/calleograph/peregovorka/wiki/Как-подключить-SIP-телефонию) |
| Outlook и Exchange | **Интеграции → Microsoft Outlook** | [Интеграция с Outlook и Exchange](https://github.com/calleograph/peregovorka/wiki/Интеграция-с-Outlook-и-Exchange) |

Служба Egress для записи и эфира занимает около 3,8 ГБ образа и перезапускает LiveKit при включении, поэтому включайте её вне встреч.

## Шаг 11. Сделайте резервную копию

```bash
cd /opt/peregovorka
sudo scripts/backup.sh --full
```

Команда сохраняет базу, копию `.env` и архив файлов. **Ожидаемый результат:** строка `Резервное копирование завершено.`, в `/srv/peregovorka-data/backups` лежат файлы `.dump`, `.env`, `.tar.gz` и их `.sha256`.

Перенесите копию с сервера. Копия `.env` содержит `APP_MASTER_KEY`: держите её отдельно от дампов. Настройте расписание: [Резервное копирование и аварийное восстановление](https://github.com/calleograph/peregovorka/wiki/Резервное-копирование-и-аварийное-восстановление). Ротация `--keep N` удаляет старый набор целиком.

## Шаг 12. Установите клиенты

В браузере ничего ставить не нужно: откройте адрес сервера в актуальном Chrome или Edge. Гостям и зрителям хватает браузера.

**Windows 10, 11 (x64).**

1. Скачайте `Peregovorka-Setup-<версия>.exe` со страницы выпуска. Ссылка в [README](../README.md#windows-и-linux). Для компьютеров организации есть MSI: [Как развернуть приложение Windows в организации](https://github.com/calleograph/peregovorka/wiki/Как-развернуть-приложение-Windows-в-организации).
2. Запустите установщик. Он пока не подписан сертификатом издателя: если появится SmartScreen, нажмите **Подробнее → Выполнить в любом случае**.
3. Введите адрес сервера и войдите.

**Ожидаемый результат:** открывается интерфейс организации, значки организаций слева.

**Linux (Ubuntu 22.04, 24.04, Debian 12, 13).**

```bash
curl -fsSL https://calleograph.github.io/peregovorka-apt/install.sh | sudo sh
```

Обновления приходят через `apt upgrade`. Подробно: [Как установить приложение для Linux](https://github.com/calleograph/peregovorka/wiki/Как-установить-приложение-для-Linux).

**Android 8.0 и новее, предварительная версия.**

1. Скачайте файл APK со страницы выпуска: ссылка в [README](../README.md#android).
2. Разрешите установку из этого источника.
3. Откройте приложение, нажмите **Добавить сервер**, введите адрес, нажмите **Проверить**, затем **Войти**.

Телефону нужен доверенный сертификат с полной цепочкой. Подробно: [Как установить приложение для Android](https://github.com/calleograph/peregovorka/wiki/Как-установить-приложение-для-Android).

## Итоговая проверка

- [ ] `status.sh`, `verify.sh`, `smoke-test.sh` без ошибок.
- [ ] Адрес открывается без предупреждения о сертификате.
- [ ] Встреча с двух устройств: звук и видео в обе стороны, в том числе из внешней сети, если она вам нужна.
- [ ] Появляются реплики стенограммы.
- [ ] Если подключена модель: после встречи формируется протокол.
- [ ] Если включена запись: пробная запись открывается в **Истории**.
- [ ] В **Администрирование → Обзор** нет критичных пунктов в блоке **Требует внимания**.
- [ ] Есть резервная копия вне сервера и копия `.env` в сейфе.
- [ ] `sudo ./scripts/update.sh --dry-run` печатает план и ничего не меняет.

Приёмка перед запуском в работу: [ACCEPTANCE_TEST.md](ACCEPTANCE_TEST.md). Что перед внедрением проверить на ваших системах: [Что проверено](https://github.com/calleograph/peregovorka/wiki/Границы-проверки).

## Как жить дальше

| Что делать | Как часто | Где |
| --- | --- | --- |
| Проверять обновления | раз в месяц | **Администрирование → Система → Обновления и версии** |
| Контролировать копии | еженедельно | журнал копий; проверка восстановления раз в квартал |
| Следить за местом на диске | еженедельно | **Администрирование → Обзор** |
| Продлевать сертификат | до окончания срока | шаг 7 |

Обновляйте вне рабочих часов: если нужны миграции, идущие встречи прервутся. Перед миграцией скрипт сам делает копию базы, а при сбое возвращает базу и код. Подробно: [Как обновить и откатить](https://github.com/calleograph/peregovorka/wiki/Как-обновить-и-откатить).
