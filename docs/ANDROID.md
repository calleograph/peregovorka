# Приложение Peregovorka для Android

Предварительная версия (0.1.x). Исходники — `mobile/android/`, выпуски — на странице релизов GitHub с тегами `android-vX.Y.Z`.
Версия приложения своя, она не совпадает с версией сервера.

## Установка

1. Скачайте `Peregovorka-<версия>-android.apk` со страницы выпуска, сверьте SHA-256 из `SHA256SUMS.txt`.
2. Разрешите установку из этого источника (Настройки → Приложения → Особый доступ → Установка неизвестных приложений).
3. Откройте приложение, нажмите «Добавить сервер», введите адрес вашей Peregovorka вида `https://meeting.example.org`.

Файл с `debugkey` в имени подписан временным ключом сборки: он годится для проверки, но следующая сборка с другим ключом не установится поверх — сначала удалите прежнюю. Выпуск с постоянным ключом организации — см. «Сборка».

## Экранная клавиатура и «Назад»

- При появлении клавиатуры содержимое сжимается до свободной области (`imePadding`), нижняя панель разделов скрывается, поле ввода остаётся над клавиатурой. Для страниц сайта то же делает уменьшение области WebView, а в самом сайте (мобильный браузер) — `interactive-widget=resizes-content` в метатеге viewport.
- Кнопка «Назад» в конференции не сворачивает приложение: закрывает открытую панель (чат, участники), затем спрашивает «Выйти из конференции?». Свернуть — жест «Домой»; звук продолжает служба переднего плана, камера выключается и возвращается при возврате.
- Если приложение ушло с переднего плана неожиданно, в журнале устройства (`adb logcat -s PGLIFE`) остаются строки `onStop/onDestroy finishing=… configChange=… call=…`: они показывают, завершилась ли Activity, сменилась ли конфигурация или это обычное сворачивание.

## Безопасность

- Только HTTPS. Недоверенный сертификат система отвергает, обхода «принять любой» нет. Корпоративные центры сертификации, установленные на устройстве (в том числе через MDM), принимаются.
- Пароль приложение не видит и не хранит. Сессия и токен доверенного устройства шифруются ключом Android Keystore (AES-GCM; ключ запись → сервер входит в AAD, секреты разных организаций не читаются друг другом). В облачные копии Android эти данные не попадают.
- Страницы сервера во встроенном окне открываются только с адреса выбранного сервера, чужие ссылки уходят во внешний браузер.
- Ссылка `peregovorka://open?url=…` не несёт команд: из неё берутся сервер и путь из белого списка.
- Выход отзывает токен доверенного устройства на сервере (`/api/v1/desktop/forget`) и стирает локальные секреты. Администратор может отозвать доступ на сервере.

## Разрешения (0.1.2)

- После первого входа показывается экран «Доступ для конференций» («Продолжить» / «Позже»); системные запросы объединены в один: микрофон, камера, «Устройства рядом» (API 31+, Bluetooth-гарнитура), уведомления (API 33+). Отказ не блокирует работу: вход во встречу выполняется, в конференции видна полоса «нет доступа» с кнопкой «Разрешить» (при «больше не спрашивать» — «Открыть настройки»). Возврат из настроек подхватывается без перезапуска (ON_RESUME → `CallManager.permissionsChanged`: включается то, что пользователь хотел и что теперь разрешено). «Профиль → Разрешения» показывает состояние.
- Выбор встречи (`JoinTarget`) и ожидающий вход хранятся в `AppViewModel` + `SavedStateHandle` (пароль комнаты не сохраняется). Причина дефекта «после разрешения вход не продолжается»: раньше это было `remember`-состояние Compose, которое теряется при пересоздании Activity или процесса во время системного диалога. Установлено по коду; на физическом телефоне не воспроизведено.
- Запросы разрешений не накладываются (`asking`-защита и `JoinPermissionFlow`), пустой список не запускает диалог.
- Выбор файла и микрофон в страницах-WebView (`SiteChrome`): вложения чата через системный выбор файла; микрофон страницы — только для собственного адреса сервера.

## Приближение демонстрации экрана (0.1.3)

- Демонстрация чужого экрана — главное содержимое конференции: вписывается в область с сохранением пропорций и занимает всё место; участники — лентой (в вертикальном положении снизу, в горизонтальном справа). Если экранов несколько, остальные показываются в ленте с подписью «экран» и выбираются нажатием.
- Жесты действуют только на область демонстрации (не на весь интерфейс): сведение/разведение двумя пальцами — масштаб ×1…×8 вокруг точки под пальцами; один палец — перемещение увеличенного изображения (края ограничены, изображение нельзя потерять за экраном); двойное нажатие — быстрое приближение ×2,5 к точке, повторное — целиком; кнопка «Показать целиком» и метка масштаба появляются при увеличении.
- «На весь экран» скрывает всё, кроме картинки (и системные панели); касание показывает панель управления, через 3,5 с она прячется; «Назад» сначала выходит из полноэкранного режима. При повороте телефона рассматриваемая область сохраняется (`ZoomMath.resize`), если не получается — возврат к целому.
- Качество: при увеличении приложение запрашивает у сервера слой демонстрации в полном разрешении (до 4K), при возврате — выбор по размеру окна (`CallManager.setScreenResolution`); поток не пересоздаётся, звук не прерывается — меняется лишь преобразование слоя.
- Проверено: JVM-тесты математики (`ZoomMathTest`), жесты на эмуляторах Android 10/14/16 в CI (`ZoomSurfaceTest`: разведение/сведение, перемещение, двойное нажатие, сброс, полноэкранный режим). **Не проверено на реальном телефоне:** плавность на слабых устройствах, 4K-демонстрация, ввод настоящим сенсорным экраном — методика: `docs/ANDROID_ZOOM_CHECK.md`.

## Подпись и обновление поверх (0.1.3)

- Причина «пакет обновления некорректен»: у выпусков 0.1.1 и 0.1.2 разные сертификаты — сборка без секретов подписи использует отладочный ключ, который создаётся заново на каждом запуске CI (проверено `scripts/android_release_check.py` на опубликованных файлах: SHA-256 сертификата 0.1.1 — `5D:A4:77:30…CA:A0:75`, 0.1.2 — `88:55:7D:3F…A9:74:16`; пакет `org.peregovorka.android` и `versionCode` 101 → 102 в порядке, расходится только сертификат), а обновление Android принимает только с тем же ключом и большим `versionCode`. С 0.1.4 все публичные выпуски подписываются постоянным ключом организации (SHA-256 `30:01:6B:BA…3D:49`, секреты CI); схема, площадки и восстановление — [ANDROID_SIGNING.md](ANDROID_SIGNING.md).
- Проверки перед публикацией (`.github/workflows/android.yml`, `scripts/android_release_check.py`): пакет, `versionCode` (должен вырасти), подпись; сравнение с предыдущим выпуском (скачивается с GitHub); при другом ключе — предупреждение в сборке и заметка на странице выпуска «поверх поставить нельзя»; если выпуск подписан постоянным ключом, а у предыдущего с постоянным ключом сертификат другой — выпуск останавливается. На эмуляторе `update-over-test.sh` ставит сборку с меньшим `versionCode`, затем текущую (`adb install -r`) и проверяет, что данные приложения на месте; повторная установка той же сборки тоже проходит.
- Приложение показывает в «Профиль → Сборка и подпись» тип ключа и предупреждение, пока подпись временная.

## Обрыв связи, причина отключения, значок (0.1.5)

- **Причина отключения** (`RoomEvent.Disconnected.reason`) пишется в журнал устройства (`adb logcat -s PGCALL`: `disconnected reason=…`) и уходит на сервер событием `disconnected` — её видно в «Администрирование → Диагностика клиентов». Раньше приложение закрывало звонок с общей фразой и причину теряло.
- **Повторный вход после обрыва.** Встречу завершили (`ROOM_DELETED`, `ROOM_CLOSED`) или участника удалили (`PARTICIPANT_REMOVED`) — экран завершения с этой причиной. Любой другой обрыв (сеть, перезапуск сервера звонков, сбой сигнального канала) — «Связь потеряна, восстанавливаем…» и новый вход в ту же комнату со свежим токеном: паузы 1–30 с, всего около двух минут; микрофон и камера — в прежнем состоянии; служба переднего плана держит звонок. События `rejoin_started`, `reconnected`, `rejoin_failed` — в диагностике клиентов.
- **Сторож демонстрации экрана:** если чужая демонстрация подписана, а кадры не декодируются 15 с, в журнал (`screen_frozen …`) и на сервер уходят кодек, декодер (аппаратный `c2.*`/`OMX.*` или программный `libvpx`), число полученных и декодированных кадров.
- Кнопки микрофона и камеры обновляются по состоянию LiveKit SDK (оно меняется асинхронно — после выключения микрофона кнопка могла остаться «Выключить микрофон»).
- **Значок:** исходник `mobile/android/branding/icon-512.png`, слои для всех плотностей — `python3 scripts/android_icons.py` (адаптивный значок: рисунок в безопасной зоне маски, размытый фон для эффекта глубины, монохромный слой для значков «в цвет темы» Android 13+).
- Сервер со своей стороны: вкладка браузера того же человека больше не завершает «забытую» встречу, пока человек говорит с телефона (сервер 0.59.0).

## Подключено — только с голосом и видео (0.1.6)

- **Причина круга «Связь потеряна, восстанавливаем…».** `Room.connect()` LiveKit Android SDK 2.29 возвращается сразу после сигнального входа (join), не дожидаясь медиасоединения (ICE): `Room.State.CONNECTED` выставляется позже, по ICE (`onEngineConnected`). Браузерный `livekit-client` ждёт ICE внутри `connect()`. Приложение до 0.1.6 сразу показывало «подключено»; если медиа до сервера звонков не доходило (адрес `LIVEKIT_NODE_IP` и порты UDP/TCP недоступны из сети телефона — мобильный интернет, гостевая Wi‑Fi), SDK около минуты переподключался, отключался, повторный вход 0.1.5 снова «удавался» по сигналу — и так по кругу. В CI этого не видно: эмулятор в одной сети с LiveKit.
- **Теперь** подключение считается установленным только после `Room.State.CONNECTED` (ожидание до 25 с); пока его нет, события переподключения SDK экраном не управляют. Не установилось — событие `ice_failed` («Голос и видео не прошли») в «Диагностике клиентов»; при повторном входе после двух таких попыток подряд — экран завершения: «Голос и видео не проходят: сервер звонков недоступен из сети, к которой подключён телефон. Подключитесь к рабочей Wi‑Fi или VPN и войдите снова».
- Через 3 с после подключения уходит событие `ice_stats` — путь медиа (протокол и типы кандидатов выбранной пары, например `udp host→host`).
- Несколько демонстраций экрана (до пяти, сервер 0.61.0): крупно — выбранная, остальные — в ленте, выбор нажатием.

## Плавающее окно встречи (0.1.7)

- **Системная «картинка в картинке»** (`android:supportsPictureInPicture`, `PictureInPictureParams`), без собственного окна поверх приложений и без разрешения «поверх других окон». Android 12+ — `setAutoEnterEnabled`: система сама переводит встречу в окно при жесте «Домой» и переключении приложений; Android 8–11 — переход из `onUserLeaveHint`. Только во время встречи (подключение, встреча, восстановление связи; `PipModel.wanted`). Нет поддержки (`FEATURE_PICTURE_IN_PICTURE` — Android Go, часть планшетов и приставок) или плавающие окна выключены для приложения в настройках — прежнее поведение: звук в фоне (служба `CallService`), возврат по уведомлению.
- **Что в окне** (`PipModel.focus`, `ui/Pip.kt`): чужая демонстрация экрана (целиком, `FitInside`) → говорящий собеседник (с камерой — первым) → последний говоривший, пока он в комнате (окно не перескакивает в паузах) → собеседник с камерой → любой собеседник → сам участник. Подпись — имя и выключенный микрофон; свой выключенный микрофон — значок в углу; «Связь потеряна…» при восстановлении связи. Пропорции окна — как у демонстрации (в пределах 1:2,39…2,39:1), иначе 16:9.
- **Кнопки окна** (`RemoteAction`): «Микрофон» (значок по состоянию) и «Выйти» — те же действия службы `CallService`, что в уведомлении. Возврат — касание окна / системная кнопка «развернуть»: Activity та же (`singleTask`, изменения конфигурации без пересоздания), открытые панели, чат и диалоги возвращаются.
- **Камера** в окне выключена — как при сворачивании (`onBackground`); включается в `onResume`, когда встреча снова на весь экран (не в `onStart`: при разблокировке экрана встреча может оставаться в окне). Звук, микрофон, соединение LiveKit и повторный вход после обрыва работают как в фоне.
- **Конец встречи в окне** (кнопкой «Выйти», ведущим, автозавершением): окно показывает «Встреча завершена» и через 2,5 с убирается (`moveTaskToBack`); экран завершения — при следующем открытии.

## Показ своего экрана (0.1.8)

«Ещё → Показать экран», если сервер разрешает публиковать `screen_share`.
* Согласие даётся в системном окне MediaProjection; на Android 14+ — на каждый показ. Отказ — сообщение «Показ экрана отменён».
* Захват и служба переднего плана с типом `mediaProjection` — из LiveKit SDK (`setScreenShareEnabled(true, ScreenCaptureParams(...))`). Разрешение `FOREGROUND_SERVICE_MEDIA_PROJECTION` приходит из манифеста SDK.
* Показ продолжается, когда приложение свёрнуто: передаётся то, что на экране.
* На заблокированном экране Android изображение не отдаёт; звонок при этом не прерывается.
* Остановить показ можно полосой «Вы показываете экран → Остановить», пунктом меню или из системы (шторка, «Остановить» Android 15). Во всех случаях приходит `onStop`, и интерфейс обновляется.
* Отказ системы или производителя (`SecurityException`) и отказ сервера (права, предел показов) объясняются отдельно.
* Проверка: `ScreenShareTest` на эмуляторах API 29, 34 и 36 с настоящим LiveKit. Второй участник `ci/peer.py` считает кадры демонстрации от приложения: при показе, в свёрнутом приложении, после остановки.

## Ограничения Android, о которых нужно знать

- Камера в фоне недоступна: при сворачивании приложение выключает камеру и возвращает при возврате; звук продолжается.
- Уведомления о встречах и сообщениях требуют сервиса доставки (FCM — сторонний сервис Google, требует проекта Firebase и ключа организации). Пока не сделаны: приложение ничего не отправляет в сторонние сервисы.
- Сквозное шифрование (E2EE) комнат включено в клиенте, но совместимость с ключом веб-клиента на устройстве не проверялась: если в такой комнате вместо видео чёрные плитки, сообщите.

## Сборка

Нужны JDK 21 и Android SDK (платформа 37, build-tools 37). Из каталога `mobile/android`:

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug      # тесты и линт
./gradlew :app:assembleDebug                         # APK для проверки
./gradlew :app:assembleRelease                       # APK; подписан отладочным ключом, если ключ организации не задан
./gradlew :app:bundleRelease                         # AAB для Google Play (нужен ключ)
```

Ключ организации не хранится в Git. Укажите его в окружении (`PEREGOVORKA_KEYSTORE`, `PEREGOVORKA_KEYSTORE_PASSWORD`, `PEREGOVORKA_KEY_ALIAS`, `PEREGOVORKA_KEY_PASSWORD`) или в локальном файле `mobile/android/signing.properties` (`storeFile`, `storePassword`, `keyAlias`, `keyPassword`; файл в `.gitignore`). Создание ключа: `keytool -genkeypair -v -keystore peregovorka.jks -alias peregovorka -keyalg RSA -keysize 3072 -validity 10000`. **Сохраните файл ключа и пароли в надёжном месте**: потеряв ключ, обновить приложение у пользователей поверх уже нельзя.

В CI (`.github/workflows/android.yml`) ключ берётся из секретов репозитория `ANDROID_KEYSTORE_B64` (base64 файла `.jks`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Выпуск — тег `android-vX.Y.Z`.

### Постоянный ключ подписи

Ключ должен быть **одним на всё время жизни приложения**: Android ставит обновление поверх, только если подпись совпадает; сменить ключ потом без переустановки у всех пользователей нельзя. Выпуски до 0.1.3 включительно подписаны временным ключом сборки — первый выпуск с постоянным ключом пользователи ставят после удаления прежней версии (один раз).

1. Ключ создаёт владелец (или по его поручению разработчик) **вне каталога репозитория**, с правами 600: `keytool -genkeypair -v -storetype PKCS12 -keystore peregovorka-release.jks -alias peregovorka -keyalg RSA -keysize 4096 -validity 10950` (30 лет; Google Play требует срок не ранее 2033 года).
2. Резервная копия файла `.jks` и паролей — в сейфе паролей организации и на отдельном носителе. Потеря ключа = невозможность выпускать обновления этого приложения.
3. Секреты для CI задаёт владелец репозитория (Settings → Secrets and variables → Actions или `gh secret set`):
   ```bash
   base64 -w0 peregovorka-release.jks | gh secret set ANDROID_KEYSTORE_B64
   gh secret set ANDROID_KEYSTORE_PASSWORD     # ввести пароль хранилища
   gh secret set ANDROID_KEY_ALIAS --body peregovorka
   gh secret set ANDROID_KEY_PASSWORD          # ввести пароль ключа
   ```
4. Проверка: в журнале задачи `build` workflow Android строка `apksigner verify --print-certs` показывает сертификат `CN=Peregovorka`, а файл выпуска называется `Peregovorka-X.Y.Z-android.apk` (без `debugkey`).
5. Google Play: при включённом Play App Signing этот ключ — ключ загрузки (upload key), а установочные файлы для пользователей подписывает Google. Тогда APK с GitHub и из Google Play имеют **разные подписи** и не обновляют друг друга — выберите один канал распространения для сотрудников.

### Выпуск

1. `mobile/android/VERSION` (из него сборка берёт `versionName` и `versionCode`); раздел версии в `mobile/android/CHANGELOG.md`.
2. Блок `<!-- android-release:start -->` в `README.md` и `ANDROID_VERSION` в `frontend/src/androidDist.ts` — новая версия (тест `androidDist.test.ts` сверяет оба с `VERSION`).
3. Тег `android-vX.Y.Z` → workflow собирает, проверяет на эмуляторах и публикует выпуск с APK и `SHA256SUMS.txt`.
4. Выпуск сервера с новой ссылкой — **после** публикации APK: шаг Release `scripts/check_download_links.py` не опубликует сервер, если выпуск Android или его APK отсутствует.

## Устройство

Kotlin, Jetpack Compose, LiveKit Android SDK (официальная библиотека LiveKit), OkHttp. Протокол с сервером — тот же REST API, что у веб-клиента и клиента для Windows (`/api/v1/desktop/info`, `/trust`, `/resume` для сведений о сервере и доверенного устройства). Сервер не менялся ради приложения.
Версии библиотек закреплены в `mobile/android/gradle/libs.versions.toml`. Репозиторий JitPack разрешён только для одной группы (`com.github.davidliu`, переключение динамика/Bluetooth — зависимость LiveKit).
