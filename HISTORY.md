## 2026-10-06 — Создание VoiceMeet на базе существующего PHP-проекта: архитектура, инфраструктура и вертикальный путь

**Основа.** Существовал PHP-сервис «Корпоративный AI-чат» (LDAPS-вход, группы AD, админка,
шлюз обезличивания DocClean, LLM-шлюз, SQLite). Изучены: `LdapClient`, `ChatAuthenticator`,
`AnonymizationGateway`/`AnonymizationSettings`, `SecretBox`, `RateLimiter`, `SessionManager`,
структура админки и дизайн-токены, PROJECT.md/HISTORY.md старого проекта. Решение: новый продукт
строится на стеке из ТЗ (FastAPI/React/LiveKit/Postgres/Redis/ASR-сервис); PHP-код не вписывается
в этот стек и перенесён в `legacy/php/` как справочный источник, а проверенные решения портированы.

**Сохранено/портировано из старого проекта.**
- LDAPS-вход: проверка сертификата, DN-поиск, группы через `LDAP_MATCHING_RULE_IN_CHAIN`, классификация
  кодов bind (775/533/532/773/52f) → `backend/app/auth/directory.py`.
- AES-256-GCM для секретов → `backend/app/security/secretbox.py`; защита от перебора и серверные сессии
  (HttpOnly, idle/absolute таймауты, CSRF) → `auth/{throttle,sessions,deps}.py` (Redis вместо SQLite/файлов).
- Шрифт IBM Plex Sans и нейтральная палитра → `frontend/public/fonts`, `frontend/src/styles.css`.
- Состав админки, DocClean-шлюз и LLM-адаптеры — отмечены к переносу на следующих этапах (остаются в `legacy/php`).

**Изменено/удалено из прежней структуры.** Старые `HISTORY.md` и `PROJECT.md` сохранены в
`docs/legacy/`; весь PHP-проект (кроме рабочих данных `var/`, исключённых из Git) перемещён в
`legacy/php/`; создан `legacy/README.md`. Функциональность AI-чата, проектов, файлов, лимитов токенов
новой системе не нужна.

**Сделано.**
1. Документы: `ARCHITECTURE.md`, `DEPLOYMENT.md`, `.env.example`, `docs/ASR_CONTRACT.md`, `docs/MIGRATIONS.md`, `README.md`.
2. Инфраструктура: `deployment/compose.yml` (+`compose.gpu.yml`, образ LiveKit, шаблоны nginx), скрипты
   `preflight/install/deploy/rollback/backup/restore/status/logs/smoke-test/models` (+`lib/common.sh`),
   профили shared-host/standalone, `--dry-run`.
3. Backend: конфигурация, JSON-логи с request-id и маскированием, модели и миграция `0001`, вход AD,
   сессии, ACL комнат, встречи (reaper, webhook LiveKit), токены LiveKit (identity `u-<uuid>`), приём реплик
   из Redis-стрима, WebSocket, admin-API комнат с аудитом, health/ready/version, внутренний smoke.
4. ASR-сервис: интерфейс `AsrProvider`, `GigaAmProvider`, Silero VAD, сегментатор, ограниченная очередь
   инференса, конвейер на трек, LiveKit-воркер (скрытый участник, подписка только на микрофоны), менеджер сессий, health.
5. Frontend: вход, список комнат, комната (LiveKit, плитки участников, микрофон/камера/экран, живая
   транскрипция по WebSocket), история встреч и протокол (.txt), админка комнат.

**Проверка.** Backend — 60 тестов pytest проходят; ASR — 19 тестов проходят; frontend — `tsc`, 3 теста vitest и
`vite build` проходят; `bash -n` для всех скриптов; `preflight.sh` и `install.sh --dry-run` прогнаны в Git Bash;
структура compose разобрана YAML-парсером. В ходе работы найдено и исправлено: счётчик перебора пароля комнаты
считал запрос без пароля попыткой подбора; цикл приёма сегментов не уступал циклу событий на не-блокирующем клиенте
(зависание тестов).

**Не проверялось / оставшиеся проблемы.** Нет Docker, torch, модели GigaAM, LiveKit, PostgreSQL, реального AD
и браузера: `GigaAmProvider`, `SileroVad`, `RoomWorker`, образы и `docker compose` не запускались; скрипты не
выполнялись на Linux. Не реализованы: хранилище (локально/SMB), запись аудио, очистка по срокам, кнопки
«начать/завершить запись», автопротокол, остальные разделы админки (см. PROJECT.md, раздел 8). Проект ещё не
git-репозиторий.

## 2026-10-06 — Этап 2: админка, хранилище/SMB, запись, протоколы с обезличиванием, трансляция экрана

**Основа.** Вертикальный путь и инфраструктура из предыдущей записи. Из `legacy/php` дополнительно портированы клиент
DocClean/generic API обезличивания (`AnonymizationGateway`: чанки, `verification.clean`, fail closed) и LLM-адаптеры
(OpenAI/Anthropic/OpenAI-compatible, фиксация провайдера маршрута); состав разделов админки воспроизведён в React.

**Сделано.**
1. Backend: миграция `0002` (`recordings`, `protocols`); `SettingsService` (6 групп настроек, секреты шифруются `SecretBox` с AAD по ключу,
   наружу — только «задан/нет»); `storage.py` (локальный каталог и SMB через `smbprotocol`, безопасные имена, структура
   `<комната>/<дата, день недели>/<время>`, защита от выхода из корня); `integrations/{anonymizer,llm}.py`;
   `protocols.py` (стенограмма с шапкой «Участвовали», выгрузка, автопротокол, обработка длинных встреч по частям, fail closed);
   `recordings.py` (PCM → WAV); `workers/retention.py` (раздельные сроки текста и аудио); `admin_system.py` (настройки, проверка
   подключений, пользователи с отключением, поиск групп/пользователей в AD для ACL, встречи с принудительным завершением,
   записи, состояние системы); эндпоинты протоколов/записи/`.txt`/скачивания аудио; кнопка записи (`config` для ASR).
2. ASR: флаги сессии (`transcribe`, `record_audio`) меняются на лету, запись PCM по участникам, обработка команды `config`;
   uid контейнера приведён к backend (10001), `install.sh` выдаёт этому uid только `recordings` и `exports`.
3. Frontend: админка из 10 вкладок (комнаты с поиском AD, встречи, хранилище, обезличивание, LLM и протокол, экран, пользователи,
   записи, аудит, система); комната — кнопка «Показать экран» одним кликом с профилями (1080p, VP9, contentHint, simulcast-слой,
   политика деградации), большая «сцена» с полноэкранным режимом, «вписать/заполнить» и текущим разрешением; кнопка и индикатор записи;
   история — краткие протоколы (создание, ожидание, просмотр), скачивание `.txt`; тяжёлые страницы загружаются лениво.
4. Документация: `ARCHITECTURE.md` (§3.7, 3.7.1, 3.7.2), `DEPLOYMENT.md` (§6.1), `docs/ASR_CONTRACT.md`, `PROJECT.md`, `.env.example` (`DOCS_ENABLED`).

**Проверка.** Backend — 102 теста проходят (добавлены: обезличивание и его отказы, LLM-форматы, хранилище и обход путей, SMB-пути,
PCM→WAV, секреты в настройках и аудите, отключение пользователей, поиск AD, запись/пауза, выгрузка с шапкой, краткий протокол
(LLM не видит имён; при `clean=false` не вызывается), сроки хранения, аудио админ-скачивание). ASR — 23 теста. Frontend — `tsc`,
6 тестов vitest, `vite build`. Найдено и исправлено: аудит-ключ `secrets_changed` маскировался фильтром секретов; значение `null`
срока хранения при создании комнаты подменялось значением по умолчанию («бессрочно» было недостижимо); JSON `true` не совпадал
со строкой «true» в generic-профиле обезличивателя.

**Не проверялось / оставшиеся проблемы.** См. PROJECT.md §7–8: реальные AD/LiveKit/GigaAM/SMB/Docker/браузер не использовались;
качество и устойчивость трансляции экрана, запись аудио и работа GigaAM на реальном железе не проверены; проект не git-репозиторий;
`legacy/php` оставлен (содержит рабочие данные старого проекта) — удалять по решению владельца.

## 2026-10-06 — Аудит интерфейса и админки в браузере, исправления, подготовка публикации на GitHub

**Сделано.** Поднят локальный стенд (backend с подставным AD/Redis + SQLite, Vite) и проведён аудит в Chrome (Playwright):
вход и блокировка, права, создание комнаты с поиском групп AD, все вкладки админки, валидации, секреты, отключение пользователя,
аудит, система, вход в комнату без LiveKit, мобильная ширина. Итоги и список открытых замечаний — `docs/AUDIT.md`.
Исправлено: недопустимый `pattern` идентификатора комнаты; перезапись ввода при смене вкладок настроек (ключи форм); дубли и поздняя
проверка каталога хранилища (теперь `preview` до сохранения); английские ошибки подключения и «залипший» участник при сбое входа;
шапка на мобильном; favicon и предупреждения роутера; общие настройки перенесены в «Система»; добавлены панель выбора устройств,
выход при закрытии вкладки (keepalive), возврат на экран входа при истёкшей сессии, ErrorBoundary.
Публикация: `.gitattributes` (LF для скриптов), `.gitignore` (код `legacy/php` не публикуется), CI GitHub Actions
(backend, ASR, frontend, проверка скриптов и compose), `docs/INSTALL_AND_UPDATE.md` (GitHub → сервер → обновление → откат),
локальный репозиторий `main` с первым коммитом.

**Проверка.** Backend — 102 теста, ASR — 23, frontend — `tsc`, 6 тестов vitest, `vite build`; `bash -n` всех скриптов — без ошибок.

**Не проверялось.** Живая комната (звук, экран, запись, реплики), CI на GitHub (workflow не запускался), SMB, реальный AD, Docker.
