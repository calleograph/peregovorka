# Решение проблем: HTTPS и обратный прокси

*Для кого: администратор сервера.*

Peregovorka работает только по HTTPS: без защищённого соединения браузер не даёт сайту микрофон и экран. Сертификат обычно стоит на обратном прокси (nginx, который ставит установщик, или прокси вашей организации). Требования к прокси — [Как настроить reverse proxy и HTTPS](Как-настроить-reverse-proxy-и-HTTPS), установка и замена — [Как настроить сертификаты](Как-настроить-сертификаты).

## В браузере всё открывается, а Outlook, телефоны или проверки с сервера пишут ошибку сертификата

**Почему.** Прокси отдаёт только сертификат сайта, без промежуточных. Браузеры на компьютерах сами докачивают недостающее, а OpenSSL, Python, Outlook и Android — нет. Это самая частая причина.

**Проверка.** «Администрирование → Интеграции → Microsoft Outlook», блок проверки HTTPS: состояние «неполная цепочка» и кнопка «Скачать fullchain.pem». Через SSH: `scripts/diag.sh`, файл `network.txt`, строка «сертификатов в цепочке» — значение 1 при сертификате от промежуточного центра означает неполную цепочку.

**Что сделать.** На прокси укажите файл полной цепочки: сертификат сайта плюс промежуточные, без корневого. Исправляется на прокси, а не в Peregovorka. ⚠ Перезагрузка прокси на секунды прерывает соединения.

**Если сертификат выдан внутренним центром организации** и рабочие станции доверяют ему по групповой политике, то это не неполная цепочка. Серверу нужно доверять этому центру: «Администрирование → Интеграции → Каталог: сертификаты (CA)» (для LDAPS и почты) и файл `DATA_ROOT/ca/outlook-ca.pem` для проверок Outlook. Параметр `OUTLOOK_CHECK_CA_FILE` в `.env` не действует: он не передаётся в контейнер. Телефонам корневой сертификат устанавливают по политике организации.

## «Недопустимый Origin» при входе (ошибка 403, WebSocket закрывается кодом 4403)

**Почему.** Страница открыта по адресу, которого нет в `APP_PUBLIC_URL` и `ALLOWED_ORIGINS`: по IP вместо имени, через SSH-туннель, через другой прокси или после переноса сервера на новое имя. Это защита от подделки запросов, и отключать её нельзя.

**Что сделать.** Откройте приложение по основному адресу: он указан в тексте ошибки. Если второй адрес действительно нужен, добавьте его в `ALLOWED_ORIGINS` (формат `https://имя[:порт]`, через запятую) и пересоздайте backend: ⚠ `scripts/ctl.sh restart backend` (страницы переподключатся). Это делается через SSH, потому что адреса доступа — настройка безопасности самой установки.

**Проверка.** `scripts/logs.sh backend --tail 500 | grep "Origin отклонён"` показывает, какой адрес пришёл.

## Сайт открывается, а встреча не подключается через прокси организации

Прокси должен передавать WebSocket (заголовки `Upgrade` и `Connection`) для `/livekit/` и `/api/v1/ws` и не обрывать долгие соединения. Медиа через HTTP-прокси не идёт вообще — см. [Звонки и сеть](Решение-проблем-звонков-и-сети).

## За прокси с обязательным входом не открывается эфир или гостевая ссылка

Если прокси или WAF требует входа, он не должен закрывать страницы зрителя и гостя. Для зрителя нужны `/live/*`, `/hls/*`, `/llhls/*`, `/rec/template`, `/api/v1/live/*`, для узлов CDN ещё `/cdn-origin/*`. Перечень для гостя — [Как настроить reverse proxy и HTTPS](Как-настроить-reverse-proxy-и-HTTPS). Какие настройки буферизации внешнего прокси нужны для `/llhls/`, не проверено: если задержка эфира выросла, сравните её при прямом обращении к серверу.

## После смены сертификата часть функций по-прежнему ругается

- Если сертификат стоит на nginx сервера, перечитайте его: ⚠ `sudo nginx -t && sudo systemctl reload nginx`.
- Пересоздайте web, чтобы он перечитал сертификаты: в разделе «Видеозапись» или «Трансляции» есть «Перезапустить web». ⚠ Сайт недоступен несколько секунд.
- Если сертификат сменили на прокси организации, а не на nginx сервера, Peregovorka ничего перечитывать не нужно.
- HSTS: если раньше сайт открывался по HTTPS с HSTS, а теперь сертификат недоверенный, браузер не даст «продолжить на свой риск». Нужен доверенный сертификат.
