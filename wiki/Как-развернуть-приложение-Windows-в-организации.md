# Как развернуть приложение Windows в организации

*Для кого: администратор Windows.*

## Зачем это нужно

Приложение Peregovorka можно установить на рабочие компьютеры централизованно, с заранее заданным сервером организации и политиками. Сотрудникам не нужно вводить адрес сервера и настраивать приложение самим.

## Когда пригодится

- Приложение нужно на десятках и сотнях компьютеров через групповую политику, SCCM или Intune.
- Нужно запретить подключение к чужим серверам.
- Нужно задать прокси, автозапуск и режим обновлений.

Для установки одним сотрудником: [Как установить приложение для Windows](Как-установить-приложение-для-Windows). Все свойства и политики: [Справочник: приложение для Windows](Справочник-приложение-для-Windows).

Ручная проверка на настоящих Windows 10 и 11 и в настоящем домене не записана. Сборка и тихая установка проверяются в GitHub Actions на Windows Server 2025. Начните с пилотной группы компьютеров.

## Что потребуется

- Windows 10 или 11, x64.
- Сервер Peregovorka 0.37.0 или новее. Проверка: `https://meet.example.org/api/v1/desktop/info`.
- Корневой сертификат вашего удостоверяющего центра в «Доверенных корневых центрах» Windows, если сертификат сервера внутренний. Отключить проверку сертификата в приложении нельзя.
- Решение, какой пакет нужен:

| Пакет | Для чего | Куда ставится |
| --- | --- | --- |
| `Peregovorka-Setup-X.Y.Z.exe` | установка сотрудником, по умолчанию для текущего пользователя без прав администратора | `%LOCALAPPDATA%\Programs\Peregovorka` или `Program Files` |
| `Peregovorka-X.Y.Z-x64.msi` | централизованное развёртывание, для всех пользователей; приложение само не обновляется, версию меняет администратор | `%ProgramFiles%\Peregovorka` |

EXE не ставится поверх уже установленного MSI, код выхода 2.

## Где найти

Установщики и `SHA256SUMS.txt` лежат в выпуске клиента. Настройка сервера: **Администрирование → Безопасность → Вход и сеансы**. Подпись своими сертификатами: **Администрирование → Windows-клиент → Подпись и корпоративные сборки**. Шаблоны политик: `desktop/installer/admx/` в репозитории.

## Как это сделать

### Проверьте пакет

1. Сверьте контрольную сумму с `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\Peregovorka-X.Y.Z-x64.msi -Algorithm SHA256
   ```

2. Проверьте подпись:

   ```powershell
   Get-AuthenticodeSignature .\Peregovorka-X.Y.Z-x64.msi
   ```

   Публичные выпуски не подписаны сертификатом издателя, поэтому статус не будет `Valid`, а Windows покажет SmartScreen. Для доверенного распространения соберите подписанные пакеты в **Администрирование → Windows-клиент → Подпись и корпоративные сборки**.

### Установите MSI

```powershell
# тихая установка с журналом и преднастройкой
msiexec /i Peregovorka-X.Y.Z-x64.msi /qn /l*v install.log SERVERS="Головной офис|https://meet.example.org" ALLOWADDSERVERS=0 AUTOSTART=tray

# обновление: новый пакет поверх, свойства первой установки сохраняются
msiexec /i Peregovorka-НОВАЯ-ВЕРСИЯ-x64.msi /qn

# удаление: политики, автозапуск и схема ссылок удаляются вместе с программой
msiexec /x Peregovorka-X.Y.Z-x64.msi /qn
```

Логины и пароли пользователей в MSI, командную строку и реестр не передаются. Сотрудник входит сам.

Установка EXE без окна: `Peregovorka-Setup-X.Y.Z.exe /S`. Удаление: `"%LOCALAPPDATA%\Programs\Peregovorka\Uninstall Peregovorka.exe" /S`. Данные пользователя при этом сохраняются.

### Настройте групповые политики

1. Скопируйте `desktop/installer/admx/Peregovorka.admx` и `ru-RU/Peregovorka.adml` (или `en-US`) в центральное хранилище: `\\<домен>\SYSVOL\<домен>\Policies\PolicyDefinitions`.
2. В редакторе групповых политик откройте раздел **Peregovorka**. Он есть в конфигурации компьютера и пользователя. Значения компьютера сильнее.
3. Задайте нужное: преднастроенные серверы, запрет добавления своих, разрешённые домены, автозапуск, действие кнопки закрытия, режим обновлений, уведомления, прокси.

Порядок: политика компьютера, политика пользователя, настройка пользователя. Поле, заданное политикой, пользователь видит недоступным с пометкой «Задано администратором».

### Настройте сервер

Откройте **Администрирование → Безопасность → Вход и сеансы** и задайте **Приложение Windows помнит вход**: сколько дней после входа паролем приложение открывается без пароля. По умолчанию 30, допустимо 0–90. При 0 вход действует только в пределах обычного сеанса.

Пароль не хранится, устройство получает отзываемый токен. Отозвать его можно в **Активные устройства**, выходом, отключением учётной записи. Смена пароля в домене гасит сохранённый вход при следующем запуске приложения.

## Что получится

1. На компьютере запустите приложение. Должен быть виден преднастроенный сервер.
2. Войдите, откройте комнату, проверьте микрофон и камеру.
3. Снимите диагностику без интерфейса. Приложение должно быть закрыто: оно работает в одном экземпляре.

   ```powershell
   & "$env:ProgramFiles\Peregovorka\Peregovorka.exe" --diagnostics=C:\Temp\pg-diag.json
   ```

   Получится JSON-отчёт без паролей, токенов и текста сообщений.

## Если не получается

| Что видно | Причина | Что сделать |
| --- | --- | --- |
| «Сертификат не доверен» | корневой сертификат не распространён | добавьте его групповой политикой |
| «Сертификат выдан на другое имя» | адрес не совпадает с сертификатом | укажите имя, а не IP |
| Нельзя добавить свой сервер | `ALLOWADDSERVERS=0` или политика | это ожидаемое поведение |
| Значение MSI не снимается | оно сохранено в реестре | удалите и поставьте заново без свойства или управляйте политикой |
| Код выхода 2 при установке EXE | на компьютере стоит MSI | используйте MSI |
| Приложение не обновляется | установка из MSI | ставьте новый MSI поверх |
| SmartScreen, «Неизвестный издатель» | пакет не подписан | подпишите своим сертификатом |
| Пароль просят при каждом запуске | **Приложение Windows помнит вход** равно 0 или срок вышел | проверьте настройку |

Журнал установки MSI: файл из параметра `/l*v`. Журнал приложения: `%APPDATA%\Peregovorka\logs\main.log`. Другие случаи: [Решение проблем приложения Windows](Решение-проблем-приложения-Windows).
