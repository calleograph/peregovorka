# Как развернуть приложение Windows в организации

> Относится к приложению для Windows 1.2.0 · проверено 2026-10-25 · уровень проверки: 2–3 (модульные тесты; установка, обновление и удаление MSI на Windows проверяются в CI); групповые политики и SCCM/Intune на реальном домене не проверялись · тип страницы: практическое руководство

Результат: приложение установлено на рабочие компьютеры с преднастроенными серверами и политиками. Для кого: администратор Windows. Для установки отдельным сотрудником — [[Как установить приложение для Windows|Как-установить-приложение-для-Windows]]. Справочник свойств и политик — [[Справочник: приложение для Windows|Справочник-приложение-для-Windows]].

## Что нужно заранее

- Сервер Peregovorka 0.37.0 или новее (`/api/v1/desktop/info`).
- Корневой сертификат вашего центра сертификации в «Доверенных корневых центрах» Windows (групповая политика). Отключить проверку сертификата в приложении нельзя.
- Решение, какой пакет нужен:

| Пакет | Для чего | Куда ставится |
| --- | --- | --- |
| `Peregovorka-Setup-X.Y.Z.exe` | установка сотрудником; по умолчанию для текущего пользователя без прав администратора | `%LOCALAPPDATA%\Programs\Peregovorka` или `Program Files` |
| `Peregovorka-X.Y.Z-x64.msi` | централизованное развёртывание (GPO, SCCM, Intune), для всех пользователей; приложение само не обновляется, обновляет администратор | `%ProgramFiles%\Peregovorka` |

EXE не ставится поверх уже установленного MSI (код выхода 2).

## Проверить пакет

1. Сверьте контрольную сумму с `SHA256SUMS.txt` из выпуска.
2. Проверьте подпись:

   ```powershell
   Get-AuthenticodeSignature .\Peregovorka-X.Y.Z-x64.msi     # не запускалась
   ```

   Выпуск 1.2.0 не подписан сертификатом издателя: статус не будет `Valid`. Для доверенного распространения используйте **собственные подписанные сборки** вашей организации: **Администрирование → Windows-клиент → Подпись и корпоративные сборки** ([[Справочник: приложение для Windows|Справочник-приложение-для-Windows]]).

## Установить MSI

```powershell
# тихая установка с журналом и преднастройкой (не запускалась)
msiexec /i Peregovorka-X.Y.Z-x64.msi /qn /l*v install.log SERVERS="Головной офис|https://meet.example.org" ALLOWADDSERVERS=0 AUTOSTART=tray

# обновление: новый пакет поверх; свойства первой установки сохраняются
msiexec /i Peregovorka-X.Y.Z+1-x64.msi /qn

# удаление: политики, автозапуск и схема ссылок удаляются вместе с программой
msiexec /x Peregovorka-X.Y.Z-x64.msi /qn
```

Логины и пароли пользователей в MSI, командную строку и реестр не передаются: сотрудник входит сам.

Установка EXE без окна: `Peregovorka-Setup-X.Y.Z.exe /S`; удаление: `"%LOCALAPPDATA%\Programs\Peregovorka\Uninstall Peregovorka.exe" /S` (данные пользователя сохраняются).

## Настроить групповыми политиками

1. Скопируйте шаблоны `desktop/installer/admx/Peregovorka.admx` и `ru-RU/Peregovorka.adml` (или `en-US`) в центральное хранилище: `\\<домен>\SYSVOL\<домен>\Policies\PolicyDefinitions`.
2. В редакторе групповых политик откройте раздел «Peregovorka» (есть в конфигурации компьютера и пользователя; значения компьютера сильнее).
3. Задайте нужные значения: преднастроенные серверы, запрет добавления своих, разрешённые домены, автозапуск, действие закрытия окна, режим обновлений, уведомления, прокси.

Приоритет: политика (HKLM) → политика (HKCU) → настройка пользователя. Поле, заданное политикой, пользователь видит недоступным с пометкой «Задано администратором».

## Настроить сервер

**Администрирование → Безопасность → Вход и сеансы → «Приложение Windows помнит вход»** — сколько дней после входа паролем приложение открывается без пароля (по умолчанию 30, допустимо от 0 до 90; 0 — только в пределах обычного сеанса). Отзыв: «Активные устройства», принудительный выход, отключение учётной записи. Смена пароля в AD гасит сохранённый вход при следующем запуске приложения.

## Проверить результат

1. На компьютере запустите приложение: должен быть виден преднастроенный сервер.
2. Диагностика без интерфейса (приложение должно быть закрыто, оно работает в одном экземпляре):

   ```powershell
   "%ProgramFiles%\Peregovorka\Peregovorka.exe" --diagnostics=C:\Temp\pg-diag.json     # не запускалась
   ```

   Ожидаемый результат: JSON-отчёт без паролей, токенов и текста сообщений.

## Типичные ошибки

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Приложение не видит сервер | не доверен сертификат | распространить корневой сертификат групповой политикой |
| Пользователь не может добавить свой сервер | `ALLOWADDSERVERS=0` или политика | ожидаемо |
| Значение MSI не снимается | оно сохранено в реестре | удалить и поставить заново без свойства либо управлять политикой |
| Код выхода 2 при установке EXE | на компьютере стоит MSI | использовать MSI |
