# Как настроить языковые модели

*Для кого: администратор.*

## Зачем это нужно

Протоколы, резюме и карты разговора формирует языковая модель, подключённая по API. Встроенной модели в Peregovorka нет: прежняя встроенная Qwen удалена в версии 0.56.0, при обновлении её контейнер и файл удаляются сами. Как формируется документ — [Как работают стенограмма и протоколы](Как-работают-стенограмма-и-протоколы). Выбор модели для пользователя — [Как выбрать языковую модель](Как-выбрать-языковую-модель).

Стенограмму делает другая служба, она работает на вашем сервере: [Как настроить распознавание речи](Как-настроить-распознавание-речи).

## Когда пригодится

- Первая настройка протоколов.
- Смена провайдера или модели.
- Протокол обрезается или не формируется.

## Что потребуется

Роль администратора. Адрес API, ключ и название модели: облачной (OpenAI, Anthropic), корпоративного шлюза или своего сервера в сети организации (любой OpenAI-совместимый). Доступ с сервера до адреса API.

## Где найти

**Администрирование → Интеграции → Языковая модель (LLM)**.

## Как это сделать

### Подключить модель

1. **Интеграции → Языковая модель (LLM) → вкладка «Подключения» → «Добавить подключение»**.
2. Заполните форму: тип (OpenAI, Anthropic, OpenAI-совместимый, «свой OpenAI-подобный сервис»), адрес, идентификатор модели, ключ, дополнительные заголовки (секретные значения шифруются), таймаут, максимальная длина ответа (общие потолки по задачам: протокол 60 000, резюме 40 000, карта 60 000 токенов), окно контекста (можно оставить 0 — см. ниже), рассуждения модели, температура (по умолчанию 0), возможности провайдера.
3. Нажмите «Проверить». Одно подключение может обслуживать и протокол, и резюме или только одну задачу.
4. На вкладке **«Назначения»** выберите, чем формировать протокол, резюме и карту разговора: «Языковая модель по API» или «Отключено» (для резюме и карты ещё «Так же, как протокол»).

   Ожидаемый результат: в строке задачи — выбранная модель и «готова».

Пароли, токены и ключи, произнесённые на встрече, в модель не уходят никогда: они убираются из текста на сервере перед каждым запросом.

HTTPS-адреса внешних служб проверяются по корпоративному набору CA, если включена соответствующая опция.

### Рассуждения модели и окно контекста

- **Рассуждения.** Многие модели сначала «думают» и тратят на это тот же лимит ответа, время и деньги. Для протокола по готовой стенограмме это не нужно, поэтому в подключениях «OpenAI-совместимый» и «свой» параметр **«Рассуждения модели»** по умолчанию — «Отключать» (шлюзу передаётся `reasoning: {effort: none}`; если он не принимает параметр, запрос повторяется без него). «Автоматически» отключает рассуждения только тогда, когда весь лимит ответа ушёл на них; «Не трогать» оставляет решение модели. На встрече в три часа (≈170 тыс. знаков) с моделью DeepSeek V4.1 Flash протокол собирался 40–55 секунд вместо 4,5 минут (проверено на настоящем OpenAI-совместимом шлюзе; другие провайдеры и модели не проверялись).
- **Окно контекста.** Если оставить 0, сервис при формировании документа спрашивает у шлюза список моделей (`GET <адрес>/models`, тем же ключом) и берёт `context_length`; ответ запоминается на сутки. Встреча, которая в окно помещается, обрабатывается **одним запросом**; если шлюз окно не сообщает, длинная встреча идёт заметками по частям, и тогда окно лучше указать вручную. Определённое значение видно в диагностике документа.

### Обезличивание

Перед отправкой в модель материалы можно обезличить на сервере: участники становятся «Иван И.» или «Участник 2», серверы, контакты, реквизиты и суммы заменяются. По умолчанию обезличивание в комнатах выключено; руководитель комнаты включает его в настройках комнаты, администратор может сделать его обязательным. Подробно — [Как настроить обезличивание](Как-настроить-обезличивание).

### Выбрать модель для комнаты или встречи

Наследование: система → комната → встреча, отдельно для протокола и резюме. В **Настройки комнаты → Языковая модель** руководитель выбирает «как в системе», конкретное подключение или «отключена». Для идущей встречи — «Эта встреча». Если выбранная модель удалена или отключена, действует параметр «Если выбранная для комнаты модель недоступна»; разовый выбор в окне «Сформировать» молча другой моделью не заменяется.

## Что получится

- На вкладке **Назначения** в строке задачи стоит выбранная модель и «готова».
- На пробной встрече формируется протокол.

## Если не получается

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Протокол «failed» | модель не настроена или не ответила, обезличивание не выполнено, таймаут | причина показана в строке документа |
| «Языковая модель по умолчанию отключена или не настроена» после обновления | раньше протокол формировала встроенная Qwen, а подключения по API не было | подключить модель на вкладке «Подключения» и выбрать её в «Назначениях» |
| Протокол обрезан | ответ оборван по лимиту длины | увеличить максимум длины ответа внешней модели; для длинной встречи указать окно контекста (или оставить 0, если шлюз его сообщает) |
| «Модель израсходовала весь лимит ответа на рассуждения» | рассуждающая модель, рассуждения не отключены | «Рассуждения модели» → «Отключать» |
