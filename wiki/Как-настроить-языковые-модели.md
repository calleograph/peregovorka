# Как настроить языковые модели

> Относится к версии 0.39.4 · проверено 2026-10-25 · уровень проверки: 2–3 (автотесты и стенд); локальная модель измерена на синтетических встречах; внешние API проверены подставными HTTP-ответами · тип страницы: практическое руководство

Результат: протоколы и резюме формируются выбранной моделью — встроенной локальной или внешней. Для кого: администратор. Как формируется документ — [[Как работают стенограмма и протоколы|Как-работают-стенограмма-и-протоколы]].

## Что нужно заранее

- Для встроенной модели: около 2,5 ГБ свободной памяти (лимит контейнера `LLM_LOCAL_MEM`, по умолчанию 3500m), файл модели (~1,3 ГБ) в `DATA_ROOT/models/llm`.
- Для внешней: адрес API, ключ и название модели.

## Встроенная локальная модель

Qwen3 1.7B (квантование Q4_K_M, формат GGUF) работает в отдельном контейнере `llm-local` на процессоре, в сети без выхода в интернет и без опубликованных портов. Данные встречи наружу не уходят.

1. Установщик скачивает файл сам (`LLM_LOCAL_ENABLED=yes` по умолчанию). Если интернета не было, откройте **Администрирование → Языковая модель (LLM) → «Скачать модель»** либо выполните на сервере:

   ```bash
   sudo scripts/models.sh --llm-only                         # не запускалась
   sudo scripts/models.sh --llm-only --from-dir /путь/к/каталогу   # закрытая сеть
   scripts/models.sh --llm-only --check                      # проверить файл
   ```

   Перед использованием проверяются наличие, размер (1 282 439 584 байт) и SHA-256. Повреждённый файл скачивается заново, неверный сохраняется как `*.failed`.

2. В разделе «Языковая модель (LLM)» выберите в блоке «Системные значения по умолчанию»: для протокола — «Локальная: Qwen3 1.7B Q4_K_M», «Внешняя LLM» или «Отключено»; для резюме — «Такая же, как для протокола», «Локальная», «Внешняя LLM» или «Резюме не формировать».

   Ожидаемый результат: в блоке «Встроенная локальная модель» файл проверен, сервер модели отвечает.

3. На общем сервере уменьшите потоки, чтобы не отбирать процессор у распознавания: `LLM_LOCAL_THREADS` (по умолчанию 4) в `.env`. Отключить модель совсем: `LLM_LOCAL_ENABLED=no`.

Важно знать:

- Модель небольшая: она годится для рабочих протоколов с вычиткой, но не для юридически значимых документов без проверки.
- Время на процессоре заметное: протокол 60-минутной встречи формируется в фоне десятки минут (измерено на синтетических встречах).
- Прежние модели Qwen3 0.6B сняты с вооружения; сохранённый выбор молча заменяется на 1.7B.

## Внешняя модель

1. **Языковая модель (LLM) → «Внешний API по умолчанию» / «Внешние API (профили)»**.
2. Заполните форму: тип (OpenAI, Anthropic, OpenAI-совместимый, «свой OpenAI-подобный сервис»), адрес, идентификатор модели, ключ, дополнительные заголовки (секретные значения шифруются), таймаут, максимальная длина ответа (по умолчанию для резюме 2000 токенов, для протокола 7000), окно контекста, температура (по умолчанию 0), возможности провайдера.
3. Нажмите «Проверить». Один профиль может обслуживать и протокол, и резюме или только одну задачу; отметка «по умолчанию для всех» работает, когда выбран режим «Внешняя LLM».

HTTPS-адреса внешних служб проверяются по корпоративному набору CA, если включена соответствующая опция.

## Обезличивание

**Администрирование → Интеграции → Обезличивание**: адрес и токен сервиса (DocClean или произвольный JSON API), режим и группы данных, таймауты. Режим можно задать для всей системы и для комнаты: наследовать, всегда, выключено. Правило «fail closed»: при включённом обезличивании сбой сервиса не приводит к отправке данных наружу, протокол не создаётся. Если обезличивание выключено, текст уходит модели как есть, и окно «Сформировать протокол» об этом предупреждает. Для локальной модели обезличивание по умолчанию не применяется.

## Выбрать модель для комнаты или встречи

Наследование: система → комната → встреча, отдельно для протокола и резюме. В «Настройки комнаты → Языковая модель» руководитель выбирает «как в системе», локальную, конкретный внешний профиль или «отключена». Для идущей встречи — «Эта встреча». Если выбранная модель удалена или отключена, действует параметр «Если выбранная для комнаты модель недоступна»; разовый выбор в окне «Сформировать» молча другой моделью не заменяется.

## Распознавание речи

**Администрирование → Интеграции → Распознавание речи (ASR)**: состояние модели, «Протестировать модель» и «Сравнить установленные модели» (встроенный тестовый WAV, скорость, RTF, нагрузка, WER и CER, пунктуация). Не запускайте тест во время встреч: по умолчанию он блокируется. Штатная модель — GigaAM v3 e2e RNNT (полная, PyTorch). Квантованная модель снята с вооружения.

Потоки процессора для ASR: `ASR_CPU_THREADS` и `ASR_INTEROP_THREADS`. Произведение `ASR_CPU_THREADS × ASR_MAX_CONCURRENT_INFERENCE` не должно превышать число ядер. Ориентиры для общего сервера: 4 vCPU — 2 потока, 8 vCPU — 4 потока. Подобрать по задержке:

```bash
scripts/asr-bench.sh --wav речь.wav --threads 2,4       # не запускалась
```

## Типичные ошибки

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «ЛОКАЛЬНАЯ LLM НЕ ЗАГРУЖЕНА» при установке | не было интернета | «Скачать модель» или `scripts/models.sh --llm-only` |
| Протокол «failed» | не настроены обезличивание или модель, отказ сервиса, таймаут | причина показана в строке документа |
| Протокол обрезан | ответ оборван по лимиту длины | увеличить максимум длины ответа внешней модели |
| ASR красный | нет файлов модели или прав на них | `scripts/models.sh`; [[Диагностика]] |
