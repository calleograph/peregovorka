# Мониторинг и журналы

*Для кого: администратор и служба поддержки.*

## Зачем это нужно

Страница показывает, где смотреть состояние сервера, как найти причину сбоя и как выгрузить журналы без раскрытия секретов.

## Когда пригодится

- Ежедневная проверка сервера.
- Пользователи жалуются на сбой.
- Нужно передать сведения в поддержку.

## Что потребуется

Роль администратора в приложении. Для команд: доступ к серверу по SSH. Правила `sudo` — [Справочник: скрипты и команды](Справочник-скрипты-и-команды).

## Где найти

| Раздел | Что показывает |
| --- | --- |
| **Обзор → Обзор**, блок **Требует внимания** | всё, что требует действия: службы, ключ шифрования, место, видеозапись и трансляции, хранилища, невыгруженные записи, копии, ограничение входа, обезличивание, сверка, почта. У пункта есть описание, влияние и переход к настройке. Число проблем стоит значком в меню |
| **Обзор → Обзор**, блоки **Первоначальная настройка и проверка сервера** и **Сервисы** | чек-лист и состояние PostgreSQL, Redis, LiveKit, ASR, каталога. Проверки идут с сервера, а не с устройства пользователя |
| **Обзор → Технические показатели** | процессор, память, диск, версии, хранилище записей, параметры ядра, **Время входа в комнату**, кнопки **Скачать диагностический отчёт**, **Повторить выгрузку записей**, **Запустить очистку по срокам** |
| **Обзор → Производительность** | пулы базы, соединения PostgreSQL, отказы 503, нагрузка LiveKit, очередь тяжёлых задач |
| **Обзор → Диагностика клиентов** | события из браузеров: причины остановки показа экрана, ошибки устройств, потери связи, FPS, битрейт, RTT |

В комнате есть режим **⚙ Диагностика** с теми же цифрами в реальном времени.

## Как это сделать

### Проверить сервер из терминала

Команды только читают данные, кроме `smoke-test.sh`, который создаёт и удаляет тестовую встречу.

```bash
cd /opt/peregovorka
sudo scripts/status.sh                        # службы и health
sudo scripts/logs.sh backend -f               # журнал в реальном времени
sudo scripts/logs.sh livekit-egress --tail 300
sudo scripts/logs.sh mediamtx --tail 100
sudo scripts/verify.sh                        # итоговая проверка
sudo scripts/smoke-test.sh                    # сквозная проверка
sudo scripts/diag.sh                          # архив без секретов
```

`logs.sh` принимает службы `postgres redis livekit backend asr web livekit-sip livekit-egress mediamtx`. `status.sh` учитывает в итоге `livekit-egress` и `livekit-sip`, если они включены; `mediamtx` виден в списке, но на итог не влияет.

### Настроить внешний мониторинг

| Что наблюдать | Как | Норма |
| --- | --- | --- |
| Живость | `https://<адрес>/api/v1/health/live` | HTTP 200 |
| Готовность | `https://<адрес>/api/v1/health/ready` | HTTP 200, `"status":"ready"`; 503 — ядро недоступно |
| Диск | `df -h DATA_ROOT` | хватает на записи и обновление, см. ниже |
| Сертификат | срок публичного сертификата | продление заранее |
| Копии | строка `Резервное копирование завершено.` и код 0 | каждую ночь |

Обновлению нужно 15 ГБ на диске Docker и `MIN_FREE_DISK_GB` (30 ГБ), если данные на том же диске. Запись и эфиры нуждаются в отдельном запасе: [Как настроить видеозапись и трансляции на сервере](Как-настроить-видеозапись-и-трансляции-на-сервере).

Метрики Prometheus для приложения не реализованы. Метрики LiveKit (порт 6789) и Egress (порт 9090) доступны только внутри сети проекта и наружу не публикуются.

### Найти запись в журнале событий

**Хранение и журналы → Журнал событий.** Категории: `auth`, `room`, `network`, `device`, `client`, `llm`, `storage`, `admin`, `system`, `live`. Пароли, ключи, токены и содержимое разговоров не записываются.

| Действие | Как |
| --- | --- |
| Найти | поиск, период, уровень, категория, пользователь, комната, условия; щелчок по значению добавляет условие |
| ⚠ Удалить | флажки или «Удалить все по фильтру» с подтверждением; удаление пишется в аудит |
| Выгрузить | «Выгрузить за сутки» или «Полный архив за 30 дней»: ZIP с `journal.csv`, `journal.ndjson`, `audit.csv` |
| Срок хранения | **Хранение журнала**, по умолчанию 30 дней, очистка раз в час |
| Хранить вовне | отключите локальное хранение и ведите журнал на диск или SMB |

Соединение дольше 4 секунд пишет `ice_slow`, не установленное — `ice_failed`. Событий диагностики не более 240 в минуту на пользователя.

### Посмотреть журнал аудита

**Безопасность → Журнал аудита.** Кто, что и когда изменил. Вручную записи не удаляются. Список событий — [Справочник: журнал аудита и события](Справочник-журнал-аудита-и-события).

### Собрать диагностический отчёт

Кнопка **Скачать диагностический отчёт** или `sudo scripts/diag.sh`. Пароли, токены, ключи API и LiveKit, мастер-ключ, `access_token` в URL, пароль LDAP и JWT заменяются на `***`. Перед созданием архива `diag.sh` ищет в нём значения секретов из `.env` и при находке архив не создаёт. Пакет содержит журналы всех служб, включая `livekit-egress` и `mediamtx`.

### Следить за эфиром

Показатели идущего эфира — в [панели диагностики эфира](Панель-диагностики-эфира). Проблемы эфиров попадают и в журнал событий, категория `live`.

## Что получится

Вы видите проблему в **Требует внимания** или внешнем мониторинге, находите службу через `status.sh` и причину в журнале, а поддержке передаёте архив без секретов.

## Если не получается

| Симптом | Куда смотреть |
| --- | --- |
| ASR красный | `sudo scripts/logs.sh asr`, [Как настроить распознавание речи](Как-настроить-распознавание-речи) |
| Долгий вход в комнату | **Время входа в комнату**, `smoke-test.sh`, маршрут `/rtc/v1` |
| Записи не выгружаются | **Встречи → Записи встреч**, **Повторить выгрузку записей**, кнопка **Проверить** у хранилища |
| Журнал службы пуст после перезапуска | журнал Docker удаляется с контейнером; сохраняйте `diag.sh` до перезапуска |
