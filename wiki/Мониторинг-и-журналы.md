# Мониторинг и журналы

> Относится к версии 0.39.4 · проверено 2026-10-25 · уровень проверки: 2–3 (автотесты, стенд); страница «Производительность» на Linux с cgroup v2 не проверялась · тип страницы: практическое руководство

Результат: вы видите состояние сервера, находите причину сбоя и выгружаете журналы без раскрытия секретов. Для кого: администратор и служба поддержки.

## Что нужно заранее

- Права администратора и доступ по SSH к серверу.

## Посмотреть состояние

В браузере: **Администрирование → Обзор**:

| Раздел | Что показывает |
| --- | --- |
| Состояние системы | CPU, память, диск; PostgreSQL, Redis, LiveKit, ASR, каталог; модель и очередь распознавания, средняя задержка и RTF; комнаты и пользователи онлайн; хранилища; версии (приложение, commit, сборка, LiveKit, SDK); параметры ядра; **время входа по этапам** (backend, сеть и прокси, сигналинг, ICE, микрофон, ASR); размер журнала; кнопки «Скачать диагностический отчёт», «Повторить выгрузку записей», «Запустить очистку по срокам» |
| Первоначальная настройка и проверка сервера | чек-лист с проверками публичного адреса и TLS, звонков LiveKit, медиапортов, связи с каталогом, распознавания, модели, места на диске, ключа шифрования; проверки идут с самого сервера, а не с устройства пользователя |
| Диагностика клиентов | события из браузеров: причины остановки показа экрана, ошибки устройств, потери связи, FPS, битрейт, RTT |
| Производительность | занятость пулов базы, соединения PostgreSQL, отказы 503, нагрузка LiveKit, очередь тяжёлых задач |

В комнате есть режим «⚙ Диагностика» с теми же цифрами в реальном времени.

На сервере:

```bash
scripts/status.sh              # состояние и health сервисов проекта
scripts/logs.sh backend -f     # журналы (postgres redis livekit backend asr web); секреты маскируются
scripts/verify.sh              # проверка, только чтение
scripts/smoke-test.sh          # сквозная проверка с итоговой таблицей
scripts/diag.sh                # диагностический пакет (архив) без секретов
scripts/ctl.sh status          # контейнеры проекта
```

Команды не запускались при подготовке вики. `diag.sh` перед созданием архива сверяет содержимое с секретами из `.env` и при находке архив не создаёт.

## Журнал событий

**Администрирование → Хранение и журналы → Журнал событий.** Категории: `auth`, `room`, `network`, `device`, `client`, `llm`, `storage`, `admin`, `system`. Пароли, ключи, токены и содержимое разговоров не записываются.

| Действие | Как |
| --- | --- |
| Найти | поиск, период, уровень, категория, пользователь, комната, произвольные условия («равно», «содержит», «начинается с» и другие); щелчок по значению добавляет условие |
| Удалить | флажки (Shift — диапазон) или «Удалить все по фильтру» с подтверждением; удаление пишется в аудит |
| Выгрузить | «Выгрузить за сутки» или «Полный архив за 30 дней»: ZIP с `journal.csv` (ячейки с `= + - @` экранируются), `journal.ndjson`, `audit.csv` |
| Срок хранения | по умолчанию 30 дней; очистка раз в час; «Применить срок хранения» запускает сразу |
| Хранить вовне | отключите локальное хранение (`keep_local`) и ведите журнал на диск или SMB: файлы `journal/ГГГГ-ММ-ДД/ЧЧММСС-xxxx.ndjson` |

Диагностика клиента при входе: тип и задержка сети, число ядер и память, размер экрана, число и названия устройств, состояние разрешений. Соединение дольше 4 секунд пишет `ice_slow`, не установленное — `ice_failed`. Событий диагностики не более 240 в минуту на пользователя.

## Журнал аудита

**Администрирование → Безопасность → Журнал аудита.** Кто, что и когда изменил; вручную не удаляется. Список событий — [[Справочник: журнал аудита и события|Справочник-журнал-аудита-и-события]].

## Диагностический отчёт

**Состояние системы → «Скачать диагностический отчёт»** или `scripts/diag.sh`. Пароли, токены, ключи API и LiveKit, мастер-ключ, `access_token` в URL, пароль LDAP bind и JWT заменяются на `***` в отчёте, в `diag.sh`, `logs.sh` и выводе `docker compose config`.

## Сторонние метрики

Метрики LiveKit читаются по внутреннему имени службы; порт метрик 6789 наружу не публикуется. Метрики Prometheus для приложения не реализованы ([[Планы развития|Планы-развития]]).

## Типичные ошибки

| Симптом | Куда смотреть |
| --- | --- |
| ASR красный | `scripts/logs.sh asr`, `scripts/models.sh`, [[Диагностика]] |
| Долгий вход в комнату | «Время входа по этапам», `smoke-test.sh` (маршрут `/rtc/v1`) |
| Записи не выгружаются | «Записи аудио», кнопка «Повторить выгрузку записей», «Хранилище → Проверить подключение» |
