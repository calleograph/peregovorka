# Решение проблем: приложение для Windows

*Для кого: служба поддержки, администратор рабочих станций и сотрудник, у которого не работает приложение. Для Linux большинство разделов подходят тоже, отличия указаны на странице [Как установить приложение для Linux](Как-установить-приложение-для-Linux).*

## Зачем это нужно

Страница помогает найти причину сбоя приложения: сервер не добавляется, окно пустое, вход не сохраняется, нет уведомлений.

## Что потребуется

Отчёт диагностики. Соберите его первым делом:

1. Откройте **Настройки → Диагностика**.
2. Нажмите **Сохранить отчёт**.

В отчёт не попадают пароли, токены, cookie и содержимое сообщений.

## Где найти

- Если окно не открывается, создайте отчёт из командной строки: `Peregovorka.exe --diagnostics=<файл>`.
- Журнал приложения лежит в `%APPDATA%\Peregovorka\logs\main.log`. Кнопка **Папка журналов** открывает этот каталог.

## Как это сделать

Найдите свой симптом в разделе ниже и выполните действие. Если сбой остался, передайте отчёт в поддержку: [Руководство технической поддержки](Руководство-технической-поддержки).

## Что получится

Приложение работает, а если причину не удалось устранить, у поддержки есть отчёт и журнал.

## Если не получается

### Сервер не добавляется

| Сообщение | Причина | Что сделать |
| --- | --- | --- |
| **Нужен защищённый адрес https://.** | указан адрес `http://` | укажите `https://…` |
| **Адрес не похож на адрес сервера.** | опечатка | проверьте адрес |
| **Сервер не найден** | нет имени в DNS | проверьте адрес, VPN |
| **Сервер недоступен** | нет сети до сервера | откройте адрес в браузере на том же компьютере |
| **Сервер не отвечает** | истекло время ожидания | проверьте сеть, VPN и прокси |
| **Сертификат не доверен** | Windows не доверяет центру, выдавшему сертификат | установите корневой сертификат организации в доверенные, обычно групповой политикой |
| **Сертификат выдан на другое имя** | имя не совпадает с адресом | введите адрес по имени, а не по IP |
| **Срок действия сертификата истёк** | сертификат просрочен или неверна дата | проверьте дату на компьютере, продлите сертификат |
| **Ошибка прокси-сервера** | прокси недоступен | проверьте **Настройки → Сеть** |
| **Это не сервер Peregovorka** | по адресу другой сайт | проверьте адрес |
| **Не поддерживается версия сервера** | сервер старше нужного приложению | обновите сервер |
| **Добавление серверов запрещено политикой организации.** | подключения задаёт администратор | обратитесь к администратору |

### Пустое окно или «not found» при запуске

Отчёт `--diagnostics`, раздел `shell`, и журнал `main.log` (строки `shell.not_found`, `preload.error`) называют, какой файл программы не загрузился. Обычно помогает переустановка поверх той же версией. В **Настройки → Диагностика** строка **Файлы программы** показывает, не повреждена ли установка.

### Вход не сохраняется, приходится входить заново

Приложение хранит отзываемый ключ устройства, а Windows его защищает. Ключ перестаёт действовать, если его отозвали на сервере, истёк срок или сменился профиль Windows. Срок задаёт администратор сервера, по умолчанию 30 дней. Войдите снова, ключ выпустится заново.

### Нет уведомлений о сообщениях и встречах

Проверьте **Настройки → Уведомления**: уведомления включены, **Не беспокоить** выключено. Затем проверьте уведомления приложения в параметрах Windows, режим фокусировки и групповую политику `Notifications`. Когда страница организации видна на экране, уведомление показывается внутри неё, а не системным окном. Подробнее: [Как настроить уведомления](Как-настроить-уведомления).

### Windows предупреждает SmartScreen при установке

Установщики пока не подписаны сертификатом издателя. Нажмите **Подробнее**, затем **Выполнить в любом случае**. Для установки на все компьютеры организации используйте MSI и групповые политики: [Как развернуть приложение Windows в организации](Как-развернуть-приложение-Windows-в-организации).

### Картинка из чата видна только отправителю или не открывается

Отправитель видит «✓ загружено» только после того, как сервер принял файл целиком и вернул размер и контрольную сумму, совпавшие с исходными. Без этой отметки сообщение с файлом отправить нельзя, а рядом с файлом показана причина и кнопка **Повторить**. Получатель, у которого картинка не открылась, видит причину и тоже может нажать **Повторить**.

Что собрать, если сбой повторяется:

- отчёт диагностики: в журнале `main.log` строки `page.attachment` показывают операцию (`upload`, `open`, `discard`), код ответа сервера или сетевую ошибку;
- события `chat_upload_failed` и `chat_attachment_failed` в **Админ → Обзор → Диагностика клиентов**.

Причина сбоя на настоящем Windows пока не установлена. На тестовом экземпляре под Linux всё работало. Рабочие гипотезы: защитная программа или прокси меняют или обрывают запрос, либо «ленивый» снимок экрана в буфере обмена Windows. Начинайте с журнала `page.attachment`: код 4xx или 5xx указывает на сервер или прокси, сетевая ошибка на защитную программу или сеть.
