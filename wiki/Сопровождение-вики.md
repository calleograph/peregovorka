# Сопровождение вики

> Относится к версии 0.40.0 · проверено 2026-10-26 · уровень проверки: 1 (правила и скрипты репозитория; опубликована 2026-10-26; отображение главной, «Как устроена Peregovorka» с диаграммой и «Как провести встречу» проверено в браузере) · тип страницы: практическое руководство

Результат: вики не отстаёт от продукта. Для кого: тот, кто выпускает версии и ведёт документацию. Правила чтения вики — [[Как читать эту вики|Как-читать-эту-вики]].

## Где живут исходники

Исходники страниц лежат в основном репозитории, каталог `wiki/`: так изменения документации проходят ту же проверку, что и код, и привязаны к выпускам. В вики GitHub страницы копируются отдельным шагом. Служебные файлы: `Home.md`, `_Sidebar.md`, `_Footer.md`. Каталог `wiki/_meta/` (матрица покрытия, таблица фактов, отчёт о пробелах) в вики не публикуется.

Вики GitHub — отдельный git-репозиторий `calleograph/peregovorka.wiki.git`; он появляется после сохранения первой страницы в веб-интерфейсе. Вики GitHub не поддерживает pull request: рекомендуется ограничить правку вики пользователями с правом записи (Settings → Features → Wikis → «Restrict editing to collaborators»). Если для документации нужны обязательное ревью и сборка в CI, лучше подойдёт каталог `docs/` с публикацией через GitHub Pages.

## Проверить исходники

```bash
python3 scripts/check_wiki.py            # ссылки, шапки, блоки «Что дальше», версии, частные данные
python3 scripts/check_wiki.py --strict   # предупреждения тоже считаются ошибками
```

Скрипт проверяет: что ссылки `[[…]]` и `[…](…)` ведут на существующие страницы (ссылки с расширением `.md` запрещены), у каждой страницы есть строка «Относится к версии …, проверено …, уровень проверки …», блок «Что дальше», страница есть в `_Sidebar.md`, версия в шапке совпадает с `VERSION`, нет секретов, доменов и адресов вне разрешённых примеров (`example.org`, `192.0.2.x`). Орфографию проверьте редактором или `aspell --lang=ru` (не запускалась).

## Опубликовать

Публикацию выполняет владелец (или тот, кому он доверил) явной командой. Скрипт показывает перечень файлов и сводку изменений и спрашивает подтверждение; принудительной перезаписи истории (`force push`) он не делает:

```bash
scripts/publish-wiki.sh            # показывает, что изменится; ничего не отправляет
scripts/publish-wiki.sh --yes      # отправляет после показа сводки
```

Первый раз: в веб-интерфейсе репозитория откройте вкладку **Wiki** и сохраните пустую страницу Home (это создаёт репозиторий вики), затем запустите скрипт. Изображения кладите в каталог `wiki/images/`: скрипт копирует его вместе со страницами.

## Что делать при каждом выпуске

1. Откройте `CHANGELOG.md` и `HISTORY.md` нового выпуска: что изменилось для читателя.
2. Обновите версию в шапках страниц, которые затронуты, и дату проверки; для остальных страниц версию менять не нужно, пока они остаются верными (проверьте их выборочно).
3. Обязательно сверьте:

| Страница | Что проверить |
| --- | --- |
| `Home` | версии сервера и приложения, статус |
| `Системные-требования` | пороги `preflight.sh`, версии ОС |
| `Возможности`, `Планы-развития` | новые функции и статусы, закрытые планы |
| `Границы-проверки` | числа тестов, новые проверки на реальной инфраструктуре |
| `Известные-проблемы` | закрытые проблемы, найденные расхождения |
| `Справочник-конфигурация` | сравнить с `.env.example` и `backend/app/config.py` |
| `Справочник-публичный-API` | сравнить с `/api/public/v1/openapi.json` |
| `Справочник-скрипты-и-команды` | заголовки скриптов в `scripts/` |
| `Справочник-приложение-для-Windows`, `Как-установить-приложение-для-Windows` | версия клиента, ссылки на выпуск |
| `Как-обновить-и-откатить` | поведение `update.sh` |
| `Как-подключить-календарь-Exchange`, `Как-пользоваться-календарём-Outlook`, `Как-подключить-надстройку-Outlook` | права Graph и EWS, правила согласия, ограничения повторов, гостевые ссылки |
| `Как-восстановить-материалы-после-переноса`, `Как-опубликовать-сервис-в-интернете` | формат `manifest.json`, правила доверия, перечень портов (`netrules.py`) |
| `Как-настроить-звук-и-видео-в-приложении-Windows` | пункты «Звук и видео», причины отказа микрофона, команды системных окон |
| `_Footer` | версия сервера и приложения, дата |

4. Запустите `python3 scripts/check_wiki.py` и исправьте ошибки.
5. После выпуска опубликуйте вики и откройте 3–4 страницы в браузере: названия и ссылки с кириллицей, таблицы, схема Mermaid на странице «Как устроена Peregovorka».

Документы `docs/` в репозитории остаются источником подробностей; вики описывает пути читателей и ссылается на них. Не дублируйте факты: исправляйте в одном месте.
