## 1. Из чего состоит система

| Служба compose | Что делает | Публикуется наружу | Данные |
| --- | --- | --- | --- |
| `web` | интерфейс, nginx: `/api`, `/livekit`, `/hls`, `/llhls` | `WEB_BIND_ADDR:WEB_PORT`, обычно `127.0.0.1` | — |
| `backend` | API, вход, встречи, протоколы, интеграции, фоновые задачи | нет | `DATA_ROOT/{recordings,exports,chat-files,avatars,branding,ca,live,ext,updater}` |
| `asr` | распознавание речи, подключается к встречам как участник | нет | `DATA_ROOT/models` (чтение), `recordings` |
| `livekit` | сервер звонков | `LIVEKIT_TCP_PORT/tcp`, `LIVEKIT_UDP_PORT/udp`; API только `127.0.0.1:LIVEKIT_HTTP_PORT` | — |
| `postgres` | база данных | нет | `DATA_ROOT/postgres` |
| `redis` | сессии, очереди, координация | нет | `DATA_ROOT/redis` |
| `livekit-egress` | запись и эфир, **по включению** | нет | `recordings`, `live`, временные файлы в `live/tmp` |
| `mediamtx` | низкая задержка эфира, вместе с `livekit-egress` | нет | — |
| `livekit-sip` | телефония, **по включению** | порты SIP и RTP | — |

Схема — [Как устроена Peregovorka](Как-устроена-Peregovorka), подробно — [Архитектура и техническое устройство](Архитектура-и-техническое-устройство). На одном сервере может работать несколько экземпляров с разными именами проекта и портами.

| Что | Где |
| --- | --- |
| Каталог установки: код, скрипты, `.env` | `APP_ROOT`, например `/opt/peregovorka`; найти: `docker compose ls` |
| Параметры и секреты | `APP_ROOT/.env`, права 600, [Справочник: конфигурация](Справочник-конфигурация) |
| Данные | `DATA_ROOT`, например `/srv/peregovorka-data`; всегда локальный диск |
| Резервные копии | `BACKUP_DIR`, по умолчанию `DATA_ROOT/backups` |
| Пакеты диагностики | `APP_ROOT/diagnostics` |
| Помощник обновлений | служба `peregovorka-updater-<проект>` |

## 2. Сеть

```
Пользователь ──443/tcp──► ваш reverse proxy (TLS) ──► [nginx хоста :NGINX_LISTEN_PORT] ──► web 127.0.0.1:WEB_PORT
Пользователь ──LIVEKIT_UDP_PORT/udp, LIVEKIT_TCP_PORT/tcp──► сервер (напрямую, мимо HTTP-прокси; за NAT — проброс без смены номера)
```

| Требование | Почему |
| --- | --- |
| DNS-имя и доверенный сертификат с **полной цепочкой** | без HTTPS браузер не даёт микрофон и экран; неполная цепочка ломает телефоны, Outlook и проверки сервера |
| Прокси передаёт WebSocket для `/livekit/` и `/api/v1/ws`, таймаут чтения от 1 часа, `X-Forwarded-Proto` | иначе встреча не подключается или рвётся |
| Адреса медиа: `LIVEKIT_NODE_IP` и `LIVEKIT_PUBLIC_IP` | LiveKit сообщает клиентам адреса; проверка — `scripts/medianet.sh check` |
| Порты медиа открыты от клиентов до сервера | UDP основной путь, TCP запасной |
| `APP_PUBLIC_URL` совпадает с адресом в браузере или он есть в `ALLOWED_ORIGINS` | иначе «Недопустимый Origin» |

**TURN и STUN.** STUN используется только для определения публичного адреса за NAT. Встроенный TURN установщик не настраивает. Клиенты, которым разрешён только исходящий 443/tcp через прокси, к медиа не подключатся.

Правила для межсетевого экрана по вашему `.env`: `scripts/ports.sh --format md`. Публикация в интернет — [Как опубликовать сервис в интернете](Как-опубликовать-сервис-в-интернете).

## 4. Установка

| Путь | Когда | Документ |
| --- | --- | --- |
| Одной командой `sudo ./install.sh` | чистый сервер, всё ставится само, самоподписанный сертификат | [Установка на чистый сервер](Установка-на-чистый-сервер) |
| Мастер `scripts/setup.sh --profile shared-host` | сервер с другими приложениями, есть Active Directory | [Установка на общий сервер](Установка-на-общий-сервер) |
| Вручную: `.env` и `scripts/install.sh` | закрытая сеть, нет каталога, особые требования | ниже |

### Установка вручную

1. Получите код выпуска: `git clone --depth 1 --branch vX.Y.Z https://github.com/calleograph/peregovorka.git /opt/peregovorka`.
2. Создайте настройки: `cp .env.example .env && chmod 600 .env`.
3. Задайте `COMPOSE_PROJECT_NAME`, `INSTALL_PROFILE`, `APP_PUBLIC_URL`, `APP_ROOT`, `DATA_ROOT`, **`BACKUP_DIR`** (`<DATA_ROOT>/backups`, иначе `backup.sh` не сможет писать), порты `WEB_PORT`, `LIVEKIT_HTTP_PORT`, `LIVEKIT_TCP_PORT`, `LIVEKIT_UDP_PORT`, `LIVEKIT_NODE_IP`, `LIVEKIT_PUBLIC_URL`.
4. Замените все значения `CHANGE_ME_…` случайными: `openssl rand -base64 32` для `APP_MASTER_KEY`, `openssl rand -hex 24` для остальных.
5. Если nginx хоста не нужен, задайте `NGINX_MANAGE=no`. LDAP можно оставить пустым и подключить каталог в браузере.
6. Посмотрите план: `scripts/install.sh --profile shared-host --dry-run`.
7. Установите ⚠: `scripts/install.sh --profile shared-host`. В закрытой сети добавьте `--models-from <каталог с файлами модели>`. Сбой этапа: повторите ту же команду или `--from <этап>`.
8. Создайте администратора: `scripts/bootstrap-admin.sh`. Пароль показывается один раз.
9. Настройте прокси и сертификат, затем выполните `scripts/smoke-test.sh`.

На тестовом экземпляре установка заняла около 40 минут, из них сборка образов около 22 минут. Без Buildx сборка идёт классическим сборщиком автоматически.

## 5. Повседневная работа

| Задача | Команда | Последствия |
| --- | --- | --- |
| Проверить состояние | `scripts/status.sh` | нет |
| Посмотреть журнал | `scripts/logs.sh <служба> --tail 200` | нет |
| Итоговая и сквозная проверка | `scripts/verify.sh`, `scripts/smoke-test.sh` | smoke создаёт и удаляет тестовую встречу |
| ⚠ Перезапустить службу | `scripts/ctl.sh restart <служба>` | [таблица последствий](Как-управлять-службами#перезапустить-одну-службу-) |
| ⚠ Применить изменения `.env` | [по типу параметра](Как-управлять-службами#применить-правку-env-) | как перезапуск |
| ⚠ Остановить всё | `scripts/ctl.sh stop` | система недоступна, идущая запись закрывается, данные сохраняются |
| ⚠ Запустить всё | `scripts/ctl.sh start` | контейнеры запускаются без сборки |
| Собрать пакет для поддержки | `scripts/diag.sh` | нет |
| ⚠ Резервная копия | `scripts/backup.sh` | база не блокируется; старые наборы удаляются ротацией |

Расписание: ежедневная копия базы, еженедельная копия файлов, ежемесячная проверка `scripts/check-updates.sh`, ежеквартальная проверка восстановления. Подробно — [Резервное копирование и аварийное восстановление](Резервное-копирование-и-аварийное-восстановление). Что наблюдать — [Мониторинг и журналы](Мониторинг-и-журналы).

## 6. Операции: последствия и проверка

| Операция | Остановка | Влияние на пользователей | Условия | Проверка | Документ |
| --- | --- | --- | --- | --- | --- |
| ⚠ Обновление | да, на время перезапуска, с миграциями дольше | встречи прерываются | свободное место, нет важных встреч | `report.txt`, `verify.sh`, `smoke-test.sh`, `/api/v1/version` | [Как обновить и откатить](Как-обновить-и-откатить) |
| ⚠ Откат | да | встречи прерываются | была предыдущая версия, нет новой миграции, иначе код 3 | `status.sh`, версия | там же |
| ⛔ Восстановление базы | `backend`, `asr`, `web` | недоступность; **данные после копии теряются** | решение владельца, тот же `APP_MASTER_KEY` | `status.sh`, вход, «История» | [Резервное копирование и аварийное восстановление](Резервное-копирование-и-аварийное-восстановление) |
| ⛔ Перенос на другой сервер | да | недоступность | та же версия на новом сервере | количества встреч и записей совпадают | там же, раздел 6 |
| ⚠ Смена адреса | `backend`, `web` | вход по старому адресу перестаёт работать | DNS, сертификат, прокси готовы | вход по новому адресу | [Как настроить сертификаты](Как-настроить-сертификаты) |

**Сохранность данных.** Штатные скрипты не удаляют `DATA_ROOT`, модели и тома и не выполняют `docker system prune` и `docker volume prune`. PostgreSQL и Redis лежат в каталогах сервера, поэтому пересоздание контейнера их не трогает. `update.sh` при нехватке места чистит кэш сборки и образы без тега: на общем сервере это затрагивает весь Docker, см. [Справочник: скрипты и команды](Справочник-скрипты-и-команды#чего-скрипты-не-делают-никогда).

## 7. Если что-то сломалось

1. **Сохраните сведения:** `scripts/diag.sh` и текст ошибки.
2. **Найдите компонент:** `scripts/status.sh`, затем `scripts/logs.sh <служба> --tail 300` и `scripts/verify.sh`.
3. **Выберите минимальное действие:** перезапуск одной службы, правка `.env`, `sudo scripts/models.sh`. Только потом обновление, откат или восстановление.
4. **Проверьте:** `status.sh`, `smoke-test.sh`, встреча двух участников.
5. **Запишите** в паспорт экземпляра, что случилось и что сделано.

Симптомы и решения — [Диагностика](Диагностика) и [Решение проблем](Решение-проблем). Порядок для первой линии — [Руководство технической поддержки](Руководство-технической-поддержки). Полный порядок при серьёзном сбое — [Сценарий: восстановление после сбоя](Сценарий-Восстановление-после-сбоя).
