# Как подключить почту

*Для кого: администратор.*

## Зачем это нужно

Через почтовый сервер организации Peregovorka отправляет материалы встреч и другие письма. Пока почта не настроена, материалы по почте не уходят.

## Когда пригодится

- Участники должны получать протоколы и стенограммы.
- Появился новый почтовый сервер или учётная запись.
- Письма перестали доходить.

## Что потребуется

- Роль администратора.
- Адрес и порт сервера SMTP, способ защиты.
- Учётная запись с правом отправки от имени выбранного отправителя. Для пересылки по адресу сервера она не нужна.
- Доступ с сервера Peregovorka до порта SMTP.
- Для внутреннего центра сертификации: его сертификат в [наборе CA](Как-настроить-сертификаты#добавить-сертификат-центра-для-ldaps-и-почты).

## Где найти

| Раздел | Что там |
| --- | --- |
| **Интеграции → Почта: сервер SMTP** | профили сервера, проверка, тестовое письмо |
| **Система → Почта: правила рассылки** | формат вложений, предел размера, повторы, разрешённые домены |
| **Система → Почта: шаблоны писем** | тексты писем |
| **Хранение и журналы → Почта: журнал отправки** | что и кому ушло, ошибки, повтор |

## Как это сделать

### Создать профиль

1. Откройте **Интеграции → Почта: сервер SMTP**.
2. Нажмите **＋ Добавить профиль**.
3. Заполните **Название**, **Сервер SMTP**, **Порт** и **Защита соединения**:
   - **STARTTLS (обычно порт 587)**;
   - **SSL/TLS (обычно порт 465)**;
   - **Без шифрования (порт 25, только внутри сети)**.
4. В блоке **Аутентификация** выберите **Способ**:
   - **Логин и пароль**;
   - **Без аутентификации (relay по адресу сервера)**;
   - **Windows NTLM (Microsoft Exchange)**.
5. Заполните **Адрес отправителя** и **Отображаемое имя**. Обычно это адрес `noreply@example.org`.
6. Оставьте включённым **Проверять сертификат сервера почты**. Если выключить, профиль будет отмечен «сертификат не проверяется».
7. Нажмите **Сохранить**. Пароль хранится зашифрованным и после сохранения не показывается.

Профилей может быть несколько. Письма отправляет активный, остальные резервные. **Сделать активным** переключает профиль.

### Проверить

1. Нажмите **Проверить соединение**. Этапы: DNS, подключение, защита, вход. При отказе показан текст ответа сервера.
2. Нажмите **Отправить тестовое письмо**, укажите свой адрес.

Тестовое письмо уходит сразу, минуя очередь.

### Exchange, который объявляет только NTLM

Если проверка пишет, что сервер предлагает только `NTLM`, посмотрите строку «Способы входа». Она показывает список до и после STARTTLS.

- Если после STARTTLS есть `LOGIN` или `PLAIN`, включите STARTTLS и оставьте **Логин и пароль**.
- Если остался только `NTLM`, выберите **Windows NTLM (Microsoft Exchange)**. Логин: `ДОМЕН\логин` или `логин@домен`. Способ работает только по защищённому соединению и только с NTLMv2.

Настройки почтового сервера менять не нужно. На настоящем Exchange этот путь не подтверждён.

### Задать правила рассылки

В **Система → Почта: правила рассылки**:

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| **Формат документов во вложении** | DOCX | DOCX, PDF, HTML или текст |
| **Максимальный размер вложений в письме** | 10 МБ | если больше, вместо вложений даётся ссылка на встречу, она открывается после входа |
| **Попыток отправки** | 4 | повторы при временной ошибке |
| **Пауза до первого повтора** | 5 минут | каждая следующая вдвое длиннее |
| **Хранить журнал отправки** | 90 дней | срок журнала |
| **Разрешённые домены получателей** | пусто, любые адреса | письма на другие домены не отправляются ни автоматически, ни вручную |

Запись аудио по почте не отправляется.

### Как уходят письма

Письма материалов идут через очередь и не задерживают работу страниц. Постоянная ошибка повторов не получает. Что и кому отправлять после встречи, задаёт руководитель комнаты: [Автоотправка материалов](Автоотправка-материалов).

## Что получится

- Тестовое письмо пришло.
- В **Обзор → Обзор** нет предупреждения о почте.
- После встречи письма видны в **Почта: журнал отправки** с результатом.

## Если не получается

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| Нет соединения | закрыт порт или неверный адрес | проверьте сеть с сервера |
| `550 … permissions to send as this sender` | у учётной записи нет права «Send As» | выдайте его на почтовом сервере |
| «способы входа, объявленные сервером: NTLM» | профиль с логином и паролем, сервер предлагает только NTLM | см. раздел выше |
| «NTLM-ответ не является NTLMv2» | сервер работает с устаревшим NTLMv1 | включите NTLMv2 на Exchange |
| Ошибка сертификата | сервер подписан внутренним центром | добавьте CA, не отключайте проверку без причины |
| Получатель помечен «в каталоге нет адреса» | в AD пустой атрибут `mail` | заполните атрибут |
| Письмо без вложений, но со ссылкой | документы больше предела | ожидаемо |
