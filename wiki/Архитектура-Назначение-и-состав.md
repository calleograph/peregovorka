# Архитектура: назначение и состав

*Для кого: администратор и инженер, впервые знакомящийся с продуктом.*

**Что получится:** вы понимаете, что делает Peregovorka, из каких частей состоит и за что отвечает каждая.

## Назначение

Peregovorka — система видеовстреч, которая разворачивается на сервере организации. Звук, видео, стенограммы и материалы остаются в её инфраструктуре. Подробно о подходе: [Что такое Peregovorka](Что-такое-Peregovorka).

Основные сценарии:

- совещание с автоматической стенограммой и протоколом;
- встреча с гостями по ссылке;
- конференция из календаря Outlook;
- массовая трансляция: выступающие в комнате, зрители по ссылке, параллельно на внешних площадках;
- переписка в корпоративных чатах;
- выгрузка материалов через публичный API и webhooks.

Полный перечень: [Возможности](Возможности).

## Состав серверной части

Один экземпляр — один проект Docker Compose. Все службы работают в контейнерах. На хосте — только необязательные nginx и помощник обновлений.

| Служба | Технология | Отвечает за | Не отвечает за |
|---|---|---|---|
| `web` | nginx, собранный React | статику, маршрутизацию `/api/`, `/livekit/`, раздачу HLS, источник для узлов CDN | бизнес-логику, TLS для зрителей за внешним прокси |
| `backend` | Python, FastAPI, SQLAlchemy | вход, права, комнаты, встречи, токены, настройки, стенограммы, протоколы, почту, аудит, API, фоновые задачи | передачу медиа |
| `livekit` | LiveKit Server | звук, видео, показ экрана | хранение, запись |
| `asr` | GigaAM, Silero VAD, PyTorch | распознавание речи, файлы участников | доступ к базе: только через Redis |
| `postgres` | PostgreSQL 16 | основная база | сессии и очереди |
| `redis` | Redis 7 | сессии, очереди, обмен с ASR, шина LiveKit и Egress | долговременное хранение |
| `livekit-egress` *(профиль `video`)* | LiveKit Egress | видеозапись, HLS, RTMP | авторизацию зрителей |
| `livekit-sip` *(профиль `sip`)* | LiveKit SIP | звонки через АТС | правила маршрутизации: они в backend |

На хосте:

| Компонент | Что делает | Обязателен |
|---|---|---|
| nginx хоста | TLS или промежуточный прокси, по одному site-файлу на проект | нет: можно использовать внешний прокси |
| `peregovorka-updater-<проект>` | служба systemd от root: выполняет обновление и обслуживание по запросу из администрирования | нет: без неё обновление запускается командой |

Отдельные серверы:

| Компонент | Что делает | Статус |
|---|---|---|
| Узел CDN | раздаёт эфиры зрителям: nginx и njs, служба systemd | реализовано с 0.66.0, см. [Узлы CDN](Узлы-CDN) |
| Языковая модель | формирует протоколы, резюме, карту разговора | подключается по API: OpenAI, Anthropic, любой OpenAI-совместимый сервер; встроенной модели нет |

## Клиенты

| Клиент | Системы | Как устроен |
|---|---|---|
| Браузер | актуальные Chrome и Edge; Firefox и Safari не проверялись | приложение React, отдаёт `web` |
| Приложение для Windows | Windows 10, 11 | Electron, EXE и MSI |
| Приложение для Linux | Ubuntu 22.04, 24.04, Debian 12, 13, x86_64 и ARM64 | Electron, пакет `.deb`, APT-репозиторий |
| Приложение для Android | Android 8 и новее | страницы сервера в WebView, конференция на LiveKit Android SDK |
| Надстройка Outlook | Outlook | панель внутри почтового клиента |

Точные версии — [Границы проверки](Границы-проверки) и страницы установки приложений. Приложения подключаются к серверу организации; внутри них работает тот же интерфейс, поэтому большинство новых функций не требует обновления приложения.

## Поддерживаемые системы сервера

Ubuntu 24.04 (рекомендуется), Ubuntu 22.04 и новее, Debian 12 и новее, x86_64. Узел CDN: Ubuntu 22.04, 24.04, 26.04, Debian 12, 13 на amd64 и arm64.

## Технологии

Python 3.12, FastAPI, SQLAlchemy, Alembic, PostgreSQL 16, Redis 7, LiveKit (WebRTC), React, TypeScript, Vite, nginx, Docker Compose, PyTorch, GigaAM, Silero VAD, Electron, Kotlin. Версии закреплены в `backend/app/components.json` и проверяются перед каждым выпуском: [Обновление](Как-обновить-и-откатить).

## Внешние интеграции

Каталог домена (LDAPS), почта (SMTP), файловые хранилища (SMB), языковые модели, Exchange и Outlook, АТС (SIP), Bitrix24, площадки трансляций (RTMP/RTMPS). Все необязательны: без них работает вход локального администратора, встречи и стенограмма. Подробно: [Каталог интеграций](Архитектура-Каталог-интеграций).
