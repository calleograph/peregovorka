# Архитектура: назначение и состав

*Для кого: администратор и инженер, впервые знакомящийся с продуктом.*

## Назначение

Peregovorka — система видеовстреч, которая разворачивается на сервере организации. Звук, видео, стенограммы и материалы остаются в её инфраструктуре. Подробно о подходе: [Что такое Peregovorka](Что-такое-Peregovorka).

Основные сценарии:

- совещание с автоматической стенограммой и протоколом;
- встреча с гостями по ссылке;
- конференция из календаря Outlook;
- трансляция: выступающие в комнате, зрители по ссылке, параллельно на внешних площадках;
- переписка в корпоративных чатах;
- выгрузка материалов через публичный API и webhooks.

Полный перечень: [Возможности](Возможности).

## Состав серверной части

Один экземпляр — один проект Docker Compose. Все службы работают в контейнерах. На хосте работают только необязательные nginx и помощник обновлений.

Это единая таблица служб. Другие страницы вики на неё ссылаются и состав не повторяют.

| Служба | Запуск | Технология | Отвечает за | Не отвечает за |
|---|---|---|---|---|
| `web` | всегда | nginx, собранный React | статику, маршрутизацию `/api/` и `/livekit/`, раздачу HLS с диска, прокси `/llhls/` к MediaMTX, проверку подписи зрителя, источник `/cdn-origin/` для узлов CDN | бизнес-логику; TLS, если перед ним стоит прокси |
| `backend` | всегда | Python 3.12, FastAPI, SQLAlchemy | вход, права, комнаты, встречи, токены, настройки, стенограммы, протоколы, почту, аудит, API, фоновые задачи, выдачу подписанных ссылок зрителям | передачу медиа и сегментов эфира |
| `livekit` | всегда | LiveKit Server (SFU) | звук, видео, показ экрана, просмотр эфира по WebRTC | хранение, запись |
| `asr` | всегда | GigaAM, Silero VAD, PyTorch | распознавание речи, запись дорожек участников | работу с базой: служба к ней не обращается. Пароль базы всё же есть в её окружении: `compose.yml` передаёт общий блок переменных |
| `postgres` | всегда | PostgreSQL 16 | основную базу | сессии и очереди |
| `redis` | всегда | Redis 7 | сессии, очереди, обмен с ASR, шину LiveKit, SIP и Egress | долговременное хранение |
| `livekit-egress` | профиль `video` | LiveKit Egress: Chrome и кодировщик | видеозапись, эфир: выходы MP4, HLS, RTMP на площадки, внутренний RTMP в MediaMTX | авторизацию зрителей |
| `live-relay` | профиль `video` | тот же образ, что у `backend` | Ретрансляция на внешние площадки: по процессу `ffmpeg -c copy` на площадку, поток читается из `mediamtx`. Сбой одной площадки не касается эфира, записи и других площадок | `mediamtx`, площадки |
| `mediamtx` | профиль `lowlat` | MediaMTX | LL-HLS: делает эфир с низкой задержкой из внутреннего RTMP без перекодирования | запись, площадки: падение службы их не затрагивает |
| `livekit-sip` | профиль `sip` | LiveKit SIP | звонки через АТС | правила маршрутизации: они в `backend` |

Профиль `sip` включается при `SIP_ENABLED=yes`. Профиль `video` включается при `VIDEO_ENABLED=yes`. Профиль `lowlat` добавляется только вместе с `video`, когда образ MediaMTX уже лежит на сервере. Если образа нет, эфиры идут обычным HLS.

На хосте:

| Компонент | Что делает | Обязателен |
|---|---|---|
| nginx хоста | TLS или промежуточный прокси, по одному site-файлу на проект | нет: можно использовать внешний прокси |
| `peregovorka-updater-<проект>` | служба systemd от root: выполняет обновление и обслуживание по запросу из администрирования | нет: без неё те же действия запускаются командой |

Отдельные серверы:

| Компонент | Что делает | Статус |
|---|---|---|
| Узел CDN | раздаёт эфиры зрителям: nginx и njs, служба systemd | см. [Узлы CDN](Узлы-CDN) |
| Языковая модель | формирует протоколы, резюме, карту разговора | подключается по API: OpenAI, Anthropic, любой OpenAI-совместимый сервер; встроенной модели нет |

## Клиенты

| Клиент | Системы | Как устроен |
|---|---|---|
| Браузер | актуальные Chrome и Edge; Firefox и Safari не проверялись | приложение React, его отдаёт `web` |
| Приложение для Windows | Windows 10, 11 | Electron, EXE и MSI |
| Приложение для Linux | Ubuntu 22.04, 24.04, Debian 12, 13, x86_64 и ARM64 | Electron, пакет `.deb`, репозиторий APT |
| Приложение для Android | Android 8.0 и новее, предварительная версия | страницы сервера в WebView, конференция на LiveKit Android SDK |
| Надстройка Outlook | Outlook | панель внутри почтового клиента |

Что из этого проверялось: [Границы проверки](Границы-проверки). Различия клиентов: [Веб-версия и приложения](Веб-версия-и-приложения). Приложения подключаются к серверу организации, внутри них работает тот же интерфейс, поэтому большинство новых функций не требует обновления приложения.

## Поддерживаемые системы сервера

Установщик принимает Ubuntu начиная с 22 и Debian начиная с 12. Рекомендуется Ubuntu 24.04. Для производных дистрибутивов гарантий нет. Другая архитектура, кроме x86_64, даёт предупреждение проверки, а не отказ, и не проверялась. Что из этого реально проверено: [Системные требования](Системные-требования#поддерживаемые-системы-сервера).

Узел CDN: Ubuntu 22.04, 24.04, 26.04, Debian 12, 13 на amd64 и Ubuntu 24.04 на arm64.

## Технологии

Python 3.12, FastAPI, SQLAlchemy, Alembic, PostgreSQL 16, Redis 7, LiveKit (WebRTC), MediaMTX, React, TypeScript, Vite, nginx, Docker Compose, PyTorch, GigaAM, Silero VAD, Electron, Kotlin. Версии закреплены в `backend/app/components.json` и проверяются перед выпуском: [Как обновить и откатить](Как-обновить-и-откатить).

## Внешние интеграции

Каталог домена (LDAPS), почта (SMTP), файловые хранилища (SMB), языковые модели, Exchange и Outlook, АТС (SIP), Bitrix24, площадки трансляций (RTMP и RTMPS). Все необязательны: без них работают вход локального администратора, встречи и стенограмма. Подробно: [Каталог интеграций](Архитектура-Каталог-интеграций).
