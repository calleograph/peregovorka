# Справочник: скрипты и команды

*Для кого: администратор сервера.*

Скрипты лежат в `scripts/` каталога установки (по умолчанию `/opt/peregovorka`) и работают **только с текущим экземпляром** (`COMPOSE_PROJECT_NAME`). Параметр `--env ФАЙЛ` выбирает другой файл `.env`. Вывод Docker проходит через маскирование секретов.

Обозначения: ⚠ — команда меняет конфигурацию, контейнеры или данные; ⛔ — заменяет или удаляет данные. Без знака — только чтение.

**Когда нужен `sudo`.** `.env` имеет режим 600. После установки одной командой он принадлежит root, поэтому там запускайте всё через `sudo`. На общем сервере, где `.env` принадлежит вашему пользователю из группы `docker`, `sudo` обязателен для `video.sh`, `sip.sh`, `volumes.sh`, `repair.sh`, `tune-kernel.sh --apply`, `updater.sh install`; `medianet.sh` требует только права записи в `.env`.

## Установка и подготовка

| Скрипт | Назначение | Параметры |
| --- | --- | --- |
| ⚠ `install.sh` в корне | установка одной командой на чистый сервер | `--host`, `--https-port`, `--dir`, `--data`, `--ref`, `--skip-models`, `--yes` |
| ⚠ `scripts/setup.sh` | мастер первой установки: вопросы, подбор портов, секреты, план | `--profile`, `--env-only`, `--auto`, `--host`, `--https-port`, `--name`, `--data`, `--skip-models`, `--public-ip` |
| `scripts/preflight.sh` | проверка сервера и конфигурации | `--profile`, `--phase pre\|post`, `--skip-network`, `--probe-build` |
| `scripts/prereq.sh` | проверка системных программ и Docker, для обоих профилей | `--check`, `--list`, `--profile standalone\|shared-host` |
| ⚠ `scripts/prereq.sh --install` | ставит недостающее; на `shared-host` Docker и nginx не ставит | `--profile` |
| ⚠ `scripts/install.sh` | установка по этапам, повторный запуск безопасен | см. ниже |
| ⚠ `scripts/models.sh` | подготовка модели распознавания | `--model`, `--from-dir`, `--skip-full` |
| ⚠ `scripts/bootstrap-admin.sh` | создаёт локального администратора, пароль показывается один раз | `--username` |
| ⚠ `scripts/admin-reset.sh` | новый пароль администратора, завершение его сеансов, снятие блокировки, запись в аудит | `--username`, `--create`, `--yes` |
| ⚠ `scripts/security-reset.sh` | аварийно выключает ограничение по доверенным подсетям, список сетей сохраняется | `--unblock-all`, `--yes` |
| `scripts/tune-kernel.sh` | показывает параметры ядра | — |
| ⚠ `scripts/tune-kernel.sh --apply` | применяет их для всего сервера; на `shared-host` всегда спрашивает подтверждение | `--yes` только на `standalone` |

### Параметры `scripts/install.sh`

Этапы: `prerequisites → preflight → dirs → kernel → models → pull → build → database → migrations → services → healthcheck → nginx → firewall → verify → helper → report`.

| Параметр | Когда нужен | Последствия |
| --- | --- | --- |
| `--profile` | всегда, если профиля нет в `.env` | `standalone` ставит программы и меняет параметры ядра, `shared-host` нет |
| `--dry-run` | посмотреть план | ничего не меняет |
| `--from ЭТАП` | продолжить с нужного этапа | предыдущие этапы пропускаются, следующие выполняются |
| `--force-build` | пересобрать образы | дольше |
| `--adopt-images` | образы проекта собраны вручную, и вы принимаете их как актуальные | сборка пропускается; ответственность за версию образов на вас |
| `--skip-preflight` | проверка ошибочно мешает, причину вы понимаете | проблемы сервера всплывут позже |
| `--skip-models` | модель подготовите позже | звонки работают, стенограммы нет |
| `--models-from КАТАЛОГ` | закрытая сеть | модель копируется из каталога с файлами |
| `--skip-admin` | администратора создадите сами | первичного пароля не будет |
| `--skip-start` | нужны только образы | запуск, nginx и последующие этапы не выполняются |
| ⚠ `--configure-firewall` | хотите открыть медиапорты через `ufw` | добавляет два правила `ufw allow`: TCP и UDP порты LiveKit. Без параметра межсетевой экран не меняется |

## Эксплуатация

| Скрипт | Назначение | Параметры |
| --- | --- | --- |
| `scripts/status.sh` | состояние служб. Код 0 — шесть основных служб здоровы, а также `livekit-egress` и `livekit-sip`, если включены. `mediamtx` на итог не влияет | `--wait СЕК` |
| `scripts/logs.sh` | журналы `postgres redis livekit backend asr web livekit-sip livekit-egress mediamtx`; секреты маскируются | `-f`, `--tail N` (200) |
| `scripts/ctl.sh status` | то же, что `status.sh` | — |
| ⚠ `scripts/ctl.sh restart [служба…]` | пересоздать контейнеры по `.env` без сборки. **Без имени — все контейнеры, встречи и эфиры прерываются** | имена служб как у `logs.sh` |
| ⚠ `scripts/ctl.sh stop [служба…]` | остановить контейнеры, данные остаются. Egress получает до 60 с на закрытие файла | те же |
| ⚠ `scripts/ctl.sh start [служба…]` | запустить без сборки; пересоздаёт контейнеры с изменённой конфигурацией | те же |
| `scripts/verify.sh` | итоговая проверка; FAIL — код 1, WARN — 0 | — |
| `scripts/smoke-test.sh` | сквозная проверка, создаёт и удаляет тестовую встречу; `Smoke test: PASS` | `--login ЛОГИН`, `--no-public` |
| `scripts/diag.sh` | диагностический пакет без секретов, включая журналы всех служб | `--out`, `--tail`, `--no-public` |
| `scripts/ports.sh` | перечень портов по `.env` | `--format text\|md\|csv\|json\|request`, `--out`, `--live` |
| `scripts/asr-bench.sh` | подбор потоков ASR; загружает вторую копию модели | `--wav`, `--threads`, `--interop`, `--repeat`, `--seconds`, `--synthetic` |
| `scripts/collect-metrics.sh` | запись нагрузки на время приёмки | `--minutes`, `--interval`, `--out` |

Порядок управления службами и последствия — [Как управлять службами](Как-управлять-службами).

## Дополнительные службы и сеть

| Скрипт | Назначение | Последствия |
| --- | --- | --- |
| `scripts/video.sh status` | состояние видеоподсистемы | нет |

| ⚠ `scripts/video.sh disable [--yes]` | выключает Egress и MediaMTX | идущие записи и эфиры закрываются, меняет `.env`; LiveKit перезапускается, если телефония выключена |
| `scripts/sip.sh status` | состояние телефонии | нет |
| ⚠ `scripts/sip.sh enable\|disable [--yes]` | включает и выключает телефонию | меняет `.env`, порты SIP/RTP, перезапускает LiveKit |
| `scripts/sip.sh firewall` | показывает правила `ufw` для адресов АТС | нет |
| ⚠ `scripts/sip.sh firewall --apply` | создаёт эти правила | меняет `ufw` |
| `scripts/medianet.sh check [--json]` | адреса, порты, NAT; с `sudo` ещё межсетевой экран | нет |
| ⚠ `scripts/medianet.sh apply [--public-ip auto\|off\|IPv4]` | пересчитывает адреса | меняет `.env`, перезапускает `livekit` и `backend`, звонки прерываются |
| ⚠ `scripts/medianet.sh ports --tcp N --udp N` | меняет порты медиа | меняет `.env`, перезапускает `livekit` и `backend`. Межсетевой экран и проброс меняйте заранее |
| `scripts/volumes.sh list` | состояние внешних томов | нет |
| ⚠ `scripts/volumes.sh attach ПУТЬ` | открывает каталог приложению | см. [Внешние тома](Внешние-тома) |
| ⚠ `scripts/volumes.sh detach ИД` | снимает подключение, данные на ресурсе остаются | запись в это хранилище останавливается |
| ⚠ `scripts/volumes.sh reconcile` | сверяет подключения с монтированием | помощник делает это сам каждые 15 с |

## Исправления

`sudo scripts/repair.sh --scan` ищет известные проблемы и ничего не меняет. Код 1 значит, что проблемы найдены. `scripts/repair.sh --list` выводит идентификаторы. ⚠ `sudo scripts/repair.sh ИД` выполняет одно исправление, предварительно проверив, что проблема есть.

| ИД | Что делает | Последствия |
| --- | --- | --- |
| `data_dirs` | создаёт недостающие каталоги данных, назначает владельца | меняет права в `DATA_ROOT` |
| `nginx_site` | обновляет свой сайт nginx, с проверкой и откатом | перезагрузка nginx |
| `sysctl` | применяет параметры ядра, только `standalone` | влияет на весь сервер |
| `prereq_missing` | ставит недостающие программы, только `standalone` | установка пакетов |
| `deploy_incomplete` | завершает прерванное развёртывание той же версии | как обновление, встречи прерываются |
| `image_commit` | пересобирает образы без сведений о версии | сборка, перезапуск служб |
| `migrations` | делает копию базы и применяет миграции | меняет схему базы |
| `reverify` | запускает полную проверку | тестовая встреча, данные не меняются |
| `sip_enable`, `sip_disable` | запускает или останавливает телефонию | как `sip.sh` |

## Обновление, откат, копии

| Скрипт | Назначение | Параметры |
| --- | --- | --- |
| `scripts/check-updates.sh` | что вышло нового | — |
| ⚠ `scripts/update.sh` | штатное обновление | см. [Как обновить и откатить](Как-обновить-и-откатить) |
| ⚠ `scripts/deploy.sh` | устарел, обёртка над `update.sh` | те же |
| ⚠ `scripts/rebuild.sh` | пересборка образов тем же способом, что `update.sh` | `--if-changed`, `--pull`, `--no-restart`, `--wait`, `backend`, `asr`, `web`, `livekit` |
| ⚠ `scripts/rollback.sh` | возврат кода и образов, база не откатывается | `--to SHA`, `--yes`, `--dry-run`, `--wait` |
| ⚠ `scripts/backup.sh` | дамп базы и проверка `pg_restore --list`; старые наборы удаляет ротация | `--keep N` (14), `--with-env`, `--with-recordings`, `--full`, `--label` |
| ⛔ `scripts/restore.sh ДАМП` | заменяет базу копией, сначала страховочный дамп | `--files АРХИВ`, `--yes` |

`backup.sh --full` равен `--with-env --with-recordings`. `restore.sh --files` заменяет каталоги файлов и откладывает прежние.

## Помощник обновлений

| Команда | Что делает |
| --- | --- |
| `scripts/updater.sh status` | работает ли помощник и что выполняет |
| `scripts/updater.sh verify` | проверяет службу, процесс и связь |
| `scripts/updater.sh check` | разовая сверка с репозиторием |

## Коды возврата

| Скрипт | Код | Значение |
| --- | --- | --- |
| `update.sh` | `0` | всё в порядке |
| `update.sh` | `3` | обновление выполнено, интеграции требуют внимания |
| `update.sh` | `1` | остановка или сбой |
| `rollback.sh` | `3` | откат остановлен: новая схема БД неизвестна целевой версии кода |
| `smoke-test.sh` | `0` / `3` / `1` | ошибок нет / работает, но есть проблема внешнего окружения / сбой системы |
| `verify.sh`, `status.sh` | `1` | есть FAIL или нездоровая служба |
| `diag.sh` | `2` | найдено значение секрета, архив не создан |
| `ports.sh` | `2` | нет `.env` или неверные аргументы |

## Чего скрипты не делают никогда

`apt upgrade`, `dist-upgrade`, `autoremove`, перезагрузка; `docker system prune`, `docker volume prune`; остановка и перезапуск чужих контейнеров; правка чужих файлов nginx, Apache, PHP; удаление `DATA_ROOT` и моделей; пересоздание каталога PostgreSQL; перезапись `.env`; `git reset --hard`.

Одно исключение касается общего кэша Docker. При нехватке места `update.sh` выполняет `docker builder prune` и `docker image prune -f`. Эти команды действуют на весь сервер: удаляются образы без тега и неиспользуемый кэш сборки других проектов. Чужие образы с тегом и тома не удаляются. Отключить очистку: `UPD_DISK_MAINTENANCE=0`.
