# Справочник: скрипты и команды

Все скрипты лежат в `scripts/` каталога проекта (по умолчанию `/opt/peregovorka`) и работают **только с текущим экземпляром** (`COMPOSE_PROJECT_NAME`). Параметр `--env FILE` задаёт другой файл `.env`. Любой скрипт, который печатает вывод Docker, маскирует секреты.

## Установка и подготовка

| Скрипт | Назначение | Основные параметры |
| --- | --- | --- |
| `install.sh` (в корне) | установка одной командой на чистый сервер | `--host`, `--https-port`, `--dir`, `--data`, `--ref`, `--skip-models`, `--yes` |
| `scripts/setup.sh` | мастер первой установки (`shared-host` и `standalone`): вопросы, подбор портов, генерация секретов, план | `--profile`, `--env-only` |
| `scripts/preflight.sh` | проверка хоста и конфигурации, **ничего не меняет** | `--phase post`, `--profile` |
| `scripts/prereq.sh` | проверка и установка системных зависимостей | `--check`, `--profile standalone\|shared-host` |
| `scripts/install.sh` | установка по этапам, повторный запуск безопасен | `--profile`, `--dry-run`, `--from ЭТАП`, `--force-build`, `--adopt-images`, `--skip-preflight`, `--skip-models`, `--models-from КАТАЛОГ`, `--skip-admin`, `--skip-start`, `--configure-firewall` |
| `scripts/models.sh` | подготовка моделей распознавания и локальной LLM | `--model`, `--from-dir`, `--llm`, `--llm-only`, `--soft`, `--force`, `--check`, `--skip-full` |
| `scripts/bootstrap-admin.sh` | создаёт локального администратора и показывает первичный пароль один раз | `--username` |
| `scripts/security-reset.sh` | аварийное выключение ограничения по доверенным подсетям (список сетей сохраняется) и, с `--unblock-all`, снятие блокировок адресов; без веб-интерфейса, запись в аудит | `--unblock-all`, `--yes` |
| `scripts/admin-reset.sh` | восстановление доступа локального администратора: новый пароль, завершение сеансов, сброс блокировки, запись в аудит | `--username`, `--create`, `--yes` |
| `scripts/tune-kernel.sh` | показывает рекомендуемые параметры ядра; применяет с подтверждением | `--apply` |

Этапы установки: `prerequisites → preflight → dirs → kernel → models → pull → build → database → migrations → services → healthcheck → nginx → firewall → verify → helper → report`.

## Эксплуатация

| Скрипт | Назначение | Основные параметры |
| --- | --- | --- |
| `scripts/status.sh` | состояние и health сервисов; код 0 — все `running` и `healthy` | `--wait СЕК` |
| `scripts/logs.sh` | журналы сервисов `postgres redis livekit backend asr web` | `-f`, `--tail N` |
| `scripts/ctl.sh` | `status`, `restart`, `stop`, `start` сервисов своего проекта; данные не удаляются | `[сервис …]` |
| `scripts/verify.sh` | итоговая проверка, только чтение; FAIL — код 1, WARN — 0 | — |
| `scripts/smoke-test.sh` | сквозная проверка с итоговой таблицей; заканчивается `Smoke test: PASS` | `--login ЛОГИН`, `--no-public` |
| `scripts/diag.sh` | диагностический пакет без секретов | `--out`, `--tail` |
| `scripts/asr-bench.sh` | подбор потоков ASR по задержке | `--wav`, `--threads`, `--interop`, `--repeat`, `--synthetic`, `--concurrency` |
| `scripts/collect-metrics.sh` | запись нагрузки сервера на время приёмочного теста | `--minutes`, `--interval`, `--out` |
| `scripts/sip.sh` | `enable`, `disable`, `status`, `firewall [--apply]` для телефонии | `--yes` |
| `scripts/ports.sh` | перечень сетевых портов и правил межсетевого экрана по `.env`; работает без Docker и веб-интерфейса, ничего не меняет и не открывает | `--env`, `--format text\|md\|csv\|json\|request`, `--out`, `--live` |
| `scripts/repair.sh` | «Исправить автоматически» из терминала | `--scan` и выбор исправления |
| `scripts/updater.sh` | помощник обновлений: `run`, `check`, `install`, `status`, `print-unit`, `uninstall` | `--yes` |

## Обновление, откат, копии

| Скрипт | Назначение | Основные параметры |
| --- | --- | --- |
| `scripts/check-updates.sh` | что нового вышло; ничего не меняет | — |
| `scripts/update.sh` | штатное обновление | `--dry-run`, `--yes`, `--ref`, `--pull`, `--force-build`, `--no-backup`, `--skip-models`, `--no-nginx`, `--skip-smoke`, `--skip-netcheck`, `--wait`, `--stash` |
| `scripts/deploy.sh` | устарел, обёртка над `update.sh` | те же |
| `scripts/rebuild.sh` | пересборка образов тем же способом, что `update.sh` | `--if-changed`, `--pull`, `--no-restart`, `--wait`, `backend`, `asr`, `web`, `livekit` |
| `scripts/rollback.sh` | возврат кода и образов (не базы) | `--to SHA`, `--yes`, `--dry-run` |
| `scripts/backup.sh` | дамп PostgreSQL (`pg_dump -Fc`) | `--keep N`, `--with-env`, `--with-recordings`, `--label` |
| `scripts/restore.sh` | восстановление БД из дампа с подтверждением и страховочным дампом | `--yes` |

Подробные сценарии: [Как обновить и откатить](Как-обновить-и-откатить), [Как сделать резервную копию и перенести сервер](Как-сделать-резервную-копию-и-перенести-сервер).

## Коды возврата

| Скрипт | Код | Значение |
| --- | --- | --- |
| `update.sh` | `0` | всё в порядке |
| `update.sh` | `3` | обновление выполнено, интеграции требуют внимания |
| `update.sh` | `1` | остановка или сбой |
| `rollback.sh` | `3` | откат остановлен: новая схема БД неизвестна целевой версии кода |
| `verify.sh` | `1` | есть FAIL |

## Чего скрипты не делают никогда

`apt upgrade`, `dist-upgrade`, `autoremove`, перезагрузка; `docker system prune`, `docker volume prune`; остановка и перезапуск чужих контейнеров; правка чужих файлов nginx, Apache, PHP; удаление `DATA_ROOT` и моделей; пересоздание тома PostgreSQL; перезапись `.env`; `git reset --hard`.
