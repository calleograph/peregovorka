# Как настроить видеозапись и трансляции на сервере

*Для кого: администратор сервера.*

## Зачем это нужно

Видеозапись встреч и прямые эфиры выполняет одна служба, `livekit-egress`. Внутри неё работает браузер, который смотрит комнату и кодирует видео. Служба `mediamtx` снижает задержку для зрителей. По умолчанию обе выключены.

Как запускает запись пользователь, описано в [Как записать видео встречи](Как-записать-видео-встречи). Эта страница про сервер: включение, место на диске, ограничения и выключение.

## Когда пригодится

- В комнатах нужна видеозапись или эфиры.
- Планируется длинный эфир и нужно рассчитать диск.
- Запись остановилась из-за нехватки места.
- Нужно отключить функцию на сервере.

## Что потребуется

- Роль администратора. Для команд: `sudo`.
- Помощник обновлений для кнопок в браузере. Проверка: `sudo scripts/updater.sh status`.
- Доступ сервера к реестрам образов. Закрытая сеть: параметр `IMAGE_MIRRORS` ([Справочник: конфигурация](Справочник-конфигурация)).
- Свободное место по расчёту ниже.

Сколько одновременных записей и эфиров выдержит ваш сервер, эта страница не утверждает: см. [Производительность и масштабирование](Производительность-и-масштабирование).

## Где найти

- **Администрирование → Интеграции → Видеозапись**: служба, пределы, хранение файлов.
- **Администрирование → Интеграции → Трансляции**: включение эфиров, площадки, низкая задержка, диагностика.

## Рассчитать место на диске

Файл записи проходит два этапа. Пока идёт эфир или запись, он лежит в `DATA_ROOT/live/tmp`. В конце задания он копируется в `DATA_ROOT/recordings`, и лишь затем файл из `live/tmp` исчезает.

**Каталог `DATA_ROOT` должен быть на локальном диске.** `live/tmp` нельзя выносить на сетевой ресурс: службе нужен локальный сокет. В файловое хранилище уходит только готовая запись.

| Что считаем | Значение | Статус и условия |
| --- | --- | --- |
| Эфир 1080p, `live/tmp` | около 2,2 ГБ в час | Проверено в ограниченном сценарии: один эфир 2 часа, синтетические выступающие |
| Копия в `recordings` | столько же, около 2,2 ГБ в час | Расчётная оценка: копия равна файлу |
| Образ Egress на диске Docker | около 3,8 ГБ | Проверено в ограниченном сценарии: измерено на одной установке |
| Другие качества и запись обычной встречи | см. подсказку у поля качества | Значения приблизительные, зависят от содержимого кадра |

Пример для самой длинной записи. Эфир 1080p на 3 часа, `live/tmp` и `recordings` на одном диске: 3 × 2,2 + 3 × 2,2 = 13,2 ГБ, плюс запас 1 ГБ, итого около 14 ГБ. Это расчётная оценка. Одновременные эфиры и записи складывайте.

Защита от переполнения работает так:

- Новая запись или эфир не начинаются, если свободно меньше порога. Поля **Не начинать запись, если свободно меньше** и **Не начинать эфир, если свободно меньше**, по умолчанию 10 ГБ. Этот порог проверяется только при запуске. Идущие запись и эфир сервер останавливает по своему запасу, чтобы успеть закрыть файл.
- Во время работы сервер сравнивает свободное место с размером `live/tmp` плюс 1 ГБ. Если места меньше, **все** идущие эфиры и записи останавливаются заранее, чтобы файл успел закрыться. Причина видна администратору: «На диске сервера заканчивается место».

Проверить место:

```bash
df -h /srv/peregovorka-data
sudo du -sh /srv/peregovorka-data/live/tmp /srv/peregovorka-data/recordings
```

## Как это сделать

### Включить службу ⚠

**Назначение.** Скачать образы и запустить `livekit-egress` и `mediamtx`.

**Условия.** Свободно не меньше 8 ГБ на томе данных: иначе скрипт откажет. Идущие звонки на несколько секунд прервутся, поэтому выбирайте время без важных встреч.

**Порядок в браузере.**

1. Откройте **Интеграции → Видеозапись**.
2. Нажмите **Установить и включить** и прочитайте окно с последствиями.
3. Подтвердите. Ход виден на странице.

**Порядок в терминале.**

```bash
cd /opt/peregovorka
sudo scripts/video.sh enable
```

Скрипт спросит подтверждение. Без терминала добавьте `--yes`.

**Последствия.** В `.env` записываются `VIDEO_ENABLED=yes` и служебная строка `LIVEKIT_REDIS_LINE`. Скачиваются образы, запускается `mediamtx`, перезапускается `livekit`, запускается `livekit-egress`. Портов наружу эти службы не открывают. Межсетевой экран и nginx не меняются.

Если образ `mediamtx` не скачался, включение не останавливается: зрители будут смотреть обычный поток.

### Разрешить функции в приложении

Служба на сервере ещё не включает запись в комнатах.

1. **Интеграции → Видеозапись**: включите **Включить видеозапись встреч**, задайте пределы, нажмите сохранение.
2. **Интеграции → Трансляции**: включите **Включить трансляции** и задайте пределы.

| Поле | Значение по умолчанию | На что влияет |
| --- | --- | --- |
| **Одновременных записей на сервере** | 2 | лишние записи не начнутся |
| **Предел одной записи** | 6 часов | дальше файл закрывается, запись продолжается новым фрагментом |
| **Общий объём видеозаписей** | 0, без предела | при достижении новые записи не начинаются, старые не удаляются |
| **Где хранить готовые видеозаписи** | как аудиозаписи | см. [Подключение внешних хранилищ](Подключение-внешних-хранилищ) |
| **Одновременных эфиров на сервере** | 1 | лишние эфиры не начнутся |
| **Не начинать эфир при нагрузке Egress от** | 85 % | проверка только при запуске, идущий эфир она не останавливает |

Предельная длительность испытана до 2 часов на эфире. Более длинные записи и эфиры не подтверждены испытаниями.

### Настроить низкую задержку ⚠

Настройки в **Интеграции → Трансляции**.

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| **Низкая задержка для зрителей (LL-HLS)** | включено | нужна работающая служба `mediamtx` |
| **Зрителей с низкой задержкой, не больше** | 300 | остальные смотрят обычный поток |
| **Зрителей по WebRTC, не больше** | 0, выключено | зрителю нужен доступ к портам сервера звонков |
| **Автоматически переходить на «только звук» при плохой связи** | включено | зритель с низкой задержкой выбирает качество сам (**Авто**, **Высокое**, **Низкое 360p**, **Только звук**); в режиме **Авто** при слабой связи он идёт на ступень ниже и возвращается, когда связь наладилась. Дорожки готовятся только пока идёт эфир с низкой задержкой и работает служба `live-relay`. Звук не перекодируется. Низкое качество перекодируется только пока им кто-то пользуется: около одного ядра процессора на эфир, с пониженным приоритетом, процесс останавливается через 1,5 минуты после последнего зрителя |

Safari, iPhone и узлы CDN смотрят обычный поток. Комната с раздачей через CDN низкую задержку не получает.

Безопасный предел для WebRTC-зрителей не определён: они создают нагрузку на сервер звонков и исходящий канал. Включайте малыми значениями и следите за [панелью диагностики эфира](Панель-диагностики-эфира). Порты для таких зрителей — [Справочник: порты и сеть](Справочник-порты-и-сеть#трансляции).

Цифры задержки и условия замеров — [Производительность и требования к серверу для трансляций](Производительность-и-требования-к-серверу-для-трансляций).

### Проверить состояние

Операция только читает данные.

```bash
sudo scripts/video.sh status
sudo scripts/status.sh
sudo scripts/logs.sh livekit-egress --tail 200
```

`video.sh status` показывает, включена ли подсистема, какой образ, сколько свободно и работает ли контейнер.

### Перезапустить службу ⚠

**Интеграции → Видеозапись → Перезапустить службу** или:

```bash
sudo scripts/ctl.sh restart livekit-egress
sudo scripts/ctl.sh restart mediamtx
```

Перезапуск `livekit-egress` закрывает идущие записи и эфиры, записанная часть сохраняется. Звонки не прерываются. Кнопка в браузере пересоздаёт только `livekit-egress`. Служба `mediamtx` перезапускается командой. Подробно — [Как управлять службами](Как-управлять-службами).

### Выключить ⚠

**Условия.** Идущие записи и эфиры будут остановлены. Убедитесь, что их нет.

**Порядок.** Кнопка **Выключить** в **Интеграции → Видеозапись** или:

```bash
sudo scripts/video.sh disable
```

**Последствия.**

- `livekit-egress` и `mediamtx` останавливаются, на закрытие файла есть до 60 секунд, контейнеры удаляются.
- В `.env` записывается `VIDEO_ENABLED=no`.
- Если телефония не включена, служебная строка `LIVEKIT_REDIS_LINE` очищается, и `livekit` перезапускается: звонки прервутся на несколько секунд.
- Готовые записи, настройки комнат и образы остаются.

## Что получится

- `sudo scripts/video.sh status` показывает включённую подсистему и контейнер `running / healthy`.
- В разделах **Видеозапись** и **Трансляции** служба работает.
- В настройках комнаты на вкладке **Встреча и запись** можно выбрать режим записи.
- Пробная запись появляется в **Администрирование → Встречи → Записи встреч**.

## Если не получается

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| `Мало места на томе данных` | свободно меньше 8 ГБ | освободите место и повторите |
| Образ не скачивается | сеть или реестр | повторите действие; при необходимости задайте `IMAGE_MIRRORS` |
| Контейнер не запущен | образ не скачан или служба упала | `sudo scripts/video.sh status`, затем `sudo scripts/logs.sh livekit-egress --tail 300` |
| Запись остановилась, «На диске сервера заканчивается место» | не хватает места под `live/tmp` и копию | освободите место, пересчитайте по таблице выше |
| Зрители не получают низкую задержку | `mediamtx` не работает, комната с CDN, Safari | [Как управлять службами](Как-управлять-службами#проверить-службу-низкой-задержки) |
| Зрители WebRTC уходят на обычный поток | закрыты порты медиа | [Как настроить LiveKit](Как-настроить-LiveKit) |

Полный разбор — [Решение проблем: видеозапись и трансляции](Решение-проблем-видеозаписи-и-трансляций) и [Диагностика трансляций](Диагностика-трансляций).
