# Решение проблем: микрофон

*Для кого: служба поддержки и администратор.*

## Микрофон не открывается в браузере

| Сообщение | Причина | Что сделать |
| --- | --- | --- |
| доступ запрещён | пользователь запретил доступ в браузере | значок замка в адресной строке → разрешить микрофон |
| «Доступ к микрофону запрещён системой» | параметры конфиденциальности Windows («Микрофон → доступ для классических приложений») или защитная программа | разрешить в параметрах Windows; проверить защитную программу |
| «Микрофон занят» | устройство держит другая программа, часто в «монопольном режиме» | закрыть другие конференции и программы записи; снять флажок монопольного режима в свойствах устройства («Звук → Запись → Свойства → Дополнительно») |
| «Микрофон не запустился» | Windows отказала без уточнения: защитная программа, драйвер, формат | см. ниже раздел о защитных программах |
| нет микрофона | устройство не подключено или отключено в Windows | подключить или включить в «Звук → Запись» |

Без HTTPS браузер не даёт сайту микрофон вообще — см. [HTTPS и обратный прокси](Решение-проблем-HTTPS-и-прокси).

Короткие отказы сразу после закрытия устройства страница повторяет сама: до трёх раз, примерно в течение секунды. Если микрофон пропал посреди встречи (вынули гарнитуру, его занял другой звонок), страница сообщает об этом и несколько раз сама пробует включить его снова.

## В Edge микрофон работает, а в приложении для Windows — нет

Это открытый вопрос: причина ещё не подтверждена на Windows. Вот что известно на сегодня.

**Подтверждено разбором исходного кода Chromium:**
- Edge и приложение используют один и тот же движок и открывают микрофон одинаково, в общем (не монопольном) режиме. Повтор открытия, который недолго был в движке в виде эксперимента, сняли и из Edge, так что разница не в нём.
- Если устройство монопольно держит другая программа, это мешает Edge и приложению одинаково. Значит, когда Edge работает, а приложение нет, причина, скорее всего, другая.

**Гипотезы, которые ещё проверяются на Windows:**
1. **Защитная программа.** Некоторые антивирусы пропускают звук с микрофона только к доверенным программам. В Kaspersky Endpoint Security это компонент «Предотвращение вторжений»: по умолчанию звук получают программы из группы «Доверенные». Edge подписан Microsoft и обычно доверенный, а приложение Peregovorka пока не подписано сертификатом издателя. Такой случай известен и у других приложений на том же движке.
2. **Быстрые закрытия и открытия микрофона** при входе во встречу, смене устройства или шумоподавления. С версий 0.51.0 и 1.4.0 запросы микрофона идут по одному, а короткие отказы повторяются.

**Что сделать.**
- Если на компьютере стоит защитная программа, попросите её администратора проверить журнал на блокировку доступа к микрофону и разрешить приложению Peregovorka доступ к аудиопотоку (или перевести его в «Доверенные»). Затем перезапустите приложение.
- Соберите сведения для поддержки: в Edge и в приложении «Устройства… → Подробная проверка микрофона → Скопировать полный отчёт», а в приложении ещё «Настройки → Диагностика → Сохранить отчёт». Раздел `audio` отчёта содержит коды ошибок Windows, защитные программы и время, когда Windows в последний раз отдавала звук приложению и браузерам.
- Администратор видит общую картину в «Администрирование → Обзор → Диагностика клиентов → Микрофон по клиентам»: «открылся со 2–4 попытки» означает короткую гонку, которую повтор закрыл, а «повтор не помог» — настоящую блокировку.

Методика сравнения для поддержки — `docs/DESKTOP_MIC_DIAGNOSTICS.md` в репозитории.
