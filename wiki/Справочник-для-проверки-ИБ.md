# Справочник для проверки ИБ

*Для кого: служба ИБ, архитектор, администратор.*

Сведения о продукте для внутренней проверки: какие данные обрабатываются, куда могут уходить, где хранятся секреты, какие учётные записи нужны, что журналируется и где проходят границы защиты. Механизмы подробно: [Безопасность и приватность](Безопасность-и-приватность) и [Шифрование](Шифрование).

## 1. Обрабатываемые данные

| Категория | Примеры | Где хранится | Защита при хранении |
| --- | --- | --- | --- |
| Учётные данные сотрудников | Логин, ФИО, должность, подразделение, почта, телефон, фото | PostgreSQL, `DATA_ROOT/avatars` | Нет |
| Пароли сотрудников из каталога | — | Не хранятся: передаются контроллеру домена при входе | — |
| Пароль локального администратора | — | PostgreSQL | Хэш argon2id |
| Содержимое встреч | Звук и видео при записи, стенограммы, чаты, протоколы, резюме, карты, схемы досок, вложения | PostgreSQL, каталоги `DATA_ROOT`, выбранные хранилища | Чат встречи и стенограммы: AES-256-GCM при включённом шифровании хранилища. Файлы записей и вложения приложением не шифруются |
| Корпоративные чаты | Сообщения и вложения сотрудников | PostgreSQL, файловое хранилище | Нет |
| Метаданные | Кто, когда, в какой комнате, адреса входа, события безопасности | PostgreSQL | Нет. Записи аудита подписаны HMAC-SHA256 |
| Сеансы | Данные сеанса, токен CSRF, токены гостей и устройств | Redis | Ключом служит хэш идентификатора, токены устройств хранятся как хэш. Значения не шифруются |
| Ключ сквозного шифрования встречи | Случайная строка на 256 бит | Redis на время встречи | Нет. Удаляется при завершении встречи, запасной срок 3 дня |
| Секрет TOTP | Секрет пользователя | PostgreSQL. До подтверждения кода Redis на 10 минут | AES-256-GCM в базе, ключ `APP_MASTER_KEY` |
| Резервные коды TOTP | 10 кодов | PostgreSQL | HMAC-SHA256 с ключом сервера |
| Секреты интеграций | Пароли LDAP, SMTP, SMB, EWS, ключи языковых моделей и API, секреты webhooks | PostgreSQL | AES-GCM, ключ `APP_MASTER_KEY` |
| Ключи публичного API | — | PostgreSQL | Только SHA-256 |
| Пароли комнат | — | PostgreSQL | Только argon2id |

Медиапотоки звонка шифруются при передаче (DTLS-SRTP). В режиме **Полное (без стенограммы и записи)** службы сервера не получают ключ, поэтому распознавание речи и запись звука в такой комнате отключены. В режиме с доверенным компонентом служба распознавания получает ключ встречи. Сервер звонков содержимое в обоих режимах не видит.

## 2. Исходящие соединения сервера

После установки сервер обращается к внешним системам только по настройке администратора или по его действию в интерфейсе. Исключения перечислены в таблице: проверка обновлений и определение публичного адреса. При чтении кода телеметрии не найдено.

| Назначение | Когда | Какие данные уходят | Как отключить |
| --- | --- | --- | --- |
| Контроллеры домена, LDAPS 636 или STARTTLS 389 | Вход, поиск пользователей | Логин, пароль при входе, запросы атрибутов | Не настраивать каталог |
| SMTP | Рассылка материалов, уведомления | Письма: тема, текст, вложения протоколов по правилам рассылки | Выключить почту |
| SMB и смонтированные папки | Запись файлов | Записи, протоколы, вложения, журналы по настройке | Не выбирать хранилище |
| Exchange EWS, Microsoft Graph | Сверка календарей, Outlook | Данные событий календаря выбранных ящиков | Выключить интеграцию |
| Языковая модель по API: OpenAI, Anthropic, совместимый шлюз | Формирование протокола, резюме, карты | Текст стенограммы и чата встречи. Пароли, токены и ключи маскируются всегда. Имена, контакты и реквизиты маскируются, если обезличивание включено в комнате или обязательно | Не подключать модель, включить **Обязательно для всех комнат** в разделе **Обезличивание** |
| Bitrix24 | Обновление профиля | Запросы чтения сотрудников | Не настраивать |
| Webhooks | События встреч и документов | По выбранным событиям: идентификаторы, ссылки, статусы | Не создавать получателей |
| Площадки трансляций по RTMP или RTMPS | Прямой эфир | Видеопоток эфира | Не настраивать площадки |
| Узлы CDN Peregovorka | Установка, управление и работа узлов | SSH-подключение к узлу, поток эфира, статистика | Не подключать узлы |
| SIP-транк АТС | Звонок на телефон | Голос участников звонка | Не включать SIP |
| Серверы STUN | Режим адреса `nat-stun` при запуске LiveKit и каждые 5 минут | Запрос публичного адреса | `LIVEKIT_STUN_SERVERS` для своего сервера, `LIVEKIT_PUBLIC_IP=<адрес>` или `off` без обращений |
| GitHub, репозиторий проекта | Помощник проверяет обновления раз в 30 минут и получает их | Запрос к репозиторию без данных установки | Не устанавливать помощник, обновлять вручную |
| PyPI, npm, GitHub API | Открыта таблица **Версии компонентов** в **Система → Обновления и версии** | Запросы версий публичных пакетов | Закрыть исходящий доступ: таблица покажет отсутствие данных, работа не нарушится |
| GitHub Releases, канал издателя приложения Windows | Администратор проверил канал в **Windows-клиент → Подпись и корпоративные сборки** | Запрос файла `update.json` и подписи | Не использовать функцию |
| Источники при установке и сборке: GitHub, реестры образов, PyPI, npm, индекс PyTorch, CDN модели распознавания, CDN Microsoft для Office.js | Только `install.sh`, `update.sh`, `rebuild.sh`, `models.sh` | Запросы пакетов | Сборка с зеркалами, модели через `--models-from` |

Распознавание речи и обезличивание не обращаются в сеть. Исходный текст, найденные значения и таблица замен в журналы не пишутся, только число замен по категориям ([Как настроить обезличивание](Как-настроить-обезличивание)).

Точный перечень портов и исходящих направлений: [Порты и сервисы](Архитектура-Порты-и-сервисы) и [Каталог интеграций](Архитектура-Каталог-интеграций).

Браузеры участников обращаются к серверу по HTTPS и напрямую к LiveKit на порты медиа. Адреса STUN получают и браузеры ([Справочник: порты и сеть](Справочник-порты-и-сеть#адреса-для-звука-и-видео-nat)). TURN не используется. Надстройка Outlook в классическом режиме загружает Office.js с CDN Microsoft, а в режиме Office.js с сервера берёт файлы с вашего сервера.

## 3. Секреты и ключи

| Секрет | Где | Кто имеет доступ | Смена |
| --- | --- | --- | --- |
| `APP_MASTER_KEY`: шифрование секретов и данных в базе, подпись аудита | `.env` в каталоге установки, права 600 | root и владелец каталога установки | Встроенной смены нет. Замена без перешифрования делает данные нечитаемыми, потеря ключа означает их потерю |
| `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `INTERNAL_API_TOKEN` | `.env` | То же | Правка `.env` и пересоздание сервисов в окно обслуживания |
| Пароли интеграций и ключи API | База, в зашифрованном виде | Администраторы вводят, обратно они не показываются | В интерфейсе |
| Ключ шифрования автоматических копий настроек | База, в зашифрованном виде | Показывается один раз при создании | Создать новый ключ. Прежние копии открываются прежним ключом |
| Секрет TOTP пользователя | База, AES-256-GCM | Нет доступа через интерфейс | Сброс второго фактора администратором |
| Токен устройства приложения | Redis (хэш). На устройстве: файл, зашифрованный средствами ОС, в Windows через DPAPI | Нет доступа через интерфейс | Выход, завершение сеанса, смена пароля, отключение учётной записи |

`scripts/logs.sh` и `scripts/diag.sh` маскируют пароли, токены, ключи, `access_token` в адресах. `diag.sh` не создаёт архив, если находит значение секрета из `.env`. Резервные копии базы содержат зашифрованные секреты, копия `.env` открытые: храните их раздельно.

## 4. Учётные записи

| Учётная запись | Где | Права |
| --- | --- | --- |
| Сервисная учётная запись каталога | AD | Чтение пользователей и групп в Base DN, прав записи не нужно |
| Почтовый ящик отправителя | Почтовый сервер | Отправка от своего имени |
| Учётная запись SMB | Файловый сервер | Чтение, запись, создание и удаление в выделенной папке |
| Учётная запись EWS, приложение Graph | Exchange, Entra ID | «Рецензент» на календари или ограниченная имперсонация. Graph: `Calendars.ReadBasic.All` для чтения, запись календаря по [требованиям Outlook](Outlook-Требования-и-совместимость) |
| Локальный администратор | Приложение | Создаётся при установке, пароль показывается один раз. Рекомендуется второй фактор |
| Администраторы приложения | Группы каталога: `LDAP_ADMIN_GROUP_DN` и **Администраторы сервера** | Полный доступ к настройкам и материалам |
| Помощник обновлений | Служба systemd на хосте | root, принимает только фиксированный список действий |
| Контейнеры `backend`, `asr` | Docker | uid 10001. `no-new-privileges` у backend, web, redis |

Роли пользователей и права на материалы: [Справочник: роли и права](Справочник-роли-и-права).

## 5. Журналирование

| Журнал | Где | Что попадает | Хранение |
| --- | --- | --- | --- |
| Журнал аудита | **Безопасность → Журнал аудита** | Действия администраторов, входы, доступ к материалам. Записи подписаны | **Хранение и журналы → Хранение журнала**, поле **Хранить журнал аудита**. По умолчанию 0: не удалять |
| Журнал событий | **Хранение и журналы → Журнал событий** | Диагностика без паролей, токенов и содержимого разговоров | Там же, поле **Хранить записи журнала**. По умолчанию 30 дней |
| События безопасности | **Безопасность → События и блокировки** | Неудачные входы, блокировки, срабатывания WAF, ошибки прав | **Безопасность → Хранение журнала безопасности**. По умолчанию 30 дней и 200 000 строк |
| Журнал отправки почты | **Хранение и журналы → Почта: журнал отправки** | Получатели, статусы | **Система → Почта: правила рассылки**, поле **Хранить журнал отправки**. По умолчанию 90 дней |
| История действий комнаты | Страница встречи, вкладка **История действий** | Выборка из аудита, писем и встреч по этой комнате. Видят администратор и руководитель | По сроку аудита и встреч |
| Журналы контейнеров | `scripts/logs.sh`, драйвер журналов Docker | Технические сообщения | По настройке Docker, ротация на стороне администратора хоста |

Выгрузка в SIEM: прямой интеграции с syslog или SIEM нет. Журнал событий можно дублировать файлами NDJSON в файловое хранилище, в каталог `Logs/journal/<дата>/`. Записи аудита и значимые события безопасности попадают и в журнал событий.

Полный перечень событий: [Справочник: журнал аудита и события](Справочник-журнал-аудита-и-события).

## 6. Настройки, которые проверить при приёмке

| Проверка | Где | Ожидаемое |
| --- | --- | --- |
| HTTPS с полной цепочкой | Внешний прокси, `scripts/diag.sh` → файл `network.txt` | Цепочка полная, `Verify return code: 0` |
| `COOKIE_SECURE=true` | `.env` | `true` при HTTPS |
| `DOCS_ENABLED=false` | `.env` | `false` |
| Доступ только из нужных сетей | **Безопасность → Доверенные подсети**, межсетевой экран | По политике организации |
| Группы допуска | **Комнаты и пользователи → Кто может входить**, `LDAP_ACCESS_GROUP_DN` | Заданы, если входить должны не все сотрудники |
| Второй фактор для администраторов | **Безопасность → Вход и сеансы** | Поле **Политика**: **Обязательна администраторам** или строже |
| Адрес клиента | **Безопасность → Сеть и IP-адреса (прокси, WAF)**, блок **Что сервер видит сейчас** | Настоящий адрес клиента |
| Защита от перебора и CAPTCHA | **Безопасность → События и блокировки**, строка состояния | Защита входа **включена**, CAPTCHA не **выключена** |
| Встроенный WAF | **Безопасность → Защита веб-приложения (WAF)** | Режим по решению ИБ, рядом с внешним WAF допускается **Наблюдение** |
| Внешняя языковая модель и обезличивание | **Интеграции → Языковая модель (LLM)**, **Интеграции → Обезличивание** | Соответствует решению о передаче данных |
| Шифрование хранилища | **Безопасность → Шифрование хранилища** | Включено, если требуется защита чата и стенограмм в базе |
| Права на файлы | `ls -l .env`, `ls -ld <DATA_ROOT>/*` | `.env` 600, каталог копий 700 |
| Порты снаружи | `scripts/ports.sh --format md` | Только HTTPS и порты медиа. PostgreSQL, Redis и порт web не наружу |
| Сроки хранения | **Хранение и журналы**, настройки материалов | По политике организации |

## 7. Границы защиты

- Администратор сервера с root и доступом к `.env` и Docker имеет доступ ко всем данным. Шифрование в базе защищает копии и диск, но не от владельца сервера.
- Сквозное шифрование не защищает от владельца сервера Peregovorka: ключ встречи создаётся сервером и лежит в Redis.
- Процесс backend расшифровывает данные в памяти. Распознавание речи слышит звук комнат без сквозного шифрования и комнат с доверенным компонентом.
- Записи встреч на диске и в хранилищах приложение не шифрует. Используйте шифрование тома или ресурса.
- Встроенный WAF и блокировка адресов смотрят на запросы без признака входа и проверяют наличие признака, а не его подлинность. Это защита от массового сканирования.
- HSTS включается вручную. В nginx нет ограничения частоты, защита работает в приложении.
- Обновление из браузера выполняет служба от root с белым списком действий.
- Внешний тест на проникновение и нагрузочные испытания защиты не проводились. Внутренний аудит версий 0.8.5 и 0.9.0 проведён по чек-листу OWASP Top 10 и API Security Top 10: `docs/SECURITY_AUDIT.md` в репозитории.
- Настоящий Active Directory и связка LDAP или AD под нагрузкой не проверялись. В нагрузочных прогонах каталог был подставным, вход шёл до начала измерений и не более 100 одновременно.
- Настоящие внешние прокси, WAF и сеть IPv6 не проверялись, заголовки эмулировались.
- Соответствие стандартам и сертификация не заявляются.
- Приложение для Windows: у установщиков нет сертификата издателя. Приложение для Android с версии 0.1.4 подписано постоянным ключом.
