# Справочник для проверки ИБ

> Относится к версии 0.50.1 · проверено 2026-10-29 · уровень проверки: 1–2 (перечни составлены по коду, `deployment/compose.yml`, `.env.example` и тестам; внешний аудит и тест на проникновение не проводились) · тип страницы: справочник

Что это: сведения о продукте для внутренней проверки информационной безопасности — какие данные обрабатываются, куда могут уходить, где хранятся секреты, какие учётные записи нужны, что журналируется и где проходят границы защиты. Механизмы подробно — [[Безопасность и приватность|Безопасность-и-приватность]] и [[Шифрование]]. Для кого: служба ИБ, архитектор, администратор.

## 1. Обрабатываемые данные

| Категория | Примеры | Где хранится | Шифрование при хранении |
| --- | --- | --- | --- |
| Учётные данные сотрудников | логин, ФИО, должность, подразделение, электронная почта, фото (из AD/Bitrix24 или правка профиля) | PostgreSQL, `DATA_ROOT/avatars` | нет (кроме секретов TOTP) |
| Пароли сотрудников AD | — | **не хранятся**: передаются контроллеру домена при входе (LDAP bind) | — |
| Пароль локального администратора | — | хэш argon2 в базе | — |
| Содержимое встреч | звук и видео (только при записи), стенограммы, чаты, протоколы, резюме, карты, схемы досок, вложения | PostgreSQL, `DATA_ROOT/recordings`, `chat-files`, выбранные хранилища (SMB/папка) | чат и стенограммы — AES-256-GCM при включённом «Шифровании хранилища»; файлы записей — нет |
| Метаданные | кто, когда, в какой комнате, IP-адреса входа, события безопасности | PostgreSQL (журнал событий, аудит) | нет; аудит подписан HMAC |
| Сессии | идентификатор сессии, CSRF-токен | Redis | нет (идентификатор случайный, cookie HttpOnly) |
| Секреты интеграций | пароли LDAP bind, SMTP, SMB, EWS, ключи внешних LLM и API, секреты webhooks | PostgreSQL | AES-GCM, ключ `APP_MASTER_KEY` |
| Ключи публичного API, пароли переговорных | — | только хэш (SHA-256 / argon2) | — |

Медиапотоки звонка шифруются при передаче (DTLS-SRTP); при включённом сквозном шифровании комнаты сервер не может расшифровать звук и видео, распознавание речи в такой комнате невозможно.

## 2. Исходящие соединения сервера

После установки сервер обращается к внешним системам только по настройке администратора или по его действию в интерфейсе. Телеметрии нет (проверено чтением кода: все фиксированные внешние адреса backend перечислены в таблице).

| Назначение | Когда | Какие данные уходят | Как отключить |
| --- | --- | --- | --- |
| Контроллеры домена (LDAPS 636) | вход, поиск пользователей | логин, пароль при bind, запросы атрибутов | не настраивать LDAP (только локальные учётные записи) |
| SMTP | рассылки материалов, уведомления | письма: тема, текст, вложения протоколов (по правилам рассылки) | выключить почту |
| SMB / смонтированные папки | запись файлов | записи, протоколы, вложения | не выбирать профиль |
| Exchange EWS / Microsoft Graph | сверка календарей, Outlook | данные событий календаря выбранных ящиков | выключить интеграцию |
| Внешняя языковая модель (OpenAI, Anthropic, OpenAI-совместимый шлюз, «свой» сервис) | формирование протокола, резюме, карты | **текст стенограммы и чата встречи** (после обезличивания, если оно включено); при выключенном обезличивании — как есть, с предупреждением | режим «Локальная модель» или «отключена» на уровне системы и комнат |
| Обезличиватель (DocClean или свой JSON API) | перед отправкой во внешнюю модель | текст встречи | выключить обезличивание (тогда во внешнюю модель текст уходит как есть) |
| Bitrix24 | обновление профиля | запросы чтения сотрудников | не настраивать |
| Webhooks | события (завершение встречи, документы) | по выбранным событиям: идентификаторы, ссылки, статусы | не создавать получателей |
| Площадки трансляций (RTMP/RTMPS), CDN | прямой эфир | видеопоток эфира | не включать трансляции |
| SIP-транк АТС | звонок на телефон | голос участников звонка | не включать SIP |
| GitHub (git) | проверка и получение обновлений помощником | запрос к репозиторию, без данных установки | не устанавливать помощник; обновлять вручную |
| PyPI, npm, GitHub API (`api.github.com`) | администратор открыл «Система → Обновления и версии → Версии компонентов» (результат кэшируется) | запросы версий публичных пакетов; данные установки не передаются (User-Agent `peregovorka-version-check`) | закрыть исходящий доступ сервера: таблица покажет «нет данных», работа не нарушается |
| GitHub Releases (канал издателя Windows-клиента) | администратор нажал «Проверить канал издателя» в «Windows-клиент → Подпись и корпоративные сборки» | запрос файла `update.json` и подписи | не использовать функцию |
| `login.microsoftonline.com`, `graph.microsoft.com` | только при подключённом Microsoft 365 | см. строку Exchange/Graph | — |
| Источники при **установке и сборке**: GitHub, Docker Hub, GHCR, PyPI, npm, индекс PyTorch, CDN модели GigaAM, Hugging Face (локальная LLM), CDN Microsoft (Office.js в образ) | только `install.sh`, `update.sh`, `rebuild.sh`, `models.sh` | запросы пакетов | сборка в контуре с зеркалами; модели — `--models-from` |

Локальная языковая модель (`llm-local`) работает в сети Docker без выхода наружу (`internal`). Распознавание речи (ASR) не обращается в сеть.

Браузеры участников обращаются к серверу Peregovorka (443) и напрямую к LiveKit (порты медиа). Внешние STUN/TURN не используются. Надстройка Outlook в классическом режиме загружает Office.js с CDN Microsoft (`appsforoffice.microsoft.com`), в режиме Office.js с сервера — с вашего сервера.

## 3. Секреты и ключи

| Секрет | Где | Кто имеет доступ | Смена |
| --- | --- | --- | --- |
| `APP_MASTER_KEY` (шифрование секретов и данных в базе, HMAC паспортов встреч) | `APP_ROOT/.env`, права 600 | root и владелец каталога установки | смена требует перешифрования — не выполнять без разработчика; потеря ключа = потеря зашифрованных данных |
| `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `LIVEKIT_API_KEY/SECRET`, `INTERNAL_API_TOKEN` | `.env` | то же | правка `.env` + перезапуск соответствующих сервисов (окно обслуживания) |
| Пароли интеграций и ключи API | база, зашифрованы | администраторы приложения вводят, обратно не показываются | в интерфейсе |
| Ключ шифрования автокопий конфигурации | база, зашифрован | показывается один раз при создании | создать новый ключ |
| Секрет TOTP пользователя | база, AES-256-GCM | — | сброс второго фактора администратором |
| Токен устройства приложения Windows | база (хэш), на устройстве — DPAPI | — | отзыв в профиле / администрировании |

Журналы, `scripts/logs.sh`, `scripts/diag.sh` маскируют пароли, токены, ключи, `access_token` в адресах, JWT. `diag.sh` не создаёт архив, если находит значение секрета из `.env`. Резервные копии базы содержат зашифрованные секреты, копия `.env` — открытые: храните их раздельно.

## 4. Учётные записи

| Учётная запись | Где | Права (минимально необходимые) |
| --- | --- | --- |
| Сервисная учётная запись AD (LDAP bind) | AD | чтение пользователей и групп в `LDAP_BASE_DN`; прав записи не нужно |
| Почтовый ящик отправителя | почтовый сервер | отправка от своего имени |
| Учётная запись SMB | файловый сервер | чтение, запись, создание и удаление в выделенной папке |
| Учётная запись EWS / приложение Graph | Exchange / Entra ID | «Рецензент» на календари или ограниченная имперсонация; Graph `Calendars.ReadBasic.All` (минимум; проверено только тестами) |
| Локальный администратор Peregovorka | приложение | создаётся при установке, пароль показывается один раз; рекомендуется TOTP |
| Администраторы приложения | группа AD `LDAP_ADMIN_GROUP_DN` или назначение в интерфейсе | полный доступ к настройкам и материалам |
| Помощник обновлений | служба systemd на хосте | root; принимает только фиксированный список действий от root/самого себя |
| Контейнеры `backend`, `asr` | — | uid 10001 без привилегий; `no-new-privileges` у backend, web, redis |

Роли пользователей и права на материалы — [[Справочник: роли и права|Справочник-роли-и-права]].

## 5. Журналирование

| Журнал | Где | Что попадает | Хранение |
| --- | --- | --- | --- |
| Журнал событий | «Хранение и журналы → Журнал событий» | категории `auth`, `room`, `network`, `device`, `client`, `llm`, `storage`, `admin`, `system`; без паролей, токенов и содержимого разговоров | «Хранение журнала» |
| Журнал аудита | «Безопасность → Журнал аудита» | действия администраторов и доступ к материалам; HMAC-цепочка | «Хранение журнала» |
| События безопасности и блокировки | «Безопасность → События и блокировки» | неудачные входы, блокировки, срабатывания WAF | «Хранение журнала безопасности» |
| Журнал отправки почты | «Хранение и журналы → Почта: журнал отправки» | получатели, статусы | там же |
| Журналы контейнеров | `scripts/logs.sh`, драйвер журналов Docker | технические сообщения, JSON | по настройке Docker (ротация — ответственность администратора хоста) |

Выгрузка журналов в SIEM: журнал событий может дублироваться в файловое хранилище (`Logs/journal/…`); прямой интеграции с syslog/SIEM нет.

## 6. Настройки, которые проверить при приёмке

| Проверка | Где | Ожидаемое |
| --- | --- | --- |
| HTTPS с полной цепочкой и современными протоколами | reverse proxy; `scripts/diag.sh` → `network.txt` | цепочка полная, `Verify return code: 0` |
| `COOKIE_SECURE=true` | `.env` | true при HTTPS |
| Доступ к приложению только из нужных сетей | «Безопасность → Доверенные подсети», межсетевой экран | по политике организации |
| Группа допуска AD (`LDAP_ACCESS_GROUP_DN`) | `.env` / «Кто может входить» | задана, если входить должны не все сотрудники |
| Двухфакторная защита для администраторов | «Безопасность → Вход и сеансы» | обязательна для администраторов |
| Защита от перебора, CAPTCHA | «Безопасность» | включены |
| Внешняя языковая модель и обезличивание | «Интеграции → Языковая модель (LLM)», «Обезличивание» | соответствует решению о передаче данных; при внешней модели — обезличивание «всегда» |
| Шифрование хранилища | «Безопасность → Шифрование хранилища» | включено, если требуется защита чата и стенограмм в базе |
| Права на `.env` и `DATA_ROOT` | `ls -l .env`, `ls -ld <DATA_ROOT>/*` | `.env` — 600; `backups` — 700 |
| Порты, открытые наружу | `scripts/ports.sh --format md` | только 443 (прокси) и порты медиа LiveKit; PostgreSQL, Redis, порт web — не наружу |
| Сроки хранения | «Хранение и журналы» | по политике организации |

## 7. Границы защиты

- Администратор сервера (root, доступ к `.env` и Docker) имеет доступ ко всем данным: шифрование в базе защищает копии и посторонний доступ к диску, но не от владельца сервера.
- Процесс backend расшифровывает данные в памяти, чтобы показать их пользователям; распознавание речи слышит звук комнат без сквозного шифрования.
- Записи встреч на диске и в хранилищах не шифруются приложением — используйте шифрование тома или ресурса.
- HSTS включается вручную; ограничение частоты на уровне nginx не настроено (защита в backend).
- Обновление из браузера выполняет служба от root (белый список действий).
- Внешний тест на проникновение и нагрузочные испытания безопасности не проводились; внутренний аудит — по OWASP Top 10 / API Top 10 ([SECURITY_AUDIT.md](https://github.com/calleograph/peregovorka/blob/main/docs/SECURITY_AUDIT.md)).
- Приложение для Windows: установщики не подписаны сертификатом издателя; приложение для Android 0.1.1 подписано временным ключом.
