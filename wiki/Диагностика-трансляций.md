# Диагностика трансляций

*Для кого: администратор сервера, руководитель комнаты.*

## Зачем это нужно

Страница помогает найти причину, если эфир не стартует, зрители не видят картинку или площадка не принимает поток. Сообщения приведены дословно: ищите свой текст в таблицах.

## Когда пригодится

- Кнопка эфира вернула ошибку.
- Зрители пишут, что видео нет.
- У площадки статус **ошибка**.

## Что потребуется

Руководителю комнаты хватит окна **Трансляция**. Администратору нужен раздел администрирования и для журналов доступ по SSH.

## Где найти

| Что | Где |
|---|---|
| Состояние службы и проверки по цепочке | **Администрирование → Интеграции → Трансляции** |
| Идущие и прерванные эфиры, зрители, нагрузка, площадки | там же |
| Показатели и журнал эфира | [панель диагностики](Панель-диагностики-эфира): **Ещё → Диагностика эфира** |
| История эфиров | **Администрирование → Интеграции → Трансляции**, блок **Диагностика эфиров** |
| Журнал службы эфира | `scripts/logs.sh livekit-egress --tail 200` |
| Журнал службы низкой задержки | `scripts/logs.sh mediamtx --tail 200` |
| Сборка отчёта для поддержки | `scripts/diag.sh` |

Команды выполняются по SSH из каталога установки.

## Как это сделать

1. Прочитайте сообщение в комнате или в окне **Трансляция**. Найдите его ниже.
2. Если сообщения нет, откройте **Администрирование → Интеграции → Трансляции** и начните с первой непройденной проверки.
3. Если эфир идёт, откройте панель диагностики. Цветная полоса покажет проблемный этап.
4. Если плохо одному зрителю, попросите его открыть **Статистика воспроизведения**.

Как читать проверки и чинить службу: [Решение проблем: видеозапись и трансляции](Решение-проблем-видеозаписи-и-трансляций).

## Эфир не начинается

| Сообщение | Причина и действие |
|---|---|
| «Трансляции выключены администратором…» | **Администрирование → Интеграции → Трансляции → Включить трансляции** |
| «В этой комнате трансляция не включена…» | вкладка **Трансляция** → **Разрешить трансляции в этой комнате** |
| «При сквозном шифровании трансляция недоступна…» | так задумано: у сервера нет ключа, чтобы собрать картинку |
| «В комнате включено шифрование хранилища…» | запись и эфир с ним не поддерживаются |
| «Нечего вещать: включите собственный просмотр или добавьте хотя бы одну внешнюю площадку.» | всё выключено: включите собственный просмотр или добавьте площадку |
| «Сейчас идёт максимально допустимое число эфиров…» | достигнут предел **Одновременных эфиров на сервере**, 1 по умолчанию. Дождитесь окончания. Значение 2 и выше не испытано |
| «Сервер трансляций сейчас загружен…» | нагрузка выше **Не начинать эфир при нагрузке Egress от**, 85 % по умолчанию. Дождитесь, когда процессор освободится |
| «Мало свободного места на томе трансляций…» | освободите диск |
| «Запись эфира невозможна…» | эфира без записи не бывает: [Запись трансляции](Запись-трансляции) |
| «В комнате никого нет: начинать эфир не с кого.» | войдите в комнату |
| «Сервер звонков недоступен: эфир не начат.» | [Звонки и сеть](Решение-проблем-звонков-и-сети) |
| «Служба трансляций (LiveKit Egress) недоступна или не установлена…» | карточка службы: **Установить и включить** или **Повторить запуск** |
| «Эфир уже запускается.» | подождите |
| «Браузер службы трансляций не запустился вовремя…» | не хватает процессора: [Решение проблем](Решение-проблем-видеозаписи-и-трансляций) |

## В комнате нет нужной кнопки

| Что не видно | Причина |
|---|---|
| Пункт **Трансляция…** в **Ещё** | трансляции выключены на сервере или в комнате, либо вы вошли по гостевой ссылке |
| Кнопка **Начать эфир** в окне | у вас нет права управлять эфиром: окно показывает только статус |
| **Выйти в эфир** и **Настройки эфира** | комната не трансляционная: используйте **Ещё → Трансляция…**; либо нет права управлять эфиром |
| Панель вопросов | комната не трансляционная |
| Всё перечисленное в приложении для Android | в нём нет кнопок эфира |

## Эфир идёт, а зрители не видят

| Что видно | Причина и действие |
|---|---|
| Зритель видит «Эфир запускается» дольше минуты | служба не создала плейлист. Смотрите журнал службы. Частая причина: `LIVEKIT_NODE_IP=127.0.0.1` |
| «Не удаётся получить поток эфира…» | `web` не видит том трансляций или секрет подписи. Проверьте `${DATA_ROOT}/live/nginx/secret.conf` и журнал `web`: секрет применяется сам раз в 5 секунд, отказ `nginx -t` или нехватка прав видны в журнале |
| Плейлист отвечает 403 | подпись не сошлась. Новый секрет применяется сам за несколько секунд, зрителю достаточно обновить страницу |
| Плейлист отвечает 410 | срок подписи вышел. Страница зрителя продлевает сама, внешнему плееру нужна новая ссылка |
| Плейлист отвечает 404 | ссылка отозвана, пароль менялся или эфир закончился и каталог убран |
| «Не удаётся получить поток» через CDN | CDN не отдаёт `/hls/…`: проверьте пересылку путей и срок кеша плейлиста |
| Зрители за прокси не открывают страницу | пути `/live/`, `/hls/`, `/llhls/`, `/api/v1/live/` должны быть открыты без входа |
| «Проверить CDN»: «CDN ответил … а не «ok» от источника» | CDN не пересылает `/hls/` на ваш сервер или подставляет свою страницу |
| Большая задержка | панель, вкладка **Поток**, строка **Низкая задержка**. Safari, iPhone и комнаты с CDN всегда на обычном HLS |

## Внешняя площадка

| Что видно | Причина и действие |
|---|---|
| Статус **ошибка**, «Connection refused», «Could not connect…» | сервер площадки недоступен с вашего сервера. Проверьте адрес, порт и исходящий доступ: `rtmp` порт 1935, `rtmps` порт 443 |
| Статус **ошибка**, `Connection reset by peer` на RUTUBE | трансляция завершена, ключ не принимается. Запустите её заново в студии |
| Статус **идёт**, зрители площадки ничего не видят | не запущен эфир в студии: RUTUBE запуск трансляции, VK кнопка **Опубликовать** |
| Статус **подключается…**, на площадке пусто | неверный или просроченный ключ: **Изменить**, новый ключ, **Сохранить** |
| «Эта площадка уже добавлена…» | тот же сервер и ключ есть в списке |
| «Ключ потока не задан или не читается: задайте его заново.» | ключ утрачен или сменился главный ключ сервера |
| «Адрес сервера ведёт во внутреннюю сеть…» | администратор включает **Разрешить серверы RTMP во внутренней сети** |
| «Этот адрес сервера не разрешён…» | адреса локального компьютера, link-local и метаданных облака запрещены всегда |
| «Площадка … отключена администратором сервера.» | администратор разрешает её в настройках трансляций |

Ошибка площадки не останавливает эфир и другие площадки. Новый ключ начинает работать сразу. После правки адреса, если статус не изменился, снимите и поставьте отметку **в эфире**.

## Эфир оборвался

| Сообщение | Причина и действие |
|---|---|
| **Эфир прерван**, причина «Служба трансляций перестала отвечать во время эфира.» | служба упала. Сервер закрывает эфир сам в течение минуты, конференция продолжается. После запуска службы начните эфир заново |
| «Кодирование эфира остановилось…» | не хватает процессора: снизьте качество или разгрузите сервер |
| «Страница эфира не начала запись вовремя…» | проверьте, что сервер звонков доступен службе эфира |
| «На диске сервера заканчивается место» | сервер закрыл запись заранее: освободите `${DATA_ROOT}` |
| Эфир закончился сам | все вышли, встреча завершена или достигнут предел: [Управление прямым эфиром](Управление-прямым-эфиром) |

## Что получится

Вы знаете, на каком этапе сбой и что делать. Если причина не найдена, передайте в поддержку журнал из панели, кнопка **Отчёт**, и архив `scripts/diag.sh`.
