# Справочник: конфигурация

*Для кого: администратор сервера.*

Файл `.env` лежит в корне проекта (права 600), в Git не попадает. Шаблон — `.env.example`. Установщик создаёт `.env` сам и генерирует секреты. Значения, начинающиеся с `CHANGE`, обязательны к замене: `preflight.sh` откажет, если они остались. `.env` не заменяется при обновлении; безопасные новые параметры добавляются в конец блоком «добавлено scripts/update.sh», остальные перечисляются в итоге обновления. Основная часть настройки выполняется в браузере ([Как подключить Active Directory](Как-подключить-Active-Directory)).

Значения в таблицах — **значения из шаблона**; «пример» означает, что значение зависит от установки.

**Как применить правку.** Обычный параметр: ⚠ `scripts/ctl.sh restart <служба>`. Адреса LiveKit: ⚠ `sudo scripts/medianet.sh apply`. Порты медиа: ⚠ `sudo scripts/medianet.sh ports --tcp N --udp N`. Параметры `NGINX_*`: ⚠ `sudo scripts/install.sh --profile <профиль> --from nginx`. Полная таблица — [Как управлять службами](Как-управлять-службами#применить-правку-env-).

## Экземпляр

| Параметр | Значение в шаблоне | Назначение |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `peregovorka-prod` (пример) | уникальное имя compose-проекта; префикс имён контейнеров, сетей и томов; только `a-z`, `0-9`, `-`, `_`, начинается с буквы |
| `INSTALL_PROFILE` | `shared-host` | `shared-host` или `standalone` |
| `APP_PUBLIC_URL` | `https://meet.example.org` (пример) | публичный адрес приложения (схема и хост, без пути); основа проверки Origin и ссылок |
| `APP_ROOT` | `/opt/peregovorka` | каталог проекта (для справки) |
| `DATA_ROOT` | `/srv/peregovorka-data` | корень постоянных данных; локальный абсолютный путь Linux |
| `IMAGE_TAG` | `dev` | тег локально собираемых образов; `update.sh` ставит короткий SHA |
| `LOG_LEVEL`, `LOG_FORMAT` | `INFO`, `json` | уровень (`DEBUG`, `INFO`, `WARNING`, `ERROR`) и формат (`json`, `console`) журнала |
| `DOCS_ENABLED` | `false` | включает `/api/v1/docs` и `/api/v1/openapi.json` внутреннего API; только для отладки |

## Порты и сеть

| Параметр | Значение в шаблоне | Назначение |
| --- | --- | --- |
| `WEB_BIND_ADDR`, `WEB_PORT` | `127.0.0.1`, `18480` | вход контейнера `web`, только HTTP. Значение `0.0.0.0` открывает его на всех адресах сервера мимо nginx и TLS. Меняйте адрес, только если прокси стоит на другом сервере, и закройте порт межсетевым экраном для всех, кроме прокси |
| `NGINX_LISTEN_PORT` | `18400` | порт host-nginx |
| `LIVEKIT_HTTP_PORT` | `17880` | API LiveKit, только loopback |
| `LIVEKIT_BIND_ADDR` | `0.0.0.0` | адрес привязки медиапортов. Конкретный адрес ограничит приём одним интерфейсом: клиенты с других сетей не подключатся |
| `LIVEKIT_TCP_PORT`, `LIVEKIT_UDP_PORT` | `17881`, `17882` | ICE/TCP и ICE/UDP (один mux-порт) |
| `LIVEKIT_NODE_IP` | `192.0.2.10` (пример) | адрес сервера в его сети (интерфейс); установщик определяет, обновление проверяет; обязателен |
| `LIVEKIT_PUBLIC_IP` | `auto` | публичный адрес для пользователей из интернета: `auto` (адрес на интерфейсе или STUN за NAT), `off` (только локальная сеть) или IPv4; применить — `sudo scripts/medianet.sh apply` |
| `LIVEKIT_STUN_SERVERS` | `stun.cloudflare.com:3478,global.stun.twilio.com:3478,stun.l.google.com:19302` | серверы STUN (host:port через запятую) по порядку до первого ответившего; если не ответил ни один — встроенные. Их же получают браузеры |
| `LIVEKIT_IP_RECHECK` | `300` | как часто (секунды) сервер звонков за NAT заново определяет публичный адрес; `0` — не проверять |
| `LIVEKIT_MEDIA_MODE`, `LIVEKIT_RTC_*` | вычисляются | режим (`direct`, `nat-stun`, `nat-manual`, `lan`) и производные настройки LiveKit; пишет `scripts/medianet.py`, вручную не менять |
| `LIVEKIT_PUBLIC_URL` | `wss://meet.example.org/livekit` (пример) | адрес сигналинга для браузера |
| `LIVEKIT_TOKEN_TTL_SECONDS` | `300` | срок токена подключения |
| `LIVEKIT_ROOM_DEPARTURE_TIMEOUT`, `LIVEKIT_ROOM_EMPTY_TIMEOUT` | `60`, `300` | сколько секунд комната открыта после ухода всех и пустая |
| `LIVEKIT_IMAGE_TAG` | `v1.13.10` | проверенная версия; не `latest` |
| `HOST_NETDEV` | закомментирован, `/proc/1/net/dev` | счётчики сети сервера для диагностики эфира; `/dev/null` отключает |

Порты автоматически не занимаются; их проверяет `preflight.sh`. Точный перечень правил по вашему `.env` — `scripts/ports.sh` и раздел «Сетевая доступность» ([Как опубликовать сервис в интернете](Как-опубликовать-сервис-в-интернете)).

Для раздела «Сетевая доступность» compose передаёт контейнеру `backend` служебные значения `NET_INSTALL_PROFILE`, `NET_LIVEKIT_BIND_ADDR`, `NET_LIVEKIT_HTTP_PORT`, `NET_WEB_BIND_ADDR`, `NET_WEB_PORT`, `NET_NGINX_LISTEN_PORT`, `NET_SIP_BIND_ADDR` (копии параметров выше; секретов в них нет). В `.env` их задавать не нужно.

## Секреты и базы

| Параметр | Назначение |
| --- | --- |
| `APP_MASTER_KEY` | base64 от 32 случайных байт (`openssl rand -base64 32`); шифрует секреты в БД. **Потеря означает потерю зашифрованных настроек. На работающем сервере не меняйте:** зашифрованные данные перестанут читаться, а выданные ссылки эфира станут недействительными. Вписывать ключ из копии нужно только при восстановлении |
| `INTERNAL_API_TOKEN` | токен внутренних вызовов (`openssl rand -hex 32`) |
| `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | ключ и секрет LiveKit; секрет не короче 32 символов |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | база; не публикуется наружу. Пароль задаётся при первом создании базы: простая правка в `.env` его не меняет, и приложение перестанет подключаться |
| `POSTGRES_MAX_CONNECTIONS` | `300`; установщик подбирает по числу vCPU |
| `POSTGRES_IDLE_IN_TX_MS` | не задан, `0`; тайм-аут простоя транзакции на стороне PostgreSQL, выключен |
| `BACKEND_WORKERS` | `1`; установщик подбирает по числу vCPU. Выбор значения — [Производительность и масштабирование](Производительность-и-масштабирование) |
| `REDIS_PASSWORD` | пароль Redis |

## Active Directory (прежний способ, необязательно)

`LDAP_URIS` (только `ldaps://`, несколько через запятую), `LDAP_BASE_DN`, `LDAP_BIND_DN`, `LDAP_BIND_PASSWORD`, `LDAP_CA_FILE`, `LDAP_LOGIN_ATTRIBUTE` (`sAMAccountName`), `LDAP_DISPLAY_NAME_ATTRIBUTE` (`displayName`), `LDAP_ADMIN_GROUP_DN`, `LDAP_ACCESS_GROUP_DN` (пусто — любой доменный пользователь), `LDAP_TIMEOUT_SECONDS` (`5`). Начиная с 0.3.0 настраивается в браузере; значения из `.env` работают как «основное подключение».

## Сессии и защита входа

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `COOKIE_SECURE` | `true` | флаг Secure |
| `TRUSTED_PROXY_HOPS` | `1` | сколько прокси перед контейнером web добавляют `X-Forwarded-For` (значение по умолчанию; в «Безопасность → Сеть и IP-адреса» можно переопределить) |
| `TRUSTED_PROXY_CIDRS` | `127.0.0.0/8,::1/128` | адреса доверенных прокси, пропускаемые справа налево (то же: можно переопределить в админке) |
| `ALLOWED_ORIGINS` | пусто | дополнительные адреса (`схема://хост[:порт]`, без пути) |
| `IP_ACCESS_DISABLE` | `0` | аварийно: `1` выключает ограничение по доверенным подсетям после перезапуска `backend`. Есть и команда `scripts/security-reset.sh`. После работ уберите |
| `SESSION_IDLE_TIMEOUT_SECONDS`, `SESSION_ABSOLUTE_TIMEOUT_SECONDS` | `28800`, `86400` | неактивность и предельная жизнь сеанса |

## Хранение и фоновые задачи

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `DEFAULT_TEXT_RETENTION_DAYS` | пусто | срок не определяет: действуют общие сроки сервера (Общие настройки → Сроки хранения материалов). Значение только запоминается у новой временной комнаты и в паспорте встречи |
| `DEFAULT_AUDIO_RETENTION_DAYS` | `60` | то же для аудио |
| `MEETING_END_GRACE_SECONDS` | `60` | задержка до автоматического завершения встречи после ухода последнего |
| `VOLUME_ALLOWED_ROOTS` | закомментирован, `/mnt:/media:/srv` | откуда разрешено подключать [внешние тома](Внешние-тома), через двоеточие; из браузера не расширить |
| `HEAVY_CONCURRENCY` | `2` | число тяжёлых фоновых задач одновременно; 0 — по ядрам и памяти |
| `HEAVY_MAX_DEFER_SECONDS` | `1800` | сколько ждать, пока идёт встреча и сервер занят |

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `BACKUP_DIR` | `/srv/peregovorka-data/backups` | локальный путь; UNC и `smb://` отвергаются |

## Обслуживание диска при обновлении

Параметры закомментированы в шаблоне, значения по умолчанию подходят большинству серверов.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `UPD_MIN_FREE_GB` | `15` | сколько должно быть свободно на диске Docker для сборки |
| `UPD_BUILD_CACHE_MAX_GB` | `20` | больший кэш сборки подрезается и при достатке места |
| `UPD_BUILD_CACHE_KEEP_DAYS` | `7` | неиспользуемый кэш старше удаляется первым |
| `UPD_BUILD_CACHE_KEEP_GB` | `8` | до какого размера подрезается кэш при нехватке места |
| `UPD_KEEP_IMAGE_VERSIONS` | `2` | сколько новых версий образов хранить сверх работающей и версии отката |
| `UPD_DISK_MAINTENANCE` | включено | `0` выключает очистку; на общем сервере это отключает и действие на общий кэш Docker |

Обычно менять их не нужно. Для проверок Outlook проще положить файл в `DATA_ROOT/ca/outlook-ca.pem`, см. [Как настроить сертификаты](Как-настроить-сертификаты).
