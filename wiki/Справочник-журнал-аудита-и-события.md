# Справочник: журнал аудита и события

*Для кого: администратор, служба ИБ, техническая поддержка.*

В системе четыре журнала с разным назначением:

| Журнал | Для чего | Где |
| --- | --- | --- |
| Журнал аудита | Кто, что и когда изменил, для расследований | **Администрирование → Безопасность → Журнал аудита** |
| События безопасности | Атаки и срабатывания защиты | **Администрирование → Безопасность → События и блокировки** |
| Журнал событий | Диагностика работы | **Администрирование → Хранение и журналы → Журнал событий** |
| История действий комнаты | События одной комнаты для её руководителя | Страница встречи, вкладка **История действий** |

Пароли, токены, ключи и содержимое документов и разговоров в журналы не попадают.

## Журнал аудита

Просмотр, выгрузка и проверка доступны только администраторам. Вручную записи не удаляются.

### Поля записи

В выгрузке столбцы называются так:

| Столбец | Содержимое |
| --- | --- |
| `timestamp` | Время в UTC |
| `event_type` | Действие |
| `actor_id`, `actor_name` | Исполнитель |
| `actor_type` | `user`, `guest`, `system`, `service` |
| `source_ip`, `user_agent` | Откуда выполнено |
| `session_id` | Необратимый отпечаток сеанса, а не сам идентификатор |
| `object_type`, `object_id` | Объект |
| `result` | `success`, `denied`, `failure` |
| `request_id` | Связь с техническим журналом |
| `details` | Подробности, очищенные от секретов |

В `auth.login_failed` поле `details.code` называет причину отказа. Коды перечислены ниже.

### Фильтры и выгрузка

Фильтры на странице: поиск, **Кто выполнил**, **Действие, например room.**, результат, тип исполнителя, **Тип объекта**, **IP**, период.

Кнопки **CSV** и **JSON** выгружают записи по текущим фильтрам, до 100 000 записей. CSV идёт с BOM для Excel. Ячейки, начинающиеся с `=`, `+`, `-`, `@`, экранируются. Сама выгрузка записывается в аудит.

### Целостность

Каждая запись подписана HMAC-SHA256 ключом, производным от `APP_MASTER_KEY`.

Кнопка **Проверить целостность** находит изменённые записи и пропуски в нумерации. Записи без подписи считаются отдельно.

Проверка не видит удаление самых свежих записей и подмену одновременно ключа и базы. Без `APP_MASTER_KEY` проверка невозможна.

### Срок хранения

**Хранение и журналы → Хранение журнала**, поле **Хранить журнал аудита**. Значение 0 используется по умолчанию и означает «не удалять». Если задать срок, записи старше него удаляются раз в час вместе с журналом событий. Удаляется только начало журнала, поэтому проверка целостности остаётся чистой.

## События безопасности

Страница показывает сводку за сутки и таблицу. Значимые события дублируются в журнал событий с категорией `security`.

| Событие | Подпись в интерфейсе |
| --- | --- |
| `login_failed` | Неудачная попытка входа |
| `login_blocked` | Вход отклонён защитой от перебора |
| `captcha_required` | Показана CAPTCHA |
| `captcha_passed` | CAPTCHA пройдена |
| `captcha_failed` | CAPTCHA не пройдена |
| `ip_blocked` | Адрес заблокирован автоматически |
| `ip_blocked_manual` | Адрес заблокирован администратором |
| `ip_unblocked` | Блокировка адреса снята |
| `limit_shared` | Общий адрес: блокировка заменена CAPTCHA |
| `access_denied_net` | Отказ: адрес вне разрешённых подсетей |
| `blocked_ip_request` | Запрос заблокированного адреса |
| `waf_hit` | Срабатывание правила WAF |
| `permission_denied` | Ошибка проверки прав (403) |
| `ip_access_changed` | Изменено ограничение по подсетям |
| `security_settings_changed` | Изменены настройки безопасности |

Значения в колонке **Правило**:

| Правило | Что значит |
| --- | --- |
| `ip_failures` | Много неудач с адреса за окно подсчёта |
| `spray` | Попытки входа в много разных учётных записей с одного адреса |
| `account_guard` | По записи много неудач, незнакомые адреса не доходят до каталога |
| `rate_ip` | Слишком много запросов ко входу в минуту |
| `manual` | Заблокировано администратором |
| `allowed_networks` | Адрес вне разрешённых подсетей |
| `ip_block` | Запрос от заблокированного адреса |
| `waf:<правило>` | Правило WAF, например `waf:path_traversal` |
| `waf_api_probe` | Блокировка за перебор путей |
| `captcha:<назначение>` | CAPTCHA для `login`, `guest` или `temp_room` |

Частота записи ограничена: не больше 240 событий в минуту на процесс, не больше 20 неудачных входов в минуту на адрес. Отказы по подсетям, блокировкам и срабатывания WAF пишутся не чаще раза в минуту на адрес и правило. `permission_denied` пишется раз в минуту на адрес и путь. Пропущенные события считаются, и сводка показывает их число.

Выгрузка CSV и JSON: не больше 50 000 строк, событие `security.events.export`. Срок и размер задаёт **Хранение журнала безопасности**: 30 дней и 200 000 строк по умолчанию, очистка раз в час.

## Журнал событий

Откройте **Администрирование → Хранение и журналы → Журнал событий**. Подробности работы: [Мониторинг и журналы](Мониторинг-и-журналы).

| Категория | Подпись | События |
| --- | --- | --- |
| `auth` | вход | `login_ok`, `login_failed`, `login_denied_acl`, `login_locked`, `totp_failed`, `logout`, `ldap_test`, `access_check` |
| `security` | без подписи | Копии значимых событий безопасности |
| `room` | комнаты | `join`, `join_denied`, `leave`, `join_attempt`, `join_ok`, `join_failed`, гостевые входы, действия модератора |
| `network` | сеть и подключение | Обрывы и повторные подключения, `ice_failed`, `ice_slow`, `network_info` |
| `device` | оборудование | Занятый или недоступный микрофон и камера, отказ браузера в разрешениях, `device_inventory` |
| `client` | клиент | Показ экрана, вложения чата и другие события браузера |
| `llm` | протоколы и LLM | Создание протоколов, проверки профилей API |
| `storage` | хранилище | `chat_file_save_failed`, `storage_unavailable`, `meeting_mix_failed`, `recording_export_failed`, сверка и перенос |
| `admin` | администрирование | Зеркало записей журнала аудита |
| `system` | система | Запуск приложения, запросы обновлений и исправлений |
| `mail` | без подписи | Проверка профиля и тестовая отправка |
| `live` | без подписи | Узлы CDN и диагностика эфира |
| `outlook`, `sip`, `api`, `profile` | без подписи | События интеграций, телефонии, webhooks и обогащения профилей |

Запись `page.image_failed` относится к журналу приложения для Windows на устройстве, а не к журналу сервера.

Срок хранения задаёт поле **Хранить записи журнала**, по умолчанию 30 дней. Очистка выполняется раз в час, кнопка **Применить срок хранения** запускает её сразу. Администратор может удалить выбранные записи. Такие удаления сами записываются в журнал аудита.

Журнал можно дублировать файлами NDJSON в файловое хранилище. Выгрузка за сутки или 30 дней создаёт ZIP с файлами `journal.csv`, `journal.ndjson` и `audit.csv`.

## История действий комнаты

Откройте страницу встречи и вкладку **История действий**. Вкладка доступна администратору и руководителю комнаты. Обычному участнику журнал недоступен.

Вкладка собирает записи аудита этой комнаты, письма с результатом доставки, начало и завершение встреч. Типы событий: **Участники**, **Встреча**, **Доступ**, **Материалы**, **Рассылка**, **Настройки**, **Файлы**. Фильтры: период, **Тип**, **Пользователь**.

## Коды отказа входа

Код виден в `details.code` записи `auth.login_failed` и в данных записи `login_failed` журнала событий. Что делать при каждом отказе: [Решение проблем: вход и каталог](Решение-проблем-входа-и-каталога).

| Код | Что значит |
| --- | --- |
| `invalid_credentials` | Неверный логин или пароль |
| `account_locked` | Запись заблокирована в домене |
| `account_disabled` | Запись отключена или просрочена в каталоге |
| `password_expired` | Срок действия пароля истёк |
| `password_must_change` | В домене требуется смена пароля |
| `account_restriction` | Вход ограничен политикой домена |
| `account_disabled_local` | Запись отключена администратором Peregovorka |
| `not_configured` | Каталог не подключён |
| `directory_unavailable` | Каталог недоступен, ошибка TLS или сервисной записи |
| `throttled` | Вход отклонён защитой от перебора, событие `auth.login_locked`. Большинство таких отказов происходит раньше проверки пароля: они попадают только в события безопасности как `login_blocked` |
| `access_denied` | Пароль верен, но нет разрешения на вход, событие `auth.login_denied` |
| `protection_unavailable` | Недоступно хранилище счётчиков |

Запись журнала событий `login_denied_acl` появляется при `access_denied`. Причины видны в её тексте: пользователь не входит в разрешённую группу или подключение каталога не предназначено для входа пользователей.

Точную причину недоступности каталога показывает журнал контейнера backend: поле `directory_code` со значениями `tls_error`, `service_account_error`, `server_unavailable`.

Коды публичного API: `invalid_api_key`, `key_revoked`, `key_expired`, `ip_not_allowed` ([Справочник: публичный API](Справочник-публичный-API)).
