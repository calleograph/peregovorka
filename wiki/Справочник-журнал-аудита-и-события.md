# Справочник: журнал аудита и события

> Относится к версии 0.39.4 · проверено 2026-10-25 · уровень проверки: 1–2 (код и документы `docs/AUDIT_LOG.md`, `docs/JOURNAL_AND_SECURITY.md`; тесты) · тип страницы: справочник

В системе два журнала с разным назначением: **журнал аудита** (кто, что и когда изменил; для расследований) и **журнал событий** (диагностика). Пароли, токены, ключи и содержимое документов в них не попадают.

## Журнал аудита

Раздел: **Администрирование → Безопасность → Журнал аудита**. Просмотр, выгрузка и проверка доступны только администраторам.

### Что записывается

| Область | События (`action`) |
| --- | --- |
| Вход | `auth.login`, `auth.login_failed`, `auth.login_denied`, `auth.login_locked`, `auth.logout`, `auth.totp_failed`, `auth.backup_code_used`, `captcha.rejected` |
| Двухфакторная защита | `auth.totp_enable`, `auth.totp_disable`, `auth.totp_backup_regenerate`, `auth.totp_reset` |
| Комнаты и встречи | `meeting.join`, `meeting.join_denied`, `meeting.leave`, создание, изменение и удаление комнат, завершение встречи, выдача и отзыв доступа, `room.manage.update`, `room.guest_link.*`, `room.create_peer`, `room.update_peer`, `room.rotate_peer`, `room.close_peer` |
| Материалы | `protocol.export`, `transcript.download`, `chat_file.download`, `board.download`, скачивание аудио, удаление протоколов и записей, `meeting.materials.send` |
| Пользователи и каталог | `user.activate`, `user.deactivate`, `ldap.create`, `ldap.update`, `ldap.delete`, `ldap.legacy_import`, `ca.add`, `ca.delete`, `local_admin.*` |
| Настройки | `settings.<группа>.update` (секреты заменены), `config.export`, `config.import`, `setup.check` |
| Резервные копии | `backup.create`, `backup.verify`, `backup.download`, `backup.key_create`, `backup.settings` |
| Шифрование | `crypto.rotate`, `crypto.reseal`, `room.update` (поле `encrypt_storage`) |
| Профили | `profile.edit`, `profile.restore` |
| Чаты | создание и переименование группы, добавление и исключение участников, роли, выход, удаление сообщения (без текста), скачивание документа, изменение настроек «Чаты» |
| Outlook | `outlook.token`, `outlook.create`, `outlook.sync`, `outlook.reschedule`, `outlook.cancel`, `outlook.package`, `outlook.sync_test`, `outlook.sync_run` |
| API | действия интеграций записываются как `api:<название интеграции>`; создание, замена, отзыв ключей, правка прав |
| Сам аудит | `audit.export`, `audit.verify` |

### Поля записи

`timestamp` (UTC), `event_type`, `actor_id`, `actor_type` (`user`, `guest`, `system`, `service`), `actor_name`, `source_ip`, `user_agent`, `session_id` (необратимый отпечаток), `object_type`, `object_id`, `result` (`success`, `denied`, `failure`), `request_id` (связь с техническим журналом), `details`.

### Фильтры и выгрузка

Фильтры: исполнитель, действие, результат, тип исполнителя и объекта, IP, период, произвольный текст. Выгрузка в CSV (с BOM для Excel; ячейки, начинающиеся с `= + - @`, экранируются) или JSON, не более 100 000 записей; сама выгрузка записывается в аудит.

### Целостность

Каждая запись подписана HMAC-SHA256 (ключ производный от `APP_MASTER_KEY`). «Проверить целостность» находит изменённые записи и пропуски в нумерации. **Не видит:** удаление самых свежих записей и подмену одновременно ключа и базы. Записи старше версии 0.20 (до подписи) считаются отдельно.

### Срок хранения

«Хранение и журналы → Хранение журнала → Хранить журнал аудита». `0` (по умолчанию) — не удалять; иначе записи старше срока удаляются раз в час вместе с журналом событий (удаляется только начало, проверка целостности остаётся чистой).

## Журнал событий

Раздел: **Администрирование → Хранение и журналы → Журнал событий**. Подробности работы — [[Мониторинг и журналы|Мониторинг-и-журналы]].

| Категория | События |
| --- | --- |
| `auth` | входы, отказы, блокировки, выход |
| `room` | вход и выход из комнат, отказы |
| `network` | обрывы, повторные подключения, ICE (`ice_failed`, `ice_slow`), сведения о сети |
| `device` | занятый или недоступный микрофон и камера, отказ браузера в разрешениях, список устройств |
| `client` | показ экрана и другие события браузера |
| `llm` | создание протоколов (профили API, было ли обезличивание), проверки API |
| `storage` | ошибки выгрузки записей (`chat_file_save_failed`, `storage_unavailable`) |
| `admin` | зеркало действий администраторов |
| `system` | запуск приложения |

Срок хранения по умолчанию 30 дней; очистка раз в час. Событие `meeting_mix_failed` показывает сбой формирования общей аудиозаписи, `page.image_failed` в журнале приложения для Windows — сбой загрузки картинки страницы.

## Коды отказа входа

В журнале backend: `invalid_credentials`, `account_locked`, `tls_error`, `service_account_error`, `login_denied_acl`; для API: `invalid_api_key`, `key_revoked`, `key_expired`, `ip_not_allowed` ([[Справочник: публичный API|Справочник-публичный-API]]).
