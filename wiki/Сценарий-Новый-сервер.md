# Сценарий: новый сервер

*Для кого: администратор, который вводит Peregovorka в работу.*

## Зачем это нужно

Сценарий ведёт от пустого сервера до работающей системы. Команды и подробности лежат в инструкциях по ссылкам, здесь порядок и то, что проверить на каждом этапе.

## Когда пригодится

- Первая установка в организации.
- Отдельный сервер для пилота.

Если система уже работала и сервер потерян, идите по странице [Сценарий: восстановление после сбоя](Сценарий-Восстановление-после-сбоя).

## Что потребуется

- Сервер по странице [Системные требования](Системные-требования).
- Права `sudo`, доступ сервера в интернет или план для закрытой сети.
- DNS-имя и сертификат для рабочей эксплуатации.
- Доступ к межсетевому экрану и маршрутизатору.
- Второе устройство для пробной встречи.

Нагрузку заранее оцените по странице [Производительность и масштабирование](Производительность-и-масштабирование): вместимость всей системы испытаниями не подтверждена.

## Где найти

Этапы 1–4, 6 и 8 выполняются в терминале сервера. Этапы 5 и 7 — в браузере: **Администрирование**.

## Как это сделать

### Этап 1. Выбрать способ установки

| Ваш случай | Инструкция |
| --- | --- |
| сервер только под Peregovorka | [Установка на чистый сервер](Установка-на-чистый-сервер), профиль `standalone` |
| на сервере уже работают другие приложения | [Установка на общий сервер](Установка-на-общий-сервер), профиль `shared-host` |

### Этап 2. Установить

Для выделенного сервера:

```bash
wget -O install.sh https://raw.githubusercontent.com/calleograph/peregovorka/main/install.sh
chmod +x install.sh
sudo ./install.sh --host meet.example.org
```

**Проверка.** Блок «УСТАНОВКА ЗАВЕРШЕНА» с адресом, логином `admin` и первичным паролем. Пароль показывается один раз.

### Этап 3. Сохранить ключ и проверить систему

1. Скопируйте `/opt/peregovorka/.env` в сейф паролей. Файл читается только через `sudo`: `sudo cat /opt/peregovorka/.env`. Без `APP_MASTER_KEY` зашифрованные настройки не восстановить.
2. Выполните проверки:

   ```bash
   cd /opt/peregovorka
   sudo scripts/status.sh
   sudo scripts/verify.sh
   sudo scripts/smoke-test.sh
   ```

**Проверка.** «Все сервисы работают», `Peregovorka deployment verified`, `Smoke test: PASS`. Предупреждения про TLS на этом этапе допустимы: сертификат пока самоподписанный.

### Этап 4. Настроить адрес и сеть

1. Поставьте сертификат: [Как настроить сертификаты](Как-настроить-сертификаты).
2. Откройте порты медиа: [Как настроить LiveKit](Как-настроить-LiveKit).

**Проверка.** Браузер открывает сайт без предупреждения, `sudo scripts/medianet.sh check` без ошибок.

### Этап 5. Войти и настроить интеграции

Войдите как `admin` и задайте новый пароль: не короче 12 символов, не менее двух видов символов, без имени пользователя. Откроется окно **Первоначальная настройка**: каждый шаг в нём можно пропустить, а окно закрыть кнопкой **Закрыть и не показывать снова**. Подключайте только нужное:

| Что | Инструкция |
| --- | --- |
| вход сотрудников | [Как подключить Active Directory](Как-подключить-Active-Directory) |
| кто может войти и кто администратор | [Управление пользователями](Управление-пользователями) |
| комнаты и доступ к ним | [Как настроить переговорки и доступ](Как-настроить-переговорки-и-доступ) |
| почта | [Как подключить почту](Как-подключить-почту) |
| языковая модель для протоколов | [Как настроить языковые модели](Как-настроить-языковые-модели) |
| обезличивание | [Как настроить обезличивание](Как-настроить-обезличивание) |
| файловые хранилища | [Подключение внешних хранилищ](Подключение-внешних-хранилищ) |
| видеозапись и эфиры | [Как настроить видеозапись и трансляции на сервере](Как-настроить-видеозапись-и-трансляции-на-сервере) |
| телефония | [Как подключить SIP-телефонию](Как-подключить-SIP-телефонию) |

**Проверка.** В **Обзор → Обзор** блок **Требует внимания** пуст или содержит только понятные вам пункты.

### Этап 6. Включить резервные копии

```bash
cd /opt/peregovorka
sudo scripts/backup.sh --full
```

Задайте расписание и копию вне сервера: [Резервное копирование и аварийное восстановление](Резервное-копирование-и-аварийное-восстановление).

**Проверка.** Строка `Резервное копирование завершено.`, копия лежит вне сервера.

### Этап 7. Провести пробную встречу

1. Создайте комнату: [Как создать комнату](Как-создать-комнату).
2. Проведите встречу с двух устройств. Один участник подключается из той сети, где будут ваши пользователи. Если каталога ещё нет, второй участник входит по гостевой ссылке: шаги 7–8 страницы [Быстрый старт](Быстрый-старт).
3. Получите стенограмму и протокол: [Сценарий: получение протокола](Сценарий-Получение-протокола).

**Проверка.** Участники слышат друг друга, появляются реплики, протокол сформирован.

### Этап 8. Проверить обновление

```bash
cd /opt/peregovorka
sudo scripts/updater.sh status
sudo scripts/check-updates.sh
sudo scripts/update.sh --dry-run
```

**Проверка.** Строка «Исполнитель работает», напечатан план обновления или `Новых commit'ов нет — установка на актуальной версии.`. Ничего не изменилось.

## Что получится

Рабочая система: HTTPS на вашем имени, звонки из нужных сетей, стенограмма и протокол, регулярные копии, понятный порядок обновления. Запишите параметры в паспорт экземпляра: [шаблон](https://github.com/calleograph/peregovorka/blob/main/docs/STAND_PASSPORT_TEMPLATE.md).

## Если не получается

| Этап | Симптом | Что сделать |
| --- | --- | --- |
| 2 | установка остановилась | запустите ту же команду снова, строка `FAIL` называет причину: [Установка на чистый сервер](Установка-на-чистый-сервер) |
| 3 | сервис нездоров | [Как управлять службами](Как-управлять-службами), [Диагностика](Диагностика) |
| 4 | сайт есть, звука нет | [Решение проблем: звонки и сеть](Решение-проблем-звонков-и-сети) |
| 5 | «Недопустимый Origin» | [Решение проблем: HTTPS и обратный прокси](Решение-проблем-HTTPS-и-прокси) |
| 7 | нет реплик | [Как настроить распознавание речи](Как-настроить-распознавание-речи) |
| 7 | нет протокола | [Как настроить языковые модели](Как-настроить-языковые-модели) |
