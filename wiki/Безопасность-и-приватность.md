# Безопасность и приватность

Страница описывает механизмы защиты, границы доверия и известные риски. Каждое утверждение названо механизмом и уровнем проверки ([Как читать эту вики](Как-читать-эту-вики)). Слова «безопасно» и «надёжно» без механизма здесь не используются. Порядок сообщения об уязвимостях — [Политика безопасности](Политика-безопасности).

## Что проверялось

Разработчики провели внутренний аудит по собственному чек-листу OWASP Top 10 и OWASP API Security Top 10 (чтение кода, конфигурации Docker Compose и nginx, тесты, `npm audit`, `pip-audit`, сканирование репозитория на частные данные, проверочная «атака» на тестовый сервер через публичный API: 26 проверок). **Независимого внешнего аудита и тестирования на проникновение нет.** Отчёт и перечень найденного и исправленного — `docs/SECURITY_AUDIT.md` в репозитории.

## Какие данные хранятся и куда уходят

| Данные | Где | Уходит наружу |
| --- | --- | --- |
| Записи, стенограммы, чаты, протоколы, пароли | ваш сервер (PostgreSQL, `DATA_ROOT`, выбранный SMB) | нет |
| Модели распознавания и локальная языковая модель | ваш сервер | нет (загрузка при установке) |
| Текст встречи для протокола | локальная модель на сервере | при выборе внешней модели — на её адрес, **после обезличивания, если оно включено**; при выключенном обезличивании текст уходит как есть, и окно «Сформировать протокол» предупреждает |
| Профиль сотрудника | из AD при входе; из Bitrix24 только чтение | нет |
| Аутентификационные данные | пароль передаётся в AD как значение и нигде не сохраняется | нет |

Распознавание речи и локальная модель не обращаются в интернет. Внешние STUN и TURN не используются. Единственные обращения в сеть после установки — те, что вы сами подключили (каталог, почта, SMB, внешняя модель, обезличиватель, портал Bitrix24, получатели событий, АТС). Уровень 1.

## Вход и сессии

| Механизм | Описание | Уровень |
| --- | --- | --- |
| LDAPS с проверкой цепочки и имени | `ssl.CERT_REQUIRED`; «мягкого» режима нет; пароль проверяется bind от имени найденного DN | 1–2 |
| Серверные сессии | в Redis; cookie `HttpOnly`, `SameSite=Lax`, `Secure` по настройке; идентификатор случайный | 1–2 |
| CSRF и Origin | токен CSRF на изменяющих запросах и обязательная проверка заголовка `Origin` по списку из `.env`; отключить проверку нельзя | 1–2 |
| Перебор паролей | блокировка по логину и по IP без обращения к AD; CAPTCHA после серии неудач | 2–3 |
| Двухфакторная защита | TOTP RFC 6238, резервные коды, политика по группам; секрет шифруется AES-256-GCM | 2–3 |
| Допуск по группам AD | пока список допуска пуст, входит любой активный пользователь каталога | 2 |
| Сеансы | таймауты неактивности (8 часов) и предельной жизни (24 часа); до 5 сеансов на учётную запись | 2 |
| Приложение для Windows | отзываемый токен устройства под защитой DPAPI; пароль не хранится | 2–3 |

## Права и изоляция

- Права проверяются на сервере; запрет публикации дополнительно в токене LiveKit. Роли — [Справочник: роли и права](Справочник-роли-и-права).
- Публичный API: ключ хранится как SHA-256, сравнение за постоянное время, область комнат, права на каждый маршрут, чужие объекты отвечают как несуществующие, лимиты и идемпотентность.
- Webhooks: подпись HMAC-SHA256 с меткой времени, защита от SSRF (проверка всех IP при сохранении и при каждой отправке, запрет частных сетей и метаданных облака), редиректы не выполняются.
- Контейнеры: PostgreSQL, Redis, ASR и `llm-local` не публикуются; `llm-local` в сети без выхода наружу; backend и ASR работают от uid 10001; `no-new-privileges` у backend, web и redis. `cap_drop` и `read_only` **не** включены (не проверялись на реальном Docker).
- Доска draw.io и карта разговора встраиваются в `iframe sandbox` без доступа к cookie и API.
- Вложения чата: тип определяется по содержимому, исполняемые и «активные» расширения запрещены, ответы с `nosniff` и CSP `default-src 'none'; sandbox`.

## Секреты

Пароли и ключи хранятся в `.env` (права 600) и зашифрованно в БД (AES-GCM; ключ `APP_MASTER_KEY`). Скрипты, журналы и диагностика маскируют секреты; `diag.sh` не создаёт архив, если находит секрет. В репозиторий не попадают частные данные: сканер `scripts/check_private_data.py` запускается в CI. Закрытые ключи и сертификаты подписи не попадают в установочные пакеты (проверка в CI). Уровень 2.

## Журналы и аудит

Журнал событий и журнал аудита не содержат паролей, ключей, токенов и содержимого разговоров. Аудит подписан HMAC; проверка целостности не обнаруживает удаление самых свежих записей и подмену ключа вместе с базой ([Справочник: журнал аудита и события](Справочник-журнал-аудита-и-события)). Уровень 2.

## Обновление и привилегии

Обновление из браузера выполняет помощник на хосте от root. Он принимает запрос из фиксированного белого списка действий; значения проверяются шаблонами, окружение дочерних команд стерильно, запрос живёт не более 10 минут и принимается только от root, самого исполнителя или пользователя контейнера backend (исправлено по итогам внутреннего аудита). Произвольных команд из браузера нет. На общем сервере любой локальный пользователь не может запросить действие через каталог обмена.

## Шифрование

Защита соединения (TLS), транспортное шифрование звонка (DTLS-SRTP), шифрование чата и стенограмм в базе (AES-256-GCM) и сквозное шифрование звука и видео описаны на странице [Шифрование](Шифрование). Граница доверия: сервер расшифровывает данные в памяти, чтобы показать их пользователям.

## Известные риски и ограничения

| Риск | Состояние |
| --- | --- |
| HSTS не включён | намеренно: сначала проверка цепочки HTTPS на вашем сервере ([Как настроить reverse proxy и HTTPS](Как-настроить-reverse-proxy-и-HTTPS)) |
| Ограничения частоты на уровне nginx нет | защита в backend по логину и IP; общий NAT делает лимиты nginx вредными |
| Ранняя история публичного репозитория содержит организационные имена | в двух ранних коммитах 2026-10-06 остались имя домена, структура DN, имя служебной учётной записи (без пароля), частный адрес; из рабочего дерева удалены; история не переписывалась без решения владельца |
| Зависимости заданы точными версиями, проверка уязвимостей по OSV при выпуске | при выпуске выполняется `deps.py verify --online`; закрытие найденных уязвимостей — через ревизию |
| Админ сервера | видит содержимое в памяти; защита хранилища не защищает от владельца сервера |
| Публичный API: скачивание очень больших записей | файл читается целиком в память; потоковой отдачи нет |
| Приложение для Windows | предварительный выпуск, установщики не подписаны сертификатом издателя; сборка предупреждена SmartScreen |
| Нагрузочные испытания безопасности | не проводились |
