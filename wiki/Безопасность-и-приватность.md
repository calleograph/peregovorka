# Безопасность и приватность

*Для кого: администратор, служба ИБ, руководитель, принимающий решение о внедрении.*

Страница описывает механизмы защиты, границы доверия и известные риски. Каждое утверждение названо механизмом, а не общими словами. Настройка входа описана отдельно: [Как настроить безопасность входа](Как-настроить-безопасность-входа). Сведения для приёмки собраны в статье [Справочник для проверки ИБ](Справочник-для-проверки-ИБ). Как сообщить об уязвимости: [Политика безопасности](Политика-безопасности).

## Что проверялось

Разработчики провели внутренний аудит по собственному чек-листу OWASP Top 10 и OWASP API Security Top 10. Он охватил версии 0.8.5 и 0.9.0: чтение кода, конфигурации Docker Compose и nginx, тесты, `npm audit`, `pip-audit`, сканирование репозитория на частные данные и проверочную атаку на публичный API из 26 проверок. Отчёт: `docs/SECURITY_AUDIT.md` в репозитории.

Защита входа, подсети и встроенный WAF появились позже. Их проверяли автотестами и сценариями в браузере на тестовом экземпляре.

**Независимого внешнего аудита и теста на проникновение нет.** Записей о них в проекте нет. Соответствие отраслевым стандартам и сертификация не заявляются. Что не подтверждено на настоящих системах: [Что проверено](Границы-проверки).

## Какие данные хранятся и куда уходят

| Данные | Где | Уходит наружу |
| --- | --- | --- |
| Записи, стенограммы, чаты, протоколы | Ваш сервер: PostgreSQL, `DATA_ROOT`, выбранные хранилища | Нет, кроме подключённых вами рассылок и хранилищ |
| Модели распознавания речи и имён | Ваш сервер | Нет. Загружаются при установке и сборке |
| Текст встречи для протокола | Языковая модель по API, которую подключил администратор | Да, на адрес модели. Пароли, токены и ключи маскируются всегда. Имена, контакты и реквизиты маскируются, если обезличивание включено в комнате или обязательно. Окно **Сформировать протокол** заранее показывает, будет ли обезличивание |
| Профиль сотрудника | Из каталога при входе, из Bitrix24 только чтение | Нет |
| Пароль сотрудника | Передаётся контроллеру домена при входе и нигде не сохраняется | Только в каталог |

Распознавание речи и обезличивание не обращаются в интернет. После установки сервер обращается только к тому, что вы подключили: каталог, почта, хранилища, языковая модель, Bitrix24, получатели событий, АТС, площадки трансляций. Есть ещё проверки обновлений и версий компонентов. Сервер STUN используется только для определения публичного адреса за NAT ([Справочник: порты и сеть](Справочник-порты-и-сеть#адреса-для-звука-и-видео-nat)). TURN не используется. Полный перечень: [Справочник для проверки ИБ](Справочник-для-проверки-ИБ).

## Вход и сеансы

| Механизм | Как работает |
| --- | --- |
| LDAPS или STARTTLS с проверкой цепочки и имени | Сертификат проверяется обязательно, режима без проверки нет. Пароль проверяется входом от имени найденного пользователя |
| Серверные сеансы | Хранятся в Redis. В Redis ключом служит хэш идентификатора, поэтому дамп Redis не даёт готовых cookie |
| Cookie | `HttpOnly`, `SameSite=Lax`, `Secure` по настройке `COOKIE_SECURE`, значение случайное |
| CSRF и Origin | Изменяющие запросы требуют токен CSRF. Заголовок Origin, если он есть, сверяется со списком разрешённых адресов. Отключить проверку нельзя |
| Защита от перебора | Счётчики в Redis по записи, адресу, их паре и частоте. CAPTCHA, замедление, защита каталога, временная блокировка адреса. Учётная запись целиком не блокируется |
| Двухфакторная защита | TOTP по RFC 6238, резервные коды, политика по ролям и группам. Секрет зашифрован AES-256-GCM, резервные коды хранятся как HMAC-SHA256 |
| Допуск по группам каталога | Проверяется после пароля. Пока список допуска пуст, входит любой активный пользователь каталога |
| Сроки сеанса | 8 часов без активности и 24 часа всего по умолчанию. До 5 сеансов на учётную запись |
| Приложения для Windows и Linux | Отзываемый токен устройства, защищённый средствами ОС. Пароль не хранится. На сервере лежит только хэш токена |

## Права и изоляция

- Права проверяются на сервере. Запрет публикации дополнительно заложен в токен подключения к встрече. Роли: [Справочник: роли и права](Справочник-роли-и-права).
- Публичный API: ключ хранится как SHA-256, сравнение идёт за постоянное время. Ключу задаются область комнат, права и список адресов. Чужие объекты отвечают как несуществующие. Есть лимиты и идемпотентность.
- Webhooks: подпись HMAC-SHA256 с меткой времени. Адрес получателя проверяется при сохранении и при каждой отправке. Частные сети запрещены, пока администратор их явно не разрешит. Адреса метаданных облака запрещены всегда.
- Контейнеры: PostgreSQL, Redis и служба распознавания не публикуются наружу. Backend и служба распознавания работают от непривилегированного пользователя с uid 10001. `no-new-privileges` включён у backend, web и redis. `cap_drop` и `read_only` не включены.
- Доска draw.io и карта разговора встраиваются в `iframe sandbox` без доступа к cookie и API.
- Вложения чата: тип определяется по содержимому, исполняемые и активные типы запрещены. Ответы идут с `nosniff` и CSP `default-src 'none'; sandbox`.
- Ответы контейнера web содержат CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` и `Permissions-Policy`.

## Секреты

- Пароли и ключи хранятся в `.env` с правами 600 и в базе в зашифрованном виде (AES-GCM, ключ `APP_MASTER_KEY`).
- Скрипты, журналы и диагностика маскируют секреты. `scripts/diag.sh` не создаёт архив, если находит значение секрета из `.env`.
- Сканер `scripts/check_private_data.py` запускается в CI и не даёт частным данным попасть в репозиторий.
- Копия базы содержит секреты в зашифрованном виде, копия `.env` в открытом. Храните их раздельно.

## Журналы и аудит

Журнал событий, журнал аудита и журнал событий безопасности не содержат паролей, ключей, токенов и содержимого разговоров. Записи аудита подписаны HMAC-SHA256. Проверка целостности не обнаруживает удаление самых свежих записей и подмену ключа вместе с базой. Подробности: [Справочник: журнал аудита и события](Справочник-журнал-аудита-и-события).

## Обновление и привилегии

Обновление из браузера выполняет помощник на хосте от root.

- Он принимает только запросы из фиксированного списка действий: проверка, обновление, исправление, поиск проблем, действия с компонентами и томами.
- Значения проверяются, окружение дочерних команд стерильно.
- Запрос живёт не больше 10 минут.
- Файл запроса принимается только от root, самого исполнителя или пользователя контейнера backend. Другой локальный пользователь общего сервера запросить действие не может.
- Произвольных команд из браузера нет.

## Шифрование

Защита соединения (TLS), транспортное шифрование звонка (DTLS-SRTP), шифрование чата и стенограмм в базе (AES-256-GCM) и сквозное шифрование звука и видео описаны на странице [Шифрование](Шифрование).

Граница доверия: сервер расшифровывает данные в памяти, чтобы показать их пользователям. Администратор сервера с доступом к процессу и мастер-ключу может получить содержимое. Записи встреч и файлы приложение не шифрует.

## Встроенная защита не заменяет сетевую

Встроенный слой видит только трафик, который идёт через приложение. Порты медиа, SIP и файлы эфира закрываются внешним межсетевым экраном. Защиту от DDoS обеспечивает оператор связи. Подробно: [Защита публичного сервера](Защита-публичного-сервера-Peregovorka).

## Известные риски и ограничения

| Риск | Состояние |
| --- | --- |
| HSTS не включён в шаблон nginx | Намеренно: сначала проверьте цепочку HTTPS на своём сервере ([Как настроить reverse proxy и HTTPS](Как-настроить-reverse-proxy-и-HTTPS)) |
| В nginx нет ограничения частоты | Защита работает в приложении. Лимиты nginx вредны за общим NAT |
| Блокировка адреса и встроенный WAF | Срабатывают на запросы без признака входа. На этом шаге проверяется наличие признака, а не подлинность. Вход от заблокированного адреса закрыт независимо от этого |
| Ранняя история публичного репозитория | В ранних коммитах остались организационные значения без паролей. Из рабочего дерева удалены, история не переписывалась без решения владельца |
| Зависимости | Заданы точными версиями. При выпуске выполняется проверка по базе OSV, найденное закрывается через ревизию компонентов |
| Администратор сервера | Видит содержимое в памяти. Шифрование хранилища не защищает от владельца сервера |
| Публичный API, очень большие записи | Файл читается в память целиком, потоковой отдачи нет |
| Приложение для Windows | Сертификата издателя у установщиков нет, поэтому Windows показывает предупреждение SmartScreen |
| Наплыв входов через LDAP или AD | Требует дополнительного тестирования. Настоящий каталог под нагрузкой не проверялся |
| Вход через настоящий Active Directory | В репозитории нет записи о такой проверке |
| Нагрузочные испытания защиты | Не проводились |
