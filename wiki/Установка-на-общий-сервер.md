# Установка на общий сервер

*Для кого: администратор сервера, где уже работают сайты и сервисы (профиль `shared-host`).*

## Зачем это нужно

Профиль `shared-host` ставит Peregovorka рядом с другими приложениями и не меняет их настройки. Если сервер свободен, используйте [Установка на чистый сервер](Установка-на-чистый-сервер).

| Действие | Что делает установщик |
| --- | --- |
| Docker и nginx | не ставит; проверяет и сообщает, чего не хватает |
| Параметры ядра и межсетевой экран | не меняет |
| Чужие сайты nginx, Apache, PHP, контейнеры | не трогает |
| nginx | создаёт **один** новый файл сайта с пометкой `managed-by: peregovorka:<проект>`; перед перезагрузкой выполняет `nginx -t`, при ошибке откатывает свои изменения |
| Docker | свой compose-проект, свои образы и сеть; чужие контейнеры не останавливает |
| `apt upgrade`, `dist-upgrade`, `autoremove`, перезагрузка | никогда |

Обновление при нехватке места выполняет `docker builder prune` и `docker image prune -f`. Это затрагивает кэш сборки и образы без тега всего сервера. Отключить: `UPD_DISK_MAINTENANCE=0` в `.env`.

## Когда пригодится

- На сервере работают другие сайты, и порт 443 занят.
- Перед сервером стоит прокси организации.
- Нужно несколько экземпляров Peregovorka на одном сервере.

## Что потребуется

| Что | Зачем |
| --- | --- |
| Сервер по странице [Системные требования](Системные-требования) | запуск контейнеров |
| Docker и Compose, Buildx желателен | ставятся вручную |
| Ваш пользователь в группе `docker` | мастер и скрипты работают без `sudo`, `.env` принадлежит вам |
| Каталог данных с правом записи для вашего пользователя | мастер предложит `/srv/<экземпляр>-data`. Создайте его заранее: `sudo mkdir -p <каталог> && sudo chown $USER <каталог>`. Установщик спросит пароль `sudo`: каталогам записей он назначает владельца с номером 10001 |
| nginx, если оставить `NGINX_MANAGE=yes` | без него `preflight` даст `FAIL`. Иначе задайте `NGINX_MANAGE=no` и настройте прокси сами |
| Системные программы | проверка `scripts/prereq.sh` |
| Каталог Active Directory | мастер в этом профиле спрашивает его параметры, см. ниже |
| DNS-имя и HTTPS | без HTTPS браузер не даёт микрофон и экран |
| Свободные порты: веб, ICE/TCP и ICE/UDP LiveKit, порт API LiveKit на `127.0.0.1` | мастер подбирает и проверяет занятость |

### Если каталога Active Directory нет

Мастер без `--auto` требует LDAPS-серверы, Base DN, служебную запись, группу администраторов и путь к файлу CA, пустой ответ не принимается. Если файла CA нет, `preflight` даёт `FAIL`.

Без каталога используйте ручную установку: заполните `.env` из образца, оставив параметры LDAP пустыми, и запустите `scripts/install.sh`. Порядок — [Руководство системного администратора](Руководство-системного-администратора#установка-вручную). Каталог подключается потом в браузере.

## Где найти

Команды выполняются в терминале сервера. Перечень создаваемых объектов — в разделе «Что получится».

## Как это сделать

1. Скачайте проект конкретной версии. Тег возьмите на [странице выпусков](https://github.com/calleograph/peregovorka/releases).

   ```bash
   git clone --depth 1 --branch vX.Y.Z https://github.com/calleograph/peregovorka.git /var/www/projects/peregovorka
   cd /var/www/projects/peregovorka
   ```

2. Проверьте сервер. Команда ничего не меняет.

   ```bash
   scripts/prereq.sh --check --profile shared-host
   ```

   Команда проверяет системные программы, Docker, Compose и Buildx. nginx на этом профиле проверяет `preflight` на следующем шаге. Если не хватает только Buildx, можно продолжать: сборка пойдёт классическим сборщиком. Подсказка скрипта про `--install` здесь не поможет: Docker на этом профиле ставите вы.

3. Подготовьте файл CA контроллеров домена и запустите мастер ⚠.

   ```bash
   scripts/setup.sh --profile shared-host
   ```

   Мастер спрашивает имя экземпляра, DNS-имя, IP-адрес сервера, публичный адрес, каталог данных, число прокси и параметры Active Directory. Затем он подбирает свободные порты и **создаёт секреты**: править `.env` вручную не нужно. После этого готовит модель, запускает `preflight` и показывает план `install --dry-run`.

4. Прочитайте план. Изменения начнутся только после ответа `y`. До него можно остановиться в любой момент.

5. Сохраните в сейф паролей значение `APP_MASTER_KEY`, которое напечатал мастер, и первичный пароль из блока **ПЕРВИЧНЫЙ ВХОД**. Пароль показывается один раз. Если мастер не создал администратора, выполните `scripts/bootstrap-admin.sh`.

6. Проверьте систему.

   ```bash
   scripts/smoke-test.sh
   ```

   Ожидаемый результат: `Smoke test: PASS`.

7. Настройте внешний прокси: он передаёт трафик на `NGINX_LISTEN_PORT`, тот на контейнер `web` (`127.0.0.1:WEB_PORT`). Общие файлы nginx установщик не редактирует. Требования — [Как настроить reverse proxy и HTTPS](Как-настроить-reverse-proxy-и-HTTPS).

8. Откройте порты медиа: [Как настроить LiveKit](Как-настроить-LiveKit).

9. Поставьте помощника обновлений, если нужны кнопки обновления и служб в браузере. На этом профиле он не ставится сам.

   ```bash
   sudo scripts/updater.sh install --yes
   ```

### Параметры ядра ⚠

Установщик их не меняет: они общие для сервера. Посмотреть значения и применить осознанно:

```bash
scripts/tune-kernel.sh
sudo scripts/tune-kernel.sh --apply
```

Скрипт требует подтверждения, `--yes` на этом профиле игнорируется.

**Последствия для других приложений.** Увеличиваются максимальные буферы сокетов и очередь сетевого устройства. Обычно это не мешает, но влияет на весь сервер. `vm.overcommit_memory=1` меняет учёт памяти для всех процессов: система охотнее выделяет память, а при её нехватке процессы завершает ядро. Если на сервере работает чувствительная к памяти база данных, согласуйте изменение с её владельцем. Без этих параметров Peregovorka работает, но при нагрузке возможны потери звука.

## Что получится

| Путь | Что |
| --- | --- |
| `$DATA_ROOT/{postgres,redis,models,recordings,live,exports,backups,state,updater,ca,chat-files,avatars,branding}` | данные |
| `$NGINX_SITES_AVAILABLE/$NGINX_SITE_NAME` и ссылка | один файл сайта, при `NGINX_MANAGE=yes` |
| образы `<проект>-{backend,asr,web,livekit}`, сеть `<проект>_default`, контейнеры `<проект>-<служба>-1` | ресурсы compose-проекта |

Система отвечает по вашему адресу, `Smoke test: PASS`, чужие сайты работают как раньше.

## Если не получается

| Симптом | Что делать |
| --- | --- |
| `prereq.sh` пишет `Docker: не хватает …` | установите Docker и плагины, повторите |
| `nginx не найден (NGINX_MANAGE=yes)` | установите nginx или задайте `NGINX_MANAGE=no` |
| `preflight` ругается на порт | выберите другой порт в `.env`; автоматически порты не занимаются |
| `preflight` не находит файл CA | положите PEM по указанному пути |
| `DATA_ROOT=… не существует и родитель недоступен для записи` | создайте каталог данных, см. «Что потребуется» |
| В `nginx -t` ошибка | свои изменения откатаны, `reload` не выполнялся, приложение работает на `127.0.0.1:WEB_PORT` |
| Предупреждение о параметрах ядра | см. раздел выше |
