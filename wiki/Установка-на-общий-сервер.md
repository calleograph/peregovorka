# Установка на общий сервер

*Для кого: администратор сервера, где уже работают сайты и сервисы (профиль `shared-host`).*

**Что получится:** Peregovorka работает рядом с другими приложениями и не меняет их настройки. Если сервер свободен, используйте [Установка на чистый сервер](Установка-на-чистый-сервер).

## Что гарантирует профиль

| Действие | Что делает установщик |
| --- | --- |
| Docker и nginx | не ставит; показывает список недостающего и ждёт ваших действий |
| Параметры ядра и файрвол | не меняет |
| Чужие site-файлы nginx, Apache, PHP, контейнеры | не трогает |
| nginx | создаёт **один** новый site-файл с маркером `managed-by: peregovorka:<проект>`; перед перезагрузкой выполняет `nginx -t`, при ошибке откатывает свои изменения |
| Docker | свой compose-проект, свои образы, сеть и тома; `docker prune` и остановка чужих контейнеров никогда не выполняются |
| `apt upgrade`, `dist-upgrade`, `autoremove`, перезагрузка | никогда |

## Что нужно заранее

| Что | Зачем |
| --- | --- |
| Сервер Ubuntu или Debian x86_64, от 4 vCPU, 8 ГБ памяти, 30 ГБ диска | запуск контейнеров |
| Docker и Compose plugin (Buildx желателен) | ставятся вручную; проверка: `scripts/prereq.sh --check --profile shared-host` |
| DNS-имя и HTTPS | без HTTPS браузер не даёт микрофон и экран |
| Свободные порты: веб (TCP), ICE/TCP и ICE/UDP LiveKit, loopback-порт LiveKit API | мастер подбирает и проверяет занятость |

## Шаги

1. Скачайте проект конкретной версии (тег последнего релиза со [страницы выпусков](https://github.com/calleograph/peregovorka/releases)).

   ```bash
   git clone --depth 1 --branch vX.Y.Z https://github.com/calleograph/peregovorka.git /var/www/projects/peregovorka
   cd /var/www/projects/peregovorka
   ```

   Ожидаемый результат: каталог проекта с файлом `VERSION`.

2. Запустите мастер.

   ```bash
   scripts/setup.sh --profile shared-host
   ```

   Мастер задаёт вопросы (имя экземпляра, DNS-имя, каталог данных), подбирает свободные порты, **генерирует секреты** (править `.env` вручную не нужно), готовит модель, запускает `preflight` и показывает план `install --dry-run`.

3. Прочитайте план. Применение начнётся только после вашего ответа «y». Остановиться можно в любой момент до него.

4. После установки проверьте систему.

   ```bash
   scripts/smoke-test.sh
   ```

   Ожидаемый результат: `Smoke test: PASS`.

## Три порта на общем сервере

Внешний reverse proxy с HTTPS передаёт трафик на `NGINX_LISTEN_PORT` управляемого nginx Peregovorka, тот — на контейнер `web` (`127.0.0.1:WEB_PORT`). Общие файлы nginx установщик не редактирует. Требования к вашему прокси — [Как настроить reverse proxy и HTTPS](Как-настроить-reverse-proxy-и-HTTPS).

## Что создаётся на хосте

| Путь | Что |
| --- | --- |
| `$DATA_ROOT/{postgres,redis,models/gigaam,models/llm,recordings,exports,backups,state,…}` | данные |
| `$NGINX_SITES_AVAILABLE/$NGINX_SITE_NAME` и симлинк | один site-файл (при `NGINX_MANAGE=yes`) |
| образы `<проект>-{backend,asr,web,livekit}`, сеть `<проект>_default`, контейнеры `<проект>-<сервис>-1` | ресурсы compose-проекта |

## Параметры ядра

На `shared-host` установщик параметры ядра не меняет: они общие для сервера. Посмотреть значения и команды: `scripts/tune-kernel.sh`; применить осознанно: `sudo scripts/tune-kernel.sh --apply` (скрипт требует подтверждения, `--yes` игнорируется). Рекомендуемые значения — [Справочник: порты и сеть](Справочник-порты-и-сеть).

## Типичные ошибки

| Симптом | Что делать |
| --- | --- |
| `preflight` ругается на порт | выбрать другой порт в `.env`; автоматически порты не занимаются |
| В `nginx -t` ошибка | свои изменения откатаны, `reload` не выполнялся; приложение работает на `127.0.0.1:WEB_PORT` |
| Предупреждение о параметрах ядра | применить вручную `scripts/tune-kernel.sh` |
