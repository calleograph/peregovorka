# Узлы CDN

*Для кого: администратор сервера.*

## Зачем это нужно

Отдельный Linux-сервер раздаёт эфиры зрителям, а основной сервер Peregovorka отдаёт ему каждый сегмент один раз. Сервер подключается прямо из администрирования, вручную настраивать его не нужно.

## Когда пригодится

- Зрителей больше, чем выдержит канал основного сервера.
- Эфир закрытый, поэтому внешняя площадка не подходит.
- Договора со сторонним CDN нет.

## Как это работает

Основной сервер формирует эфир и выдаёт зрителю подписанную ссылку на узел. Узел сам проверяет подпись, забирает сегменты с основного сервера при первом запросе и раздаёт их зрителям из своего кеша, без перекодирования: 1080p и 1440p остаются теми же.

- На основном сервере остаются служебные запросы зрителей: страница, выдача ссылки, пульс, вопросы.
- Зрители через узел смотрят обычный HLS: низкой задержки в такой комнате нет.
- Трансляция на YouTube, RUTUBE и другие площадки от узлов не зависит.
- Записи эфиров открываются с основного сервера.
- Если сторонний CDN уже подключён, он продолжит работать: [CDN для массовых мероприятий](CDN-для-массовых-мероприятий).

Вместимость узла проверена только моделированием: 1500 зрителей 1080p, 60 с, на одной машине. Статус: проверено в ограниченном сценарии. Числа и условия: [Производительность и требования к серверу для трансляций](Производительность-и-требования-к-серверу-для-трансляций).

## Что потребуется

- Отдельный сервер: Ubuntu 22.04, 24.04, 26.04 или Debian 12, 13. Статус: подтверждено испытаниями, установка на виртуальных машинах этих систем, amd64, и Ubuntu 24.04 arm64.
- Вход по SSH: root или пользователь с sudo.
- Свободные порты 80 и 443, на сервере не установлен nginx из пакетов системы.
- Имя в DNS, например `cdn1.example.org`, которое указывает на этот сервер.
- Доступ с узла к основному серверу по HTTPS и к `nginx.org`.

Сколько ресурсов нужно под вашу аудиторию, покажет блок **Расчёт оборудования и ключ подписи**. Это расчётная оценка, а не проверенная конфигурация: [Производительность и требования](Производительность-и-требования-к-серверу-для-трансляций).

## Где найти

**Администрирование → Интеграции → Трансляции**, блок **Узлы CDN**.

## Подключение сервера

1. В блоке **Узлы CDN** нажмите **Подключить сервер**.
2. Укажите адрес и порт SSH, нажмите **«Получить отпечаток сервера»**.
3. На самом сервере выполните команду из подсказки и сравните отпечаток. Совпал — отметьте галочку. Не совпал — не продолжайте: подключение могло быть перехвачено.
4. Укажите публичное имя, название, пользователя, пароль или закрытый ключ и способ получения сертификата:
   - **Let's Encrypt** — автоматически, если имя указывает на сервер и порт 80 открыт из интернета;
   - **Свой сертификат** — PEM с цепочкой и ключ без пароля;
   - **Самоподписанный** — только для испытаний: браузеры зрителей его не примут.
5. Нажмите **«Проверить сервер»**. Ничего не устанавливается: покажутся система, ресурсы, оценка аудитории и препятствия.
6. Нажмите **«Установить»**. Этапы видны в карточке узла.

   Что получится: все этапы отмечены, последний «Проверка раздачи тестового эфира», состояние узла «работает».

Пароль нужен только для установки: он хранится зашифрованным не дольше 30 минут и удаляется после неё. Дальше узлом управляет отдельная учётная запись `pgcdn` с ключом основного сервера, которая может только вызывать `pgcdn-ctl`. Пароль на сервере лучше сменить: основной сервер его больше не использует.

## Включение

1. В блоке **«Узлы CDN»** отметьте **«Раздавать эфиры через свои узлы»**.
2. Проверьте **«Адрес источника для узлов»**: по нему узлы забирают сегменты. Пусто — публичный адрес сервера.
3. В настройках комнаты: **Трансляция → Дополнительно → Раздавать через CDN**.

Новые зрители получат ссылку на узел. Те, кто уже смотрит, перейдут на него при плановом продлении ссылки.

## Ручная установка скриптом

Если основному серверу нельзя давать вход на сервер узла:

1. В окне подключения отметьте **«Установлю сам скриптом на сервере»**. Отпечаток всё равно нужен: по нему основной сервер будет проверять узел. На сервере должен работать SSH, доступный основному серверу.
2. В карточке узла скачайте пакет и настройки. Файл настроек содержит ключ доступа к источнику, передавайте его защищённо.
3. На сервере:
   ```bash
   mkdir pgcdn && tar -xzf peregovorka-cdn-node-*.tar.gz -C pgcdn
   sudo bash pgcdn/install.sh --config pgcdn-cdn1.example.org.json
   ```
   Что получится: последняя строка `@@PGCDN done ok`.
4. Удалите файл настроек с сервера и нажмите **«Подключить установленный»**.

## Несколько узлов

Подключите следующий сервер тем же способом. Зрители распределяются между исправными узлами пропорционально весу и остаются на своём узле. Добавлять и удалять узлы можно во время эфира.

Если узел перестал отвечать, плеер сразу переходит на другой узел или на основной сервер, а через 30 секунд сервер перестаёт выдавать этот узел новым зрителям. Заминка при отказе узла составила ≈ 7 с, при отказе всех узлов ≈ 8–16 с. Статус: проверено в ограниченном сценарии, настоящий браузер, несколько зрителей; перенос всей аудитории на основной сервер не проверялся. Узел вернулся — через 30 секунд он снова в работе. Зрителей между регионами автоматически не делит: выбор идёт только по весу.

Если недоступны все узлы, зрители смотрят с основного сервера. Снимите **«Если все узлы недоступны — раздавать с этого сервера»**, если его канал этого не выдержит: тогда плеер будет повторять попытки.

## Показатели

| Столбец | Что значит |
|---|---|
| Зрители | разных адресов за последние 40 с и оценка предела узла. Зрители за одним NAT считаются как один адрес |
| CPU, RAM | загрузка сервера узла |
| Отдаёт | исходящий трафик к зрителям |
| Источник | что узел забрал с основного сервера |
| Кеш | занято и предел |
| Зап./с | запросов зрителей в секунду |
| Из кеша | доля ответов без обращения к источнику |

Точное число зрителей эфира — в блоке состояния трансляций выше: оно считается по пульсу плеера.

## Управление узлом

Нажмите название узла в таблице:

- **Проверить раздачу** — тестовый эфир через узел: совпадение данных, кеш, отказ поддельной и просроченной ссылки.
- **Применить настройки** — отправить узлу текущие настройки.
- **Обновить узел** — появляется, если вышел новый пакет узла.
- **Не направлять зрителей** — вывести узел из работы, не удаляя. Те, кто уже смотрит, уйдут при продлении ссылки.
- **Журнал** — ошибки nginx на узле и журнал установки.
- **Удалить** — служба на сервере удаляется, доступ узла к основному серверу отзывается. Сервер недоступен — можно «забыть» узел: доступ отзовётся, а на сервере останется неработающий nginx. Удалить его вручную: `sudo pgcdn-ctl uninstall`.

**Сменить ключ** в разделе «Расчёт оборудования и ключ подписи» меняет ключ подписи ссылок. Двойная смена полностью отзывает старый ключ: сделайте её, если узел был скомпрометирован.

## Если не получается

| Признак | Причина и что сделать |
|---|---|
| Этап «Подключение по SSH» — ошибка | адрес, порт, логин или пароль; ключ сервера изменился — подключите узел заново и сверьте отпечаток |
| Этап «Пакеты nginx и njs» — ошибка | нет доступа к `nginx.org` и зеркалам пакетов по HTTPS; на сервере есть nginx из пакетов системы |
| Этап «Сертификат Let's Encrypt» — ошибка | имя не указывает на сервер или порт 80 закрыт из интернета |
| Этап «Связь с источником» — ошибка | неверный «Адрес источника для узлов» или сервер узла его не видит |
| Этап «Проверка раздачи» — ошибка | основной сервер не может открыть узел по публичному имени: DNS, порт 443, сертификат |
| Узел «не отвечает» | сервер выключен или порт 443 закрыт. Зрители уже переведены; посмотрите «Журнал» |
| Зрители останавливаются при низкой загрузке узла | упёрлись в канал провайдера: см. столбец «Отдаёт» и [требования](Производительность-и-требования-к-серверу-для-трансляций) |

После ошибки установки нажмите **«Повторить установку»**: повторный запуск безопасен.

## Откат

Снимите **«Раздавать эфиры через свои узлы»**. Новые зрители получат прямую раздачу, остальные перейдут на неё при продлении ссылки. Настройки узлов сохраняются.
