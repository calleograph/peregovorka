# Централизованная установка надстройки администратором Exchange

*Для кого: администратор Exchange или Microsoft 365.*

## Зачем это нужно

Администратор ставит надстройку один раз, и кнопка **Добавить конференцию** появляется у нужных сотрудников без их участия.

> На настоящем сервере Exchange установка не проверялась. Сценарии PowerShell разобраны парсером, но `Install-OutlookAddin.ps1` и `Uninstall-OutlookAddin.ps1` на Exchange не выполнялись. Сначала запустите их с `-WhatIf` и поставьте надстройку на тестовую группу.

## Когда пригодится

- Надстройка нужна всей организации или отделу.
- Сотрудникам запрещено добавлять надстройки самим.
- Изменился адрес сервера или манифест.

## Что потребуется

- Включённая интеграция и публичный HTTPS-адрес: [Как подключить надстройку Outlook](Как-подключить-надстройку-Outlook).
- Роль **Org Marketplace Apps** или **Org Management**.
- Exchange Management Shell. Для Exchange Online сначала выполните `Connect-ExchangeOnline`.
- Манифест или архив установки.

## Где найти

| Что | Где |
| --- | --- |
| Полный пакет с входом | **Администрирование → Интеграции → Microsoft Outlook → Скачать надстройку для этого сервера** |
| Пакет без входа | `https://meet.example.org/outlook`, блок **Для администратора Exchange**, кнопка **Скачать полный пакет установки (ZIP)** |
| Только манифест | кнопка **Только манифест (XML)** или `https://meet.example.org/api/v1/outlook/manifest.xml` |
| Отдельные сценарии | та же страница, кнопки с именами файлов |

## Как это сделать

### Локальный Exchange

1. Распакуйте `Peregovorka-Outlook.zip` на компьютере с Exchange Management Shell.
2. Проверьте условия. Сценарий ничего не меняет:

   ```powershell
   .\Test-OutlookAddin.ps1
   ```

   Запустите его и на рабочей станции сотрудника: так проверяется то, что увидит Outlook. Часть про Exchange выполняется только в Exchange Management Shell.

3. Посмотрите, что будет сделано:

   ```powershell
   .\Install-OutlookAddin.ps1 -WhatIf
   ```

4. Установите надстройку выбранным сотрудникам:

   ```powershell
   .\Install-OutlookAddin.ps1 -ProvidedTo SpecificUsers -UserList 'ivanov@example.org','petrova@example.org'
   ```

5. Проверьте работу у этих сотрудников.
6. Установите всем:

   ```powershell
   .\Install-OutlookAddin.ps1 -Replace
   ```

7. Подождите. Клиенты получают надстройку не сразу, до нескольких часов. Перезапустите Outlook.

Параметры сценария:

| Параметр | Значение |
| --- | --- |
| `-ProvidedTo` | `Everyone` или `SpecificUsers` |
| `-UserList` | адреса сотрудников для `SpecificUsers` |
| `-DefaultState` | `Enabled`, `Disabled` или `AlwaysEnabled` |
| `-ManifestUrl` | установка по прямой ссылке вместо файла |
| `-Replace` | заменить установленную запись |
| `-LogPath` | путь к журналу, по умолчанию `Peregovorka-Outlook-install-*.log` в текущем каталоге |

Сценарий безопасно запускать повторно: дубликат не создаётся. Адреса и идентификатор берутся из манифеста.

Вместо сценария можно использовать Центр администрирования Exchange: **Organization → Add-ins → «+» → Add from file**. Названия пунктов сверьте со справкой своей версии.

### Microsoft 365

1. Откройте Центр администрирования Microsoft 365.
2. Выберите **Settings → Integrated apps → Upload custom apps**.
3. Выберите тип **Office Add-in** и файл `Peregovorka-Outlook.xml`.
4. Назначьте пользователей или группы.
5. Подождите: распространение занимает до 24 часов.

Подробности у Microsoft: [централизованное развёртывание](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/manage-deployment-of-add-ins).

Сценарии PowerShell тоже подходят после `Connect-ExchangeOnline`.

## Что получится

- `Get-App -OrganizationApp` показывает одну запись Peregovorka.
- В журнале сценария есть строка о добавлении и проверке.
- В окне новой встречи есть группа **Peregovorka** и кнопка **Добавить конференцию**. В Outlook в браузере при первом запуске нужно подтвердить доверие к домену.
- В блоке **Состояние и проверки** нет строк с крестиком, в **Журнал надстройки и сверки** есть запись **панель запущена Office**.

Идентификатор надстройки вычисляется из адреса сервера и не меняется при повторном скачивании.

## Обновление

Логика надстройки обновляется вместе с сервером, ставить ничего не нужно. Версия манифеста растёт с версией продукта, поэтому сценарий может сообщить о разнице версий. Это не значит, что обновление обязательно.

Манифест нужно заменить, если изменились:

- адрес сервера;
- **Источник библиотеки Office.js**;
- **Передавать изменения при отправке приглашения**.

Скачайте пакет заново и выполните:

```powershell
.\Install-OutlookAddin.ps1 -Replace
```

После смены адреса идентификатор будет другим. Сначала удалите прежнюю надстройку прежним манифестом или ключом `-AppId`.

Если манифест включает передачу при отправке, администратор Microsoft 365 должен подтвердить его повторно.

## Удаление

```powershell
.\Uninstall-OutlookAddin.ps1 -WhatIf
.\Uninstall-OutlookAddin.ps1
```

В Microsoft 365: **Integrated apps → Peregovorka → Remove**.

Конференции и ссылки в отправленных приглашениях продолжат работать: комнаты хранятся в Peregovorka.

## Если не получается

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| «Команда … не найдена» | сценарий запущен не в Exchange Management Shell | запустите его там или после `Connect-ExchangeOnline` |
| «Нет прав на управление приложениями организации» | нет нужной роли | выдайте **Org Marketplace Apps** или **Org Management** |
| «Манифест не загружен прямой ссылкой без перенаправлений» | прокси перенаправляет адрес | уберите перенаправление или ставьте из файла |
| «Для обновления запустите сценарий с ключом -Replace» | установлена другая версия манифеста | выполните с `-Replace`, если нужна замена |
| `Test-OutlookAddin.ps1` показывает `RemoteCertificateChainErrors` | нет доверия цепочке | установите сертификаты или исправьте цепочку на прокси |
| Кнопка не появилась через несколько часов | клиент не получил надстройку | перезапустите Outlook, проверьте `Get-App -OrganizationApp` |
| Найдено несколько записей | дубликат | удалите лишние, установите заново |
