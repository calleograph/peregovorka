# Участие в разработке

> Относится к версии 0.39.4 · проверено 2026-10-25 · уровень проверки: 1–2 (команды сборки и тестов взяты из `docs/INTERNALS.md`, `desktop/package.json`, `CLAUDE.md`; backend, frontend и shell тесты запускались при подготовке выпусков) · тип страницы: практическое руководство

Результат: вы собрали проект, прогнали тесты и знаете правила предложения изменений. Для кого: разработчик. Устройство системы — [[Как устроена Peregovorka|Как-устроена-Peregovorka]].

**Файла `CONTRIBUTING` в репозитории нет.** Ниже — правила, записанные в `CLAUDE.md`, `docs/VERSIONING.md` и `docs/PRIVACY_OF_CONFIG.md`. Формальный порядок принятия сторонних предложений владельцем не описан (ТРЕБУЕТ ПРОВЕРКИ).

## Что нужно заранее

- Python 3.12 и новее, Node.js 24, npm; для скриптов — Bash.
- Docker нужен только для проверок установки на реальном контейнере; тесты скриптов используют подставной Docker.

## Состав репозитория

| Каталог | Содержимое |
| --- | --- |
| `backend/` | FastAPI, миграции Alembic, тесты |
| `asr-service/` | служба распознавания |
| `frontend/` | React и TypeScript (Vite) |
| `desktop/` | приложение для Windows (Electron) |
| `deployment/` | `compose.yml`, шаблоны nginx, `compat.env` |
| `scripts/`, `tests/scripts/` | скрипты установки и эксплуатации, их тесты |
| `tests/live/` | живые сценарии против стенда |
| `docs/` | документация |

## Собрать и проверить

```bash
# backend
cd backend && pip install -r requirements-dev.txt && pytest

# ASR (torch и GigaAM не нужны: подставные провайдер и VAD)
cd asr-service && pip install -r requirements-dev.txt && pytest

# frontend
cd frontend && npm ci && npm test && npm run build

# скрипты
bash tests/scripts/run.sh

# приложение для Windows (из каталога desktop/)
npm ci && npm run typecheck && npm test
npm run dev                      # из исходников
npm run preview                  # собранная программа без установщика + проверки
```

Команды взяты из документации и не запускались при подготовке вики; backend, frontend и shell прогонялись при выпуске 0.39.4. LDAP в тестах подменяется. Полный прогон backend занимает около 15–25 минут.

## Правила изменений

1. Приоритеты: надёжность, работающая функциональность, скорость, безопасность, затем новые возможности.
2. Не называйте проверенным то, что не запускалось: в описании изменений разделяйте «проверено запуском», «автотест», «code review», «не проверено».
3. Изменения страницы комнаты — только с живой проверкой в браузере (`tests/live/`).
4. В репозиторий не попадают частные данные: только `example.org`, `192.0.2.x` и подобные. Перед фиксацией запускайте `python3 scripts/check_private_data.py`; в CI есть отдельное задание `private-data`.
5. Схема базы меняется только миграциями Alembic (`backend/migrations/versions`), «расширяющими»; тест `test_migrations.py` проверяет совпадение со схемой моделей.
6. Историю git не переписывайте без согласия владельца.
7. Зависимости закреплены точными версиями; новые версии проходят ревизию при выпуске (`scripts/deps.py review`, `docs/DEPENDENCIES.md`).

## Выпуск версий

Схема `MAJOR.MINOR.PATCH`; единственный источник версии — файл `VERSION`. Перед каждым выпуском: `VERSION` → CHANGELOG языком пользователя → HISTORY → PROJECT → README → docs → CI → release. `CHANGELOG.md` — для пользователя, `HISTORY.md` — для разработчика, `README.md` — витрина. Подробности — `docs/VERSIONING.md`. Приложение для Windows версионируется отдельно (теги `desktop-vX.Y.Z`).
