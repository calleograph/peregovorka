# Диагностика

*Для кого: администратор сервера и вторая линия поддержки.*

Страница организована по симптомам: найдите то, что вы видите, проверьте причину и выполните исправление. Если не помогло, соберите данные для обращения (раздел в конце). Команды запускайте из каталога установки. После установки одной командой нужен `sudo`, правило — [Справочник: скрипты и команды](Справочник-скрипты-и-команды). Действия, которые меняют систему, отмечены ⚠.

Короткий путь по симптомам и компонентам, с действиями прямо из администрирования, — раздел [Решение проблем](Решение-проблем).

## Что собрать сначала

```bash
cd /opt/peregovorka
sudo scripts/status.sh                # состояние контейнеров
sudo scripts/logs.sh backend --tail 200
sudo scripts/smoke-test.sh            # сквозная проверка
```

В браузере: **Администрирование → Обзор → Обзор**, **Технические показатели** и **Диагностика клиентов**.

## Не открывается страница или нет входа

### «Недопустимый Origin» (HTTP 403 при входе, WebSocket закрывается кодом 4403)

- **Причина:** страница открыта по адресу, которого нет в `APP_PUBLIC_URL` и `ALLOWED_ORIGINS` (IP вместо имени, SSH-туннель на `127.0.0.1`, другой прокси).
- **Проверка:** `sudo scripts/logs.sh backend --tail 500 | grep "Origin отклонён"` покажет полученный адрес. В тексте ошибки при входе указан нужный адрес.
- **Исправление:** откройте приложение по основному адресу или добавьте адрес в `ALLOWED_ORIGINS` и примените изменения ⚠ (`sudo scripts/ctl.sh restart backend`). Проверка Origin и CSRF не отключаются.
- **Если не помогло:** проверьте, что прокси передаёт `X-Forwarded-Proto: https` ([Как настроить reverse proxy и HTTPS](Как-настроить-reverse-proxy-и-HTTPS)).

### Не входит доменная учётка

- **Причина и проверка:** журнал backend содержит код: `invalid_credentials` (неверный пароль), `account_locked` (блокировка нашей защитой или AD), `tls_error` (цепочка или имя сертификата LDAPS), `service_account_error` (сервисная запись), `login_denied_acl` (нет в группе допуска).
- **Исправление:** **Интеграции → Каталог: подключения LDAP/AD**, кнопка проверки показывает этап сбоя; «Проверить пользователя» показывает решение по допуску ([Как подключить Active Directory](Как-подключить-Active-Directory)). Блокировка защиты снимается через 5 минут (по умолчанию).
- **Если не помогло:** войдите локальным администратором; сбросьте его пароль `sudo /opt/peregovorka/scripts/admin-reset.sh`.

### Потерян пароль локального администратора

`sudo /opt/peregovorka/scripts/admin-reset.sh` (при отсутствии учётной записи — с `--create`). Новый пароль показывается один раз, нужно сменить при входе.

## Нет звука, видео или экрана

### Страница открыта, комната «подключается» бесконечно

- **Причина:** закрыты или не проброшены `LIVEKIT_UDP_PORT/udp` и `LIVEKIT_TCP_PORT/tcp` на пути клиент → сервер, либо клиентам объявляется недоступный адрес.
- **Проверка:** `sudo scripts/medianet.sh check` (адреса ICE, проброс, CGNAT, порты Docker) и `sudo scripts/smoke-test.sh` (строки RTC TCP и UDP, `/rtc/v1`, WebSocket); с клиентского компьютера проверьте доступность портов.
- **Исправление:** откройте или пробросьте порты без смены номера (не через HTTP-прокси); пересчитать адреса — `sudo scripts/medianet.sh apply` ([Справочник: порты и сеть](Справочник-порты-и-сеть#адреса-для-звука-и-видео-nat)).

### `ERR_CONNECTION_RESET` при входе через VPN

- **Причина:** слишком большой MTU VPN-адаптера, пакеты теряются на пути; не ошибка приложения.
- **Исправление:** уменьшить MTU (помогало `MTU=1250`). Windows: `netsh interface ipv4 set subinterface "<адаптер>" mtu=1250 store=persistent`. Проверить WebSocket на прокси.

### Вход в комнату занимает 5 и более секунд

- **Проверка:** `smoke-test.sh`: «LiveKit /rtc/v1: маршрут» должен быть OK; `404` означает устаревший LiveKit. **Обзор → Технические показатели**, блок **Время входа в комнату**: какой этап длинный.
- **Что видит пользователь:** небольшая плашка «Подключение · …» слева над панелью управления; по нажатию — этапы со временем и подсказка к затянувшемуся этапу.
- **Исправление:** обновить до проверенной версии LiveKit (`update.sh` выставляет её сам).

### Ошибка WebSocket при открытой странице

- **Причина:** устройство не доверяет сертификату публичного адреса или маршрут через VPN.
- **Проверка:** Чек-лист **Первоначальная настройка и проверка сервера** в **Обзор → Обзор** называет этап сбоя публичного адреса (DNS, TCP, TLS, авторизация, прокси, маршрут), но проверяет **с сервера**, а не с устройства.
- **Исправление:** установить корневой сертификат на устройстве или перейти на имя с доверенным сертификатом.

### Нет микрофона в браузере

- **Причина:** страница не по HTTPS или доступ запрещён браузером.
- **Исправление:** использовать HTTPS и разрешить доступ.

### Показ экрана прерывается

- **Проверка:** «Диагностика клиентов» (причина), режим «⚙ Диагностика» в комнате (FPS, потери), параметры ядра.
- **Исправление:** профиль «Чёткость» для слайдов и «Плавность» для видео; параметры ядра ([Справочник: порты и сеть](Справочник-порты-и-сеть)).

## Нет стенограммы

- **Причина:** ASR не готов (нет модели, нет прав, не загружена) или служба недоступна. Звонок при этом работает.
- **Проверка:** `curl https://meet.example.org/api/v1/health/ready` (поле `asr`), `sudo scripts/logs.sh asr`, **Обзор → Обзор**, блок **Сервисы**. Признаки: `PermissionError` на `/models/...` — права на каталог моделей; `FileNotFoundError` на `.ckpt` — нет модели.
- **Исправление:** `sudo scripts/models.sh` (скачивает недостающее, исправляет права внутри `DATA_ROOT/models`), затем ⚠ `sudo scripts/ctl.sh restart asr`; при закрытой сети `--from-dir`. Установщик исправляет ошибку прав сам и перезапускает только `asr`.
- **Если не помогло:** убедитесь, что транскрибация в комнате не остановлена руководителем и запись не отключена.

## Не формируется протокол

- **Причина:** модель не настроена или вернула отказ; обезличивание не выполнено (нет моделей распознавания имён, в тексте остался секрет); таймаут.
- **Проверка:** причина показана в строке документа в «Истории»; журнал событий, категория `llm`.
- **Исправление:** [Как настроить языковые модели](Как-настроить-языковые-модели).

## Не работает хранилище или почта

| Симптом | Причина | Исправление |
| --- | --- | --- |
| Нет файлов в хранилище | неверные права, закрыт `445/tcp` | кнопка **Проверить** в **Файловых хранилищах**, права учётной записи |
| Запись аудио «ошибка выгрузки» | хранилище недоступно | восстановить доступ, «Повторить выгрузку записей»; файл на диске сервера не потерян |
| Вложение чата не принимается | хранилище недоступно, запрещённый тип, превышен размер | событие `chat_file_save_failed` в журнале |
| Письмо не уходит | отказ SMTP | **Почта: сервер SMTP → Проверить соединение** покажет код и текст ответа сервера; **Почта: журнал отправки** |

## Не идёт запись или эфир

| Симптом | Причина | Исправление |
| --- | --- | --- |
| «Все сервисы работают», а записи нет | видеоподсистема выключена | `sudo scripts/video.sh status`, [Как настроить видеозапись и трансляции на сервере](Как-настроить-видеозапись-и-трансляции-на-сервере) |
| Запись остановилась, «На диске сервера заканчивается место» | не хватает места под `live/tmp` и копию файла | освободите место, расчёт — на той же странице |
| Эфир с задержкой 7–8 секунд вместо 3 | `mediamtx` не работает, комната с CDN или Safari | `sudo scripts/logs.sh mediamtx --tail 100`, ⚠ `sudo scripts/ctl.sh restart mediamtx` |
| Сбой службы записи | ошибка браузера внутри Egress, память, диск | `sudo scripts/logs.sh livekit-egress --tail 300`, [Решение проблем: видеозапись и трансляции](Решение-проблем-видеозаписи-и-трансляций) |

## Сбой установки или обновления

- Установщик и `update.sh` печатают этап и причину; при падении сервиса — последние строки журнала сервиса и действие. Данные, `.env` и модели не затрагиваются.
- `install.sh`: повторите команду; `--from ЭТАП` продолжает с места ([Установка на чистый сервер](Установка-на-чистый-сервер)).
- `update.sh`: обрыв — повторить; локальные правки обновление сохраняет само в `DATA_ROOT/backups/local-changes-…`; сеть при сборке — повтор с проверкой источников ([Как обновить и откатить](Как-обновить-и-откатить)).
- `commit=unknown` — `./scripts/rebuild.sh`.

## Приложение для Windows

См. таблицы сообщений в [Справочник: приложение для Windows](Справочник-приложение-для-Windows). Отчёт: **Настройки → Диагностика → Сохранить отчёт** или `Peregovorka.exe --diagnostics=<файл>`. Журнал: `%APPDATA%\Peregovorka\logs\main.log`.

## Что приложить к обращению

- Версия сервера и commit (раздел «Обновления и версии» или `/api/v1/version`).
- Диагностический отчёт: **Обзор → Скачать диагностический отчёт** или `sudo scripts/diag.sh` (секреты маскируются; при находке секрета архив не создаётся).
- Текст ошибки и `request_id` (для API — заголовок `X-Request-ID`).
- Для приложения Windows — JSON-отчёт диагностики.
- Не прикладывайте `.env`, пароли и токены.
