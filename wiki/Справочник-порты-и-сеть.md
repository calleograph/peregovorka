# Справочник: порты и сеть

## Точный перечень для вашего сервера

Таблицы ниже — общий справочник по стандартной установке. **Точный перечень для вашей установки** (с вашими портами, режимом HTTPS, телефонией и подключёнными интеграциями) показывают Администрирование → Система → «Сетевая доступность» и команда `scripts/ports.sh` — они строятся по настройкам сервера, а не по этой таблице. Как пользоваться: [Как опубликовать сервис в интернете](Как-опубликовать-сервис-в-интернете).

## Что должно быть доступно участникам

| Порт | Протокол | Назначение | Куда |
| --- | --- | --- | --- |
| 443 (или порт из `APP_PUBLIC_URL`) | TCP, HTTPS | страница, API, WebSocket событий, сигналинг звонков (`/livekit/`), редактор доски (`/drawio/`), гостевая ссылка | на внешний reverse proxy или nginx хоста |
| `LIVEKIT_UDP_PORT` | UDP | звук, видео и показ экрана (WebRTC), основной путь | **напрямую** на сервер (адреса — ниже); через HTTP-прокси медиа не ходит |
| `LIVEKIT_TCP_PORT` | TCP | то же, запасной путь при закрытом UDP (качество хуже) | напрямую на сервер |

Значения портов задаются в `.env` (в шаблоне — `17882` и `17881`). Остальное наружу не открывайте.

## Адреса для звука и видео (NAT)

LiveKit сообщает клиентам адреса сервера в кандидатах ICE. Какие именно — решает установщик и каждое обновление (`scripts/medianet.py`), настройки администратора сохраняются:

| Как стоит сервер | Режим | Что получают клиенты |
| --- | --- | --- |
| Публичный адрес прямо на интерфейсе | `direct` | этот адрес |
| За NAT, публичный адрес определяется сам | `nat-stun` | публичный адрес (определяется через STUN при каждом запуске и проверяется каждые 5 минут) **и** адрес сервера в локальной сети |
| За NAT, адрес задан явно (`LIVEKIT_PUBLIC_IP=<IPv4>`) | `nat-manual` | заданный публичный адрес и адрес в локальной сети |
| Только локальная сеть (`LIVEKIT_PUBLIC_IP=off`) или публичный адрес не определён | `lan` | адрес в локальной сети |

* `LIVEKIT_NODE_IP` — адрес сервера в его сети (интерфейс). `LIVEKIT_PUBLIC_IP` — `auto` (по умолчанию), `off` или IPv4. Внешний адрес в `LIVEKIT_NODE_IP` больше не пишут: прежнюю схему обновление переносит само.
* Пользователи офиса подключаются к адресу в локальной сети напрямую, пользователи из интернета — к публичному через проброс портов. «Петля» NAT на маршрутизаторе не нужна.
* **Проброс за NAT:** UDP `LIVEKIT_UDP_PORT` и TCP `LIVEKIT_TCP_PORT` на адрес сервера в локальной сети **без смены номера и протокола**: LiveKit сообщает клиентам именно эти номера. Готовые правила показывают «Сетевая доступность» и `scripts/medianet.sh check`.
* **STUN.** Сервер обращается к серверам STUN только в режиме `nat-stun`. Серверы пробуются по очереди до первого ответившего: сначала `LIVEKIT_STUN_SERVERS`, затем встроенные — Cloudflare, Twilio, Google. Если какой-то из них не отвечает у провайдера или через VPN, адрес всё равно определится. Те же адреса LiveKit передаёт браузерам для их кандидатов ICE. Можно указать STUN организации. Если не ответил ни один, LiveKit объявит последний известный публичный адрес. TURN в установке нет.
* **Смена VPN, провайдера или маршрута.** Публичный адрес проверяется каждые 5 минут. Если он сменился и это подтвердилось три раза подряд, сервер звонков перезапускается с новым адресом, а участники переподключаются сами. Проверка `scripts/medianet.sh check` покажет, если объявленный адрес расходится с текущим.
* **CGNAT и двойной NAT.** Если адрес сервера или путь в интернет проходит через диапазон оператора CGNAT (RFC 6598), проброс на своём маршрутизаторе не поможет. Нужен публичный адрес у оператора, VPN или площадка с публичным адресом. `scripts/medianet.sh check` и кнопка «Проверить медиасоединения» показывают такие признаки.
* Изменить адрес — `sudo scripts/medianet.sh apply --public-ip auto|off|<IPv4>`. Сменить порты медиа согласованно — `sudo scripts/medianet.sh ports --tcp N --udp N`: меняются `.env`, публикация Docker, конфигурация LiveKit и перечень портов.

## Порты на сервере

| Переменная | Протокол | Где слушает | Назначение |
| --- | --- | --- | --- |
| `WEB_PORT` с адресом `WEB_BIND_ADDR` | TCP | контейнер `web`, по умолчанию `127.0.0.1` | вход для nginx хоста или внешнего прокси |
| `NGINX_LISTEN_PORT` | TCP | nginx хоста | порт site-файла Peregovorka, куда ходит внешний прокси |
| `LIVEKIT_HTTP_PORT` | TCP | только `127.0.0.1` | API и WebSocket LiveKit |
| `LIVEKIT_TCP_PORT`, `LIVEKIT_UDP_PORT` | TCP, UDP | `LIVEKIT_BIND_ADDR` | ICE |
| `SIP_SIGNALING_PORT` | UDP и TCP | `SIP_BIND_ADDR`, только при включённой телефонии | SIP; нужен только АТС |
| `SIP_RTP_START`–`SIP_RTP_END` | UDP | `SIP_BIND_ADDR`, только при включённой телефонии | RTP; нужен только АТС |
| 6789 | TCP | внутри сети проекта | метрики LiveKit, наружу не публикуются |
| PostgreSQL, Redis, ASR | — | **не публикуются** | внутренняя сеть проекта |

`/internal/` из интернета и локальной сети недоступен (404).

## Исходящие соединения сервера

| Куда | Зачем | Когда |
| --- | --- | --- |
| GitHub, PyPI, npm, Docker Hub, apt-зеркала, источник моделей GigaAM, Hugging Face | установка, сборка, обновление | только при установке и обновлении; в работе нужна только локальная сеть |
| Контроллеры домена, `636/tcp` (LDAPS) или `389/tcp` (STARTTLS) | вход, поиск, профили | всегда, если подключён каталог |
| SMTP-сервер | рассылка материалов | если настроена почта |
| SMB-сервер, `445/tcp` | хранилища | если настроены |
| Языковая модель по API | протоколы, резюме, карта | если подключена |
| Портал Bitrix24 (только чтение) | профили | если включено |
| Получатели событий (HTTPS) | webhooks | если созданы |
| АТС | SIP | если включена телефония |

## Параметры ядра для WebRTC

| Параметр | Типовое значение | Рекомендуется |
| --- | --- | --- |
| `net.core.rmem_max`, `net.core.wmem_max` | 212992 | не менее 5 000 000 (LiveKit предупреждает о малом буфере) |
| `net.core.netdev_max_backlog` | 1000 | не менее 5000 |
| `vm.overcommit_memory` | 0 | 1 (рекомендация Redis) |

На `standalone` установщик применяет значения сам (`/etc/sysctl.d/99-peregovorka.conf`). На `shared-host` параметры глобальны: `sudo scripts/tune-kernel.sh --apply` требует подтверждения.

## Работа через VPN и NAT

- Если страница открывается, а вход в комнату рвётся с `ERR_CONNECTION_RESET`, проверьте MTU VPN-адаптера (помогало `MTU=1250`).
- Маршрут до `LIVEKIT_NODE_IP` должен идти через туннель; VPN должен пропускать UDP. Если UDP запрещён, звонок заработает по TCP-порту, но медиа по TCP чувствительнее к потерям.
- Гости извне: публичный HTTPS-адрес и те же порты LiveKit.

## Трансляции

- **Зрители** смотрят HLS по тому же адресу и порту 443, что и сайт (`/hls/…` и страница `/live/…`): отдельных портов открывать не нужно. Каждый зритель собственной раздачи — исходящий поток ≈ 3,1 Мбит/с (720p) или ≈ 5,1 Мбит/с (1080p): ширину канала считайте от числа зрителей.
- **Внешние площадки**: контейнер Egress сам подключается наружу по RTMP (порт 1935) или RTMPS (порт 443) к адресам, которые вы добавили в комнате. Входящих портов для этого не нужно; разрешите исходящие соединения контейнера к нужным серверам.
- Egress общается с LiveKit и Redis внутри сети проекта (порты наружу не публикуются, как и у видеозаписи).
