# Справочник: порты и сеть

> Относится к версии 0.39.4 · проверено 2026-10-25 · уровень проверки: 1 (`deployment/compose.yml`, `.env.example`, документы) · тип страницы: справочник

## Что должно быть доступно участникам

| Порт | Протокол | Назначение | Куда |
| --- | --- | --- | --- |
| 443 (или порт из `APP_PUBLIC_URL`) | TCP, HTTPS | страница, API, WebSocket событий, сигналинг звонков (`/livekit/`), редактор доски (`/drawio/`), гостевая ссылка | на внешний reverse proxy или nginx хоста |
| `LIVEKIT_UDP_PORT` | UDP | звук, видео и показ экрана (WebRTC), основной путь | **напрямую** на `LIVEKIT_NODE_IP`; через HTTP-прокси медиа не ходит |
| `LIVEKIT_TCP_PORT` | TCP | то же, запасной путь при закрытом UDP (качество хуже) | напрямую на `LIVEKIT_NODE_IP` |

Значения портов задаются в `.env` (в шаблоне — `17882` и `17881`). Внешние STUN и TURN не используются. Адрес `LIVEKIT_NODE_IP` должен быть достижим и сотрудникам, и гостям; при проброшенных портах укажите внешний IP и проверьте доступ из локальной сети.

Остальное наружу не открывайте.

## Порты на сервере

| Переменная | Протокол | Где слушает | Назначение |
| --- | --- | --- | --- |
| `WEB_PORT` с адресом `WEB_BIND_ADDR` | TCP | контейнер `web`, по умолчанию `127.0.0.1` | вход для nginx хоста или внешнего прокси |
| `NGINX_LISTEN_PORT` | TCP | nginx хоста | порт site-файла Peregovorka, куда ходит внешний прокси |
| `LIVEKIT_HTTP_PORT` | TCP | только `127.0.0.1` | API и WebSocket LiveKit |
| `LIVEKIT_TCP_PORT`, `LIVEKIT_UDP_PORT` | TCP, UDP | `LIVEKIT_BIND_ADDR` | ICE |
| `SIP_SIGNALING_PORT` | UDP и TCP | `SIP_BIND_ADDR`, только при включённой телефонии | SIP; нужен только АТС |
| `SIP_RTP_START`–`SIP_RTP_END` | UDP | `SIP_BIND_ADDR`, только при включённой телефонии | RTP; нужен только АТС |
| 6789 | TCP | внутри сети проекта | метрики LiveKit, наружу не публикуются |
| PostgreSQL, Redis, ASR, llm-local | — | **не публикуются** | внутренняя сеть проекта; `llm-local` в сети без выхода в интернет |

`/internal/` из интернета и локальной сети недоступен (404).

## Исходящие соединения сервера

| Куда | Зачем | Когда |
| --- | --- | --- |
| GitHub, PyPI, npm, Docker Hub, apt-зеркала, источник моделей GigaAM, Hugging Face | установка, сборка, обновление | только при установке и обновлении; в работе нужна только локальная сеть |
| Контроллеры домена, `636/tcp` (LDAPS) или `389/tcp` (STARTTLS) | вход, поиск, профили | всегда, если подключён каталог |
| SMTP-сервер | рассылка материалов | если настроена почта |
| SMB-сервер, `445/tcp` | хранилища | если настроены |
| Внешняя LLM и обезличиватель | протоколы | если подключены |
| Портал Bitrix24 (только чтение) | профили | если включено |
| Получатели событий (HTTPS) | webhooks | если созданы |
| АТС | SIP | если включена телефония |

## Параметры ядра для WebRTC

| Параметр | Типовое значение | Рекомендуется |
| --- | --- | --- |
| `net.core.rmem_max`, `net.core.wmem_max` | 212992 | не менее 5 000 000 (LiveKit предупреждает о малом буфере) |
| `net.core.netdev_max_backlog` | 1000 | не менее 5000 |
| `vm.overcommit_memory` | 0 | 1 (рекомендация Redis) |

На `standalone` установщик применяет значения сам (`/etc/sysctl.d/99-peregovorka.conf`). На `shared-host` параметры глобальны: `sudo scripts/tune-kernel.sh --apply` требует подтверждения.

## Работа через VPN и NAT

- Если страница открывается, а вход в комнату рвётся с `ERR_CONNECTION_RESET`, проверьте MTU VPN-адаптера (помогало `MTU=1250`).
- Маршрут до `LIVEKIT_NODE_IP` должен идти через туннель; VPN должен пропускать UDP. Если UDP запрещён, звонок заработает по TCP-порту, но медиа по TCP чувствительнее к потерям.
- Гости извне: публичный HTTPS-адрес и те же порты LiveKit.
