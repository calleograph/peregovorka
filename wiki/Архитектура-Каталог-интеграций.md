# Архитектура: каталог интеграций

*Для кого: администратор, инженер поддержки.*

По каждой интеграции здесь видно, как она работает, что нужно настроить и как искать причину сбоя. Пошаговая настройка лежит на страницах по ссылкам.

Сводка:

| Интеграция | Компонент | Направление | Протокол | Обязательна |
|---|---|---|---|---|
| LDAP / AD | `backend` | сервер → каталог | LDAPS 636, STARTTLS 389 | нет |
| SMTP | `backend` | сервер → почта | SMTP | нет |
| Файловые хранилища | `backend` | сервер → SMB | SMB 2/3 | нет |
| LiveKit | все | внутри | WebSocket, WebRTC | да |
| Egress | `livekit-egress` | внутри, наружу RTMP | Redis, WebRTC, RTMP | для записи и эфира |
| MediaMTX | `mediamtx`, `web` | внутри | RTMP, HTTP | нет: без него зрители смотрят обычный HLS |
| ASR | `asr` | внутри | Redis, WebRTC, HTTP 8090 от `backend` | для стенограммы |
| Языковая модель | `backend` | сервер → модель | HTTPS | для протоколов |
| SIP | `livekit-sip` | сервер ↔ АТС | SIP, RTP | нет |
| Exchange, Outlook | `backend`, надстройка | сервер → Exchange | HTTPS | нет |
| Площадки RTMP | `livekit-egress` | сервер → площадка | RTMP, RTMPS | нет |
| Узлы CDN | `backend`, `web` | в обе стороны | SSH, HTTPS | нет |
| Bitrix24 | `backend` | сервер → портал | HTTPS | нет |
| Публичный API, webhooks | `backend` | в обе стороны | HTTPS | нет |
| APT-репозиторий | приложение Linux | клиент → репозиторий | HTTPS | для Linux |

## LDAP / Active Directory

- **Назначение:** вход доменной учётной записью, группы доступа, профили.
- **Как работает:** поиск служебной записью, проверка пароля входом самого пользователя, вложенные группы через `LDAP_MATCHING_RULE_IN_CHAIN`.
- **Настройка:** адреса контроллеров, Base DN, служебная запись; сертификаты в **Каталог: сертификаты (CA)**; доступ в **Кто может входить** и **Администраторы сервера**.
- **Безопасность:** только LDAPS или STARTTLS, сертификат проверяется по каталогу CA, пароль записи зашифрован.
- **Типовые ошибки:** неверный CA, неверный DN, истёкший пароль записи, контроллер недоступен.
- **Диагностика:** **Администрирование → Интеграции → Каталог: подключения LDAP/AD**, кнопка проверки подключения; [Решение проблем: вход и каталог](Решение-проблем-входа-и-каталога).
- **Настройка по шагам:** [Как подключить Active Directory](Как-подключить-Active-Directory).

## SMTP

- **Назначение:** материалы встреч, приглашения, уведомления.
- **Как работает:** очередь писем в базе, ведущий процесс отправляет с повторами, журнал доставки.
- **Настройка:** **Администрирование → Интеграции → Почта: сервер SMTP**: сервер, порт, защита, логин, отправитель; NTLM для Exchange.
- **Безопасность:** STARTTLS или SSL; NTLM — только по защищённому каналу; пароль зашифрован.
- **Типовые ошибки:** отказ авторизации, запрет отправителя, размер вложения.
- **Диагностика:** тестовое письмо, журнал доставки, [Решение проблем: Outlook и почта](Решение-проблем-Outlook-и-почты).
- **Настройка по шагам:** [Как подключить почту](Как-подключить-почту).

## Файловые хранилища

- **Назначение:** записи, стенограммы, протоколы, доски, вложения.
- **Как работает:** SMB 2/3 реализован в приложении; локальный каталог — в том числе примонтированный NFS или iSCSI. S3 не реализован.
- **Настройка:** **Администрирование → Интеграции → Файловые хранилища**: профиль с сервером, ресурсом, учётной записью и папками. Внешний том: смонтированный на сервере каталог подключается отметкой **Внешний том**, см. [Внешние тома](Внешние-тома).
- **Безопасность:** отдельная запись с правами на папку, пароль зашифрован.
- **Типовые ошибки:** нет прав, ресурс недоступен, нет места.
- **Диагностика:** **Проверить** в профиле, **Хранение и журналы → Целостность хранилищ**, [Решение проблем: хранилища](Решение-проблем-файловых-хранилищ).
- **Настройка по шагам:** [Подключение внешних хранилищ](Подключение-внешних-хранилищ).

## LiveKit

- **Назначение:** звук, видео, показ экрана.
- **Как работает:** SFU на закреплённой версии; `backend` выдаёт токены с правами роли и получает webhook.
- **Настройка:** порты, адреса ICE: `scripts/medianet.sh`, [Как настроить LiveKit](Как-настроить-LiveKit).
- **Безопасность:** токены с правами роли, DTLS-SRTP, по настройке E2EE.
- **Типовые ошибки:** закрытые медиапорты, неверный адрес за NAT.
- **Диагностика:** **Сетевая доступность**, `scripts/medianet.sh check`, [Решение проблем: звонки и сеть](Решение-проблем-звонков-и-сети).

## LiveKit Egress

- **Назначение:** видеозапись и эфир.
- **Как работает:** задания через Redis, браузер в памяти открывает страницу-рекордер, кодировщик пишет MP4, HLS, RTMP на площадки и внутренний RTMP в MediaMTX. MP4 лежит в `live/tmp` до конца задания, затем копируется в том записей.
- **Настройка:** **Интеграции → Видеозапись** или **Трансляции**, кнопка **Установить и включить**. Команда на сервере: `sudo scripts/video.sh enable`. Инструкция: [Как настроить видеозапись и трансляции на сервере](Как-настроить-видеозапись-и-трансляции-на-сервере).
- **Безопасность:** страница-рекордер получает подписанный токен; контейнер без внешних портов; нужна возможность `SYS_ADMIN` для песочницы браузера.
- **Типовые ошибки:** служба не включена, нет связи с Redis, нехватка места в `live/tmp`, нагрузка выше предела, браузер не поднялся за 20 секунд.
- **Диагностика:** проверки в разделе, `scripts/logs.sh livekit-egress --tail 200`, [Решение проблем: видеозапись и трансляции](Решение-проблем-видеозаписи-и-трансляций).

## MediaMTX

- **Назначение:** LL-HLS для зрителей с основного сервера.
- **Как работает:** принимает внутренний RTMP от Egress на порту 1935 и без перекодирования отдаёт LL-HLS на порту 8888. Наружу портов нет, запросы идут через `web`, который проверяет подпись.
- **Настройка:** служба запускается вместе с `video.sh enable`. В **Интеграции → Трансляции** настройки **Низкая задержка для зрителей (LL-HLS)** и **Зрителей с низкой задержкой, не больше**.
- **Безопасность:** имя потока равно идентификатору доступа, отзыв ссылки переводит поток на новое имя.
- **Типовые ошибки:** образ не загружен, служба остановлена. Зрители в обоих случаях смотрят обычный HLS.
- **Диагностика:** строка **Низкая задержка** в панели диагностики эфира, `scripts/logs.sh mediamtx`. Перезапуск: `sudo scripts/ctl.sh restart mediamtx`. Команда `scripts/status.sh` эту службу не показывает.

## ASR

- **Назначение:** стенограмма.
- **Как работает:** скрытый участник комнаты, VAD, GigaAM, сегменты через Redis. Управление моделями: `backend` обращается к службе по HTTP 8090.
- **Настройка:** **Администрирование → Интеграции → Распознавание речи (ASR)**, `scripts/models.sh`, [Как настроить распознавание речи](Как-настроить-распознавание-речи).
- **Безопасность:** работает на сервере, наружу ничего не передаёт.
- **Типовые ошибки:** модель не подготовлена, очередь растёт из-за нехватки процессора.
- **Диагностика:** очередь и RTF в разделе «Обзор», `scripts/asr-bench.sh`.

## Языковая модель

- **Назначение:** протоколы, резюме, карта разговора.
- **Как работает:** единственная точка выхода `LlmClient.complete`, текст делится на фрагменты, результат проверяется.
- **Настройка:** подключение и назначения: [Как настроить языковые модели](Как-настроить-языковые-модели).
- **Безопасность:** маскировка секретов всегда, обезличивание по настройке, ключ зашифрован.
- **Типовые ошибки:** пустой ответ, обрыв по длине, отказ провайдера.
- **Диагностика:** «Проверить», журнал обращений.

## SIP

- **Назначение:** вход и выход в телефонную сеть.
- **Как работает:** служба LiveKit SIP соединяет транк АТС с комнатами, правила в `backend`.
- **Настройка:** [Как подключить SIP-телефонию](Как-подключить-SIP-телефонию).
- **Безопасность:** порты открываются только АТС, адреса — списком.
- **Типовые ошибки:** закрыт RTP, неверный диапазон, адрес за NAT.
- **Диагностика:** **Администрирование → Интеграции → SIP-телефония**, `scripts/sip.sh`.

## Exchange и Outlook

- **Назначение:** встречи из календаря, надстройка Outlook.
- **Как работает:** чтение и запись календаря через EWS или Graph; надстройка — панель внутри Outlook.
- **Настройка:** [Интеграция с Outlook и Exchange](Интеграция-с-Outlook-и-Exchange).
- **Безопасность:** отдельная учётная запись службы, зашифрованные данные входа.
- **Типовые ошибки:** нет прав на почтовый ящик, манифест не установлен.
- **Диагностика:** [Диагностика ошибок Outlook](Outlook-Диагностика-типичных-ошибок).

## Площадки RTMP

- **Назначение:** эфир на YouTube, RUTUBE, VK, Twitch, свой сервер.
- **Как работает:** выход Egress, добавляется, снимается и получает новый ключ без остановки эфира.
- **Настройка:** адрес и ключ в комнате, кнопка **Настройки эфира**; разрешённые площадки в **Интеграции → Трансляции**.
- **Безопасность:** ключ зашифрован и не отдаётся API; проверка адреса от обращений к внутренней сети.
- **Типовые ошибки:** «Проверить сервер» проходит, а ключ неверный: ключ проверяет площадка только при старте.
- **Диагностика:** статус площадки в окне **Настройки эфира**, [Решение проблем](Решение-проблем-видеозаписи-и-трансляций).

## Узлы CDN

- **Назначение:** раздача эфиров с отдельных серверов.
- **Как работает:** узел забирает HLS с `/cdn-origin/` и сам проверяет подпись ES256.
- **Настройка:** [Узлы CDN](Узлы-CDN).
- **Безопасность:** у узла нет закрытых ключей; пароль только на установку; управление только `pgcdn-ctl`.
- **Типовые ошибки:** см. таблицу на странице узлов.
- **Диагностика:** карточка узла, «Проверить раздачу», «Журнал».

## APT-репозиторий

- **Назначение:** установка и обновление приложения для Linux.
- **Как работает:** клиент получает пакет из подписанного репозитория.
- **Настройка:** [Как установить приложение для Linux](Как-установить-приложение-для-Linux).
- **Безопасность:** подпись репозитория, отпечаток проверяется при подключении.
- **Типовые ошибки:** не подключён ключ, нет доступа к репозитории.
- **Диагностика:** `apt update`, раздел «Диагностика» в [docs/LINUX.md](https://github.com/calleograph/peregovorka/blob/main/docs/LINUX.md).

## Bitrix24, API, webhooks

- [Bitrix24](Как-подключить-Bitrix24): только чтение профилей и подразделений по HTTPS. CRM, календаря и уведомлений нет. Ручная правка пользователя сильнее синхронизации.
- [Публичный API](Как-использовать-публичный-API): ключи с областями, журнал, ограничения. Записи отдаются только по участникам, без общей аудиозаписи и видео.
- [Webhooks](Как-использовать-webhook): подпись получателю, повторы с нарастающей паузой, до 3 адресов. При выключенном API события не создаются.
