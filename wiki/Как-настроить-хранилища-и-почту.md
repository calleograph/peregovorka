# Как настроить хранилища и почту

> Относится к версии 0.39.4 · проверено 2026-10-25 · уровень проверки: 2 (автотесты, подставной SMB-клиент и подставной SMTP-сервер); **настоящие SMB и Exchange не проверялись** · тип страницы: практическое руководство

Результат: записи, протоколы и вложения чата сохраняются в нужное место, а материалы встреч уходят по почте. Для кого: администратор. Справка по данным — [[Справочник: конфигурация|Справочник-конфигурация]].

## Что нужно заранее

- Для SMB: сервер, ресурс, учётная запись с правом записи, доступность `445/tcp` с сервера Peregovorka.
- Для почты: адрес SMTP-сервера, порт, способ защиты (None, STARTTLS, SSL/TLS), учётная запись с правом отправки от имени отправителя.
- Каталог `DATA_ROOT` — всегда **локальный** путь Linux на сервере; UNC-путь и `smb://` отвергаются.

## Создать профиль хранилища

1. **Администрирование → Хранилища (серверы файлов)**.
2. Создайте профиль: название, тип (SMB или локальный каталог), сервер, ресурс, подкаталог, домен, учётная запись, пароль. Пароль хранится зашифрованным (AES-GCM, ключ `APP_MASTER_KEY`) и обратно не показывается.
3. Нажмите «Проверить»: система делает пробную запись и создаёт подпапки.

   Ожидаемый результат: проверка успешна, в ресурсе появились подпапки.

Один профиль используют несколько функций; пароль вводить повторно не нужно.

| Функция (раздел) | Подпапка в профиле |
| --- | --- |
| Записи аудио (`audio_storage`) | `Audio/` |
| Протоколы и материалы встречи (`storage`) | `Transcripts/`, `Protocols/`, `Chat/`, `Boards/` |
| Вложения чата (`chat_files`) | `Chat/files/<встреча>/<id>.<расширение>` |
| Журнал событий (`journal`) | `Logs/journal/…` |

Выберите профиль в разделе каждой функции. Выбор профиля не переносит уже записанные файлы: они остаются на прежнем месте. Профиль, который выбран функцией или хранит вложения чата, удалить нельзя. Выгруженные файлы по срокам хранения не удаляются.

Структура протоколов: `<комната>/<дата, день недели>/<время>/…`.

## Если хранилище недоступно

Файл не теряется молча: запись аудио остаётся на диске приложения со статусом «ошибка выгрузки» и выгружается повторно (кнопка «Повторить выгрузку записей»); вложение чата не принимается («хранилище вложений недоступно», событие `chat_file_save_failed`); недоступные профили при выгрузке протоколов пишут событие `storage_unavailable`.

## Сверить хранилище с базой

**Администрирование → Хранилища → Сверка хранилищ**: сервис сравнивает метаданные с реальным диском или SMB. Удалённый вручную файл получает состояние `missing`, ссылка на скачивание больше не отдаётся. Неизвестные файлы не импортируются, только считаются. Недоступное хранилище не равно удалённым файлам: объекты помечаются «не удалось проверить». Если пропало не менее 95 % файлов выборки (и не менее 10), изменения не применяются, пока вы не подтвердите. Расписание: раз в 12 часов по умолчанию (от 1 до 168). Кнопка «Проверить / синхронизировать хранилище» запускает сверку сразу.

## Настроить исходящую почту

1. **Администрирование → Интеграции → Исходящая почта (SMTP)** → создайте профиль: сервер, порт, защита, аутентификация, адрес и имя отправителя (обычно noreply), таймаут, проверка сертификата. Можно завести несколько профилей; письма отправляет активный.
2. Нажмите «Проверить соединение»: этапы DNS → подключение → защита → вход. При отказе показывается не только код, но и текст ответа сервера, например `550 5.7.60 … Client does not have permissions to send as this sender`.
3. Нажмите «Отправить тестовое письмо», введите свой адрес.

   Ожидаемый результат: письмо приходит сразу (отправка не через очередь).

Сертификат почтового сервера проверяется по системным CA и набору из «Сертификатов (CA)». Отключить проверку можно только явной настройкой профиля (в интерфейсе помечена предупреждением).

**Правила рассылки** (администратор): разрешённые домены получателей, предел вложений (по умолчанию 10 МБ), число повторов. **Журнал отправки**: время, комната, получатель, материалы, результат, число попыток, последняя ошибка; неудавшиеся письма можно повторить.

## Настроить рассылку материалов в комнате

Руководитель комнаты открывает «Настройки комнаты → Материалы после встречи» и выбирает материалы (протокол, резюме, стенограмма, при необходимости одним ZIP) и получателей (руководители, участники, выбранные сотрудники, свои адреса), включает автоматическую отправку. Настройки комнаты — значения по умолчанию для каждой встречи; для идущей встречи — кнопка «Эта встреча». Письма не отправляются внутри HTTP-запроса: они ставятся в очередь `queued → sending → sent | failed`; при временной ошибке отправка повторяется (по умолчанию 4 попытки, пауза 5 минут и далее вдвое дольше), постоянные ошибки повторов не получают. Запись аудио по почте не отправляется. Гости писем не получают.

## Типичные ошибки

| Симптом | Причина | Что делать |
| --- | --- | --- |
| В хранилище нет файлов | неверные права, закрыт `445/tcp` | «Проверить подключение»; права учётной записи на запись |
| `550 … permissions to send as this sender` | у учётной записи нет права «Send As» | выдать право на почтовом сервере |
| Получатель помечен «в каталоге нет адреса» | в AD нет атрибута `mail` | заполнить атрибут |
| Письмо без вложений, но со ссылкой | документы вместе больше предела | ожидаемо; ссылка открывается после входа |
