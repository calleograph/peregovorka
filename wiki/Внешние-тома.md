# Внешние тома

*Для кого: администратор сервера.*

## Зачем это нужно

Внешний том — это каталог на сервере, куда смонтирована сетевая папка или отдельный диск. Приложение работает в контейнере и такой каталог само не видит. Функция открывает его приложению без правки Docker и `.env` и защищает системный диск: если том отвалился, запись останавливается, а файлы не попадают на локальный диск.

Сетевую папку SMB можно подключить и напрямую, без монтирования: [Подключение внешних хранилищ](Подключение-внешних-хранилищ). Внешний том нужен для NFS, iSCSI, отдельных дисков и SMB, смонтированного средствами системы.

## Когда пригодится

- Записи должны лежать на NAS по NFS.
- На сервере есть второй диск под материалы.
- После отключения сетевой папки файлы попали на системный диск, и этого нельзя допускать.

## Что потребуется

- `sudo` на сервере: монтирование настраиваете вы.
- Работающий помощник обновлений. Он выполняет подключение и следит за томом. Проверка: `sudo scripts/updater.sh status`.
- Каталог внутри `/mnt`, `/media` или `/srv`. Другие корни задаёт параметр `VOLUME_ALLOWED_ROOTS`, из браузера его не расширить.
- Путь только из латиницы, цифр и знаков `. _ - /`, без символьных ссылок и без завершающей косой черты.
- Право записи для пользователя с номером 10001: от его имени работает приложение.

Нельзя подключить каталог внутри `DATA_ROOT` или каталога установки, а также их родительский каталог.

## Где найти

**Администрирование → Интеграции → Файловые хранилища**, кнопка **＋ Добавить хранилище**, тип **Локальный каталог на сервере приложения**, отметка **Внешний том: смонтированная сетевая папка или диск**.

## Как это сделать

### Смонтировать том на сервере ⚠

Пример для NFS. Строка в `/etc/fstab`:

```text
192.0.2.20:/export/peregovorka  /mnt/nas-records  nfs  _netdev,nofail,soft,timeo=30,retrans=2  0  0
```

Параметры `soft`, `timeo` и `retrans` нужны, чтобы при обрыве связи операции завершались ошибкой, а не ждали сервер. `nofail` не даёт системе остановиться при загрузке.

```bash
sudo mkdir -p /mnt/nas-records
sudo mount /mnt/nas-records
sudo chown 10001:10001 /mnt/nas-records    # или настройте соответствие пользователей на сервере хранения
```

### Подключить том из браузера ⚠

1. Откройте **Файловые хранилища** и нажмите **＋ Добавить хранилище**.
2. Укажите название и выберите **Локальный каталог на сервере приложения**.
3. Отметьте **Внешний том: смонтированная сетевая папка или диск**.
4. В поле **Путь на сервере** укажите `/mnt/nas-records`.
5. Нажмите **Сохранить**, затем **Проверить**.

Проверка подключает том, делает пробную запись, создаёт подпапки и ставит на томе метку. По метке приложение понимает, что пишет именно на этот том.

**Последствия.** В приложении том виден как `/data/ext/<ИД>`. Работающие контейнеры пересоздавать не нужно. Исключение — сервер без общих монтирований: тогда `backend` пересоздаётся один раз, и на несколько секунд появятся ошибки интерфейса.

Выбор хранилища для функций и перенос старых файлов — [Как перенести данные между хранилищами](Как-перенести-данные-между-хранилищами).

### Подключить том из терминала ⚠

Команды делают то же, что помощник по запросу из браузера.

```bash
cd /opt/peregovorka
sudo scripts/volumes.sh attach /mnt/nas-records    # проверить каталог и открыть его приложению
sudo scripts/volumes.sh list                       # состояние всех томов в JSON
sudo scripts/volumes.sh reconcile                  # сверить подключения с фактическим монтированием
sudo scripts/volumes.sh detach <ИД>                # снять подключение
```

| Команда | Что меняет | Последствия |
| --- | --- | --- |
| `attach ПУТЬ` | проверяет путь и запись, подключает каталог к `DATA_ROOT/ext/<ИД>`, запоминает файловую систему в `DATA_ROOT/state/volumes.tsv` | том доступен приложению |
| `detach ИД` | снимает подключение и удаляет запись о томе | приложение теряет доступ, **данные на ресурсе остаются**; запись в это хранилище останавливается, помощник том сам не вернёт |
| `reconcile` | приводит подключения в соответствие с монтированием | то же помощник выполняет сам каждые 15 секунд |
| `list` | ничего | только чтение |

`ИД` показывает `list`. Он строится из пути, например `mnt-nas-records-1a2b3c`.

### Разрешить другой корень ⚠

В `.env` укажите корни через двоеточие. Помощник читает файл заново перед каждым действием, перезапуск не нужен.

```bash
VOLUME_ALLOWED_ROOTS=/mnt:/media:/srv:/data2
```

Не добавляйте `/` и системные каталоги: параметр определяет, что приложение сможет открыть.

### Как работает защита

- Пока том не подключён, точка подключения пуста и закрыта для записи. Приложение не может туда писать.
- Каждые 15 секунд помощник сверяет том с запомненной файловой системой. Если её нет, подключение снимается, а когда том вернулся, восстанавливается само, в том числе после перезагрузки сервера.
- Перед каждой записью приложение проверяет монтирование и метку.

### Резервные копии и перенос сервера

Содержимое внешнего тома не входит в `backup.sh`. Копии делает владелец хранилища. На новом сервере смонтируйте том тем же способом и выполните `volumes.sh attach`: список томов из `DATA_ROOT/state` в архив тоже не входит.

## Что получится

- В строке хранилища нет предупреждений, видны состояние и свободное место.
- `sudo scripts/volumes.sh list` показывает `"state":"attached"`.
- Новые файлы появляются на томе в подпапках `Audio/`, `Video/`, `Protocols/` и других.

## Если не получается

| Что видно | Что значит | Что сделать |
| --- | --- | --- |
| **не подключён: запись остановлена** | ресурс не смонтирован | смонтируйте его, приложение подключит том само за 15 секунд |
| **не отвечает: запись остановлена** | сервер хранения недоступен | восстановите связь, данные на месте |
| «Пользователь приложения (uid 10001) не может записать» | нет прав на ресурсе | выдайте права или настройте соответствие пользователей |
| «Разрешены каталоги внутри…» | путь вне разрешённых корней | используйте `/mnt/…` или расширьте `VOLUME_ALLOWED_ROOTS` |
| «Путь содержит символьную ссылку» | указан не настоящий путь | укажите путь из сообщения |
| «Этот каталог уже принадлежит приложению» | каталог внутри `DATA_ROOT` или установки | выберите отдельный каталог |
| «Помощник на сервере не запущен» | нет службы обновлений | `sudo scripts/updater.sh install --yes` или `sudo scripts/volumes.sh attach ПУТЬ` |
