# Как опубликовать сервис в интернете: порты и проверка

> Относится к версии 0.40.0 · проверено 2026-10-26 · уровень проверки: 3 для построения перечня (автотесты, страница в браузере, команда на примере `.env`); **доступность из настоящего интернета, NAT и межсетевые экраны не проверялись** · тип страницы: практическое руководство

Результат: сетевой администратор получает точный перечень правил для вашего сервера. Для кого: администратор Peregovorka. Перечень строится по настройкам установки, а не из общей таблицы: другие порты в `.env` дают другой перечень.

## Получить перечень

- **В веб-интерфейсе:** Администрирование → Система → **Сетевая доступность** (или кнопка «Показать необходимые порты» в «Обзоре»). Есть «Скопировать список», «Скопировать заявку для сетевого администратора» и выгрузка TXT, CSV, Markdown.
- **В терминале, без веб-интерфейса и Docker** (читает только `.env`):

```bash
scripts/ports.sh                           # не запускалась на реальном сервере
scripts/ports.sh --format request          # заявка сетевому администратору
scripts/ports.sh --live                    # плюс адреса интеграций из базы: каталог, почта, SMB, Exchange…
```

Перечень делит правила на входящие (на межсетевом экране перед сервером) и исходящие (с сервера), показывает протокол, порт или диапазон, обязательность, компонент и назначение, предупреждения (например, частный `LIVEKIT_NODE_IP` за NAT) и порты, которые наружу публиковать **нельзя**.

## Что обычно получается

HTTPS на 443 (на reverse proxy или nginx установщика); порты LiveKit из `.env` — UDP как основной путь для звука и видео, TCP как запасной (без него пользователи за фильтрующим UDP файрволом не смогут говорить); SIP — только при включённой телефонии. Порты на сервере (`WEB_PORT`, `NGINX_LISTEN_PORT`, LiveKit API, PostgreSQL, Redis, ASR) наружу не публикуются. Подробный справочник — [[Справочник: порты и сеть|Справочник-порты-и-сеть]].

## NAT

LiveKit объявляет клиентам адрес `LIVEKIT_NODE_IP` и тот же номер порта: на NAT пробрасывайте порт **без смены номера** и укажите внешний адрес. Пользователям из локальной сети этот адрес должен быть достижим.

## Как проверить, что порт доступен снаружи

Кнопка «Проверить с сервера» выполняет соединение **изнутри**: оно не проходит внешний NAT и межсетевой экран и **не доказывает** доступность из интернета (так и написано в ответе). Для UDP внешней проверки без участия клиента не существует. Достоверно: войдите в тестовый звонок с компьютера вне сети организации (например, через мобильную сеть) и откройте «Диагностика клиентов»: видно, шёл ли звук по UDP или по TCP.

## Ограничения

Один экземпляр LiveKit; отдельный TURN и распределённые схемы штатной установкой не поддерживаются: правила для них составляются вручную. Внешние STUN/TURN приложение не использует.
