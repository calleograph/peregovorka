# Как опубликовать сервис в интернете: порты и проверка

*Для кого: администратор Peregovorka.*

**Что получится:** сетевой администратор получает точный перечень правил для вашего сервера. Перечень строится по настройкам установки, а не из общей таблицы: другие порты в `.env` дают другой перечень.

## Получить перечень

- **В веб-интерфейсе:** Администрирование → Система → **Сетевая доступность** (или кнопка «Показать необходимые порты» в «Обзоре»). Есть «Скопировать список», «Скопировать заявку для сетевого администратора» и выгрузка TXT, CSV, Markdown.
- **В терминале, без веб-интерфейса и Docker** (читает только `.env`):

```bash
scripts/ports.sh
scripts/ports.sh --format request          # заявка сетевому администратору
scripts/ports.sh --live                    # плюс адреса интеграций из базы: каталог, почта, SMB, Exchange…
```

Перечень делит правила на входящие (на межсетевом экране перед сервером) и исходящие (с сервера), показывает протокол, порт или диапазон, обязательность, компонент и назначение, предупреждения (например, частный `LIVEKIT_NODE_IP` за NAT) и порты, которые наружу публиковать **нельзя**.

## Что обычно получается

HTTPS на 443 (на reverse proxy или nginx установщика); порты LiveKit из `.env` — UDP как основной путь для звука и видео, TCP как запасной (без него пользователи за фильтрующим UDP файрволом не смогут говорить); SIP — только при включённой телефонии. Порты на сервере (`WEB_PORT`, `NGINX_LISTEN_PORT`, LiveKit API, PostgreSQL, Redis, ASR) наружу не публикуются. Подробный справочник — [Справочник: порты и сеть](Справочник-порты-и-сеть).

## NAT

За NAT пробросьте UDP `LIVEKIT_UDP_PORT` и TCP `LIVEKIT_TCP_PORT` на сервер **без смены номера и протокола**. Публичный адрес сервер определяет сам (или задайте `LIVEKIT_PUBLIC_IP`). Клиенты получают и его, и адрес в локальной сети, так что офис подключается напрямую. Готовые правила проброса и проверки (STUN, CGNAT, двойной NAT, медиапорт по публичному адресу) — в «Сетевая доступность → Медиасоединения» и `scripts/medianet.sh check`. Подробно — [Справочник: порты и сеть](Справочник-порты-и-сеть#адреса-для-звука-и-видео-nat).

## Как проверить, что порт доступен снаружи

Кнопка «Проверить с сервера» выполняет соединение **изнутри**: оно не проходит внешний NAT и межсетевой экран и **не доказывает** доступность из интернета (так и написано в ответе). Для UDP внешней проверки без участия клиента не существует. Достоверно: войдите в тестовый звонок с компьютера вне сети организации (например, через мобильную сеть). В «Сетевая доступность → Медиасоединения» появится адрес сервера, через который пошёл звук, и протокол UDP или TCP; то же видно в «Диагностика клиентов».

## Ограничения

Один экземпляр LiveKit; отдельный TURN и распределённые схемы штатной установкой не поддерживаются: правила для них составляются вручную. STUN используется только для определения публичного адреса за NAT.
