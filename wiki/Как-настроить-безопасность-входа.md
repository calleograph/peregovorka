# Как настроить безопасность входа

*Для кого: администратор сервера.*

## Зачем это нужно

Вход обычно первая цель атаки на сервер, доступный из сети. В Peregovorka вход защищают четыре механизма: второй фактор, защита от перебора, CAPTCHA и сроки сеансов. Все они работают на сервере, поэтому закрытие браузера, режим инкогнито, очистка cookie и смена User-Agent счётчики не сбрасывают.

Механизмы уже включены со значениями по умолчанию. Эта статья показывает, что стоит проверить и изменить под вашу организацию.

## Когда пригодится

- Сервер публикуется в интернете, и нужен второй фактор для администраторов.
- Служба ИБ просит описать и настроить правила входа.
- Сотрудники в офисе одновременно получают CAPTCHA или блокировку.
- В домене включена блокировка учётной записи, и сервис не должен её вызывать.
- Сотрудник потерял телефон с приложением-аутентификатором.
- Единственный локальный администратор потерял пароль.

## Что потребуется

- Права администратора Peregovorka.
- Для `.env` и консольных команд: доступ к серверу с правами root или участника группы `docker`.
- Копия `APP_MASTER_KEY` в защищённом месте, отдельно от базы. Этим ключом шифруются секреты второго фактора. Подробности: [Шифрование](Шифрование).
- Порог блокировки учётных записей в вашем домене, если вход идёт через Active Directory.
- Приложение-аутентификатор для пробы. Подходят Google Authenticator, Microsoft Authenticator, FreeOTP, Aegis и другие приложения с кодами по времени.

## Где найти

| Что настраивается | Путь |
| --- | --- |
| Второй фактор, число сеансов, срок входа в приложении Windows | **Администрирование → Безопасность → Вход и сеансы** |
| Пороги перебора, общие адреса | **Администрирование → Безопасность → Защита входа от перебора** |
| CAPTCHA и её проверка | **Администрирование → Безопасность → CAPTCHA** |
| Как сервер определяет адрес клиента | **Администрирование → Безопасность → Сеть и IP-адреса (прокси, WAF)** |
| Текущие блокировки | **Администрирование → Безопасность → Заблокированные адреса** |
| Кто вообще может войти | **Администрирование → Комнаты и пользователи → Кто может входить** |
| Сброс второго фактора и завершение сеансов сотрудника | **Администрирование → Комнаты и пользователи → Пользователи** |
| Сроки сеансов | файл `.env` в каталоге установки |

## Как это сделать

### Шаг 1. Проверьте, какой адрес видит сервер

Все счётчики и блокировки считаются по адресу клиента. Если сервер ошибается в адресе, защита срабатывает на всех сотрудников сразу. Начните с этой проверки.

1. Откройте **Безопасность → Сеть и IP-адреса (прокси, WAF)**.
2. В блоке **Что сервер видит сейчас** найдите строку **Ваш адрес для сервера**.
3. Сравните её с адресом вашего компьютера.
4. Если показан адрес прокси или внутренний адрес, настройте доверенные прокси по статье [Защита публичного сервера](Защита-публичного-сервера-Peregovorka).

### Шаг 2. Выберите политику второго фактора

1. Откройте **Безопасность → Вход и сеансы**.
2. В поле **Политика** выберите значение из таблицы.
3. Для значения **Обязательна для групп каталога** заполните поле **Группы каталога (для политики «для групп»)**. Укажите DN групп по одному в строке или через `;`, например `cn=finance,ou=groups,dc=example,dc=org`.
4. В поле **Название в приложении** задайте подпись записи в приложении-аутентификаторе.
5. Сохраните настройки.

| Политика | Что произойдёт |
| --- | --- |
| **Отключена (функция скрыта)** | Раздел настройки скрыт. Код при входе не спрашивается, даже если сотрудник настроил его раньше |
| **По желанию пользователя** | Значение по умолчанию. Каждый включает защиту сам в личном кабинете |
| **Обязательна администраторам** | Требование для администраторов приложения, включая локального администратора |
| **Обязательна всем** | Требование для всех учётных записей |
| **Обязательна для групп каталога** | Требование для участников перечисленных групп. Администраторы вне этих групп под требование не попадают |

Изменение политики не завершает открытые сеансы. Требование применяется при следующем входе. Если защита обязательна и ещё не настроена, сразу после пароля пользователь видит экран настройки. Остальные разделы для него закрыты, а сервер отвечает кодом `totp_enrollment_required`. Обязательную защиту сотрудник отключить не может.

Для администраторов начните с себя: настройте защиту и убедитесь, что вход работает, а уже потом включайте обязательную политику.

### Шаг 3. Настройте второй фактор для своей учётной записи

1. Откройте **Личный кабинет**, блок **Двухфакторная аутентификация**.
2. Введите пароль в поле **Ваш пароль** и нажмите **Настроить**.
3. Отсканируйте QR-код приложением. Если камеры нет, введите показанный ключ вручную и выберите тип кода «по времени».
4. Введите шестизначный код в поле **Код** и нажмите **Включить**. На это даётся 10 минут.
5. Сохраните 10 резервных кодов. Они показываются один раз, каждый действует один раз.
6. Отметьте **Я сохранил(а) коды** и нажмите **Готово**.

Новые резервные коды создаёт кнопка **Создать новые резервные коды**. Понадобятся пароль и текущий код из приложения, резервный код здесь не подойдёт. Прежние коды перестанут действовать.

При следующем входе после пароля появится поле **Код подтверждения**. Подходит код из приложения или резервный код.

### Шаг 4. Настройте пороги защиты от перебора

1. Откройте **Безопасность → Защита входа от перебора**.
2. Проверьте, что включён параметр **Защита входа включена**.
3. В поле **Неудач по учётной записи до защиты каталога** задайте значение ниже порога блокировки в вашем домене.
4. Перечислите адреса выхода офисов и VPN в поле **Адреса и подсети общих выходов**.
5. Сохраните настройки.

Реакции нарастают по мере неудач. Значения ниже действуют по умолчанию.

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| **Окно подсчёта неудач** | 15 минут | Период, за который считаются неудачи для блокировок |
| **Замедлять ответ, начиная с неудачи №** | 4 | Дальше ответ о неудаче задерживается. 0 отключает замедление |
| **Прибавка к задержке за каждую неудачу** | 400 мс | Шаг задержки |
| **Потолок задержки** | 3000 мс | Предел задержки |
| **Неудач по учётной записи до защиты каталога** | 10 | Дальше попытки с незнакомых адресов не доходят до каталога |
| **Неудач с одного адреса до временной блокировки** | 25 | Адрес блокируется |
| **Разных учётных записей с одного адреса до блокировки** | 8 | Признак подбора по списку логинов, ни один из которых не подошёл |
| **Длительность первой блокировки** | 15 минут | Срок первой блокировки адреса |
| **Потолок длительности при повторах** | 1440 минут | Каждый повтор вдвое дольше, но не больше этого значения |
| **Помнить прежние блокировки адреса** | 7 дней | Сколько сервер учитывает прежние блокировки |
| **Запросов ко входу с одного адреса в минуту** | 120 | Выше сервер отвечает отказом на 30 секунд. Для общих адресов предел в 10 раз выше |
| **Запросов ко входу со всех адресов в минуту** | 600 | Выше CAPTCHA требуется от всех. Режим CAPTCHA **Никогда** это отключает |
| **Считать адрес общим, если с него вошло разных пользователей** | 5 | Разные успешные входы считаются за сутки |

Как устроены счётчики:

- **Учётная запись.** `alice`, `ALICE`, `EXAMPLE\alice` и `alice@example.org` считаются одной записью.
- **Адрес.** IPv6 считается по сети /64.
- **Незнакомый адрес.** Это адрес, с которого этот логин не входил успешно последние 30 дней. С привычного адреса попытки продолжают доходить до каталога, поэтому много неверных паролей оттуда всё ещё может заблокировать запись в домене.
- **Учётная запись целиком не блокируется.** Иначе чужую запись можно было бы закрыть несколькими запросами.
- **Общий адрес целиком не блокируется.** Для него остаются CAPTCHA и замедление. Исключение: администратор блокирует такой адрес вручную с подтверждением.
- **Успешный вход** сбрасывает счётчики записи и пары «запись и адрес», но не счётчик адреса.
- **Ответы не раскрывают причину.** Пользователь видит общий текст, а сработавшее правило видно в разделе **События и блокировки**.

Выключение параметра **Защита входа включена** оставляет только CAPTCHA в режиме **Всегда**. Блокировки, замедление и защита каталога перестают действовать.

### Шаг 5. Настройте CAPTCHA

1. Откройте **Безопасность → CAPTCHA**.
2. В поле **Когда требовать проверку** выберите режим.
3. В поле **Неудачных попыток до проверки** задайте порог. По умолчанию 5.
4. В поле **За какой срок считаются неудачи** задайте окно. По умолчанию 15 минут.
5. В поле **Вид проверки** оставьте **Картинка с символами (рекомендуется)**.
6. Сохраните настройки.
7. Нажмите **Проверить CAPTCHA** и пройдите проверку в окне.

| Режим | Вход | Вход гостя по ссылке | Создание временной переговорки |
| --- | --- | --- | --- |
| **Никогда** | не спрашивается | не спрашивается | не спрашивается |
| **После серии неудачных попыток** | после порога по адресу, записи или их паре, а также при всплеске запросов со всех адресов | после порога неверных паролей комнаты с этого адреса | не спрашивается |
| **Всегда** | перед каждым входом | перед каждым входом | перед каждым созданием |

Картинка одноразовая и привязана к адресу и назначению. Срок жизни по умолчанию 180 секунд. Любая проверка расходует картинку, даже верная. Одному адресу выдаётся не больше 20 картинок в минуту. Внешних сервисов нет.

Вид **Вычислительная задача в браузере (незаметна пользователю)** оставлен для особых случаев. Браузер решает её молча, бот справится так же.

Окно **Проверка CAPTCHA** показывает ответ сервера, действующий режим, порог, срок, состояние хранилища и шрифт картинки. Попытки в этом окне не считаются неудачными входами, а пройденная здесь проверка на входе не принимается.

CAPTCHA не защищает от целенаправленного автоматического распознавания картинки. Перебор ограничивают счётчики, поэтому на неё одну полагаться нельзя.

### Шаг 6. Задайте сроки сеансов и число устройств

Число устройств настраивается в **Безопасность → Вход и сеансы**:

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| **Одновременных сеансов одной учётной записи** | 5 | 0 снимает ограничение. Сверх предела вход не выбрасывает старые сеансы, а предлагает завершить один из них |
| **Приложение Windows помнит вход** | 30 дней | Срок от входа паролем, пределы от 0 до 90. Пароль не хранится, устройство получает отзываемый токен. 0 отключает запоминание |

Сроки сеанса задаются в `.env`:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `SESSION_IDLE_TIMEOUT_SECONDS` | `28800` | выход после 8 часов без активности |
| `SESSION_ABSOLUTE_TIMEOUT_SECONDS` | `86400` | предельный срок сеанса, 24 часа |
| `COOKIE_SECURE` | `true` | cookie передаётся только по HTTPS |

Чтобы применить правку `.env`, выполните команду в каталоге установки:

```bash
sudo scripts/ctl.sh restart backend
```

Пока контейнер пересоздаётся, запросы к приложению не обслуживаются. Выполняйте команду в окно обслуживания.

Параметры `LOGIN_MAX_FAILURES_*`, `LOGIN_FAILURE_WINDOW_SECONDS` и `LOGIN_LOCKOUT_SECONDS` больше не читаются. Пороги задаются только в разделах администрирования.

Сотрудник видит свои сеансы в **Личный кабинет → Активные устройства**. Администратор открывает их кнопкой **Сеансы** в разделе **Пользователи**.

### Шаг 7. Проверьте локального администратора

Локальный администратор не зависит от каталога и нужен для аварийного входа. Обычно это запись `admin`. Его пароль хранится как хэш argon2id и должен отвечать правилам:

- не короче 12 символов;
- не менее двух видов символов: строчные и заглавные буквы, цифры, знаки;
- не содержит имя пользователя.

Если пароль потерян, выполните команду в каталоге установки:

```bash
sudo scripts/admin-reset.sh
```

Команда выдаёт новый случайный пароль, который нужно сменить при входе. Она также отключает второй фактор этой записи, завершает её сеансы, очищает счётчики неудач записи и пишет событие в журнал аудита. Блокировку адреса она не снимает.

Если локального администратора нет, добавьте `--create`. Другое имя задаёт `--username`.

### Шаг 8. Подготовьте порядок при потере устройства

| Ситуация | Что сделать |
| --- | --- |
| Есть два резервных кода, политика не обязательна | Войти одним кодом. В личном кабинете нажать **Отключить**, ввести пароль и второй код в поле **Код из приложения**. Затем настроить защиту заново |
| Есть резервный код, защита обязательна | Войти кодом и обратиться к администратору за сбросом: отключить обязательную защиту нельзя, а новые резервные коды требуют кода из приложения |
| Резервных кодов нет | Администратор нажимает **сбросить** в колонке **2FA** раздела **Пользователи** и вводит свой пароль. Резервные коды тоже удаляются |
| Устройство потерял единственный локальный администратор | Выполнить `sudo scripts/admin-reset.sh` на сервере |

Сброс записывается в журнал аудита. У доменного пользователя открытые сеансы при сбросе не завершаются. Завершите их кнопкой **Сеансы**, если устройство могло попасть к чужим людям.

## Что получится

- **Безопасность → События и блокировки** показывает плитки и строку состояния защиты: защита входа включена, режим CAPTCHA виден.
- Неверные пароли сверх порога приводят к окну **Подтвердите, что вы не робот**.
- Администратор после пароля вводит код из приложения.
- Изменения политики и все действия со вторым фактором записаны в журнал аудита. Перечень: [Справочник: журнал аудита и события](Справочник-журнал-аудита-и-события).

## Если не получается

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| Код не принимается | Часы устройства или сервера расходятся больше чем на 30 секунд, либо этот код уже использован | Синхронизируйте время и дождитесь следующего кода |
| **Слишком много неверных кодов. Повторите позже.** | 15 неверных кодов за 30 минут по этой учётной записи | Подождите или войдите после сброса второго фактора |
| При настройке второго фактора ответ `APP_MASTER_KEY не задан` | В `.env` нет мастер-ключа | Обратитесь к тому, кто устанавливал сервер. Генерировать новый ключ на работающем сервере нельзя |
| CAPTCHA или блокировка у всех сразу | Сервер видит один адрес, прокси или WAF не объявлен доверенным | Выполните шаг 1 |
| Заблокирован адрес офиса | Подбор с этого адреса или общий NAT | Снимите блокировку в **Заблокированные адреса** и добавьте адрес в **Адреса и подсети общих выходов** |
| **Защита входа временно недоступна. Повторите попытку через минуту.** | Недоступно хранилище счётчиков Redis. Вход закрывается, а не открывается без защиты. Идущие встречи это не затрагивает | Проверьте сервис `redis` по статье [Диагностика](Диагностика) |
| **Проверка «я не робот» временно недоступна** | CAPTCHA не может выдать задачу | Откройте окно **Проверка CAPTCHA** и посмотрите строки **Хранилище** и **Шрифт** |
| После восстановления на новом сервере коды не работают | Второй фактор хранится у пользователей, а они не входят в резервную копию конфигурации | Пользователи настраивают защиту заново |
| Потерян `APP_MASTER_KEY` | Секреты второго фактора больше не расшифровываются | Сбросьте второй фактор пользователям. Подробности о других данных: [Шифрование](Шифрование) |

Симптомы при входе через каталог разобраны в статье [Решение проблем: вход и каталог](Решение-проблем-входа-и-каталога).

## Что проверено и что нет

| Что | Статус |
| --- | --- |
| Пороги, замедление, блокировка и её повтор, обход через cookie и User-Agent, подмена заголовков, общий адрес, отказ Redis, два экземпляра backend с общим Redis | Проверено в ограниченном сценарии: автотесты и браузер на тестовом экземпляре, без настоящего Active Directory |
| Вход сотрудников через настоящий Active Directory | Требует дополнительного тестирования |
| Наплыв входов через LDAP или AD, пределы входа и общий NAT под нагрузкой, CAPTCHA при наплыве | Требует дополнительного тестирования. В нагрузочных прогонах каталог был подставным, вход выполнялся до начала измерений и не более 100 одновременно |
| Настоящее приложение-аутентификатор и сдвиг часов | Требует дополнительного тестирования |
| WebAuthn и ключи доступа | Не реализованы |
