# Как настроить безопасность входа

> Относится к версии 0.39.4 · проверено 2026-10-25 · уровень проверки: 2–3 (автотесты, проверка в браузере на стенде) · тип страницы: практическое руководство

Результат: включена двухфакторная защита, локальная CAPTCHA, заданы сроки сеансов и лимиты попыток. Для кого: администратор. Модель защиты — [[Безопасность и приватность|Безопасность-и-приватность]].

## Что нужно заранее

- Права администратора.
- Копия мастер-ключа `APP_MASTER_KEY` в защищённом месте: им шифруются секреты двухфакторной защиты ([[Справочник: конфигурация|Справочник-конфигурация]]).

## Включить двухфакторную аутентификацию (TOTP)

Одноразовые коды по RFC 6238 (6 цифр, шаг 30 секунд) работают с Google Authenticator, Microsoft Authenticator, FreeOTP, Aegis и другими приложениями.

1. **Администрирование → Безопасность → Вход и сеансы** → выберите политику:

| Политика | Результат |
| --- | --- |
| Отключена | функция скрыта, код при входе не спрашивается |
| По желанию | каждый включает сам в «Личный кабинет → Двухфакторная аутентификация» |
| Обязательна администраторам, всем или группам каталога | после пароля пользователь попадает на экран настройки; пока 2FA не включена, сессия годится только для настройки (остальные запросы отвечают `403 totp_enrollment_required`) |

   Политика действует и на локального администратора. Изменение не разлогинивает открытые сеансы: требование применяется при следующем входе.

2. Пользователь включает 2FA: пароль → QR-код (секрет до подтверждения хранится в Redis 10 минут) → код из приложения → **10 резервных кодов** (показываются один раз).

Вход: пароль верен → одноразовая заявка (5 минут, 5 попыток) → код или резервный код → сеанс. Секрет шифруется AES-256-GCM ключом `APP_MASTER_KEY`; резервные коды хранятся как HMAC-SHA256 и гасятся одним условным обновлением. Расхождение часов допускается ±30 секунд.

**Потеряно устройство.** Есть резервный код — войдите им и создайте новые. Нет кодов — администратор в «Пользователи» нажимает «сбросить» (нужен его пароль). Единственный локальный администратор — на сервере `./scripts/admin-reset.sh` (новый пароль и сброс 2FA).

**Ограничения.** Потеря `APP_MASTER_KEY` требует сбросить 2FA у всех. WebAuthn и ключи доступа не реализованы. Секреты 2FA и резервные коды в резервную копию настроек не входят: после восстановления на новом сервере пользователи настраивают 2FA заново.

## Включить CAPTCHA

**Администрирование → Безопасность → CAPTCHA.** Сервер выдаёт вычислительную задачу (доказательство работы, формат ALTCHA), браузер решает её за доли секунды; внешних сервисов нет.

| Режим | Когда проверка нужна |
| --- | --- |
| Никогда | никогда |
| После серии неудач (по умолчанию) | после 20 (настраивается) неудачных входов или неверных паролей комнаты с одного IP за окно (по умолчанию 60 минут) |
| Всегда | перед каждым входом, входом гостя и созданием временной переговорки |

Параметр `difficulty` — верхняя граница числа; 50 000 — доли секунды на ноутбуке, для слабых телефонов не поднимайте выше 200 000. Режим «после серии неудач» считает по IP: за общим NAT неудачи складываются; при неверных доверенных прокси все запросы выглядят как один IP ([[Как настроить reverse proxy и HTTPS|Как-настроить-reverse-proxy-и-HTTPS]]).

## Настроить сеансы и перебор паролей

| Параметр (`.env`) | По умолчанию | Назначение |
| --- | --- | --- |
| `SESSION_IDLE_TIMEOUT_SECONDS` | 28800 | неактивность до выхода (8 часов) |
| `SESSION_ABSOLUTE_TIMEOUT_SECONDS` | 86400 | предельная жизнь сеанса (24 часа) |
| `LOGIN_MAX_FAILURES_PER_USER` | 20 | неверных вводов на логин до блокировки без обращения к AD |
| `LOGIN_MAX_FAILURES_PER_IP` | 60 | то же по адресу |
| `LOGIN_FAILURE_WINDOW_SECONDS` | 900 | окно подсчёта |
| `LOGIN_LOCKOUT_SECONDS` | 300 | длительность блокировки |
| `COOKIE_SECURE` | `true` | флаг Secure у cookie |

На учётную запись допускается до 5 сеансов (настраивается), список устройств — «Активные устройства». Администратор может завершить сеансы пользователя. Значения в существующем `.env` при обновлении не меняются автоматически.

Если порог блокировки в вашем AD ниже 20, уменьшите `LOGIN_MAX_FAILURES_PER_USER` ([[Как подключить Active Directory|Как-подключить-Active-Directory]]).

## Локальный администратор

Единственная локальная учётная запись — аварийный администратор (`admin`). Пароль не короче 12 символов, не менее двух видов символов, не содержит имя пользователя. Восстановление доступа:

```bash
sudo /opt/peregovorka/scripts/admin-reset.sh          # не запускалась
sudo /opt/peregovorka/scripts/admin-reset.sh --create # создать администратора, если его нет
```

Скрипт выдаёт новый случайный пароль (его нужно заменить при входе), завершает старые сеансы, снимает блокировку и пишет событие в аудит.

## Журнал аудита

Все изменения политики, 2FA и CAPTCHA пишутся в аудит: `auth.totp_enable`, `auth.totp_disable`, `auth.totp_failed`, `auth.backup_code_used`, `auth.totp_backup_regenerate`, `auth.totp_reset`, `captcha.rejected`. Список — [[Справочник: журнал аудита и события|Справочник-журнал-аудита-и-события]].

## Типичные ошибки

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Код не принимается | расхождение часов более 30 секунд, тот же код уже использован | синхронизировать время на устройстве |
| CAPTCHA включается у всех | неверные доверенные прокси, один IP | настроить `TRUSTED_PROXY_CIDRS` |
| Пользователь потерял устройство | нет кодов | сброс 2FA администратором |
