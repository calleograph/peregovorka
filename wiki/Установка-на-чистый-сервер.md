# Установка на чистый сервер

*Для кого: администратор, у которого сервер отдан под Peregovorka (профиль `standalone`).*

**Что получится:** работающая Peregovorka с проверкой всех сервисов и локальным администратором. Краткий путь — [Быстрый старт](Быстрый-старт). Для сервера с другими приложениями — [Установка на общий сервер](Установка-на-общий-сервер).

## Что нужно заранее

- Чистая Ubuntu 24.04 (или Ubuntu 22.04+, Debian 12+) и права `root`/`sudo` ([Системные требования](Системные-требования)).
- Доступ в интернет с сервера.
- DNS-имя и сертификат HTTPS — для рабочей эксплуатации (на первый запуск хватит самоподписанного).

## Шаги

1. Скачайте и запустите установщик.

   ```bash
   wget -O install.sh https://raw.githubusercontent.com/calleograph/peregovorka/main/install.sh
   chmod +x install.sh
   sudo ./install.sh
   ```

   Параметры (все необязательны, справка — `./install.sh --help`):

   | Параметр | Значение |
   | --- | --- |
   | `--host ИМЯ_ИЛИ_IP` | адрес, по которому сервер открывают в браузере; по умолчанию основной IP сервера |
   | `--https-port N` | порт HTTPS, по умолчанию 443 |
   | `--dir КАТАЛОГ` | куда установить проект, по умолчанию `/opt/peregovorka` |
   | `--data КАТАЛОГ` | каталог данных, по умолчанию `/srv/peregovorka-data` |
   | `--ref ВЕРСИЯ` | версия или ветка; по умолчанию последний релиз, `main` — свежая разработка |
   | `--skip-models` | не скачивать модель распознавания сейчас |
   | `--yes` | не задавать вопросов |

2. Дождитесь окончания. Установщик по порядку:

   1. определяет систему и отказывается, если она не поддерживается;
   2. ставит Docker, Compose, Buildx, nginx и утилиты (`apt install` без `upgrade`, `autoremove` и перезагрузки);
   3. создаёт каталоги данных и применяет параметры ядра для WebRTC (`/etc/sysctl.d/99-peregovorka.conf`);
   4. скачивает проект в `/opt/peregovorka`, создаёт `.env` с генерируемыми секретами (права 600) и самоподписанный сертификат;
   5. готовит модели: распознавание речи GigaAM и локальную языковую модель Qwen3 1.7B;
   6. собирает образы, запускает PostgreSQL и Redis, выполняет миграции, запускает остальные сервисы;
   7. включает nginx **последним**, когда приложение уже здорово;
   8. выполняет `verify` и `smoke-test`, ставит помощника обновлений (служба systemd от root), создаёт локального администратора.

   Ожидаемый результат: сообщение «УСТАНОВКА ЗАВЕРШЕНА», адрес приложения, логин `admin` и первичный пароль.

3. Откройте приложение и продолжите настройку: [Как подключить Active Directory](Как-подключить-Active-Directory), [Как настроить хранилища и почту](Как-настроить-хранилища-и-почту).

## Модели при установке

Модель распознавания (`v3_e2e_rnnt.ckpt` и `v3_e2e_rnnt_tokenizer.model`) загружается автоматически этапом `models`. Готовой считается только пара из двух файлов. Загрузка идёт с докачкой (`curl -C -`), четырьмя попытками, тайм-аутом соединения 20 секунд и остановкой при скорости ниже 10 КБ/с в течение минуты. Размер сверяется с `Content-Length`; страница HTML вместо файла отвергается и сохраняется как `*.failed`. Контрольные суммы по умолчанию не сверяются, потому что файлы источника могут обновляться; при необходимости задайте `GIGAAM_CKPT_SHA256` и `GIGAAM_TOKENIZER_SHA256` в `.env`.

**Закрытая сеть.** Скачайте файлы на другом компьютере и подготовьте модель из каталога:

```bash
cd /opt/peregovorka
sudo scripts/install.sh --profile standalone --from models --models-from /путь/к/gigaam
```

После загрузки права внутри `DATA_ROOT/models` приводятся к виду «читается всеми» (каталоги 755, файлы 644), потому что контейнер ASR работает от пользователя с uid 10001. Чужие каталоги данных установщик не затрагивает.

Если интернета нет, локальная языковая модель не загрузится: установка продолжится с явным сообщением. Загрузить позже: **Администрирование → Языковая модель (LLM) → «Скачать модель»** или `sudo scripts/models.sh --llm-only` ([Как настроить языковые модели](Как-настроить-языковые-модели)).

## Сбои и повторный запуск

Установщик работает этапами: `prerequisites → preflight → dirs → kernel → models → pull → build → database → migrations → services → healthcheck → nginx → firewall → verify → helper → report`. Сбой печатается строкой вида `FAIL stage=build service=backend subsystem=docker-buildkit`, а при падении сервиса установщик показывает последние строки его журнала, вероятную причину и действие.

- Повторный запуск безопасен: готовые образы не пересобираются, PostgreSQL не пересоздаётся, данные не удаляются.
- Начать с нужного этапа: `sudo scripts/install.sh --profile standalone --from ЭТАП`; пересобрать образы: `--force-build`.
- При падении сервисов установщик останавливает только прикладные контейнеры проекта; nginx остаётся прежним.
- Ошибка прав на файлы модели исправляется автоматически (перезапускается только `asr`).
- Установщик никогда не выполняет `docker system prune`, не удаляет данные Docker и не перезапускает чужие контейнеры.

## Проверка

```bash
sudo ./scripts/verify.sh        # только чтение
sudo ./scripts/smoke-test.sh
```

Ожидаемый результат: `verify` без FAIL, `Smoke test: PASS`.

## Каталог трансляций

Установщик создаёт `${DATA_ROOT}/live` (владелец 10001) — общий том Egress, backend и nginx web для сегментов HLS. Включение трансляций — в **Администрирование → Трансляции** после установки службы Egress (`sudo scripts/video.sh enable`). Подробнее: [Собственная трансляция по HLS](Собственная-трансляция-по-HLS).

## Типичные ошибки

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `FAIL stage=models` | недоступен источник моделей | запустить повторно; при закрытой сети — `--models-from` |
| `FAIL … subsystem=registry-network` | недоступен Docker Hub или зеркало | повторить; уже скачанное сохраняется |
| `FAIL … subsystem=docker-buildkit` | сбой BuildKit или containerd | установщик сам переходит на старый сборщик; диагностика Docker — на стороне сервера |
| Порт занят | `preflight.sh` называет порт | изменить порт в `.env` |
| «Недопустимый Origin» | приложение открыто не по адресу `APP_PUBLIC_URL` | [Диагностика](Диагностика) |
