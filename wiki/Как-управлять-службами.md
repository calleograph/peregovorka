# Как управлять службами

*Для кого: администратор сервера.*

## Зачем это нужно

Peregovorka состоит из нескольких контейнеров Docker. На этой странице описано, как посмотреть их состояние, прочитать журнал, перезапустить, остановить и запустить одну службу или все сразу, и что при этом почувствуют пользователи.

Команды работают только с вашим экземпляром (`COMPOSE_PROJECT_NAME`). Чужие контейнеры, Docker и containerd они не трогают.

## Когда пригодится

- В «Обзоре» горит служба или пользователи жалуются на сбой.
- Вы изменили `.env` и хотите применить правку.
- Перед работами на сервере нужно остановить систему.
- Эфир не переходит на низкую задержку, и нужно проверить `mediamtx`.

## Что потребуется

- Доступ к серверу по SSH.
- Каталог установки: `/opt/peregovorka` после установки одной командой. Если не знаете путь, выполните `docker compose ls`: каталог лежит на уровень выше `deployment/`.
- Права. Файл `.env` имеет режим 600. После `install.sh` он принадлежит root, поэтому запускайте скрипты через `sudo`. На общем сервере, где `.env` принадлежит вашему пользователю из группы `docker`, `sudo` нужен только командам `video.sh`, `sip.sh`, `volumes.sh`, `repair.sh` и `tune-kernel.sh --apply`.

Все команды ниже выполняются из каталога установки. Для другого экземпляра на том же сервере добавьте `--env ФАЙЛ`.

## Какие службы есть

| Служба | Что делает | Когда работает |
| --- | --- | --- |
| `postgres` | база данных | всегда |
| `redis` | сессии, очереди, общая шина служб | всегда |
| `livekit` | сервер звонков | всегда |
| `backend` | API и фоновые задачи | всегда |
| `asr` | распознавание речи | всегда |
| `web` | сайт, сигнализация звонков, раздача эфира | всегда |
| `livekit-egress` | браузер, который записывает встречу и формирует эфир | включена видеоподсистема (`VIDEO_ENABLED=yes`, образ скачан) |
| `mediamtx` | низкая задержка эфира | вместе с `livekit-egress`, если образ MediaMTX уже на сервере |
| `livekit-sip` | телефония | включена телефония (`SIP_ENABLED=yes`, образ скачан) |

Контейнеры называются `<COMPOSE_PROJECT_NAME>-<служба>-1`. Перечень портов — [Порты и сервисы](Архитектура-Порты-и-сервисы).

## Где найти

В браузере:

- **Администрирование → Обзор → Обзор**: блоки **Требует внимания** и **Сервисы**.
- **Администрирование → Интеграции → Видеозапись** и **Трансляции**: состояние службы и кнопки **Перезапустить службу**, **Перезапустить LiveKit**, **Перезапустить web**.
- **Администрирование → Система → Обновления и версии**: помощник обновлений и **Исправить автоматически**.

Кнопки выполняет помощник обновлений на сервере. Если его нет, действуйте из терминала. Для `mediamtx` и `backend` кнопок нет: только команды ниже.

## Как это сделать

### Посмотреть состояние

Операция только читает данные.

```bash
sudo scripts/status.sh
```

Скрипт показывает контейнеры проекта, строку с `health` по каждой обязательной службе, версию backend и последние развёртывания. Код возврата `0` и строка «Все сервисы работают» означают, что шесть основных служб здоровы, а также `livekit-egress` и `livekit-sip`, если они включены в `.env`.

`mediamtx` виден в общем списке контейнеров, но на итог не влияет: это необязательная служба без проверки здоровья. Её состояние смотрите отдельно, см. раздел ниже.

После перезапуска удобно подождать готовности:

```bash
sudo scripts/status.sh --wait 180
```

### Прочитать журнал

Операция только читает данные. Пароли, токены и ключи в выводе заменяются на `***`.

```bash
sudo scripts/logs.sh backend --tail 200       # последние 200 строк одной службы
sudo scripts/logs.sh asr -f                   # в реальном времени, выход — Ctrl+C
sudo scripts/logs.sh livekit-egress --tail 300
sudo scripts/logs.sh mediamtx --tail 100
sudo scripts/logs.sh livekit-sip --tail 100
sudo scripts/logs.sh                          # все службы
```

Без `--tail` выводится 200 строк. Если служба выключена, вывод будет пустым или Docker сообщит, что такой службы нет.

### Перезапустить одну службу ⚠

**Назначение.** Вернуть службу в рабочее состояние или применить правку `.env`.

**Условия.** Сначала сохраните сведения о сбое: журнал контейнера удаляется вместе с ним. Выполните `sudo scripts/diag.sh`.

**Порядок.**

```bash
sudo scripts/ctl.sh restart backend
sudo scripts/status.sh --wait 180
```

Команда пересоздаёт контейнер из готового образа и заново читает `.env`. Сборки образов нет, зависимые службы не трогаются. Вместо `backend` подставьте имя нужной службы: `postgres`, `redis`, `livekit`, `asr`, `web`, `livekit-sip`, `livekit-egress`, `mediamtx`.

**Последствия.**

| Служба | Что почувствуют пользователи |
| --- | --- |
| `web` | сайт и API недоступны несколько секунд; страницы и встречи переподключаются сами |
| `backend` | несколько секунд ошибок интерфейса и API, звонки продолжаются |
| `asr` | пауза в стенограмме идущих встреч, звонки не прерываются |
| `livekit` | **все звонки прерываются на несколько секунд**, участники подключаются сами; идущие записи и эфиры могут завершиться |
| `livekit-egress` | **идущие записи и эфиры закрываются**, записанная часть сохраняется; звонки не прерываются |
| `livekit-sip` | идущие телефонные звонки обрываются; звонки из браузера и приложений не затрагиваются |
| `mediamtx` | зрители с низкой задержкой переходят на обычный поток; запись и внешние площадки продолжаются |
| `postgres`, `redis` | краткая недоступность всего приложения |

### Перезапустить все службы ⚠

```bash
sudo scripts/ctl.sh restart
```

Команда пересоздаёт **все** контейнеры проекта, включая `postgres`, `livekit` и `livekit-egress`. Встречи, записи и эфиры прерываются. Используйте её только вне рабочих часов и только если перезапуск одной службы не помог.

### Остановить и запустить ⚠

**Назначение.** Подготовить сервер к работам с диском, переносу или перезагрузке.

```bash
sudo scripts/ctl.sh stop                 # весь проект
sudo scripts/ctl.sh stop web backend     # только перечисленные службы
sudo scripts/ctl.sh start                # запустить всё
```

**Последствия.** `stop` останавливает контейнеры. Данные, образы и `.env` остаются. Система или выбранная служба недоступна до `start`. Если идёт запись или эфир, `livekit-egress` получает до 60 секунд на закрытие файла. Записанная часть сохраняется, встреча и эфир на этом обрываются, поэтому сначала проверьте **Администрирование → Встречи → Встречи**.

`start` запускает недостающие контейнеры без сборки. Контейнер, у которого изменилась конфигурация, пересоздаётся, остальные продолжают работать.

### Проверить службу низкой задержки

`mediamtx` принимает поток от `livekit-egress` и отдаёт его зрителям с задержкой около 3 секунд. Если служба не работает, эфир, запись и площадки продолжаются, а зрители смотрят обычный поток.

1. Откройте идущий эфир и посмотрите строку «Низкая задержка» в [панели диагностики эфира](Панель-диагностики-эфира).
2. Прочитайте журнал: `sudo scripts/logs.sh mediamtx --tail 100`.
3. Перезапустите службу ⚠: `sudo scripts/ctl.sh restart mediamtx`.
4. Если контейнера нет, образ не загрузился. Повторите ⚠ `sudo scripts/video.sh enable`: скрипт докачает образы и запустит службу.

Вернётся ли низкая задержка к уже идущему эфиру после перезапуска, не подтверждено. Проверьте результат на следующем эфире.

### Применить правку `.env` ⚠

| Что изменили | Чем применить | Что произойдёт |
| --- | --- | --- |
| обычный параметр службы | `sudo scripts/ctl.sh restart <служба>` | контейнер пересоздан |
| параметры нескольких служб | `sudo scripts/ctl.sh start` | пересоздаются только затронутые контейнеры |
| `LIVEKIT_PUBLIC_IP`, `LIVEKIT_NODE_IP`, `LIVEKIT_STUN_SERVERS` | `sudo scripts/medianet.sh apply` | адреса пересчитаны, `livekit` и `backend` перезапущены |
| `LIVEKIT_TCP_PORT`, `LIVEKIT_UDP_PORT` | только `sudo scripts/medianet.sh ports --tcp N --udp N`, вручную не правьте | см. [Как настроить LiveKit](Как-настроить-LiveKit) |
| `NGINX_*` | `sudo scripts/install.sh --profile <профиль> --from nginx` | см. [Как настроить сертификаты](Как-настроить-сертификаты) |
| `VIDEO_ENABLED`, `SIP_ENABLED` | только `video.sh` и `sip.sh` или кнопки в разделах | вручную не правьте |

`APP_MASTER_KEY` не меняйте: зашифрованные данные перестанут читаться. Перечень параметров — [Справочник: конфигурация](Справочник-конфигурация).

## Что получится

- `sudo scripts/status.sh` завершается строкой «Все сервисы работают».
- В **Обзор → Обзор** службы зелёные.
- Для окончательной проверки выполните `sudo scripts/smoke-test.sh`: ожидаемая строка `Smoke test: PASS`.

## Если не получается

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| `Неизвестный сервис/аргумент` | опечатка в имени или старая версия скриптов | сверьте имя с таблицей выше; на старой версии обновите сервер |
| `ctl.sh` не находит образ | образ удалён или не собран | `sudo scripts/rebuild.sh <служба>` для `backend`, `asr`, `web`, `livekit` |
| `health=unhealthy` после запуска | служба не поднялась | `sudo scripts/logs.sh <служба> --tail 300`, затем [Диагностика](Диагностика) |
| «Все сервисы работают», а записи нет | видеоподсистема выключена в `.env` | `sudo scripts/video.sh status` |
| Кнопки в разделах неактивны | помощник обновлений не работает | [Решение проблем: обновление и службы сервера](Решение-проблем-обновления) |
| Служба снова падает после перезапуска | причина не устранена | `sudo scripts/diag.sh`, файл `resources.txt`: память, диск, перезапуски |
