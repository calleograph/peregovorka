# Как настроить LiveKit

*Для кого: администратор сервера и сетевой администратор.*

## Зачем это нужно

LiveKit — сервер звонков. Он передаёт звук, видео и показ экрана. Страница сайта идёт через HTTPS, а медиа идёт от клиента прямо на сервер, мимо HTTP-прокси. Поэтому сайт может открываться, а звонок не подключаться.

Установщик настраивает LiveKit сам. Эта страница нужна, чтобы открыть порты, проверить адреса и изменить их без поломок.

## Когда пригодится

- Сервер стоит за NAT или в закрытой сети.
- Пользователи из интернета не слышат друг друга, а офис слышит.
- Порт занят, и его нужно сменить.
- Адрес сервера или провайдер поменялся.

## Что потребуется

- `sudo` на сервере.
- Доступ к межсетевому экрану и маршрутизатору, если они есть на пути.
- Свои номера портов: `sudo grep -E '^LIVEKIT_(TCP|UDP)_PORT=' /opt/peregovorka/.env`.

Установщик берёт 17881/tcp и 17882/udp, а если они заняты, выбирает другие.

| Порт | Куда | Зачем |
| --- | --- | --- |
| `LIVEKIT_UDP_PORT`/udp | снаружи на сервер | основной путь звука и видео |
| `LIVEKIT_TCP_PORT`/tcp | снаружи на сервер | запасной путь, если UDP закрыт; качество хуже |
| 443/tcp | на прокси или nginx | сигнализация `/livekit/` вместе с сайтом |
| `LIVEKIT_HTTP_PORT`/tcp | только `127.0.0.1` | API для служб сервера, наружу не открывать |

## Где найти

- **Администрирование → Система → Сетевая доступность**: точный перечень портов, заявка сетевому администратору, кнопка **Проверить медиасоединения**.
- В терминале: `scripts/medianet.sh`, `scripts/ports.sh`.

## Как это сделать

### Проверить настройку

Операция ничего не меняет.

```bash
cd /opt/peregovorka
sudo scripts/medianet.sh check      # адреса, порты, NAT, межсетевой экран, правила проброса
sudo scripts/ports.sh --format md   # перечень правил для сетевого администратора
sudo scripts/smoke-test.sh          # строки LiveKit, /rtc/v1, RTC TCP и RTC UDP
```

UDP снаружи с самого сервера не проверить. Окончательная проверка — звонок с устройства из нужной сети.

### Открыть порты

`medianet.sh` и обычная установка межсетевой экран не меняют, порты открываете вы. Пример для `ufw` со значениями по умолчанию:

```bash
sudo ufw allow 17881/tcp
sudo ufw allow 17882/udp
```

Если сервер за NAT, пробросьте **те же номера** на адрес сервера в локальной сети. LiveKit сообщает клиентам именно эти номера, поэтому смена номера на маршрутизаторе ломает подключение.

### Понять режим адресов

Адреса вычисляет `scripts/medianet.py` при установке, обновлении и по команде `medianet.sh apply`.

| Как стоит сервер | Режим `LIVEKIT_MEDIA_MODE` | Что получают клиенты |
| --- | --- | --- |
| публичный адрес на интерфейсе | `direct` | этот адрес |
| за NAT, адрес определяется сам | `nat-stun` | публичный адрес и адрес в локальной сети |
| за NAT, адрес задан явно | `nat-manual` | заданный адрес и адрес в локальной сети |
| только локальная сеть | `lan` | адрес в локальной сети |

В `.env` задаются два параметра: `LIVEKIT_NODE_IP` (адрес интерфейса сервера) и `LIVEKIT_PUBLIC_IP` (`auto`, `off` или IPv4). Значения `LIVEKIT_MEDIA_MODE` и `LIVEKIT_RTC_*` вручную не правьте.

В режиме `nat-stun` публичный адрес определяется через STUN при запуске и проверяется раз в 5 минут. Если новый адрес подтвердился три раза подряд, LiveKit перезапускается сам, а участники переподключаются.

### Задать публичный адрес ⚠

**Назначение.** Исправить неверно определённый адрес или перейти на работу только в локальной сети.

**Условия.** Выбирайте время без важных встреч.

```bash
sudo scripts/medianet.sh apply --public-ip 192.0.2.10   # явный адрес
sudo scripts/medianet.sh apply --public-ip off          # только локальная сеть
sudo scripts/medianet.sh apply --public-ip auto         # определять автоматически
sudo scripts/medianet.sh apply                          # пересчитать по текущему .env
```

**Последствия.** Меняется `.env`, перезапускаются `livekit` и `backend`. Звонки прерываются, клиенты подключаются сами. В конце скрипт повторяет проверку.

### Сменить порты ⚠

**Назначение.** Освободить занятый порт или привести его к правилам сети.

**Условия.** Заранее откройте новые порты на межсетевых экранах и измените проброс. Скрипт этого не сделает. Если не подготовить сеть, после смены никто не подключится.

```bash
sudo scripts/medianet.sh ports --tcp 7881 --udp 7882
```

**Порядок внутри команды.** Проверка, что порты свободны и лежат в диапазоне 1024–65535, запись в `.env`, пересчёт адресов, перезапуск `livekit` и `backend`, проверка.

**Последствия.** Звонки прерываются. Клиенты с закрытыми новыми портами не подключатся.

Не правьте `LIVEKIT_TCP_PORT` и `LIVEKIT_UDP_PORT` вручную: внутренний и опубликованный номера должны совпадать, а адреса пересчитываются этой командой.

### Настроить параметры ядра ⚠

На выделенном сервере установщик применяет их сам. На общем сервере они влияют на все приложения, поэтому решение принимаете вы.

```bash
sudo scripts/tune-kernel.sh           # показать значения, ничего не меняет
sudo scripts/tune-kernel.sh --apply   # применить, скрипт спросит подтверждение
```

**Последствия.** Создаётся файл `/etc/sysctl.d/99-peregovorka.conf`. Увеличиваются сетевые буферы и очередь, `vm.overcommit_memory` становится 1. Чужие файлы не правятся. Значения — [Справочник: порты и сеть](Справочник-порты-и-сеть#параметры-ядра-для-webrtc).

### Что менять не нужно

- **Версию.** `update.sh` сам ставит проверенный тег `LIVEKIT_IMAGE_TAG`. Значение `latest` не используйте.
- **Ключи API.** `LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET` создаёт установщик, их используют несколько служб.
- **TURN.** Установщик его не настраивает. Клиенты, которым разрешён только исходящий 443/tcp через прокси, к медиа не подключатся.

Перенос LiveKit на отдельный сервер и кластер штатно не поддерживаются. Вопросы нагрузки — [Производительность и масштабирование](Производительность-и-масштабирование).

## Что получится

- `sudo scripts/medianet.sh check` не показывает ошибок.
- В `smoke-test.sh` строки LiveKit без `FAIL`: `/rtc/v1` отвечает 400 и `join_request`, WebSocket — 101.
- Участники из нужной сети слышат и видят друг друга.

## Если не получается

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| Сайт открылся, звонок «подключается» | закрыты медиапорты или неверный адрес | `sudo scripts/medianet.sh check`, откройте порты |
| Работает только в офисе | нет проброса или неверный публичный адрес | проверьте проброс, `sudo scripts/medianet.sh apply --public-ip <IPv4>` |
| Признаки CGNAT или двойного NAT | провайдер не даёт внешний адрес | нужен публичный адрес, VPN или другая площадка |
| `TCP N уже занят на сервере` | порт занят другой программой | выберите другой порт |
| `/rtc/v1` отвечает 404 | устаревший LiveKit | обновите сервер |
| Правка `.env` не подействовала | адреса не пересчитаны | `sudo scripts/medianet.sh apply` |

Разбор симптомов — [Решение проблем: звонки и сеть](Решение-проблем-звонков-и-сети).
