# GitHub Actions: как работать быстро и без лишних прогонов

## Доступ без `gh`
* Токен — из хранилища git: `printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p'`. Только для чтения журналов и управления запусками своего репозитория; в вывод не печатать.
* Запуски коммита: `GET /repos/{o}/{r}/actions/runs?head_sha=<sha>` → `jobs_url` → шаги с `conclusion`. Журнал задачи: `GET /actions/jobs/{id}/logs` (редирект, `curl -L`), искать `##[error]`, `FAIL`, `Exception` и строки над ними.
* Ручной запуск: `POST /actions/workflows/<file>/dispatches {"ref":"<ветка>"}` (нужен `workflow_dispatch`). Отмена: `POST /actions/runs/{id}/cancel`. Артефакты: `GET /actions/runs/{id}/artifacts` → `archive_download_url`.
* Ждать — фоновой командой с циклом `until …; do sleep 30; done` или монитором, который печатает **только** завершённые задачи и упавшие шаги и сам выходит. Не опрашивать вручную каждые полминуты.

## Быстрые и длинные проверки
* Отдельный workflow для независимого модуля (`paths:`), основной — `paths-ignore:` на этот модуль: правка только модуля не запускает чужие длинные тесты. Фильтр путей **к тегам не применяется** — теги выпуска всегда идут через полный CI.
* Внутри workflow: быстрые задачи на каждый коммит, длинные (`needs: [быстрые]`) — только `main`, теги и ручной запуск (`if: github.ref_type == 'tag' || github.ref == 'refs/heads/main' || github.event_name == 'workflow_dispatch'`).
* Шаблон веток в `on.push.branches` (например, только `feat/**`): ветка `fix/…` CI не запустит — проверять имя ветки до ожидания.
* `timeout-minutes` у задачи и у шагов с внешними процессами — зависший шаг иначе живёт до 6 ч.
* Снимки экрана и отчёты проверок — артефакт с `if: always()`: виден и при падении.

## Windows-раннеры (windows-2025)
* `shell: pwsh` по умолчанию; аргументы с точкой — в кавычках: `"-c.extraMetadata.version=$v"` (иначе PowerShell режет по точке).
* Администратор есть: `New-SelfSignedCertificate`, `Import-Certificate` в LocalMachine, правила брандмауэра (`New-NetFirewallRule … -Action Block` — проверка «без сети»), `msiexec /qn /l*v` с журналом и выводом хвоста при ошибке.
* Ловушки самого Electron-приложения на раннере (холодный запуск, снимки CDP, временный профиль, PowerShell 5.1) — `electron-windows-client`, references/windows-pitfalls.md.
* Секреты в `run:` не печатать; свой пароль, созданный в шаге, — `::add-mask::` до записи в `$GITHUB_ENV`.

## Перед ожиданием CI
Всё, что можно, — локально (типы, модульные тесты, быстрые сценарии): круг CI на Windows стоит минуты, а не секунды. Нашёл ошибку в CI — сначала понять причину по журналу, исправить в общем коде и, если она повторяемая, записать в «Ловушки» профильного навыка.
