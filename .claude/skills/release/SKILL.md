# Выпуск версии Peregovorka

Главное правило: **CHANGELOG — для пользователя. HISTORY — для разработчика. README — витрина продукта.** Полные правила — [docs/VERSIONING.md](../../../docs/VERSIONING.md).

Пройди шаги по порядку и не пропускай ни одного, даже если о нём не просили:

0. **Ревизия сторонних компонентов (обязательна всегда, и для patch).** `python3 scripts/deps.py review --release X.Y.Z` → решения по каждой новой версии (обновить и проверить либо отложить: причина, задача DEP-N в docs/DEPENDENCIES.md, дата) → `apply`, `freeze`, `npm install`, `sync` → сборка образов и профильные проверки → `python3 scripts/deps.py verify --online --max-age 3` → `deps.py report` в отчёт. `release.sh` без этого не выпускает. См. docs/DEPENDENCIES.md.
1. **VERSION.** Решить: patch (законченный проверенный блок, исправления) или minor (заметный функциональный этап). Только для документации версию не поднимать.
2. **CHANGELOG.md, раздел `## Unreleased`.** Подразделы `### Новые возможности`, `### Улучшения`, `### Исправления`, `### Для администраторов` (пустые не писать).
   Простым языком: что появилось и чем полезно, что стало лучше. Никаких имён классов и файлов, «тест падал», «CI был красный», деталей рефакторинга.
   В «Для администраторов» — порты, миграции, требования, ручные действия, изменения доступа и API.
3. **HISTORY.md** — технический журнал выпуска: причины, решения, что и как проверено (реально проверено / автотест / code review / не проверено), ограничения.
4. **PROJECT.md** — состояние, ближайшие планы, известные проблемы.
5. **README.md** — проверить: новые ключевые возможности, устаревшие скриншоты (≤ 2, без ошибок на снимке), Быстрый старт, требования и порты, интеграции, API, ссылки на docs/. Изменилось — обновить в этом же выпуске.
6. **docs/ и вики** — обновить затронутые документы; `python3 scripts/check_wiki.py`, версия и дата в шапках затронутых страниц `wiki/`, `_Footer.md` (порядок — `wiki/Сопровождение-вики.md`).
7. **Проверки** — тесты backend и frontend, сборка; при изменениях комнаты — живые сценарии `tests/live/`; после push — зелёный CI.
8. **Выпуск** — `./scripts/release.sh patch|minor` (переносит Unreleased в раздел версии, пишет VERSION, коммит «Релиз X.Y.Z», тег), затем `./scripts/release.sh push`.

Клиент Windows выпускается отдельно (`desktop-vX.Y.Z`, навык `desktop-dev`). Общая дисциплина выпуска — глобальный `release-ci-discipline` (если установлен); работа с CI — `github-actions-ci`.

Ловушки выпуска:
* Новая таблица БД — миграция Alembic **и** строка в `backend/app/services/config_backup/registry.py` (иначе падает `test_config_registry`); новое поле группы настроек выгружается в резервную копию конфигурации само.
* `deps.py review` без решения по каждому «нужно решение»: новая версия — обновить или оформить `deferred` (менять `deferred.version` у уже отложенного, не заводя новую запись); изменившийся digest образа — `pin-images`, `apply`, затем проверить образ запуском (миграции на нём).
* Живые сценарии с лимитами запросов (календарь — 40 запросов списка в минуту на пользователя) два раза подряд на одном стенде могут упереться в лимит: подождать минуту.
* Вики: версию в шапке меняют только на страницах, содержание которых сверено с новой версией; остальные остаются со старой (предупреждение `check_wiki.py` ожидаемо).

В отчёте владельцу перечисли, что сделано на каждом шаге, и честно отметь непроверенное.
