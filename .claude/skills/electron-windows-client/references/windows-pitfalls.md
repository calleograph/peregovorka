# Ловушки Windows и Windows CI (Electron, NSIS, WiX, PowerShell)

Формат: симптом → причина → как предотвращено.

## Запуск и окно
* Окно «not found» только на Windows → `file://` склеен вручную (`file://C%3A/…`) → `pathToFileURL` + тест с `path.win32`.
* Кнопка ничего не делает → новый канал IPC не добавлен в список preload → тест «каждый `call("…")` оболочки разрешён и имеет обработчик».
* Отчёт `--diagnostics` говорит «оболочка не отрисована» на машине CI → холодный первый запуск дольше фиксированных 8 с → ждать показа окна (до 60 с),
  проверка отрисовки — с повторами 15 с, иначе пользователь на медленном компьютере увидит ложную ошибку.
* Проверка зависла на `Page.captureScreenshot` → окно не рисует кадры в сеансе без рабочего стола → предел времени у каждого вызова CDP, снимок необязателен;
  ключи `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding`.
* Сравнение «файлы данных до/после обновления» падает на `DIPS-wal` → служебные файлы Chromium появляются и исчезают сами → сравнивать только свои файлы.
* Профиль проверок временный (`--user-data-dir`) → у шага обновления нет `%APPDATA%\<app>` → данные пользователя для проверки обновления создавать явно.

## Установщики
* NSIS (electron-builder) не регистрирует свой протокол ссылок → `customInstall`/`customUnInstall` в `include.nsh` (SHCTX, не удалять при `--updated`).
* WiX: относительный `-bindpath` разрешается не от рабочего каталога → пустой MSI; только абсолютные пути, `-wx`, проверка размера пакета (порог снизу и сверху).
* WiX: файлы должны входить в `ComponentGroup` под `Feature` (иначе WIX0267); значок «Программ и компонентов» — только `.ico` (exe попадает в MSI несжатым,
  +250 МБ); `--` нельзя в XML-комментарии.
* Свойства MSI для политик с «запоминанием» при обновлении (RegistrySearch → SetProperty) — цель `msi` electron-builder этого не умеет, нужен свой WiX.
* Настройки организации в корпоративный MSI — строками таблицы `Property` копии пакета **до** подписи; EXE после подписи не меняется (настройки — `.reg`/GPO).

## PowerShell и CI на Windows
Общие правила раннеров (кавычки в pwsh, права администратора, маскирование) — навык `github-actions-ci`.
* Вывод дочернего Windows PowerShell 5.1 по-русски → `[Console]::OutputEncoding = UTF8` в родительском pwsh.
* `pgrep -f`/`pkill -f` с шаблоном из собственной команды убивает свою же оболочку (Linux-агент) — искать `ps -eo pid,args | grep "[x]yz"`.
* Самоподписанный сертификат: до импорта в Root/TrustedPublisher `Get-AuthenticodeSignature` → `UnknownError` (подпись цела, издатель не доверен) —
  проверять это явно, а не считать подпись «доверенной».
* Действия на машине CI (импорт сертификата в Root, правило брандмауэра для запуска без сети) допустимы — машина одноразовая; у пользователей — никогда.

## Linux-стенд для Electron
* Xvfb без root, `--no-sandbox` только для проверок; `safeStorage` без связки ключей недоступен — заглушка шифрования только в режиме испытаний из исходников.
* Шум `libGL`/`EGL` в журнале под Xvfb — не ошибка приложения.
