# Подпись, ключи обновлений, корпоративные сборки

## Два разных ключа
| | Сертификат подписи кода (Authenticode) | Ключ обновлений (Ed25519) |
| --- | --- | --- |
| Подписывает | exe, установщики EXE/MSI | манифест новых версий |
| Проверяет | Windows (SmartScreen, UAC, AppLocker, «Доверенные издатели») | само приложение до загрузки и установки |
| Хранится | хранилище Windows подписывающего узла (неэкспортируемый) или секрет CI (PFX) | секрет CI или файл 0600 на узле |
Смена одного не затрагивает другой. Закрытые части — никогда в git, журналах CI, пакетах, базе данных, браузере; CI ищет их в пакетах перед публикацией.

## Режимы подписи в CI
* Нет сертификата → неподписанная **тестовая** сборка, предварительный выпуск с явной пометкой.
* Самоподписанный (издатель = субъект) → подписанная тестовая; открытая часть `.cer` прикладывается для распространения доверия администратором.
* Сертификат УЦ → доверенный выпуск. Переменная «доверенный режим»: без сертификата УЦ и ключа обновлений выпуск **падает**, а не публикует тихо неподписанное.
* На ветках без секретов — **одноразовые** сертификат и ключ, созданные на машине CI: проверяют весь путь подписи и обновления, в выпуски по тегу не попадают.
* Проверки: EKU Code Signing `1.3.6.1.5.5.7.3.3`, закрытый ключ, срок; `Get-AuthenticodeSignature` и `signtool verify /pa`; электрон-билдер подписывает
  сам (`CSC_LINK`/`CSC_KEY_PASSWORD`), MSI — signtool отдельно.
* Запись секретов репозитория может быть запрещена правилами агента — не обходить, а дать владельцу готовые команды `gh secret set`.

## Обновление полным установщиком
Манифест (версия, заметки, страница, файл: имя, адрес, размер, SHA-256) + подпись Ed25519; открытые ключи встраиваются при сборке, **несколько через
запятую** — для смены ключа (выпуск N несёт старый и новый, подписан старым; дальше — новым). Клиент: проверка подписи → «Скачать» (повтор после
обрыва, проверка места, размер и SHA-256, при подписанной программе — Authenticode того же издателя) → «Установить»: запустить установщик
`/S --updated --force-run`, **выйти только после события `spawn`**, никогда во время звонка/показа экрана. Только версия новее установленной.
Корпоративное зеркало: установщик рядом с манифестом (адрес из подписанного манифеста не нужен — подлинность по SHA-256).
`electron-updater` без сертификата УЦ ставит неподписанное (проверка издателя выключена) — поэтому независимая подпись манифеста.
Установка MSI под управлением администратора сама не обновляется.

## Корпоративная подпись без передачи ключа
Подписывающий агент на доверенном Windows-узле организации: свой токен (на сервере — хеш), сам опрашивает сервер, выполняет **фиксированный список**
заданий-данных (создать сертификат, зарегистрировать по отпечатку, проверить, собрать выпуск) — никаких команд с сервера. Источник исходных пакетов задан
**на узле**, пакеты сверяются с SHA256SUMS и подписью издателя. Сведения о сертификате сервер берёт из DER, а не со слов агента. Сервер принимает
пакет, только если SHA-256 загруженного совпал и подпись `Valid` выбранным сертификатом. PFX импортируется на узле (пароль вводится там же).
Доверие на компьютерах сотрудников распространяет администратор (GPO: Root, Intermediate, Trusted Publishers) — программа корни не меняет.
