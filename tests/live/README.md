# Живой smoke-test комнаты

Проверка «как у пользователя»: три настоящих браузера (Chromium-семейство с поддельными камерой и микрофоном) входят в комнату через **настоящий LiveKit** и проходят сценарий.
В CI не запускается (нужны браузер и бинарник LiveKit); **запускать перед каждым релизом, который меняет страницу комнаты, экран «перед входом», чат, звук или события реального времени.** Статические тесты этого не заменяют (история 0.8.5: «more hooks»).

## Что проверяется
вход троих · звук идёт по WebRTC (пакеты считаются через `getStats`) · камера включается/выключается (видео ↔ аватар) · аватар с картинкой и инициалы · «Заглушить для себя» (меню, метка, звук только у себя) ·
поднятая рука доходит до остальных и звучит · сообщение чата доходит и звучит · перезагрузка страницы внутри встречи (заглушённый остаётся заглушённым) · обрыв сети на 6 с и возврат · ошибок страницы нет.
Не проверяется: стенограмма (нужен ASR), запись, показ экрана, Draw.io, реальные окна запроса разрешений (в автоматизации их нет — только эмуляция в других проверках).

## Запуск
1. `livekit-server` той же версии, что в `.env.example` (`LIVEKIT_IMAGE_TAG`), с ключом `devkey` и секретом из 40 символов `s`, на `127.0.0.1:7880`, RTC-порты 50000–50100 (`node_ip: 127.0.0.1`).
2. `python tests/live/devserver_live.py` — backend на 8000 (нужны зависимости backend + Pillow); `npm run dev` в `frontend` — страница на 5173 (прокси на 8000).
3. `pip install websockets`; `python tests/live/smoke_room.py` (переменные: `BROWSER_PATH`, `PEREGOVORKA_URL`, `SMOKE_OUT`).
Между запусками состояние встречи остаётся в памяти backend — перезапускайте стенд для чистого прогона.
