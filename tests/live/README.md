# Живой smoke-test комнаты

Проверка «как у пользователя»: три настоящих браузера (Chromium-семейство с поддельными камерой и микрофоном) входят в комнату через **настоящий LiveKit** и проходят сценарий.
В CI не запускается (нужны браузер и бинарник LiveKit); **запускать перед каждым релизом, который меняет страницу комнаты, экран «перед входом», чат, звук или события реального времени.** Статические тесты этого не заменяют (история 0.8.5: «more hooks»).

## Что проверяется
вход троих · звук идёт по WebRTC (пакеты считаются через `getStats`) · камера включается/выключается (видео ↔ аватар) · аватар с картинкой и инициалы · «Заглушить для себя» (меню, метка, звук только у себя) ·
поднятая рука доходит до остальных и звучит · сообщение чата доходит и звучит · перезагрузка страницы внутри встречи (заглушённый остаётся заглушённым) · обрыв сети на 6 с и возврат · ошибок страницы нет.
Не проверяется: стенограмма (нужен ASR), запись, показ экрана, Draw.io, реальные окна запроса разрешений (в автоматизации их нет — только эмуляция в других проверках).

## Запуск
1. `livekit-server` той же версии, что в `.env.example` (`LIVEKIT_IMAGE_TAG`), с ключом `devkey` и секретом из 40 символов `s`, на `127.0.0.1:7880`, RTC-порты 50000–50100 (`node_ip: 127.0.0.1`).
2. `python tests/live/devserver_live.py` — backend на 8000 (нужны зависимости backend + Pillow); `npm run dev` в `frontend` — страница на 5173 (прокси на 8000).
3. `pip install websockets`; `python tests/live/smoke_room.py` (переменные: `BROWSER_PATH`, `PEREGOVORKA_URL`, `SMOKE_OUT`).
Между запусками состояние встречи остаётся в памяти backend — перезапускайте стенд для чистого прогона.

## Дополнительные сценарии
Запускаются на том же стенде (`devserver_live.py` + LiveKit + `npm run dev`):
* `scenario_chat_files.py` — вложения в чате (картинка, просмотрщик, документ, запрещённый тип);
* `scenario_history_protocol.py` — реплики стенограммы (подсовываются в поток вместо ASR через `/__dev/segment`) → завершение встречи → история → протокол с подставной LLM на порту 9100 → экспорт `.docx/.html/.md/.pdf`;
* `scenario_livekit_restart.py` — надёжность: LiveKit останавливается на 10 с во время встречи (`LIVEKIT_DIR` — каталог с `livekit-server` и `lk.yaml`), клиенты должны вернуться сами.
Комнаты стенда: у каждого сценария своя (`sales`, `pm`, `legal`, `arch`), поэтому они не мешают друг другу; между полными прогонами стенд лучше перезапускать.
* `scenario_presentation_floor.py` — презентационная комната: слушатель не публикует звук, руководитель «даёт слово» через меню плитки; завершить встречу для всех может только руководитель (кнопки нет, API отвечает 403);
* `scenario_screen_share.py` — показ экрана (в headless настоящего экрана нет — источник подменён холстом): сцена у второго участника, кадры декодируются, остановка.
* `scenario_bitrix_profile.py` — Bitrix24 как источник профиля: настоящая админка + подставной портал на `localhost:9100`; проверка соединения, пробный поиск, фоновое обновление должности/подразделения/фото, вход при недоступном портале (вход и комнаты не замедляются, прежние данные остаются).
* `scenario_public_api.py` — публичный API: интеграция и ключ создаются в настоящей админке, затем API вызывается из внешнего процесса (права, курсоры, форматы стенограммы, лимиты, отзыв ключа). Блокировщик рекламы на машине может подмешивать свой `<script>` в ответы — сценарий это учитывает.
* `scenario_recordings.py` — общая запись: два участника с разным началом, завершение встречи не ждёт сведения, Range, права, блок «Записи» и плеер в браузере (нужен `FFMPEG_BIN` у стенда; комната `north`);
* `scenario_recordings_real.py` — **настоящий звук через LiveKit**: два браузера с поддельным микрофоном, который играет русскую речь (SAPI: `make_speech.ps1`), настоящий ASR-воркер без модели (`asr_recorder_live.py`, venv ASR с `livekit`), затем сведение и проверка `analyze_mix.py`. Переменные: `ASR_PY`, `REC_DIR` (`<LIVE_DATA>/recordings`), `FFMPEG_BIN`, `REC_WORK`; запускать python из venv ASR (нужны `numpy`, `websockets`);
* `scenario_player.py` — плавающий плеер: волна по настоящим пикам (речь/пауза), перемотка щелчком/перетаскиванием/касанием, субтитры и стенограмма (синхронизация после перемотки и смены скорости, поиск), мини-плеер, переходы между разделами без остановки звука, перетаскивание и границы окна, Esc/пробел, замена записи другой, запись без волны, телефон (нужен `FFMPEG_BIN` у стенда; комната `north`);
* `scenario_guest.py` — гость по ссылке: вход без учётной записи, только чат, звук идёт, административные API закрыты (комната `it-1`, гостевая ссылка стенда).
* `scenario_presentation_perf.py` — презентация на настоящем LiveKit (руководитель + два зрителя): зрители не запрашивают микрофон и не публикуют; серверные запреты проверяются у самого LiveKit и настоящим SDK; «дать слово» (микрофон, камера, экран «Экономный 720p» по `getStats()`, доска) и «забрать слово» при идущем показе; обновление страницы; старый токен после отзыва; страница «Производительность». Нужен LiveKit с `prometheus_port: 6789` и webhook на backend (`http://127.0.0.1:8000/internal/v1/livekit/webhook`, ключ `devkey`); python с пакетами `websockets` и `livekit`;
* `scenario_audience_1000.py` — список зрителей на 1000 синтетических людей без WebRTC (dev-маршрут `/__dev/audience`): виртуализация, поиск, перенос между сценой и списком при выдаче/отзыве слова.
* `scenario_presentation_guest.py` — гость по ссылке в презентационной комнате (комната `stage` стенда): проверки оборудования нет, браузер не запрашивает микрофон и камеру, у сервера звонков у гостя нет прав и дорожек (общие перехватчики и чтение состояния LiveKit — `lk_helpers.py`).
