# Peregovorka

### Видеовстречи на сервере вашей организации: стенограмма, протоколы, трансляции и корпоративные интеграции

Сотрудники входят доменной учётной записью, речь каждого участника автоматически превращается в текст, а после встречи готовы протокол, резюме и карта разговора.
Записи, стенограммы и распознавание речи — на вашем сервере. В языковую модель уходит только текст: без паролей и ключей, а при обезличивании — без имён, контактов и реквизитов.

## Для чего это

Peregovorka заменяет внешние сервисы видеосвязи, когда разговоры и записи должны оставаться внутри организации. Сотрудники проводят встречи в браузере или приложении, система сама записывает «кто что сказал», а после встречи готовит протокол с решениями и поручениями.

Какие задачи решает:

- внутренние совещания без передачи звука и записей посторонним сервисам;
- протокол вместо ручного конспекта: решения, задачи «кто — что — срок», открытые вопросы;
- встречи с внешними участниками по гостевой ссылке;
- массовые эфиры для сотен и тысяч зрителей;
- единое место для материалов встреч с правами и сроками хранения.

## Как устроена система

**Сервер разворачивается в инфраструктуре организации:** на физическом сервере, виртуальной машине или в своём облаке. Он работает в контейнерах Docker на Linux. Внешних обязательных сервисов нет: разработчик проекта не получает ваших данных и не участвует в работе сервера.

**Клиенты подключаются к этому серверу.** Администратор сообщает сотрудникам адрес вида `https://meet.example.org`. Дальше можно работать в браузере или в приложении: внутри приложений тот же интерфейс сервера, поэтому новые функции приходят вместе с обновлением сервера.

## Безопасность и конфиденциальность

- **Данные у вас.** Звук, записи, стенограммы, распознавание речи и обезличивание работают на вашем сервере.
- **В языковую модель уходит только текст.** Пароли и ключи убираются всегда, при обезличивании — ещё имена, контакты и реквизиты. Если обработка не выполнена, отправка блокируется. Проходит ли что-то наружу, решает администратор: модель можно не подключать.
- **Права проверяет сервер**, а не интерфейс; действия администраторов и руководителей попадают в журнал аудита.
- **Секреты хранятся зашифрованными**, вход защищён от перебора, доступна двухфакторная проверка, публичный API по умолчанию выключен.

Подробно: [Безопасность и приватность](https://github.com/calleograph/peregovorka/wiki/Безопасность-и-приватность), [Справочник для проверки ИБ](https://github.com/calleograph/peregovorka/wiki/Справочник-для-проверки-ИБ), [Обработка персональных данных](https://github.com/calleograph/peregovorka/wiki/Архитектура-Обработка-персональных-данных).

  C["Браузер, Windows,<br/>Linux, Android"] -->|"HTTPS"| P["Обратный прокси"]
  P --> W["web: nginx,<br/>интерфейс"]

## Быстрый старт

На чистом сервере:

```bash
wget -O install.sh https://raw.githubusercontent.com/calleograph/peregovorka/main/install.sh
chmod +x install.sh
sudo ./install.sh
```

Установщик сам поставит Docker и остальное, запустит службы, проверит их и покажет адрес, логин и первичный пароль администратора. Откройте адрес в браузере и войдите.

## Обновление

**Администрирование → Обновления и версии → Обновить проект** или `sudo ./scripts/update.sh`. Перед обновлением делается резервная копия базы, при сбое система возвращается к прежней версии. Подробно: [Как обновить и откатить](https://github.com/calleograph/peregovorka/wiki/Как-обновить-и-откатить).

## Резервирование и восстановление

`scripts/backup.sh` делает дамп базы, ключевой файл `.env` с главным ключом храните отдельно. Что копировать, как часто и что делать при каждом виде отказа: [Резервирование и восстановление](https://github.com/calleograph/peregovorka/wiki/Архитектура-Резервирование-и-восстановление).
